# GC 垃圾回收

- **三色并发标记算法+混合写屏障机制**

- 垃圾回收的核心是 可达性分析（Reachability Analysis） 。算法从根节点集合出发，遍历所有可达的对象。任何无法从根节点到达的对象都被视为“垃圾”。



## 垃圾回收流程

1. STW 标记准备（≈0.02 ms） 暂停世界
    - 扫描根对象 → 置灰 → 开启写屏障
2. 并发标记（与用户代码并行） ≈25 %CPU
    - 后台 goroutine 把灰变黑，白变灰，直到队列为空
3. STW 标记终止（≈0.05 ms）再次暂停
    - 处理写屏障记录 → 关闭屏障 → 统计存活对象
4. 并发清扫（零停顿）回收白色对象
   - 把白色内存归还给 mspan → 空闲链表 → 可能归还 OS

## 三色并发标记算法

- 三色并发标记算法（白色 垃圾、灰色 检查态、黑色 有用）
  1. 从 root 节点开始，使用广度优先算法遍历对象，把遍历到的对象标记为灰色，
     1. Root set根节点就是发现堆内存可达数据的一组起点，一般为bss段（全局变量）、数据段（静态变量）以及协程栈对应的元数据（局部变量、函数参数）
  2. 之后再使用广度优先算法遍历灰色节点的子节点，并把之前的灰色变成黑色，
  3. 然后一直重复遍历灰色结点的逻辑，直到没有灰色结点。

- 插入屏障（仅对堆上的数据有效）
  - 插入数据时把数据置为灰色
  - 需要 STW 扫描栈上数据
  - 插入写屏障不对栈生效，需要执行下 STW 的三色标记法（需要 STW 花费时间）

- 删除屏障
  - 删除了会先变成灰色，下一个周期变成垃圾（回收精度低）

## 混合写屏障(Hybrid Write Barrier)规则

1. GC开始将栈上的对象全部扫描并标记为⿊⾊（之后不再进⾏第⼆次重复扫描，⽆须STW）。
2. GC期间，任何在栈上创建的新对象均为⿊⾊。
3. 被删除的对象标记为灰⾊。
4. 被添加的对象标记为灰⾊。

- 并发期间，用户代码可能随时修改指针，导致黑色对象指向新白色对象，从而误删。Go 1.8 引入混合写屏障：
  - 插入屏障：黑引用白时，把白染灰（强三色不变式）
  - 删除屏障：断开灰→白引用时，把白染灰（弱三色不变式）
- 由于栈操作极频繁，栈上不开启屏障，只在堆生效；GC 结束再对栈做极短 STW 重扫。

## 内存回收的触发时间

- 内存分配量达到阀值触发 gc（每当内存扩大一倍时触发 gc）
- 定期触发 gc（最长 2 分钟触发 gc）
- 执行函数触发 gc `runtime.GC()`

## Gc 性能优化

- 对象数量越多 GC 压力越大（对象复用，或者大对象组合小对象）
- 内存逃逸也会增大 GC 压力
- 参数传递指针也会增加 GC 的压力，不要盲目传递指针

## 小结

1. Go V1.3普通标记清除法，整体过程需要启动STW，效率极低。
2. Go V1.5的三⾊标记加插⼊写屏障或删除写屏障⽅法，在堆空间启动写屏障，⽽在栈空间不启动，全部扫描之后，需要重新扫描⼀次栈（需要STW），效率普通。
3. Go V1.8三⾊标记法加混合写屏障机制，在栈空间不启动屏障机制，⽽在堆空间启动屏障机制。整个过程⼏乎不需要STW，效率较⾼。


## 分代扫描（Go 1.19+ 实验特性）：

并发标记阶段优先扫描 “新生代” 对象（近期分配的对象）；
减少对 “老年代” 对象的扫描频率，降低 GC 开销

## 内存整理（Go 1.20+ 实验特性）：

在标记终止后、并发清理前，新增 “内存整理” 阶段（可选）；
将存活的黑色对象移动到连续内存区域，减少内存碎片；
该阶段仍有短暂 STW，但能提升后续内存分配效率。
