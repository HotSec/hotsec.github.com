    4. 使用装饰器给函数添加额外的功能，例如日志、时间记录、web框架绑定路由等
    5. 关键点 实现一个函数，传递一个函数作为参数，添加功能后返回一个新函数

    6. ```python
         # 基本的装饰器
         import time

         def log_time(func):
            def _log(*args,**kwargs):
               beg = time.time()
               res = func(*args, **kwargs)
               print(f'use time:{time.time() - beg}')
               return res
            return _log

         @log_time  # `@` 就时一个语法糖，相当于mysleep = log_time(mysleep)
         def mysleep():
            time.sleep(1)

         mysleep()

         newsleep = log_time(mysleep)
         newsleep()


         # 接受两个参数：prefix 和 suffix，并在被装饰函数执行前后分别打印这两个参数
         def custom_decorator(prefix, suffix):
            def decorator(func):
               def wrapper(*args, **kwargs):
                     print(f"{prefix}: 函数 {func.__name__} 即将被调用")
                     result = func(*args, **kwargs)
                     print(f"{suffix}: 函数 {func.__name__} 调用完成")
                     return result
               return wrapper
            return decorator

         # 使用装饰器并传递参数
         @custom_decorator(prefix="START", suffix="END")
         def greet(name):
            print(f"Hello, {name}!")

         greet("Alice")

       ```

            # map 相当于把每个可迭代对象应用到函数
            # 第一个参数 function 以参数序列中的每一个元素调用 function 函数，返回包含每次 function 函数返回值的新列表。

19. 什么时闭包
    1. 绑定了外部作用域的变量的函数
    2. 即使程序离开外部作用域，如果闭包仍然可见，绑定变量不会被销毁
    3. 每次运行外部函数都会重新创建闭包

    4. ```python
         from functools import wraps

         def cache(func): # 装饰器
            store = {}  # 外部变量

            @wraps(func)
            def _(n):  # 闭包函数
               if n in store:
                     return store[n]
               else:
                     res = func(n)
                     store[n] = res
                     return res
            return _

         @cache
         def fib(n):
            if n <= 1:
               return 1
            return fib(n-1) + fib(n-2)

         print(fib(1))
         print(fib(2))
         print(fib(3))
         for i in range(100):
            print(fib(i))
       ```

        with open(file_path, "r+") as f:
            m = mmap(f.fileno(), 0)
            g_index = 0
            for index, char in enumerate(m):

                if not hasattr(cls, '_instance'):
                    cls._instance = super().__new__(cls,*args,**kwargs)
                return cls._instance

        class MyClass(Singleton):
            pass

        #使用装饰器实现单例模式
        def singleton(cls):
            _instance = {}
            def wrapper(*args, **kwargs):
                if cls not in _instance:
                    _instance[cls] = cls(*args, **kwargs)
                return _instance[cls]
            return wrapper

        @singleton
        class MyClass:
            pass
        

        # 使用元类实现单例模式
        class Singleton(type):
            def __call__(cls, *args, **kwargs):

                 else:
                       print(f"Failed to add: {observer}")

              def remove(self, observer):
                 try:
                       self.observers.remove(observer)
                 except ValueError:
                       print(f"Failed to remove: {observer}")

              def notify(self):  # 调用观察者的回调
                 [o.notify_by(self) for o in self.observers]


           class Formatter(Publisher):  # 继承自发布者
              def __init__(self, name):
                 super().__init__()
                 self.name = NameError
                 self._data = 0

              @property
              def data(self):
                 return self._data

              @data.setter
              def data(self, new_value):
                 self._data = int(new_value)
                 self.notify()


           class BinaryFormatter:
              """订阅者"""

              def notify_by(self, publisher):
                 print(
                       f"{type(self).__name__}: {publisher.name} has now bin data = {bin(publisher.data)}"
                 )


           df = Formatter("formatter")  # 发布者
           bf = BinaryFormatter()  # 订阅者
           df.add(bf)
           df.data = 3
           # BinaryFormatter: <class 'NameError'> has now bin data = 0b11

## tcp

### 建立连接（三次握手）

1. 客户端发送SYN包（同步序列号）
2. 服务器回复SYN+ACK包
3. 客户端发送ACK包确认，连接建立 

### 终止连接（四次挥手）

1. 一方发送FIN包（终止）
2. 对方回复ACK确认
3. 对方发送FIN包
4. 最初一方回复ACK，连接完全关闭 


### 请详细介绍一下 TCP 的三次握手机制，为什么要三次握手？

  - TCP 报文中两个重要的字段：一个是序号字段，另一个是确认号字段
    - 客户端向服务端发送一个不带额外数据的特殊报文段，该报文段的 SYN 标志位被置 1，生成一个初始序列号seq（client_num) ----- SYN 报文段。
    - 服务端收到客户端的 SYN 报文段后，会为该tcp分配缓存和变量，会向客户端发送一个 SYN+ACK 报文段，SYN标志位为1，确认号字段client_num+1 ,最后服务端也会选取一个server_num存放到序号字段seq ----- SYN+ACK 报文段。
    - 客户端收到服务端的 SYN+ACK 报文段后，会向服务端发送一个确认报文，SYN标志位为0，确认号字段ack（server_num + 1）， ----- ACK 报文段。
  - 如果不是三次握手，二次两次的话，服务器就不知道客户端是否接收到了自己的 SYNACK 报文段，从而无法建立连接；四次握手就显得多余了

### 详细介绍一下 TCP 的四次挥手机制，为什么需要四次挥手？

  - 当客户端要服务器断开连接时，客户端 TCP 会向服务器发送一个特殊的报文段，该报文段的 FIN 标志位会被置 1，接着服务器会向客户端发送一个确认报文段。
  - 然后服务器也会客户端发送一个 FIN 标志位为 1 的终止报文段，随后客户端回送一个确认报文段，服务器立即断开连接。客户端等待一段时间后也断开连接。
  - 其实四次挥手的过程是很容易理解的，由于 TCP 协议是全双工的，也就是说客户端和服务端都可以发起断开连接。两边各发起一次断开连接的申请，加上各自的两次确认，看起来就像执行了四次挥手。

### 为什么要有TIME_WAIT 状态

  - 因为客户端最后向服务器发送的确认 ACK 是有可能丢失的，当出现超时，服务端会再次发送 FIN 报文段，如果客户端已经关闭了就收不到了。
  - 避免新旧连接混杂

### 服务器出现了大量CLOSE_WAIT 状态如何解决？

  - 程序出现了问题，对方的 socket 已经关闭连接，而我方忙于读或写没有及时关闭连接，需要检查代码，特别是释放资源的代码，或者是处理请求的线程配置。

## https

- 非对称加密来安全地交换会话密钥
- 使用哈希算法来确保数据的完整性

1. **客户端发起连接** ：

* 客户端通过发送一个HTTPS请求（通常是访问一个网址）到服务器，请求建立SSL连接。

2. **服务器响应并提供证书** ：

* 服务器接收到客户端的请求后，会响应并提供以下信息：
  * 服务器证书：这是一个由证书颁发机构（CA）签发的数字证书，包含了服务器的公钥和身份信息。
  * 服务器支持的加密套件列表：这些是服务器支持的加密算法和密钥交换协议的列表。

3. **客户端验证证书** ：

* 客户端收到服务器证书后，会进行以下验证：
  * 验证证书是否由受信任的CA签发。
  * 检查证书是否过期或被撤销。
  * 确认证书中的域名与访问的域名一致。
* 如果证书验证失败，浏览器通常会显示警告，并阻止用户继续访问。

4. **客户端生成会话密钥** ：

* 客户端生成一个随机的会话密钥（也称为预主密钥），用于对称加密通信。
* 客户端使用服务器的公钥加密这个会话密钥，然后发送给服务器。

5. **服务器解密会话密钥** ：

* 服务器使用自己的私钥解密接收到的加密会话密钥，得到客户端生成的会话密钥。

6. **客户端和服务器交换密钥协商完成信息** ：

* 客户端和服务器通过加密通信协商出最终的主密钥。
* 双方使用这个主密钥来生成加密和解密的密钥，以及验证数据的完整性。

7. **安全通信建立** ：

* 从现在开始，客户端和服务器之间的所有通信都会使用对称加密，并且通信的完整性通过MAC（Message Authentication Code）或AEAD（Authenticated Encryption with Associated Data）来保证。
* 客户端通常会发送一个加密的“Finished”消息，服务器也回送一个“Finished”消息，以确认握手过程完成。

8. **开始加密通信** ：

* 握手过程完成后，客户端和服务器就可以开始通过HTTPS进行加密的数据传输了。
