# 内存陷阱

Go 内存管理中常见的陷阱和优化方法。

---

## 一、切片泄漏

### 1.1 陷阱

```go
var data []byte

func process() []byte {
    data = make([]byte, 10000)
    return data[:10]
}
```

返回的切片引用原数组，导致 10000 字节无法释放。

### 1.2 解决

```go
func process() []byte {
    data := make([]byte, 10000)
    result := make([]byte, 10)
    copy(result, data[:10])
    return result
}
```

## 二、字符串切片泄漏

### 2.1 陷阱

```go
func getSubstring(s string) string {
    return s[:100]
}
```

返回的字符串引用原字符串底层数组。

### 2.2 解决

```go
func getSubstring(s string) string {
    return strings.Clone(s[:100])
}
```

## 三、Map 内存泄漏

### 3.1 陷阱

```go
m := make(map[string]string)
for i := 0; i < 1000000; i++ {
    m[fmt.Sprintf("key%d", i)] = "value"
}

for k := range m {
    delete(m, k)
}
```

删除后 map 内存不会释放。

### 3.2 解决

```go
m = make(map[string]string)
```

或使用 sync.Map：

```go
var m sync.Map
m.Delete("key")
```

## 四、逃逸分析

### 4.1 陷阱

```go
func newInt() *int {
    x := 42
    return &x
}
```

`x` 逃逸到堆上，增加 GC 压力。

### 4.2 解决

```go
func newInt() int {
    return 42
}
```

---

## 五、接口类型逃逸

### 5.1 陷阱

```go
func print(v interface{}) {
    fmt.Println(v)
}

func main() {
    x := 42
    print(x)
}
```

`x` 转换为接口时逃逸。

### 5.2 解决

```go
func printInt(v int) {
    fmt.Println(v)
}
```

## 六、切片预分配

### 6.1 陷阱

```go
var result []int
for i := 0; i < 10000; i++ {
    result = append(result, i)
}
```

多次扩容，产生内存碎片。

### 6.2 解决

```go
result := make([]int, 0, 10000)
for i := 0; i < 10000; i++ {
    result = append(result, i)
}
```

## 七、大对象复制

### 7.1 陷阱

```go
type BigStruct struct {
    data [10000]int
}

func process(b BigStruct) {
}
```

传值会复制整个结构体。

### 7.2 解决

```go
func process(b *BigStruct) {
}
```

## 八、time.After 泄漏

### 8.1 陷阱

```go
for {
    select {
    case <-time.After(1 * time.Second):
    }
}
```

每次循环创建新的 timer，无法被 GC。

### 8.2 解决

```go
ticker := time.NewTicker(1 * time.Second)
defer ticker.Stop()
for {
    select {
    case <-ticker.C:
    }
}
```

## 九、defer 性能

### 9.1 陷阱

```go
func process() {
    mu.Lock()
    defer mu.Unlock()

    for i := 0; i < 1000000; i++ {
    }
}
```

defer 在循环外，但函数执行时间长。

### 9.2 解决

```go
func process() {
    mu.Lock()
    doWork()
    mu.Unlock()
}
```

## 十、内存对齐

### 10.1 陷阱

```go
type Bad struct {
    a bool
    b int64
    c bool
}
```

大小为 24 字节（有 padding）。

### 10.2 解决

```go
type Good struct {
    b int64
    a bool
    c bool
}
```

大小为 16 字节。
