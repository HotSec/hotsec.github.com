# 并发陷阱

Go 并发编程中常见的陷阱和解决方法。

---

## 一、Goroutine 泄漏

### 1.1 陷阱

```go
func leak() {
    ch := make(chan int)
    go func() {
        <-ch
    }()
}
```

goroutine 永远阻塞，无法被回收。

### 1.2 解决

```go
func noLeak(ctx context.Context) {
    ch := make(chan int)
    go func() {
        select {
        case <-ch:
        case <-ctx.Done():
        }
    }()
}
```

## 二、竞态条件

### 2.1 陷阱

```go
var counter int

func increment() {
    counter++
}
```

多 goroutine 并发执行会导致数据竞争。

### 2.2 解决

```go
var counter int64

func increment() {
    atomic.AddInt64(&counter, 1)
}
```

或使用互斥锁：

```go
var (
    counter int
    mu      sync.Mutex
)

func increment() {
    mu.Lock()
    counter++
    mu.Unlock()
}
```

## 三、死锁

### 3.1 陷阱

```go
func deadlock() {
    ch := make(chan int)
    ch <- 1
}
```

无缓冲 channel 需要接收者，否则死锁。

### 3.2 解决

```go
func noDeadlock() {
    ch := make(chan int, 1)
    ch <- 1
}
```

或使用 goroutine：

```go
func noDeadlock() {
    ch := make(chan int)
    go func() {
        ch <- 1
    }()
    <-ch
}
```

## 四、循环变量捕获

### 4.1 陷阱

```go
for _, v := range values {
    go func() {
        fmt.Println(v)
    }()
}
```

所有 goroutine 可能打印相同的值。

### 4.2 解决

```go
for _, v := range values {
    v := v
    go func() {
        fmt.Println(v)
    }()
}
```

或传参：

```go
for _, v := range values {
    go func(val int) {
        fmt.Println(val)
    }(v)
}
```

## 五、Channel 关闭

### 5.1 陷阱

```go
ch := make(chan int)
close(ch)
close(ch)
```

重复关闭 channel 会 panic。

### 5.2 解决

使用 sync.Once：

```go
type SafeChan struct {
    ch   chan int
    once sync.Once
}

func (s *SafeChan) Close() {
    s.once.Do(func() {
        close(s.ch)
    })
}
```

## 六、nil Channel

### 6.1 陷阱

```go
var ch chan int
<-ch
```

从 nil channel 读取会永远阻塞。

### 6.2 利用特性

```go
func merge(ch1, ch2 <-chan int) <-chan int {
    out := make(chan int)
    go func() {
        defer close(out)
        for ch1 != nil || ch2 != nil {
            select {
            case v, ok := <-ch1:
                if !ok {
                    ch1 = nil
                    continue
                }
                out <- v
            case v, ok := <-ch2:
                if !ok {
                    ch2 = nil
                    continue
                }
                out <- v
            }
        }
    }()
    return out
}
```

## 七、WaitGroup 误用

### 7.1 陷阱

```go
var wg sync.WaitGroup
for _, v := range values {
    go func() {
        wg.Add(1)
        defer wg.Done()
        process(v)
    }()
}
wg.Wait()
```

`wg.Add` 可能在 goroutine 中执行，导致 `Wait` 提前返回。

### 7.2 解决

```go
var wg sync.WaitGroup
for _, v := range values {
    wg.Add(1)
    go func(val int) {
        defer wg.Done()
        process(val)
    }(v)
}
wg.Wait()
```

## 八、Context 取消传播

### 8.1 陷阱

```go
func process(ctx context.Context) {
    newCtx := context.Background()
    doWork(newCtx)
}
```

丢失了原始 context 的取消信号。

### 8.2 解决

```go
func process(ctx context.Context) {
    doWork(ctx)
}
```

或派生：

```go
func process(ctx context.Context) {
    newCtx, cancel := context.WithTimeout(ctx, time.Second)
    defer cancel()
    doWork(newCtx)
}
```
