# 并发优化

Go 的并发模型是性能优化的关键，合理使用 goroutine 和 channel 可以显著提升程序性能。

---

## 一、Goroutine 优化

### 1.1 控制并发数

```go
func processItems(items []Item) error {
    sem := make(chan struct{}, 10)

    var wg sync.WaitGroup
    for _, item := range items {
        wg.Add(1)
        go func(item Item) {
            defer wg.Done()
            sem <- struct{}{}
            defer func() { <-sem }()

            processItem(item)
        }(item)
    }
    wg.Wait()
    return nil
}
```

### 1.2 使用 errgroup.SetLimit

```go
func processItems(items []Item) error {
    g := new(errgroup.Group)
    g.SetLimit(10)

    for _, item := range items {
        item := item
        g.Go(func() error {
            return processItem(item)
        })
    }
    return g.Wait()
}
```

### 1.3 避免频繁创建销毁

```go
type Pool struct {
    work chan func()
    sem  chan struct{}
}

func NewPool(size int) *Pool {
    p := &Pool{
        work: make(chan func()),
        sem:  make(chan struct{}, size),
    }
    return p
}

func (p *Pool) Schedule(task func()) {
    select {
    case p.work <- task:
    case p.sem <- struct{}{}:
        go p.worker(task)
    }
}

func (p *Pool) worker(task func()) {
    defer func() { <-p.sem }()
    for {
        task()
        task = <-p.work
    }
}
```

## 二、Channel 优化

### 2.1 使用缓冲 Channel

```go
ch := make(chan int, 100)
```

- 缓冲区减少 goroutine 阻塞
- 批量处理时更高效

### 2.2 避免空 select

```go
select {}
```

- 永远阻塞，但消耗 CPU
- 使用 channel 或 context 替代

### 2.3 非阻塞操作

```go
select {
case ch <- data:
default:
}
```

## 三、锁优化

### 3.1 减少锁粒度

```go
type ShardedMap struct {
    shards [16]struct {
        sync.RWMutex
        m map[string]string
    }
}

func (m *ShardedMap) getShard(key string) *struct {
    sync.RWMutex
    m map[string]string
} {
    hash := fnv32(key)
    return &m.shards[hash%16]
}

func (m *ShardedMap) Get(key string) string {
    shard := m.getShard(key)
    shard.RLock()
    defer shard.RUnlock()
    return shard.m[key]
}
```

### 3.2 读写分离

```go
var (
    data   map[string]string
    dataMu sync.RWMutex
)

func Read(key string) string {
    dataMu.RLock()
    defer dataMu.RUnlock()
    return data[key]
}

func Write(key, value string) {
    dataMu.Lock()
    defer dataMu.Unlock()
    data[key] = value
}
```

### 3.3 使用 sync.Map

```go
var m sync.Map

m.Store("key", "value")
v, ok := m.Load("key")
m.Delete("key")
```

- 读多写少场景性能更好
- 无锁读取

## 四、内存优化

### 4.1 对象池

```go
var bufPool = sync.Pool{
    New: func() any {
        return new(bytes.Buffer)
    },
}

func process() {
    buf := bufPool.Get().(*bytes.Buffer)
    defer bufPool.Put(buf)
    buf.Reset()

}
```

### 4.2 预分配切片

```go
result := make([]int, 0, len(items))
for _, item := range items {
    result = append(result, process(item))
}
```

### 4.3 避免逃逸

```go
func bad() *int {
    x := 42
    return &x
}

func good() int {
    return 42
}
```

## 五、批处理

### 5.1 批量写入

```go
type Batcher struct {
    buffer []Item
    mu     sync.Mutex
    size   int
    flush  func([]Item)
}

func (b *Batcher) Add(item Item) {
    b.mu.Lock()
    defer b.mu.Unlock()

    b.buffer = append(b.buffer, item)
    if len(b.buffer) >= b.size {
        b.flush(b.buffer)
        b.buffer = b.buffer[:0]
    }
}
```

### 5.2 批量查询
