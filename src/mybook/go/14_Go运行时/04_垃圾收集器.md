# Go 垃圾收集器

> 主要参考：《Go语言高级编程（第2版）》第4.4节 — 柴树杉、曹春晖 著

Go 垃圾收集器（Garbage Collector，GC）是 Go 运行时的核心组件，负责自动回收不再使用的内存。Go GC 经过多代演进，从最初的标记-清除发展到现在的并发三色标记，实现了亚毫秒级的 STW（Stop-The-World）暂停时间。

## 一、GC 演进历史

### 1.1 版本演进

| 版本 | GC 算法 | STW 时间 | 特点 |
|------|---------|----------|------|
| Go 1.0 | 标记-清除 | 百毫秒级 | 简单但暂停时间长 |
| Go 1.3 | 并发标记 | 十毫秒级 | 标记阶段并发 |
| Go 1.5 | 三色并发标记 | 毫秒级 | 大幅减少 STW |
| Go 1.8 | 混合写屏障 | 亚毫秒级 | 删除栈扫描 STW |
| Go 1.19 | Pacer 优化 | 更平滑 | GC 触发更平滑 |
| Go 1.21 | Pinner API | - | 支持 CGO 内存固定 |
| Go 1.25+ | GreenTea GC | 实验性 | 分代 GC（实验） |

```
┌─────────────────────────────────────────────────────────────┐
```

## 二、三色标记算法

### 2.1 三色抽象

三色标记将对象分为三种颜色：

| 颜色 | 含义 | 状态 |
|------|------|------|
| **白色** | 未被标记 | 可能是垃圾对象 |
| **灰色** | 已标记，但引用的对象未扫描 | 待扫描 |
| **黑色** | 已标记，引用的对象已扫描 | 存活对象 |

```
初始状态：
┌─────────────────────────────────────────────────────────────┐
│                      根对象（灰色）                          │
└──────────────────────────┬──────────────────────────────────┘
                           │
         ┌─────────────────┼─────────────────┐
         ▼                 ▼                 ▼
    ┌─────────┐       ┌─────────┐       ┌─────────┐
    │  白色   │ ───→  │  白色   │ ───→  │  白色   │
    │  对象A  │       │  对象B  │       │  对象C  │
    └─────────┘       └─────────┘       └─────────┘

标记过程：
1. 从灰色对象开始，扫描其引用
2. 将引用的白色对象变灰
3. 扫描完成后，灰色对象变黑

最终状态：
    ┌─────────┐       ┌─────────┐       ┌─────────┐
    │  黑色   │       │  黑色   │       │  白色   │
    │  对象A  │       │  对象B  │       │  对象C  │ ← 垃圾
    └─────────┘       └─────────┘       └─────────┘
```

### 2.2 三色不变式

为了保证并发标记的正确性，需要满足三色不变式：

**强三色不变式**：黑色对象不会直接指向白色对象

```
不允许：
┌─────────┐       ┌─────────┐
│  黑色   │ ───→  │  白色   │  ← 禁止
└─────────┘       └─────────┘
```

**弱三色不变式**：所有被黑色对象引用的白色对象都处于灰色保护中

```
允许：
┌─────────┐       ┌─────────┐       ┌─────────┐
│  黑色   │ ───→  │  白色   │ ←───  │  灰色   │  ← 灰色保护
└─────────┘       └─────────┘       └─────────┘
```

### 2.3 写屏障

为了维护三色不变式，Go 使用写屏障（Write Barrier）：

```go
// 伪代码：写屏障
func writeBarrier(slot *unsafe.Pointer, ptr unsafe.Pointer) {
    // 1. 记录被覆盖的指针（删除屏障）
    if *slot != nil {
        shade(*slot)
    }
    
    // 2. 记录新写入的指针（插入屏障）
    if ptr != nil {
        shade(ptr)
    }
    
    // 3. 执行实际写入
    *slot = ptr
}
```

## 三、GC 工作流程

### 3.1 GC 周期

```
┌─────────────────────────────────────────────────────────────┐
│                      GC 周期                                 │
├──────────┬──────────────────────┬───────────────────────────┤
│ 标记准备  │      并发标记         │        标记终止           │
│ (STW)    │   (Concurrent Mark)  │         (STW)             │
├──────────┼──────────────────────┼───────────────────────────┤
│ 设置控制 │ 扫描根对象           │ 关闭写屏障               │
│ 启动后台 │ 并发扫描堆对象       │ 刷新缓存                 │
│ 标记器   │ 写屏障记录指针更新   │ 统计统计                 │
│          │ 辅助标记             │ 下一周期准备             │
└──────────┴──────────────────────┴───────────────────────────┘
     ~25μs           ~100ms              ~50μs
```

### 3.2 标记准备（Mark Setup）

```go
func gcStart(trigger gcTrigger) {
    // 1. 停止世界
    stopTheWorldWithSema("GC mark start")
    
    // 2. 初始化 GC 状态
    gcController.startCycle()
    
    // 3. 启动后台标记器
    for i := 0; i < gcBgMarkWorkerCount; i++ {
        go gcBgMarkWorker()
    }
    
    // 4. 启动世界
    startTheWorldWithSema()
}
```

### 3.3 并发标记

```go
func gcBgMarkWorker() {
    for {
        // 等待被唤醒
        gopark(...)
        
        // 执行标记工作
        systemstack(func() {
            gcDrain(&_p_.gcw, gcDrainUntilEmpty)
        })
    }
}

func gcDrain(w *gcWork, flags gcDrainFlags) {
    // 1. 扫描根对象
    scanRoots()
    
    // 2. 处理灰色对象
    for {
        b := w.tryGetFast()
        if b == 0 {
            b = w.tryGet()
            if b == 0 {
                return
            }
        }
        
        // 扫描对象
        scanobject(b)
    }
}

func scanobject(b uintptr) {
    // 获取对象的类型信息
    hbits := heapBitsForAddr(b)
    s := spanOfUnchecked(b)
    
    // 扫描对象中的指针
    for {
        var p uintptr
        hbits, p = hbits.next()
        if p == 0 {
            break
        }
        
        // 标记引用的对象
        if obj := *(*uintptr)(unsafe.Pointer(p)); obj != 0 {
            greyenc := greyobject(obj, b, s)
            if greyenc {
                w.put(obj)
            }
        }
    }
}
```

### 3.4 标记终止（Mark Termination）

```go
func gcMarkDone() {
    // 1. 停止世界
    stopTheWorldWithSema("GC mark termination")
    
    // 2. 关闭写屏障
    setGCPhase(_GCoff)
    
    // 3. 刷新缓存
    gcMarkTerminationFlushCache()
    
    // 4. 统计信息
    gcMarkTerminationStats()
    
    // 5. 启动世界
    startTheWorldWithSema()
}
```

## 四、混合写屏障

### 4.1 演进历程

| 版本 | 写屏障类型 | 特点 |
|------|-----------|------|
| Go 1.5 | Dijkstra 插入屏障 | 栈对象无屏障，需要 STW 重新扫描栈 |
| Go 1.6 | Dijkstra + Yuasa | 混合屏障原型 |
| Go 1.8 | 混合写屏障 | 删除栈扫描 STW |

### 4.2 混合写屏障实现

```go
// 混合写屏障：Dijkstra 插入屏障 + Yuasa 删除屏障
func gcWriteBarrier(slot *uintptr, ptr uintptr) {
    // 1. Yuasa 删除屏障：标记被删除的对象
    if *slot != 0 {
        shade(*slot)
    }
    
    // 2. Dijkstra 插入屏障：标记新插入的对象
    if ptr != 0 {
        shade(ptr)
    }
    
    // 3. 执行实际写入
    *slot = ptr
}
```

### 4.3 混合写屏障规则

```
混合写屏障的 4 条规则：

1. 删除屏障：删除时，将旧对象标记为灰色
   A.field = B  →  shade(A.field)  // 标记旧值

2. 插入屏障：插入时，将新对象标记为灰色
   A.field = B  →  shade(B)  // 标记新值

3. 栈无屏障：栈上的写操作不需要写屏障
   栈对象赋值直接执行

4. 栈扫描：GC 开始时一次性扫描所有栈
   将栈上所有对象标记为黑色
```

### 4.4 为什么删除栈扫描 STW

```
Go 1.5 的问题：
┌─────────────────────────────────────────────────────────────┐
│  GC 开始                                                     │
│    │                                                         │
│    ├── STW：扫描所有栈（将栈上对象标记为黑色）               │
│    │                                                         │
│    ├── 并发标记（开启写屏障）                                │
│    │     │                                                   │
│    │     └── 用户修改栈上指针                                │
│    │           │                                             │
│    │           └── 栈无写屏障，可能导致黑色→白色引用         │
│    │                                                         │
│    └── STW：重新扫描所有栈（修复问题）                       │
│          ↑                                                   │
│          └── 栈越多，STW 越长                                │
└─────────────────────────────────────────────────────────────┘

Go 1.8 的解决方案：
┌─────────────────────────────────────────────────────────────┐
│  GC 开始                                                     │
│    │                                                         │
│    ├── STW：扫描所有栈（将栈上对象标记为黑色）               │
│    │                                                         │
│    ├── 并发标记（混合写屏障）                                │
│    │     │                                                   │
│    │     ├── 删除屏障：保护被删除对象                        │
│    │     │                                                   │
│    │     └── 栈修改：栈对象本身是黑色，修改后仍是黑色        │
│    │           │                                             │
│    │           └── 不需要重新扫描栈                          │
│    │                                                         │
│    └── STW：标记终止（无需重新扫描栈）                       │
└─────────────────────────────────────────────────────────────┘
```

## 五、GC 触发机制

### 5.1 触发条件

```go
type gcTrigger struct {
    kind gcTriggerKind
    now  int64
    n    uint32
}

const (
    gcTriggerHeap      // 堆内存达到阈值
    gcTriggerTime      // 超过 2 分钟未 GC
    gcTriggerCycle     // 强制 GC
)
```

### 5.2 堆内存触发

```go
func (t gcTrigger) test() bool {
    if t.kind == gcTriggerHeap {
        // 堆内存达到 GOGC * 上次存活堆大小
        return memstats.heap_live >= memstats.gc_trigger
    }
    
    if t.kind == gcTriggerTime {
        // 超过 2 分钟未 GC
        if t.now == 0 {
            t.now = nanotime()
        }
        return t.now-atomic.Load64(&sched.lastgc) > forcegcperiod
    }
    
    return false
}

// GC 触发阈值计算
func gcSetTriggerRatio(triggerRatio float64) {
    // GOGC 默认值 100，即堆增长 100% 触发 GC
    goal := uint64(float64(atomic.Load64(&memstats.heap_live)) * (1 + triggerRatio))
    
    // 设置触发阈值
    atomic.Store64(&memstats.gc_trigger, goal)
}
```

## 六、GC Pacing

### 6.1 Pacer 机制

Pacer 控制 GC 的执行速度，平衡 GC CPU 使用率和堆大小：

```go
type gcControllerState struct {
    // 目标堆增长率
    triggerRatio float64
    
    // GC 执行时间比例
    goalRatio float64
    
    // 扫描工作量估计
    scanWork uint64
    
    // 辅助标记时间
    assistTime int64
}
```

### 6.2 辅助标记

当用户分配内存速度超过 GC 标记速度时，会触发辅助标记：

```go
func (c *gcControllerState) assistWork() int64 {
    // 计算需要辅助的工作量
    assistWork := c.assistWorkPerByte * bytesAllocated
    
    // 执行辅助标记
    gcDrain(&gcWork, assistWork)
    
    return assistWork
}
```

## 七、GC 性能优化

### 7.1 减少分配

```go
// Bad: 频繁分配临时对象
func process() {
    for i := 0; i < 10000; i++ {
        _ = make([]byte, 1024)
    }
}

// Good: 复用对象
var bufPool = sync.Pool{
    New: func() interface{} {
        return make([]byte, 1024)
    },
}

func process() {
    buf := bufPool.Get().([]byte)
    defer bufPool.Put(buf)
    
    for i := 0; i < 10000; i++ {
        // 使用 buf
    }
}
```

### 7.2 预分配容量

```go
// Bad: 频繁扩容
var s []int
for i := 0; i < 10000; i++ {
    s = append(s, i)
}

// Good: 预分配
s := make([]int, 0, 10000)
for i := 0; i < 10000; i++ {
    s = append(s, i)
}
```

### 7.3 避免逃逸

```go
// Bad: 返回指针导致逃逸
func newPoint() *Point {
    return &Point{X: 1, Y: 2}
}

// Good: 返回值类型
func newPoint() Point {
    return Point{X: 1, Y: 2}
}
```

### 7.4 调整 GOGC

```go
import "runtime/debug"

// 更激进的 GC，减少内存使用
debug.SetGCPercent(50)

// 更宽松的 GC，减少 CPU 使用
debug.SetGCPercent(200)
```

## 八、GC 调试

### 8.1 GODEBUG=gctrace

```bash
GODEBUG=gctrace=1 ./program

# 输出示例
gc 1 @0.003s 2%: 0.018+0.52+0.023 ms clock, 0.14+0.11/0.98/0.49+0.18 ms cpu, 4->4->0 MB, 5 MB goal, 8 P
```

字段解释：
- `gc 1`: GC 次数
- `@0.003s`: 程序启动后的时间

- `4->4->0 MB`: GC 前堆大小 → GC 后堆大小 → 存活堆大小
- `5 MB goal`: 目标堆大小
- `8 P`: P 的数量

## 九、Go 1.25+ GreenTea GC

### 9.1 分代 GC

Go 1.25 引入实验性的分代 GC（GreenTea GC）：

```bash
# 启用 GreenTea GC
GOEXPERIMENT=greentea go build
```

### 9.2 设计思想

```
分代 GC 假设：
- 大多数对象是短命的（新生代）
- 存活时间长的对象更可能继续存活（老年代）

策略：
- 新生代：频繁 GC，只扫描新生代对象
- 老年代：较少 GC，扫描所有对象
```
