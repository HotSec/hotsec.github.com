- 优点
  - 解决物理内存无法被最大化利用的问题
    - 读时共享，写时复制
  - 程序逻辑内存空间使用独立
  - 内存不够，继续虚拟磁盘空间

- mmu：内存管理单元，将虚拟内存地址映射到物理内存地址
  - 页：虚拟内存和物理内存的映射单位
  - 页表：虚拟内存和物理内存的映射关系表
  - PTE: 页表项，记录页的映射关系
  - TLB: 临时页表，缓存页表，提高映射速度
  - TLB miss：缓存未命中，需要查页表

### 内存的局部性

- 时间局部性：如果一个信息被访问，那么在不久的将来它很可能会被再次访问
- 空间局部性：如果一个信息被访问，那么在不久的将来它附近的元素很可能被访问

## Go语言内存管理相关概念

- Page：Go语言内存管理与虚拟内存交互的最小单位，默认为 8KB
- mSpan: 一组连续的 Page，用于管理内存分配，每个 mSpan 中包含 1 个或多个 Page
- Size Class
  - Object Size: 协程应用逻辑一次向Go语言内存申请的对象Object大小
  - Size Class: Go 语言内存管理中用于描述一组连续的 Page 的规格，每个 Size Class 对应一个连续的 Page 数量
  - Span Class: 额外定义的规格属性

## 内存模型

- 以空间换时间，一次缓存，多次使用
- 多级缓存，实现无/细锁化
  - ![alt text](image/9_内存管理/image.png)
  - mheap：全局的内存起源，访问要加全局锁
  - mcentral：每种对象大小规格（全局共划分为 68 种）对应的缓存，锁的粒度也仅限于同一种规格以内
  - mcache：每个 P（正是 GMP 中的 P）持有一份的内存缓存，访问时无锁

  - ![alt text](image/9_内存管理/image-2.png)

## 对象分配流程

1. 从 P 专属 mcache 的 tiny 分配器取内存（无锁）
2. 根据所属的 spanClass，从 P 专属 mcache 缓存的 mspan 中取内存（无锁）
3. 根据所属的 spanClass 从对应的 mcentral 中取 mspan 填充到 mcache，然后从 mspan 中取内存（spanClass 粒度锁）
4. 根据所属的 spanClass，从 mheap 的页分配器 pageAlloc 取得足够数量空闲页组装成 mspan 填充到 mcache，然后从 mspan 中取内存（全局锁）
5. mheap 向操作系统申请内存，更新页分配器的索引信息，然后重复4.

## 小结

- GO语言内存分析采用tcmalloc算法的改进版本，核心是分级分配和本地缓存。
- Go内存分配有三个层级
  - mcahe：每个P持有的本地缓存，访问无锁
  - mcentral：每种对象大小规格对应的缓存，锁的粒度也仅限于同一种规格以内
  - mheap：全局的内存，访问要加全局锁
- 对象分类分配
  - 微小对象（tiny allocator）：16字节以下的对象，直接从 mcache 的 tiny 分配器分配内存，无锁
  - 小对象：16字节～32KB的对象，通过size class机制，预定义了67种规则，优先从p的mcache是蹲坑的mspan中分配，没有这从mcentral中取，也没有从mehad中取，都没有向操作系统申请
  - 大对象：>32KB 的对象，直接从 mheap 分配内存，访问要加全局锁
