# Go内存逃逸

## 什么是内存逃逸

Go内存逃逸是指编译器在编译过程中，将原本应该分配在栈上的变量分配到了堆上，这种现象称为内存逃逸。

## 为什么会发生内存逃逸

一般在给一个引用类对象中的引用类成员进行赋值时可能出现逃逸现场。
可以理解为，访问一个引用对象实际上是底层通过一个指针间接地访问，但如果再访问里面的引用成员，则会有第二次间接访问，这样操作起来性能开销会很大，因此编译器会根据逃逸分析的结果来决定是否要将该引用成员分配到堆上。

go语言中的引用类型包括：func、interface、slice、map、channel、*pointer、array等。

1. 变量在外部被引用
   1. 返回局部变量执政
   2. 闭包引用的外部变量
2. 大对象
3. 变量的大小不确定
    1. 切片/map动态扩容
4. 变量被指针、切片、通道引用
5. 传递给interface{}参数的具体类型会逃逸，因为需要运行时类型信息


## 如何避免内存逃逸

1. 尽量使用局部变量
2. 尽量使用小对象
3. 尽量避免使用指针
4. 尽量避免使用切片
5. 尽量避免使用通道

## 如何检测内存逃逸

1. 使用`go tool compile -m`命令
2. 使用`go build -gcflags "-m"`命令
3. 使用`go tool pprof`命令

## 内存逃逸的例子

```go
package main

import "fmt"

func main() {
    var a int = 10
    fmt.Println(a)
}
```

在上面的例子中，变量`a`是一个局部变量，它的值是10。根据Go语言的内存逃逸规则，局部变量`a`应该分配在栈上，但是因为`fmt.Println`函数需要引用变量`a`，所以变量`a`会被分配在堆上，这种现象称为内存逃逸。

## 总结

Go语言的内存逃逸是指在编译过程中，将原本应该分配在栈上的变量分配到了堆上，这种现象称为内存逃逸。内存逃逸会导致程序的性能下降，因此需要尽量避免内存逃逸。

## 内存泄漏情况

1. goroutine泄漏
   1. goroutine没有正常退出，会一直占用内存
2. channel泄漏
   1. 例如 生产者已经结束，但是没有关闭channel，消费者一直在等待数据，导致goroutine泄漏
3. slice引用大数组
   1. 切片引用了一个大数组的部分元素，导致整个数组无法被垃圾回收
4. map元素过多
   1. map中删除只是标记删除，底层bucket不会缩减。
5. 定时器未停止
6. 循环引用

## 内存泄漏定位

- 分析思路：先看内存增长曲线，分析哪个函数分配内存最多，如果是goroutine泄漏，会看到数量异常增长，分析goroutine阻塞在哪

1. pprof工具
   1. 分析堆内存分布、协程泄漏
2. trace工具
   1. go tool trace 看协程的生命周期和阻塞情况
3. runtime统计
   1. `runtime.ReadMemStats()` 可以获取当前程序的内存统计信息，包括分配的内存、已使用的内存、垃圾回收的次数等。
   2. `runtime.NumGoroutine()` 可以获取当前程序的goroutine数量
