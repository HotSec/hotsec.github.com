# 栈内存管理

Go 的栈管理采用**连续栈（contiguous stack）**方案，与传统的分段栈不同，Go 的栈可以动态增长和收缩。

---

## 一、栈的基本概念

### 1.1 Goroutine 栈

```go
go func() {
    var buf [1024]byte
    doSomething(buf[:])
}()
```

- 每个 goroutine 有自己的栈空间
- 初始栈大小：2KB（Go 1.4+）
- 最大栈大小：默认 1GB（64位系统），可通过 `runtime/debug.SetMaxStack` 调整

### 1.2 栈 vs 堆

| 特性 | 栈 | 堆 |
|------|------|------|
| 分配速度 | 极快（移动指针） | 较慢（需要找空闲空间） |
| 释放速度 | 极快（移动指针） | 依赖 GC |
| 大小限制 | 初始 2KB，可增长 | 受系统内存限制 |
| 生命周期 | 函数返回即释放 | GC 决定 |
| 线程安全 | 每个goroutine独立 | 共享 |

## 二、栈扩容

### 2.1 扩容触发

```go
func deepRecursion(n int) int {
    if n == 0 {
        return 0
    }
    var buf [1024]byte
    _ = buf
    return deepRecursion(n - 1)
}
```

- 当 goroutine 的栈空间不足时触发扩容
- 编译器在函数入口插入栈空间检查代码（stack check）
- 检查当前栈是否足够，不够则调用 `runtime.morestack`

### 2.2 扩容策略

| Go 版本 | 扩容策略 |
|---------|---------|
| < 1.18 | 新栈 = 旧栈 × 2 |
| ≥ 1.18 | 新栈 = 旧栈 × 2（栈较小时）<br>新栈 = 旧栈 × 1.25（栈较大时） |

具体规则（Go 1.18+）：
- 旧栈 < 64KB：翻倍
- 旧栈 ≥ 64KB：增长 25%
- 最大不超过 1GB

### 2.3 扩容过程

1. 分配新的更大栈空间
2. 将旧栈数据**拷贝**到新栈
3. 调整所有指向旧栈的指针（使用 `runtime.adjustpointers`）
4. 切换到新栈继续执行

## 三、栈缩容

### 3.1 缩容触发

- 在 GC 期间检查 goroutine 栈的使用率
- 如果栈使用率低于 1/4，触发缩容

### 3.2 缩容策略

- 新栈大小 = 当前使用量 × 2
- 最小不低于 2KB
- 缩容不是立即执行，而是标记后在下次函数调用时执行

## 四、栈空间检测

### 4.1 查看栈大小

```go
func main() {
    var mem runtime.MemStats
    runtime.ReadMemStats(&mem)
    fmt.Printf("Stack in use: %d bytes\n", mem.StackInuse)
    fmt.Printf("Stack from system: %d bytes\n", mem.StackSys)
}
```

### 4.2 查看单个 goroutine 栈

```go
func printStackUsage() {
    buf := make([]byte, 1024)
    n := runtime.Stack(buf, false)
    fmt.Printf("Stack trace:\n%s\n", buf[:n])
}
```

### 4.3 限制最大栈

```go
import "runtime/debug"

func init() {
    debug.SetMaxStack(100 * 1024 * 1024)
}
```

## 五、栈逃逸分析

### 5.1 什么情况变量逃逸到堆

```go
func escape1() *int {
    x := 42
    return &x
}

func escape2() {
    x := 42
    go func() {
        fmt.Println(x)
    }()
}

func escape3() func() int {
    x := 42
    return func() int {
        return x
    }
}

func noEscape() int {
    x := 42
    return x
}
```

## 六、栈相关优化

### 6.1 减少逃逸

```go
func bad() {
    result := getResult()
    _ = result
}

func getResult() *Result {
    r := &Result{}
    return r
}

func good() {
    var r Result
    getResultInline(&r)
    _ = r
}

func getResultInline(r *Result) {
    r.Value = 42
}
```

### 6.2 控制递归深度

```go
func process(data []int, depth int) {
    if depth > 1000 {
        processIterative(data)
        return
    }
    if len(data) == 0 {
        return
    }
    process(data[1:], depth+1)
}
```

### 6.3 避免大数组作为局部变量

```go
func bad() {
    var buf [1024 * 1024]byte
    _ = buf
}

func good() {
    buf := make([]byte, 1024*1024)
    _ = buf
}
```

- 固定大小的大数组会直接占用栈空间
- 使用 `make` 分配到堆上更安全
