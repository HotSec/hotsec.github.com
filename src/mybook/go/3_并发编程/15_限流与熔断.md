## 一、限流算法

### 1.1 令牌桶算法 (Token Bucket)

```
┌──────────────┐
│  令牌桶       │  以固定速率 r 往桶中放令牌
│  ┌─┐┌─┐┌─┐  │  桶容量为 b（最大令牌数）
│  │ ││ ││ │  │
│  └─┘└─┘└─┘  │
│  容量: b     │
│  速率: r/s   │
└──────┬───────┘
       │ 取令牌
       ▼
   请求处理
```

- 桶以固定速率 `r` 生成令牌
- 桶最大容量 `b`，满了则丢弃新令牌
- 请求到来时取一个令牌，无令牌则拒绝
- **允许突发流量**（桶中有积累的令牌）

### 1.2 漏桶算法 (Leaky Bucket)

```
请求 → ┌──────────┐ → 以固定速率 r 流出
       │  漏桶     │
       │  容量: b  │
       └──────────┘
       桶满则拒绝新请求
```

- 请求进入桶中排队
- 以固定速率 `r` 处理请求
- 桶满则拒绝新请求
- **平滑流量**，不允许突发

### 1.3 滑动窗口算法

```
时间轴:
|----窗口----|
  t1  t2  t3  t4  t5  t6  now
  ✓   ✓   ✓   ✓   ✓       ← 窗口内5个请求

窗口随时间滑动，统计窗口内请求数
```

- 将时间窗口划分为多个小格子
- 统计当前窗口内的请求数
- 比固定窗口更平滑

## 二、golang.org/x/time/rate

### 2.1 基本使用

```go
import "golang.org/x/time/rate"

func main() {
    // r=2 每秒产生2个令牌, b=5 桶容量5
    limiter := rate.NewLimiter(2, 5)

    for i := 0; i < 10; i++ {
        if err := limiter.Wait(context.Background()); err != nil {
            fmt.Println("rate limit exceeded")
            continue
        }
        fmt.Printf("request %d processed\n", i)
    }
}
```

### 2.2 三种限流方式

```go
limiter := rate.NewLimiter(10, 5)

// 1. Wait/WaitN - 阻塞等待令牌
err := limiter.Wait(ctx)       // 等待1个令牌
err := limiter.WaitN(ctx, 3)   // 等待3个令牌

// 2. Reserve/ReserveN - 预约令牌（不阻塞）
r := limiter.Reserve()
if !r.OK() {
    // 请求的令牌数超过桶容量
    return
}
time.Sleep(r.Delay()) // 等待预约时间
doRequest()

// 3. Allow/AllowN - 非阻塞判断
if limiter.Allow() {
    doRequest() // 有令牌，处理请求
} else {
    // 无令牌，拒绝请求
}
```

### 2.3 HTTP 中间件限流

```go
func RateLimitMiddleware(r float64, b int) gin.HandlerFunc {
    limiter := rate.NewLimiter(rate.Limit(r), b)
    return func(c *gin.Context) {
        if !limiter.Allow() {
            c.AbortWithStatusJSON(http.StatusTooManyRequests, gin.H{
                "error": "rate limit exceeded",
            })
            return
        }
        c.Next()
    }
}

func main() {
    r := gin.Default()
    r.Use(RateLimitMiddleware(100, 50))
    r.GET("/api", handler)
    r.Run()
}
```

### 2.4 按 IP 限流

```go
type IPRateLimiter struct {
    ips map[string]*rate.Limiter
    mu  sync.RWMutex
    r   rate.Limit
    b   int
}

func NewIPRateLimiter(r rate.Limit, b int) *IPRateLimiter {
    return &IPRateLimiter{
        ips: make(map[string]*rate.Limiter),
        r:   r,
        b:   b,
    }
}

func (l *IPRateLimiter) GetLimiter(ip string) *rate.Limiter {
    l.mu.Lock()
    defer l.mu.Unlock()

    limiter, exists := l.ips[ip]
    if !exists {
        limiter = rate.NewLimiter(l.r, l.b)
        l.ips[ip] = limiter
    }
    return limiter
}

func RateLimitByIP(r rate.Limit, b int) gin.HandlerFunc {
    limiter := NewIPRateLimiter(r, b)
    return func(c *gin.Context) {
        ip := c.ClientIP()
        if !limiter.GetLimiter(ip).Allow() {
            c.AbortWithStatusJSON(http.StatusTooManyRequests, gin.H{
                "error": "too many requests",
            })
            return
        }
        c.Next()
    }
}
```

## 三、熔断器模式

### 3.1 状态机

```
        成功率正常
  ┌──────────────────┐
  │                  │
  ▼                  │
┌──────┐  失败率超阈值  ┌──────┐
│Closed│──────────→│ Open │
└──────┘            └──┬───┘
  ▲                    │
  │   探测成功          │ 超时后
  │                    ▼
  │              ┌──────────┐
  └──────────────│Half-Open │
                 └──────────┘
                    │探测失败
                    ▼
                 ┌──────┐
                 │ Open │
                 └──────┘
```

- **Closed**: 正常状态，请求正常通过
- **Open**: 熔断状态，所有请求被拒绝
- **Half-Open**: 半开状态，允许少量请求探测

### 3.2 手动实现熔断器

```go
type State int

const (
    Closed State = iota
    Open
    HalfOpen
)

type CircuitBreaker struct {
    mu           sync.Mutex
    state        State
    failures     int
    successes    int
    maxFailures  int
    timeout      time.Duration
    lastFailure  time.Time
    halfOpenMax  int
}

func NewCircuitBreaker(maxFailures int, timeout time.Duration) *CircuitBreaker {
    return &CircuitBreaker{
        state:       Closed,
        maxFailures: maxFailures,
        timeout:     timeout,
        halfOpenMax: 3,
    }
}

func (cb *CircuitBreaker) Allow() bool {
    cb.mu.Lock()
    defer cb.mu.Unlock()

    switch cb.state {
    case Closed:
        return true
    case Open:
        if time.Since(cb.lastFailure) > cb.timeout {
            cb.state = HalfOpen
            cb.successes = 0
            return true
        }
        return false
    case HalfOpen:
        return cb.successes < cb.halfOpenMax
    }
    return false
}

func (cb *CircuitBreaker) RecordSuccess() {
    cb.mu.Lock()
    defer cb.mu.Unlock()

    if cb.state == HalfOpen {
        cb.successes++
        if cb.successes >= cb.halfOpenMax {
            cb.state = Closed
            cb.failures = 0
        }
    }
}

func (cb *CircuitBreaker) RecordFailure() {
    cb.mu.Lock()
    defer cb.mu.Unlock()

    cb.failures++
    cb.lastFailure = time.Now()

    if cb.state == HalfOpen {
        cb.state = Open
    } else if cb.failures >= cb.maxFailures {
        cb.state = Open
    }
}
```

### 3.3 使用熔断器

```go
func callWithBreaker(cb *CircuitBreaker, fn func() error) error {
    if !cb.Allow() {
        return fmt.Errorf("circuit breaker is open")
    }

    err := fn()
    if err != nil {
        cb.RecordFailure()
        return err
    }

    cb.RecordSuccess()
    return nil
}
```

### 3.4 go-zero 熔断器

```go
import "github.com/zeromicro/go-zero/core/breaker"

func main() {
    brk := breaker.NewBreaker("my-service")

    err := brk.DoWithAcceptable(func() error {
        resp, err := http.Get("http://example.com/api")
        if err != nil {
            return err
        }
        defer resp.Body.Close()
        return nil
    }, func(err error) bool {
        return err != nil // 可接受的错误
    })

    if err != nil {
        fmt.Println("request failed:", err)
    }
}
```

## 四、限流 vs 熔断对比

| 维度 | 限流 | 熔断 |
|------|------|------|
| 目的 | 控制请求速率 | 保护下游服务 |
| 触发条件 | 请求速率超限 | 错误率超阈值 |
| 行为 | 排队或拒绝 | 快速失败 |
| 恢复 | 自动 | 半开探测 |
| 适用场景 | API 限流 | 依赖服务故障 |

## 五、最佳实践

### 5.1 限流配置建议

| 场景 | 算法 | 参数建议 |
|------|------|----------|
| 公开 API | 令牌桶 | r=100/s, b=200 |
| 内部服务 | 滑动窗口 | 窗口1s, 上限1000 |
| 登录接口 | 固定窗口 | 5次/分钟/IP |
| 文件上传 | 漏桶 | r=10/s, b=50 |

### 5.2 熔断配置建议

| 参数 | 建议值 | 说明 |
|------|--------|------|
| 失败阈值 | 50% | 错误率超过50%触发熔断 |
| 最小请求数 | 20 | 至少20个请求才计算错误率 |
| 熔断超时 | 30s | Open状态持续30秒 |
| 半开探测数 | 5 | 允许5个探测请求 |

### 5.3 组合使用

```go
func ProtectedCall(limiter *rate.Limiter, cb *CircuitBreaker, fn func() error) error {
    if !limiter.Allow() {
        return fmt.Errorf("rate limited")
    }

    if !cb.Allow() {
        return fmt.Errorf("circuit breaker open")
    }

    err := fn()
    if err != nil {
        cb.RecordFailure()
        return err
    }

    cb.RecordSuccess()
    return nil
}
```
