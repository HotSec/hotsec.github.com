# 包、模块与库

## 一、包（Package）

### 1.1 包的定义

```go
package mypackage

const Pi = 3.14

func Add(a, b int) int {
    return a + b
}

type Student struct {
    Name string
    age  int
}
```

- 同一目录下所有 `.go` 文件的 `package` 声明必须相同
- 包名通常与目录名一致
- `main` 包是特殊的，定义可执行程序的入口

### 1.2 标识符可见性

| 首字母 | 可见性 | 说明 |
|--------|--------|------|
| 大写 | 导出（public） | 其他包可访问 |
| 小写 | 未导出（private） | 仅包内可访问 |

```go
package mypackage

var PublicVar = "public"
var privateVar = "private"

func PublicFunc() {}
func privateFunc() {}

type PublicType struct {
    PublicField  string
    privateField string
}
```

### 1.3 包的引入

```go
import "fmt"
import "os"

import (
    "fmt"
    "os"
    "strings"
)

// 别名导入
import (
    f "fmt"
    . "os"
    _ "image/png"
)

// 别名：f.Println()
// 点导入：直接使用 Exit() 而非 os.Exit()
// 空白导入：仅执行 init()，不使用包
```

- 标准库：`"fmt"` / `"os"` / `"strings"`
- 第三方库：`"github.com/gin-gonic/gin"`
- 本地包：相对模块根目录的路径

### 1.4 init 函数

```go
package mypackage

func init() {
    // 包初始化逻辑
}

func init() {
    // 可以有多个 init 函数
}
```

- 每个包可以有多个 `init` 函数
- `init` 在 `main` 函数之前自动执行
- 执行顺序：依赖包 init → 当前包全局变量初始化 → 当前包 init
- `init` 不能被调用，不能有参数和返回值

### 1.5 空白导入

```go
import _ "image/png"
```

- 仅执行包的 `init` 函数
- 常用于注册驱动/解码器
- `database/sql` 驱动注册：`import _ "github.com/go-sql-driver/mysql"`

## 二、Go Modules

### 2.1 初始化模块

```bash
go mod init github.com/username/project
```

- 生成 `go.mod` 文件
- 声明模块路径和 Go 版本

### 2.2 go.mod 文件

```
module github.com/username/project

go 1.21

require (
    github.com/gin-gonic/gin v1.9.1
    golang.org/x/text v0.14.0
)

require (
    github.com/bytedance/sonic v1.10.0 // indirect
)
```

- `module`：模块路径
- `go`：Go 版本
- `require`：直接依赖
- `// indirect`：间接依赖

### 2.3 常用命令

```bash
go mod init <module>     # 初始化模块
go mod tidy              # 整理依赖（添加缺失/删除无用）
go mod download          # 下载依赖到缓存
go mod verify            # 验证依赖完整性
go mod graph             # 查看依赖图
go mod vendor            # 将依赖复制到 vendor 目录
go list -m all           # 列出所有依赖
go get <pkg>@<version>   # 添加/更新依赖
go get <pkg>@none        # 删除依赖
```

### 2.4 版本号规则

-语义化版本：`v1.2.3`（主版本.次版本.修订号）
- 主版本 ≥ 2 时，模块路径需加后缀：`github.com/pkg/v2`
- 伪版本：`v0.0.0-20231201000000-abcdef123456`

### 2.5 replace 指令

```
replace (
    github.com/old/pkg => github.com/new/pkg v1.0.0
    github.com/local/pkg => ../local/pkg
)
```

- 替换依赖源（用于 fork 修复/本地调试）
- 本地开发时常用 `replace` 指向本地路径

### 2.6 Go Workspace（go.work）

```bash
go work init ./module1 ./module2
go work use ./module3
```

```
go 1.21

use (
    ./module1
    ./module2
    ./module3
)
```

- 多模块开发时使用
- 替代 `replace` 指令进行本地开发
- `go.work` 文件不应提交到版本控制

## 三、包管理演进

| 阶段 | 工具 | 特点 |
|------|------|------|
| Go 1.0-1.5 | go get | 无版本概念，直接拉取最新 |
| Go 1.5 | vendor | 将依赖复制到项目目录 |
| Go 1.6-1.10 | dep/glide | 社区方案，有版本管理 |
| Go 1.11+ | go mod | 官方方案，语义化版本 |
| Go 1.18+ | go work | 多模块工作区 |
