## 一、Slice 内部实现

### 1.1 SliceHeader 结构

Slice 在运行时由 `reflect.SliceHeader` 表示：

```go
type SliceHeader struct {
    Data uintptr
    Len  int
    Cap  int
}
```

- **Data**: 指向底层数组的指针
- **Len**: 当前元素个数
- **Cap**: 底层数组容量

```
slice := make([]int, 3, 5)

┌─────────── SliceHeader ───────────┐
│  Data ──→ [0, 0, 0, _, _]        │
│  Len  = 3                         │
│  Cap  = 5                         │
└───────────────────────────────────┘
```

### 1.2 扩容策略

```go
func growslice(oldPtr unsafe.Pointer, newLen, oldCap, num int, et *_type) slice {
    newcap := oldCap
    doublecap := newcap + newcap
    if newLen > doublecap {
        newcap = newLen
    } else {
        const threshold = 256
        if oldCap < threshold {
            newcap = doublecap
        } else {
            for 0 < newcap && newcap < newLen {
                newcap += (newcap + 3*threshold) / 4
            }
        }
    }
}
```

| 旧容量 | 扩容策略 |
|--------|----------|
| < 256 | 新容量 = 旧容量 × 2 |
| ≥ 256 | 新容量 = 旧容量 + 旧容量×1.25 + 192 |

### 1.3 切片共享底层数组

```go
a := []int{1, 2, 3, 4, 5}
b := a[1:3]

// a 和 b 共享底层数组
// 修改 b 会影响 a
b[0] = 99
// a[1] 也变成 99
```

### 1.4 三参数切片

```go
a := []int{1, 2, 3, 4, 5}
b := a[1:3:3] // len=2, cap=2

// 限制 cap，防止 append 修改原数组
b = append(b, 10)
// a 不会被影响
```

## 二、String 内部实现

### 2.1 StringHeader 结构

```go
type StringHeader struct {
    Data uintptr
    Len  int
}
```

- **Data**: 指向底层字节数组的指针
- **Len**: 字符串长度（不可变）
- String 是不可变的字节切片，底层是 `[]byte`

### 2.2 String 与 []byte 转换

```go
s := "hello"

// string → []byte（发生数据拷贝）
b := []byte(s)

// []byte → string（发生数据拷贝）
s2 := string(b)

// 零拷贝转换（unsafe，仅用于只读场景）
func bytesToString(b []byte) string {
    return *(*string)(unsafe.Pointer(&b))
}

func stringToBytes(s string) []byte {
    return *(*[]byte)(unsafe.Pointer(
        &struct {
            string
            int
        }{s, len(s)},
    ))
}
```

### 2.3 字符串拼接优化

```go
// ❌ 低效：每次拼接都分配新内存
s := ""
for i := 0; i < n; i++ {
    s += str
}

// ✅ 高效：strings.Builder
var builder strings.Builder
builder.Grow(n * len(str))
for i := 0; i < n; i++ {
    builder.WriteString(str)
}
result := builder.String()
```

## 三、Interface 内部实现

### 3.1 两种接口类型

**eface**（无方法的接口，即 `interface{}`）：

```go
type eface struct {
    _type *_type
    data  unsafe.Pointer
}
```

**iface**（有方法的接口）：

```go
type iface struct {
    tab  *itab
    data unsafe.Pointer
}

type itab struct {
    inter *interfacetype
    _type *_type
    fun   [1]uintptr
}
```

### 3.2 nil 接口陷阱

```go
type MyError struct{ msg string }
func (e *MyError) Error() string { return e.msg }

func getError() error {
    var err *MyError // nil
    return err       // 接口值 != nil！
}

func main() {
    err := getError()
    fmt.Println(err == nil) // false!
}
```

原因：接口值 = (type, data)，`getError()` 返回的是 `(*MyError, nil)`，type 不为 nil，所以整个接口不为 nil。

```go
// ✅ 正确做法
func getError() error {
    return nil // 直接返回 nil 接口
}
```

### 3.3 类型断言内部

```go
var i interface{} = "hello"

// 类型断言
s := i.(string)

// 等价于检查 eface._type 是否匹配
// 匹配则返回 eface.data
```

## 四、Channel 内部实现

### 4.1 hchan 结构

```go
type hchan struct {
    qcount   uint           // 队列中元素个数
    dataqsiz uint           // 环形队列容量
    buf      unsafe.Pointer // 环形队列指针
    elemsize uint16         // 元素大小
    closed   uint32         // 是否关闭
    sendx    uint           // 发送索引
    recvx    uint           // 接收索引
    recvq    waitq          // 等待接收的 goroutine 队列
    sendq    waitq          // 等待发送的 goroutine 队列
    lock     mutex          // 互斥锁
}
```

### 4.2 有缓冲 Channel

```
ch := make(chan int, 3)

┌──────── hchan ────────┐
│ qcount: 2             │
│ dataqsiz: 3           │
│ buf: [A, B, _]  ←── 环形队列
│ sendx: 2              │
│ recvx: 0              │
│ recvq: nil            │
│ sendq: nil            │
└───────────────────────┘
```

### 4.3 无缓冲 Channel

```
ch := make(chan int)

// 发送方阻塞在 sendq
// 接收方阻塞在 recvq
// 直接从发送方拷贝到接收方，不经过 buf
```

### 4.4 Channel 操作规则

| 操作 | nil channel | 已关闭 channel | 正常 channel |
|------|-------------|---------------|-------------|
| 发送 | 永久阻塞 | **panic** | 阻塞或成功 |
| 接收 | 永久阻塞 | 返回零值 | 阻塞或成功 |
| 关闭 | **panic** | **panic** | 成功 |

## 五、Map 内部实现

### 5.1 hmap 结构

```go
type hmap struct {
    count     int            // 元素个数
    flags     uint8          // 标志位
    B         uint8          // 桶数量 = 2^B
    noverflow uint16         // 溢出桶数量
    hash0     uint32         // 哈希种子
    buckets   unsafe.Pointer // 桶数组
    oldbuckets unsafe.Pointer // 扩容时的旧桶
    nevacuate  uintptr       // 扩容进度
    extra     *mapextra      // 溢出桶信息
}
```

### 5.2 桶结构

每个桶存储 8 个键值对：

```
┌─────────── bmap ───────────┐
│ tophash[0] │ tophash[1] │ ... │ tophash[7] │
│ key[0]     │ key[1]     │ ... │ key[7]     │
│ value[0]   │ value[1]   │ ... │ value[7]   │
│ overflow ──→ 下一个溢出桶     │
└────────────────────────────┘
```

### 5.3 查找流程

```
1. 计算 hash := hashFunc(key)
2. 计算桶号: bucket = hash & (2^B - 1)
3. 计算 tophash: top = hash >> (64 - 8)
4. 在桶中遍历 tophash 匹配
5. 匹配后比较完整 key
6. 未找到则检查溢出桶
7. 仍在扩容中则检查旧桶
```

### 5.4 扩容机制

**等量扩容**（整理碎片）：
- 条件：溢出桶过多，但负载因子不高
- 效果：重新排列，减少溢出桶

**增量扩容**（翻倍）：
- 条件：负载因子 > 6.5（平均每个桶超过 6.5 个元素）
- 效果：桶数量翻倍，元素重新分配

**渐进式迁移**：
- 扩容时不一次性迁移，而是在每次读写操作时迁移 1-2 个桶
- 确保扩容不影响性能

## 六、defer 内部实现

### 6.1 _defer 结构

```go
type _defer struct {
    started bool
    heap    bool
    openDefer bool
    sp      uintptr
    pc      uintptr
    fn      func()
    _panic  *_panic
    link    *_defer // 链表指针
}
```

### 6.2 defer 三种优化路径

| 路径 | 条件 | 性能 |
|------|------|------|
| **栈上 defer** (1.13+) | defer 数量 ≤ 8 | 最快 |
| **开放编码** (1.14+) | 无循环/条件中的 defer | 极快，内联 |
| **堆上 defer** | 其他情况 | 最慢 |

### 6.3 开放编码优化

```go
// Go 1.14+ 编译器直接内联 defer
func example() {
    defer fmt.Println("cleanup")
    // 编译为：
    // fmt.Println("cleanup") // 函数退出时直接调用
}
```

条件：
- 函数内 defer 数量 ≤ 8
- defer 不在循环或条件语句中
- 没有 `defer recover()` 模式

### 6.4 defer 执行顺序

```go
func main() {
    defer fmt.Println(1)
    defer fmt.Println(2)
    defer fmt.Println(3)
}
// 输出: 3, 2, 1 (LIFO 栈顺序)
```

## 七、内存对齐

### 7.1 对齐规则

1. 结构体的起始地址是其最大对齐值的整数倍
2. 每个字段的偏移量必须是其类型对齐值的整数倍
3. 结构体总大小必须是其最大对齐值的整数倍

```go
type Bad struct {
    a bool   // 1 byte + 7 padding
    b int64  // 8 bytes
    c int32  // 4 bytes + 4 padding
}
// 总大小: 24 bytes

type Good struct {
    b int64  // 8 bytes
    c int32  // 4 bytes
    a bool   // 1 byte + 3 padding
}
// 总大小: 16 bytes
```

### 7.2 unsafe 工具

```go
var x Good
fmt.Println(unsafe.Sizeof(x))     // 16
fmt.Println(unsafe.Alignof(x))    // 8
fmt.Println(unsafe.Offsetof(x.c)) // 8
```

### 7.3 对齐优化建议

- 字段按大小降序排列
- 相同类型的字段放在一起
- 使用 `fieldalignment` linter 检测

```bash
go install golang.org/x/tools/go/analysis/passes/fieldalignment/cmd/fieldalignment@latest
fieldalignment -fix ./...
```
