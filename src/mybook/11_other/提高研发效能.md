# 提高研发效能

## 充分设计，避免返工

- 先想清楚再动手，设计文档先行
- 技术方案评审：架构/接口/数据模型/边界条件
- 返工成本远高于设计成本

## 小步快跑，先能用再好用

- MVP（最小可行产品）优先
- 快速验证核心假设
- 渐进式完善，避免过度设计

## 动态生成，生效代码

- 代码生成 > 手写重复代码
- 模板/脚手架/CRUD 生成器
- 配置驱动 > 硬编码

## 热更新 + 扩展能力

- 热更新：修改即生效，无需重启
- 插件化架构：新功能以插件形式加入
- 让更多人参与开发（低门槛扩展）

## 让 AI 做更多的事

- 代码生成：Copilot / Cursor / Claude Code
- 问答诊断：ChatGPT / Claude
- 代码审查：AI Code Review
- 测试生成：AI 辅助编写单元测试

## 工具链

- **CI/CD 自动化**：GitHub Actions / GitLab CI / Jenkins
- **代码审查（CR）**：GitLab MR / GitHub PR / Gerrit
- **自动化测试**：单元测试 / 集成测试 / E2E 测试
- **性能基准**：Benchmark / 压测 / 火焰图

## 流程优化

- 需求评审 → 技术方案 → 开发 → 评审 → 测试 → 发布
- 每个环节有明确的输入/输出/检查点
- 自动化一切可自动化的步骤

## AI Coding 效率提升

### AGENTS.md + 文档体系

- AGENTS.md：给 AI 看的项目导航地图（~200行）
- 告诉 AI "去哪里找什么"，详细内容放链接文档
- 渐进式披露：写进 AGENTS.md 的 = AI 不知道就会出错的硬性规则

### 验证闭环

- 「改 → 构建 → 启动 → 验证」自动化循环
- curl 验证规范：每个 curl 独立执行，Token 获取模板化
- 前端用 Agent Browser 截屏验证页面渲染

### Harness Engineering 四原则

1. **Map not Manual**：导航地图而非操作手册
2. **Mechanical Verification**：机械化验证，不依赖人工判断
3. **Visible Feedback**：可见反馈，问题一目了然
4. **Incremental Complexity**：渐进复杂度，先跑通再优化

### Bad Case 驱动迭代

- 每遇到一个 AI bad case，就补一条规则
- 能自动化检查的 > 写在 AGENTS.md 的 > 口头约定的
- 错误信息格式：WHAT（违规了什么）+ WHY（为什么不允许）+ HOW（怎么修复）

## 代码质量

### 静态分析

- Go：`golangci-lint` / `staticcheck`
- Python：`ruff` / `mypy` / `pylint`
- 通用：SonarQube

### 代码规范

- 统一格式化工具：`gofmt` / `black` / `prettier`
- Pre-commit Hook：提交前自动检查
- EditorConfig：跨编辑器统一配置

### 测试策略

| 类型 | 范围 | 速度 | 数量 |
|------|------|------|------|
| 单元测试 | 函数/方法 | 快 | 多 |
| 集成测试 | 模块间 | 中 | 中 |
| E2E 测试 | 完整流程 | 慢 | 少 |

- 测试金字塔：单元 > 集成 > E2E
- 关键路径必须有测试覆盖
- Mock 外部依赖，避免测试不稳定

## 知识管理

- 技术文档沉淀：架构决策记录（ADR）
- Wiki / Confluence 知识库
- 代码即文档：清晰的命名和结构
- On-call 手册：故障排查 SOP
