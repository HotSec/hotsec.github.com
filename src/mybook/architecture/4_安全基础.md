# 安全基础

## 访问控制模型

### DAC（自主访问控制）

- 资源所有者自行决定访问权限
- ACL（访问控制列表）实现
- 灵活但安全性较低

### MAC（强制访问控制）

- 系统强制执行安全策略
- 安全标签（密级/类别）
- 主体许可级别 ≥ 客体密级 → 可读
- 典型：SELinux / AppArmor

### RBAC（基于角色的访问控制）

- 用户 → 角色 → 权限
- 角色继承
- 最小权限原则
- 广泛应用于企业系统

### ABAC（基于属性的访问控制）

- 基于主体/资源/环境属性动态决策
- 策略：`subject.department == resource.department AND environment.time IN work_hours`
- 灵活但复杂

## 数字签名

### RSA 签名

```
签名：s = m^d mod n
验证：m = s^e mod n
```

### ECDSA 签名

- 基于椭圆曲线
- 更短密钥，同等安全强度
- 比特币/以太坊使用

### 数字证书

- X.509 格式
- 包含：公钥、持有者信息、有效期、CA 签名
- 证书链：根 CA → 中间 CA → 终端证书

### CA（证书颁发机构）

- 根 CA：自签名，预装在操作系统/浏览器
- 中间 CA：根 CA 签发，用于日常签发
- OCSP：在线证书状态查询
- CRL：证书吊销列表

## CIA 三元组

- **机密性（Confidentiality）**：数据不被未授权访问
- **完整性（Integrity）**：数据不被未授权修改
- **可用性（Availability）**：服务可正常使用

## 安全评估

### 等级保护

- 五个等级（一级最低，五级最高）
- 二级：一般信息系统
- 三级：重要信息系统
- 测评流程：定级 → 备案 → 建设整改 → 等级测评 → 运营维护

### 风险评估

- 资产识别 → 威胁识别 → 脆弱性识别 → 风险分析
- 风险值 = 可能性 × 影响程度

### 渗透测试

- 黑盒：无内部信息
- 白盒：有完整信息
- 灰盒：部分信息

### 安全审计

- 日志收集与分析
- 合规性检查
- 安全事件追踪
