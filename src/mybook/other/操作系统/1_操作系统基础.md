## 一、进程管理

### 1.1 进程状态

```
         ┌──────────┐
    ┌──→ │  Running  │ ←── CPU 调度
    │    └──────────┘
    │         │ 时间片用完 / I/O 等待
    │         ▼
    │    ┌──────────┐
    │    │  Ready    │ ←── I/O 完成 / 创建
    │    └──────────┘
    │         │
    │         ▼
    │    ┌──────────┐
    │    │  Blocked  │ ←── 等待 I/O / 资源
    │    └──────────┘
    │         │ I/O 完成
    └─────────┘
```

### 1.2 进程调度算法

| 算法 | 特点 | 适用场景 |
|------|------|----------|
| FCFS | 先来先服务，非抢占 | 批处理 |
| SJF | 短作业优先 | 批处理 |
| RR | 时间片轮转 | 交互式 |
| 优先级 | 高优先级先执行 | 实时系统 |
| CFS | 完全公平调度器 | Linux 默认 |

### 1.3 进程通信 (IPC)

| 方式 | 特点 |
|------|------|
| 管道 (Pipe) | 半双工，父子进程间 |
| 命名管道 (FIFO) | 任意进程间 |
| 消息队列 | 内核维护的消息链表 |
| 共享内存 | 最快，需同步 |
| 信号量 | 计数器，用于同步 |
| 信号 | 异步通知 |
| Socket | 网络通信 |

### 1.4 线程模型

| 模型 | 说明 | 示例 |
|------|------|------|
| 1:1 | 一个用户线程对应一个内核线程 | Linux, Go(GMP) |
| N:1 | 多个用户线程对应一个内核线程 | 早期 Green Thread |
| M:N | M 个用户线程映射到 N 个内核线程 | Go(GMP), Erlang |

## 二、内存管理

### 2.1 虚拟内存

```
┌──────────────────┐     ┌──────────────────┐
│   虚拟地址空间     │     │   物理地址空间     │
│                  │     │                  │
│  ┌────────────┐ │     │  ┌────────────┐ │
│  │  用户空间   │ │ MMU │  │  物理内存   │ │
│  │  (0-3GB)   │ │────→│  │            │ │
│  └────────────┘ │     │  └────────────┘ │
│  ┌────────────┐ │     │  ┌────────────┐ │
│  │  内核空间   │ │     │  │  Swap 空间  │ │
│  │  (3-4GB)   │ │     │  └────────────┘ │
│  └────────────┘ │     └──────────────────┘
└──────────────────┘
```

- 每个进程有独立的虚拟地址空间
- MMU 将虚拟地址映射到物理地址
- 页 (Page) 是映射的最小单位 (通常 4KB)

### 2.2 分页机制

```
虚拟地址: [页号 | 页内偏移]

页表: 页号 → 物理页框号

多级页表:
┌─────────┐    ┌─────────┐    ┌─────────┐
│PGD(一级)│ → │PUD(二级)│ → │PTE(三级)│ → 物理页
└─────────┘    └─────────┘    └─────────┘

TLB: 页表缓存，加速地址翻译
```

### 2.3 页面置换算法

| 算法 | 说明 | 优缺点 |
|------|------|--------|
| OPT | 最优（未来最远使用） | 理论最优，无法实现 |
| FIFO | 先进先出 | 简单，有 Belady 异常 |
| LRU | 最近最少使用 | 性能好，实现复杂 |
| Clock | 时钟算法 | LRU 的近似 |
| LFU | 最不经常使用 | 适合热点数据 |

### 2.4 缺页中断

```
1. CPU 访问虚拟地址
2. MMU 查找页表，发现页不在内存
3. 触发缺页中断 (Page Fault)
4. OS 从磁盘/swap 加载页面到内存
5. 更新页表
6. 重新执行指令
```

## 三、I/O 模型

### 3.1 五种 I/O 模型

```
1. 阻塞 I/O (Blocking I/O)
   ┌─────────────────────────────┐
   │ 应用程序调用 recvfrom()      │
   │ ████████████ 等待数据 ████████│ ← 阻塞
   │ 数据就绪，拷贝到用户空间      │
   └─────────────────────────────┘

2. 非阻塞 I/O (Non-blocking I/O)
   ┌─────────────────────────────┐
   │ recvfrom() → EWOULDBLOCK   │ ← 立即返回
   │ recvfrom() → EWOULDBLOCK   │ ← 轮询
   │ recvfrom() → 数据就绪       │ ← 成功
   └─────────────────────────────┘

3. I/O 多路复用 (I/O Multiplexing)
   ┌─────────────────────────────┐
   │ select/poll/epoll 等待       │ ← 阻塞在 select
   │ 某个 fd 就绪                 │
   │ recvfrom() 读取数据          │
   └─────────────────────────────┘

4. 信号驱动 I/O (Signal-driven I/O)
   ┌─────────────────────────────┐
   │ 注册 SIGIO 信号处理          │
   │ 做其他事情...                │
   │ 信号到达，调用 recvfrom()    │
   └─────────────────────────────┘

5. 异步 I/O (AIO)
   ┌─────────────────────────────┐
   │ 调用 aio_read()              │ ← 立即返回
   │ 做其他事情...                │
   │ 内核完成数据拷贝，通知应用    │
   └─────────────────────────────┘
```

### 3.2 select vs poll vs epoll

| 维度 | select | poll | epoll |
|------|--------|------|-------|
| fd 数量 | 1024 | 无限制 | 无限制 |
| 数据结构 | bitmap | 数组 | 红黑树 |
| 就绪通知 | 遍历所有 fd O(N) | 遍历所有 fd O(N) | 只返回就绪 fd O(1) |
| 每次调用 | 需要重新传入 fd | 需要重新传入 fd | 只需添加一次 |
| 触发模式 | 水平触发 | 水平触发 | 水平/边缘 |

### 3.3 epoll 触发模式

```
水平触发 (LT, Level Triggered):
- fd 就绪后，每次 epoll_wait 都会通知
- 可以不立即处理，下次再通知
- 编程简单，不易出错

边缘触发 (ET, Edge Triggered):
- fd 状态变化时才通知一次
- 必须立即处理完所有数据
- 效率更高，但编程复杂
- 需要配合非阻塞 I/O
```

### 3.4 Go netpoller

```
Go 网络模型:
1. goroutine 发起网络 I/O
2. runtime 将 fd 注册到 epoll
3. goroutine 挂起 (gopark)
4. epoll 返回就绪事件
5. runtime 唤醒对应 goroutine (goready)
6. goroutine 继续执行

优势: 对开发者透明，写同步代码享受异步性能
```

## 四、死锁

### 4.1 四个必要条件

1. **互斥**: 资源只能被一个进程占有
2. **持有并等待**: 持有资源同时等待其他资源
3. **不可抢占**: 已持有的资源不能被强制剥夺
4. **循环等待**: 进程间形成循环等待链

### 4.2 预防策略

| 策略 | 打破的条件 | 方法 |
|------|-----------|------|
| 预防 | 持有并等待 | 一次性申请所有资源 |
| 预防 | 不可抢占 | 超时释放资源 |
| 预防 | 循环等待 | 资源有序分配 |
| 避免 | - | 银行家算法 |
| 检测+恢复 | - | 死锁检测图 + 终止进程 |

## 五、文件系统

### 5.1 inode

```
┌────────────── inode ──────────────┐
│ 文件权限 (rwxrwxrwx)              │
│ 所有者 UID / GID                  │
│ 文件大小                          │

└───────────────────────────────────┘

目录 = 文件名 → inode 号的映射表
```
