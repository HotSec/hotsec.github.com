# 内存管理

## 虚拟内存

### 地址空间

```
用户空间 (0 - 3GB)
├── 代码段 (.text)
├── 数据段 (.data, .bss)
├── 堆 (↑ 向上增长)
├── 共享库映射区
└── 栈 (↓ 向下增长)

内核空间 (3GB - 4GB)
├── 内核代码
├── 内核数据
├── 页表
└── 设备映射
```

### 页式管理

| 概念 | 描述 |
|------|------|
| 页 (Page) | 虚拟内存固定大小块（通常 4KB） |
| 页框 (Frame) | 物理内存固定大小块 |
| 页表 (Page Table) | 虚拟页→物理帧映射 |
| TLB | 页表缓存，加速地址翻译 |
| 缺页中断 | 访问未映射页时触发 |

### 多级页表

```
虚拟地址 (48位)
├── PML4 索引 (9位) → PML4 表
├── PDPT 索引 (9位) → PDPT 表
├── PD 索引   (9位) → PD 表
├── PT 索引   (9位) → PT 表
└── 页内偏移  (12位)
```

四级页表减少内存占用：未使用的地址空间不需要分配页表。

### 页面置换算法

| 算法 | 描述 | 优缺点 |
|------|------|--------|
| OPT | 置换最远使用的页 | 理论最优，无法实现 |
| FIFO | 置换最早进入的页 | 简单，有 Belady 异常 |
| LRU | 置换最近最少使用的页 | 效果好，实现成本高 |
| Clock | 近似 LRU，环形链表 | 折中方案 |
| LFU | 置换使用频率最低的页 | 对突发访问不友好 |

### Linux 页面回收

```bash
cat /proc/vmstat | grep pgscan
cat /proc/meminfo | grep -i "active\|inactive"
```

- **Active List**：最近访问的页
- **Inactive List**：较久未访问的页
- 回收时优先从 Inactive List 取

## 内存分配

### 伙伴系统 (Buddy System)

```
Order 0: 4KB  ─┬─ 8KB ─┬─ 16KB ─┬─ 32KB ...
Order 1: 8KB  ─┘       │        │
Order 2: 16KB ──────────┘        │
Order 3: 32KB ───────────────────┘
```

- 分配：找到满足需求的最小块，必要时分裂
- 释放：检查伙伴是否空闲，空闲则合并
- 外部碎片少，内部碎片最多 50%

### Slab 分配器

```c
struct kmem_cache {
    const char *name;
    size_t object_size;
    struct list_head slabs_full;
    struct list_head slabs_partial;
    struct list_head slabs_free;
};
```

- 针对频繁分配/释放的小对象
- 每个 Slab 包含多个相同大小的对象
- 三种状态：full / partial / free
- 减少内部碎片

### 用户态分配器

| 分配器 | 特点 |
|--------|------|
| ptmalloc (glibc) | 多线程，多 arena |
| tcmalloc (Google) | 线程缓存，减少锁竞争 |
| jemalloc (Facebook) | 多 arena，低碎片 |
| mimalloc (Microsoft) | 安全，高性能 |

### malloc 流程

```
malloc(size)
    ↓
size ≤ 小对象阈值?
    ├── 是 → 从线程缓存分配
    └── 否 → size ≤ mmap 阈值?
              ├── 是 → 从堆扩展分配 (brk/sbrk)
              └── 否 → mmap 匿名映射
```

## 内存映射

### mmap

```c
void *mmap(void *addr, size_t length, int prot, int flags, int fd, off_t offset);
int munmap(void *addr, size_t length);
```

```c
#include <sys/mman.h>
#include <fcntl.h>

int fd = open("large_file", O_RDONLY);
void *ptr = mmap(NULL, file_size, PROT_READ, MAP_PRIVATE, fd, 0);

process_data(ptr, file_size);

munmap(ptr, file_size);
close(fd);
```

### 共享内存

```c
int shm_fd = shm_open("/my_shm", O_CREAT | O_RDWR, 0666);
ftruncate(shm_fd, 4096);
void *ptr = mmap(NULL, 4096, PROT_READ | PROT_WRITE, MAP_SHARED, shm_fd, 0);
```

## 内存保护

### 机制

| 机制 | 描述 |
|------|------|
| ASLR | 地址空间随机化 |
| DEP/NX | 数据不可执行 |
| Stack Canary | 栈溢出检测 |
| PIE | 位置无关可执行文件 |
| RELRO | 只读重定位 |

### OOM Killer

```bash
cat /proc/<pid>/oom_score
cat /proc/<pid>/oom_score_adj
echo -1000 > /proc/<pid>/oom_score_adj
dmesg | grep -i "oom"
```

OOM Killer 选择进程策略：
1. oom_score 越高越可能被杀
2. 占用内存越多分数越高
3. 优先级（oom_score_adj）可调整
4. 子进程得分继承

## 内存优化

### 程序层面

```go
// 对象池减少 GC 压力
var bufPool = sync.Pool{
    New: func() interface{} {
        return bytes.NewBuffer(make([]byte, 0, 4096))
    },
}

func process() {
    buf := bufPool.Get().(*bytes.Buffer)
    defer func() {
        buf.Reset()
        bufPool.Put(buf)
    }()
}

// 预分配减少扩容
s := make([]int, 0, 1000)
m := make(map[string]int, 100)
```

### 系统层面

```bash
echo 1 > /proc/sys/vm/drop_caches
echo 2 > /proc/sys/vm/drop_caches
echo 3 > /proc/sys/vm/drop_caches

sysctl vm.swappiness=10
sysctl vm.dirty_ratio=20
sysctl vm.dirty_background_ratio=10
sysctl vm.overcommit_memory=1
```
