### 健康检查

```go
type HealthChecker struct {
    targets []string
    timeout time.Duration
    interval time.Duration
}

func (hc *HealthChecker) Check(target string) bool {
    ctx, cancel := context.WithTimeout(context.Background(), hc.timeout)
    defer cancel()

    req, _ := http.NewRequestWithContext(ctx, "GET", target+"/health", nil)
    resp, err := http.DefaultClient.Do(req)
    if err != nil {
        return false
    }
    defer resp.Body.Close()
    return resp.StatusCode == 200
}
```

### 熔断器

```go
type CircuitBreaker struct {
    maxFailures int
    resetTimeout time.Duration
    failures    int
    lastFailure time.Time
    state       string
    mu          sync.Mutex
}

func (cb *CircuitBreaker) Execute(fn func() error) error {
    cb.mu.Lock()
    if cb.state == "open" {
        if time.Since(cb.lastFailure) > cb.resetTimeout {
            cb.state = "half-open"
        } else {
            cb.mu.Unlock()
            return ErrCircuitOpen
        }
    }
    cb.mu.Unlock()

    err := fn()

    cb.mu.Lock()
    defer cb.mu.Unlock()

    if err != nil {
        cb.failures++
        cb.lastFailure = time.Now()
        if cb.failures >= cb.maxFailures {
            cb.state = "open"
        }
        return err
    }

    cb.failures = 0
    cb.state = "closed"
    return nil
}
```

### 限流

```go
type RateLimiter struct {
    rate     float64
    capacity float64
    tokens   float64
    lastTime time.Time
    mu       sync.Mutex
}

func (rl *RateLimiter) Allow() bool {
    rl.mu.Lock()
    defer rl.mu.Unlock()

    now := time.Now()
    elapsed := now.Sub(rl.lastTime).Seconds()
    rl.tokens = min(rl.capacity, rl.tokens+elapsed*rl.rate)
    rl.lastTime = now

    if rl.tokens >= 1 {
        rl.tokens--
        return true
    }
    return false
}
```

## 可扩展设计

### 水平扩展

```
                  ┌── Server 1
Client → LB ─────┼── Server 2
                  └── Server 3

无状态服务 → 直接水平扩展
有状态服务 → 需要数据分片
```

### 数据库扩展

```
读写分离
┌── Master (写)
│
├── Slave1 (读)
├── Slave2 (读)
└── Slave3 (读)

分库分表
┌── Shard1 (user_id % 4 == 0)
├── Shard2 (user_id % 4 == 1)
├── Shard3 (user_id % 4 == 2)
└── Shard4 (user_id % 4 == 3)
```

### 缓存策略

```
Cache-Aside:
1. 读缓存 → 命中返回
2. 未命中 → 读数据库 → 写缓存
3. 写数据 → 写数据库 → 删缓存

Read-Through:
1. 读缓存 → 命中返回
2. 未命中 → 缓存层自动从 DB 加载

Write-Through:
1. 写缓存 → 缓存层同步写 DB

Write-Behind:
1. 写缓存 → 异步批量写 DB
```

## 常见架构模式

### CQRS

```
Command (写)                    Query (读)
┌──────────┐                  ┌──────────┐
│ Command  │                  │  Query   │
│ Handler  │                  │ Handler  │
└────┬─────┘                  └────┬─────┘
     │                             │
┌────▼─────┐    Event     ┌───────▼──────┐
│ Write DB │──────────────>│  Read DB     │
│ (OLTP)   │              │  (OLAP/缓存) │
└──────────┘              └──────────────┘
```

### Event Sourcing

```go
type EventStore interface {
    Append(aggregateID string, event Event) error
    Load(aggregateID string) ([]Event, error)
}

type Order struct {
    ID     string
    Status string
    Items  []Item
}

func (o *Order) Apply(event Event) {
    switch event.Type {
    case "OrderCreated":
        o.ID = event.Data["id"]
        o.Status = "created"
    case "ItemAdded":
        o.Items = append(o.Items, event.Data["item"].(Item))
    case "OrderPaid":
        o.Status = "paid"
    }
}
```

### 事件驱动架构

```
Producer → Message Queue → Consumer
              │
              ├── Order Service
              ├── Inventory Service
              └── Notification Service
```

```go
type EventBus interface {
    Publish(topic string, event Event) error
    Subscribe(topic string, handler EventHandler) error
}

func (s *OrderService) CreateOrder(req CreateOrderReq) (*Order, error) {
    order, err := s.repo.Create(req)
    if err != nil {
        return nil, err
    }

    s.eventBus.Publish("order.created", Event{
        Type: "OrderCreated",
        Data: order,
    })

    return order, nil
}
```

## 架构设计原则

### SOLID

| 原则 | 描述 |
|------|------|
| Single Responsibility | 单一职责 |
| Open/Closed | 开放扩展，关闭修改 |
| Liskov Substitution | 子类可替换父类 |
| Interface Segregation | 接口隔离 |
| Dependency Inversion | 依赖倒置 |

### DDD 分层

```
┌─────────────────────────────┐
│     Interface Layer          │  HTTP/gRPC/CLI
├─────────────────────────────┤
│     Application Layer       │  用例/编排
├─────────────────────────────┤
│     Domain Layer            │  实体/值对象/聚合
├─────────────────────────────┤
│     Infrastructure Layer    │  DB/MQ/外部服务
└─────────────────────────────┘
```

### 设计原则

1. **KISS**：保持简单
2. **YAGNI**：不要过度设计
3. **DRY**：不要重复
4. **关注点分离**：各层各司其职
5. **面向接口编程**：依赖抽象不依赖实现
6. **渐进式架构**：根据需求演进

### 架构决策记录 (ADR)

```markdown
# ADR-001: 选择 gRPC 作为服务间通信协议

## 状态
已接受

## 上下文
微服务间需要高效通信，支持多种语言

## 决策
使用 gRPC + Protocol Buffers

## 原因
1. 二进制协议，比 JSON 小 3-10 倍
2. 强类型，代码生成
3. 双向流支持
4. 多语言 SDK

## 后果
- 需要维护 .proto 文件
- 浏览器不直接支持（需 gRPC-Web）
- 调试不如 REST 直观
```
