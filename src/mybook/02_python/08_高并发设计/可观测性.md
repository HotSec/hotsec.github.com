# 可观测性

三大支柱：Metrics（指标）、Logs（日志）、Traces（链路追踪）。

## Prometheus

### 核心概念

- **时序数据库**：存储带时间戳的指标数据
- **Pull 模式**：主动拉取目标指标
- **PromQL**：强大的查询语言
- **多维数据模型**：指标名 + 标签（Label）唯一标识时间序列

### 指标类型

| 类型 | 说明 | 示例 |
|------|------|------|
| Counter | 只增计数器 | 请求总数、错误总数 |
| Gauge | 可增可减 | 当前连接数、温度 |
| Histogram | 分布统计 | 请求延迟分布 |
| Summary | 分位数统计 | P50/P95/P99 延迟 |

### 数据模型

```
http_requests_total{method="GET", path="/api/users", status="200"} 1234
```

- 指标名：`http_requests_total`
- 标签：`method`、`path`、`status`
- 值：`1234`

### PromQL

```promql
rate(http_requests_total[5m])
histogram_quantile(0.99, rate(http_request_duration_seconds_bucket[5m]))
sum(rate(http_requests_total[5m])) by (service)
topk(10, sum(rate(http_requests_total[5m])) by (path))
increase(http_requests_total[1h])
```

### Python 集成

```python
from prometheus_client import Counter, Histogram, Gauge, generate_latest

REQUEST_COUNT = Counter("http_requests_total", "Total requests", ["method", "path", "status"])
REQUEST_LATENCY = Histogram("http_request_duration_seconds", "Request latency", ["method"])
ACTIVE_CONNECTIONS = Gauge("active_connections", "Active connections")

REQUEST_COUNT.labels(method="GET", path="/api/users", status="200").inc()
REQUEST_LATENCY.labels(method="GET").observe(0.15)
ACTIVE_CONNECTIONS.set(42)
```

### 架构

```
应用 → /metrics → Prometheus → Alertmanager → 邮件/钉钉
                     ↓
                  Grafana 可视化
```

### 告警规则

```yaml
groups:
  - name: api_alerts
    rules:
      - alert: HighErrorRate
        expr: rate(http_requests_total{status=~"5.."}[5m]) / rate(http_requests_total[5m]) > 0.05
        for: 5m
        labels:
          severity: critical
        annotations:
          summary: "API error rate exceeds 5%"
```

## Grafana

### 核心功能

- **Dashboard**：可视化面板，支持多种图表
- **数据源**：Prometheus、Loki、Jaeger、ElasticSearch、MySQL
- **告警**：基于阈值的告警通知
- **变量**：动态过滤面板数据
- **模板**：可复用、可导入的 Dashboard

### 面板类型

| 类型 | 适用 |
|------|------|
| Time Series | 时序趋势 |
| Stat | 单值展示 |
| Table | 表格数据 |
| Heatmap | 热力图 |
| Pie Chart | 占比分布 |

### 最佳实践

- 按服务组织 Dashboard
- 使用变量切换服务/环境
- 设置合理的刷新间隔
- 添加面板说明文档

## Jaeger

### 核心概念

- **Span**：一个操作单元，包含操作名、时间、标签
- **Trace**：一个请求的完整调用链，由多个 Span 组成
- **Context**：TraceID + SpanID，跨进程传播

### 架构

```
应用 → Jaeger Agent → Jaeger Collector → Storage (ES/Cassandra)
                                              ↓
                                         Jaeger Query → UI
```

### Python 集成

```python
from jaeger_client import Config

config = Config(
    config={"sampler": {"type": "const", "param": 1}},
    service_name="my-service",
)
tracer = config.initialize_tracer()

with tracer.start_span("operation") as span:
    span.set_tag("user.id", "12345")
    with tracer.start_span("sub-operation", child_of=span) as child:
        child.log_kv({"event": "processing"})
```

### OpenTracing 语义

- `span.set_tag(key, value)`：设置标签
- `span.log_kv({"event": "..."})`：记录事件
- `span.set_baggage_item(key, value)`：跨 Span 传播数据
- `ChildOf` / `FollowsFrom`：Span 关系

## OpenTelemetry

### 统一标准

OpenTelemetry = OpenTracing + OpenCensus，统一了 Metrics、Logs、Traces 的采集标准。

### 核心组件

- **API**：与具体实现解耦的接口
- **SDK**：API 的实现，包含采集、处理、导出
- **Collector**：接收、处理、导出遥测数据

### Python 集成

```python
from opentelemetry import trace, metrics
from opentelemetry.sdk.trace import TracerProvider
from opentelemetry.sdk.trace.export import BatchSpanProcessor
from opentelemetry.exporter.otlp.proto.grpc.trace_exporter import OTLPSpanExporter
from opentelemetry.instrumentation.flask import FlaskInstrumentor

provider = TracerProvider()
processor = BatchSpanProcessor(OTLPSpanExporter(endpoint="localhost:4317"))
provider.add_span_processor(processor)
trace.set_tracer_provider(provider)

tracer = trace.get_tracer("my-service")

with tracer.start_as_current_span("process_request") as span:
    span.set_attribute("http.method", "GET")
    span.set_attribute("http.url", "/api/users")
```

### 自动埋点

```python
from opentelemetry.instrumentation.auto_instrumentation import sitecustomize
```

支持的库：Flask、Django、Requests、SQLAlchemy、Redis、aiohttp 等。

### Collector 配置

```yaml
receivers:
  otlp:
    protocols:
      grpc:
        endpoint: 0.0.0.0:4317
      http:
        endpoint: 0.0.0.0:4318

processors:
  batch:
    timeout: 5s

exporters:
  jaeger:
    endpoint: jaeger:14250
    tls: false
  prometheus:
    endpoint: 0.0.0.0:8889

service:
  pipelines:
    traces:
      receivers: [otlp]
      processors: [batch]
      exporters: [jaeger]
    metrics:
      receivers: [otlp]
      exporters: [prometheus]
```

## 日志

### 结构化日志

```python
import structlog

logger = structlog.get_logger()
logger.info("request_processed", method="GET", path="/api/users", duration_ms=45, status=200)
```

### 日志级别

| 级别 | 用途 |
|------|------|
| ERROR | 影响功能的错误 |
| WARN | 潜在问题 |
| INFO | 关键业务事件 |
| DEBUG | 调试信息 |

### 日志关联 Trace

```python
from opentelemetry import trace

span = trace.get_current_span()
ctx = span.get_span_context()
logger.info("request_processed", trace_id=hex(ctx.trace_id), span_id=hex(ctx.span_id))
```

## 可观测性体系

```
Metrics（发现异常）→ Traces（定位服务）→ Logs（查看详情）
```

- **Metrics**：宏观视角，发现系统异常
- **Traces**：微观视角，定位请求链路瓶颈
- **Logs**：细节视角，查看具体错误信息
- 三者通过 TraceID 关联
