# 海量推送系统

## 设计要点

### 分布式推送服务器

多台推送服务器组成集群，水平扩展推送能力。

```
客户端 ←→ 长连接网关 ←→ 推送服务 ←→ 消息队列 ←→ 业务服务
                ↕
           路由/调度层
```

### 路由算法

| 算法 | 原理 | 优缺点 |
|------|------|--------|
| 随机调度 | 随机选择推送服务器 | 简单，但可能不均衡 |
| 轮询调度 | 依次轮询分配 | 均衡，但无状态感知 |
| 一致性 Hash | 按用户 ID Hash 映射 | 扩缩容影响小，适合有状态连接 |
| 最小连接数 | 选择连接数最少的服务器 | 动态均衡，需实时统计 |

### 一致性 Hash 实现

```python
import hashlib
import bisect

class ConsistentHash:
    def __init__(self, nodes, replicas=100):
        self.ring = {}
        self.sorted_keys = []
        for node in nodes:
            for i in range(replicas):
                key = self._hash(f"{node}:{i}")
                self.ring[key] = node
                self.sorted_keys.append(key)
        self.sorted_keys.sort()

    def _hash(self, key):
        return int(hashlib.md5(key.encode()).hexdigest(), 16)

    def get_node(self, key):
        h = self._hash(key)
        idx = bisect.bisect(self.sorted_keys, h)
        if idx == len(self.sorted_keys):
            idx = 0
        return self.ring[self.sorted_keys[idx]]
```

## 内容发布系统

### 核心流程

```
内容创建 → 审核 → 分发 → 推送 → 用户接收
```

### 分发策略

- **推模式**：服务端主动推送，实时性高，资源消耗大
- **拉模式**：客户端定时拉取，资源消耗小，实时性低
- **推拉结合**：重要消息推送，普通消息拉取

### 消息可靠性

- 消息确认机制（ACK）
- 离线消息存储
- 消息去重（幂等性）
- 失败重试与降级
