# 微服务

## 核心组件

- **服务网关**：确保服务提供者对客户端的透明，这一层可以进行反向路由、安全认证、灰度发布、日志监控等前置动作
- **服务发现**：注册并维护远程服务及服务提供者的地址，供服务消费者发现和调用，如 etcd、Consul
- **服务框架**：实现了 RPC 框架，包含服务接口描述和实现，向注册中心发布服务等功能，如 gRPC
- **服务监控**：对服务消费者与提供者之间的调用情况进行监控和数据展示，如 Prometheus
- **服务追踪**：记录每个请求的服务器调用完整链路，以便进行问题定位和故障分析，如 Jaeger、Zipkin
- **服务治理**：通过一系列手段保证在各种意外情况下服务调用仍然能够正常进行，包括熔断、隔离、限流、降级、负载均衡等
- **基础设施**：提供底层基础数据服务，如 Kafka、MySQL、Redis、ElasticSearch
- **分布式配置中心**：统一配置管理，如 Nacos、Consul、ZooKeeper、Apollo

## 服务拆分

### 拆分原则

- **单一职责**：每个服务只负责一个业务领域
- **限界上下文**：按 DDD 领域边界拆分
- **独立部署**：服务可独立开发、测试、部署
- **数据隔离**：每个服务拥有自己的数据库
- **粗粒度优先**：先粗后细，避免过度拆分

### 拆分策略

| 策略 | 说明 | 适用 |
|------|------|------|
| 按业务域 | 用户、订单、商品 | 电商 |
| 按子域 | 核心、支撑、通用 | DDD |
| 按团队 | 康威定律 | 大团队 |
| 按变更频率 | 高频/低频 | 迭代快 |

## 服务通信

### 同步通信

| 方式 | 特点 | 适用 |
|------|------|------|
| REST/HTTP | 简单通用，文本协议 | 对外API |
| gRPC | 高性能，强类型，Protobuf | 内部服务 |
| GraphQL | 灵活查询，按需取数据 | BFF层 |

### 异步通信

| 方式 | 特点 | 适用 |
|------|------|------|
| 消息队列 | 解耦、削峰、最终一致 | 异步任务 |
| 事件驱动 | 发布订阅，松耦合 | 状态变更通知 |
| 事件溯源 | 事件即真相，可重放 | 审计、CQRS |

## 服务注册与发现

### 客户端发现

```
服务启动 → 注册到注册中心
消费者 → 从注册中心获取地址 → 直接调用
```

- etcd / Consul / Nacos / ZooKeeper
- 客户端做负载均衡

### 服务端发现

```
消费者 → 负载均衡器/网关 → 转发到服务实例
```

- Nginx / APISIX / AWS ALB
- 服务端做负载均衡

### 健康检查

- 心跳检测：定时发送心跳
- 主动探测：注册中心主动 HTTP/TCP 探测
- TTL 机制：租约到期自动摘除

## API 网关

### 核心功能

- **路由**：请求转发到后端服务
- **认证授权**：JWT / OAuth2 鉴权
- **限流熔断**：保护后端服务
- **协议转换**：HTTP ↔ gRPC
- **灰度发布**：按规则路由流量
- **日志监控**：请求日志、指标采集
- **响应聚合**：多个后端响应合并

### 常见网关

| 网关 | 语言 | 特点 |
|------|------|------|
| Nginx | C | 高性能，配置式 |
| APISIX | Lua | 动态配置，插件化 |
| Kong | Lua | 插件生态丰富 |
| Envoy | C++ | xDS 动态配置，Service Mesh |
| Traefik | Go | 自动服务发现 |

## 配置中心

### 核心能力

- 集中管理配置
- 动态推送（长轮询 / Watch）
- 版本管理与回滚
- 灰度发布配置
- 多环境隔离

### 选型

| 配置中心 | 特点 |
|----------|------|
| Nacos | 配置 + 注册中心，AP/CP 可选 |
| Apollo | 携程开源，功能完善 |
| Consul | KV + 服务发现 |
| etcd | 简单可靠，Watch 机制 |

## 数据一致性

### 跨服务事务

- **Saga**：长事务编排，每个步骤有补偿
- **TCC**：Try-Confirm-Cancel，业务层面保证
- **本地消息表**：本地事务 + 消息表 + 定时投递
- **事务消息**：RocketMQ 半消息机制

### 数据查询

- **API 组合**：网关/BFF 聚合多个服务数据
- **CQRS**：命令走主库，查询走读模型
- **数据冗余**：订阅事件同步数据到查询服务

## 微服务陷阱

- **分布式单体**：服务拆了但耦合没减
- **过度拆分**：服务太多，运维成本爆炸
- **共享数据库**：服务间通过DB耦合
- **同步调用链过长**：级联失败风险
- **忽视运维**：没有监控、日志、追踪
