# 缓存

## 缓存策略

### Cache Aside（旁路缓存）

最常用模式，应用层负责维护缓存：

```
读取：先查缓存 → 命中返回 → 未命中查DB → 写入缓存
写入：先更新DB → 删除缓存
```

- 优点：缓存与DB解耦，简单可靠
- 缺点：首次请求必穿透；极端并发下可能短暂不一致

### Read Through / Write Through

缓存层代理数据访问：

- **Read Through**：缓存未命中时，由缓存层负责从DB加载
- **Write Through**：写入时同步更新缓存和DB
- 适用：读多写少，一致性要求高

### Write Behind（异步写）

- 写入时只更新缓存，异步批量写入DB
- 优点：写入性能极高
- 缺点：数据可能丢失，一致性弱

### Refresh Ahead

- 缓存过期前主动刷新
- 避免缓存失效瞬间的流量冲击

## 缓存问题

### 缓存穿透

查询不存在的数据，请求直达数据库。

**解决方案**：
- **布隆过滤器**：在缓存前加布隆过滤器，不存在的key直接拦截
- **缓存空值**：查询为空时缓存空值，设置短TTL
- **请求校验**：业务层过滤非法请求

```python
def get_user(user_id):
    data = cache.get(f"user:{user_id}")
    if data is not None:
        return data if data != "NULL" else None
    user = db.query(User).get(user_id)
    if user:
        cache.set(f"user:{user_id}", user, ttl=3600)
    else:
        cache.set(f"user:{user_id}", "NULL", ttl=60)
    return user
```

### 缓存击穿

热点key过期瞬间，大量请求同时穿透到DB。

**解决方案**：
- **互斥锁**：只允许一个请求重建缓存
- **逻辑过期**：不设TTL，数据中包含逻辑过期时间，过期后异步更新
- **热点key永不过期**：配合主动更新

```python
import threading

lock = threading.Lock()

def get_hot_key(key):
    data = cache.get(key)
    if data is not None:
        return data
    with lock:
        data = cache.get(key)
        if data is not None:
            return data
        data = db.query(key)
        cache.set(key, data, ttl=3600)
    return data
```

### 缓存雪崩

大量key同时过期，或缓存服务宕机。

**解决方案**：
- **过期时间加随机值**：`ttl = base_ttl + random(0, 300)`
- **多级缓存**：本地缓存 + 分布式缓存
- **缓存高可用**：Redis Sentinel / Cluster
- **熔断降级**：缓存不可用时返回默认值

### 缓存与数据库一致性

| 策略 | 一致性 | 性能 | 适用场景 |
|------|--------|------|----------|
| 先更新DB再删缓存 | 较强 | 好 | 大多数场景 |
| 先删缓存再更新DB | 弱 | 好 | 低并发 |
| 延迟双删 | 较强 | 中 | 高并发 |
| 订阅binlog | 强 | 中 | 强一致性要求 |

**延迟双删**：
```
删除缓存 → 更新DB → 延迟N毫秒 → 再删缓存
```

**Canal 订阅 binlog**：
```
更新DB → binlog → Canal → 删除/更新缓存
```

## Redis 缓存

### 数据结构选择

| 结构 | 场景 |
|------|------|
| String | 简单KV、计数器、分布式锁 |
| Hash | 对象属性、用户信息 |
| List | 消息队列、最新列表 |
| Set | 去重、标签、共同好友 |
| ZSet | 排行榜、延迟队列 |
| Bitmap | 签到、在线状态 |
| HyperLogLog | UV 统计 |

### 过期策略

- **惰性删除**：访问时检查是否过期
- **定期删除**：周期性随机抽样删除过期key

### 淘汰策略

| 策略 | 说明 |
|------|------|
| noeviction | 不淘汰，写入报错（默认） |
| allkeys-lru | 所有key中淘汰最久未使用 |
| allkeys-lfu | 所有key中淘汰使用频率最低 |
| allkeys-random | 随机淘汰 |
| volatile-lru | 过期key中淘汰最久未使用 |
| volatile-lfu | 过期key中淘汰使用频率最低 |
| volatile-ttl | 过期key中淘汰TTL最短的 |

### 缓存预热

```python
def warm_up():
    hot_users = db.query("SELECT * FROM users WHERE is_hot = 1")
    for user in hot_users:
        cache.set(f"user:{user.id}", user, ttl=3600)
```

## 多级缓存架构

```
请求 → 本地缓存(L1) → 分布式缓存(L2) → 数据库
         ↓miss            ↓miss           ↓miss
      返回数据          查L2            查DB
                        命中→回写L1     命中→回写L2+L1
```

- **L1 本地缓存**：进程内，微秒级，容量小
- **L2 分布式缓存**：Redis，毫秒级，容量大
- **L3 数据库**：持久化，百毫秒级
