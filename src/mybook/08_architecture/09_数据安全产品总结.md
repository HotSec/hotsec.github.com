# 数据安全产品总结

## 一、数据安全产品核心分类

| 产品类型 | 英文缩写 | 核心功能 | 典型应用场景 |
|---------|---------|---------|-------------|
| 数据泄露防护 | **DLP** | 监控和阻止敏感数据泄露 | 终端、网络、存储数据泄露防护 |
| 数据脱敏 | - | 将敏感数据替换为虚构但真实的数据 | 测试环境、开发环境、数据共享 |
| 数据加密 | - | 加密存储和传输中的数据 | 数据库加密、文件加密、传输加密 |
| 数据分类分级 | - | 按敏感程度对数据分类并分级管理 | 数据治理、合规审计 |
| 数据库审计 | DBAudit | 记录和分析数据库访问行为 | 数据库安全监控、合规审计 |
| 数据访问控制 | DAC/MAC/RBAC | 控制数据访问权限 | 权限治理、最小权限原则 |
| 数据防篡改 | - | 确保数据完整性不被篡改 | 区块链、数字签名、哈希校验 |
| 隐私计算 | - | 数据可用不可见 | 联邦学习、同态加密、MPC |

## 二、数据泄露防护（DLP）

### 2.1 DLP 核心能力

| 能力分类 | 功能说明 |
|---------|---------|
| **发现（Discovery）** | 扫描和发现存储中的敏感数据（结构化、非结构化） |
| **监控（Monitor）** | 监控数据访问和流动，包括终端、网络、邮件 |
| **阻止（Prevent）** | 基于策略阻止敏感数据违规外流 |
| **响应（Response）** | 告警通知、事件调查、溯源分析 |

### 2.2 DLP 部署架构

| 部署方式 | 监控范围 | 特点 |
|---------|---------|------|
| **终端DLP** | 个人电脑、服务器本地文件操作 | 深度监控终端行为，可阻止剪贴板、USB拷贝 |
| **网络DLP** | 网络流量、邮件、Web上传、IM软件 | 监控网络边界数据流动，需流量镜像或串联部署 |
| **存储DLP** | 数据库、文件服务器、云存储 | 静态数据扫描，定期检查敏感数据存储情况 |
| **云DLP** | SaaS应用、云存储、云平台 | 云原生部署，集成云服务API |

### 2.3 敏感数据识别

| 识别技术 | 原理 | 典型数据类型 |
|---------|------|-------------|
| **正则表达式** | 基于模式匹配 | 身份证号、银行卡号、手机号 |
| **关键词匹配** | 基于预设关键词 | 机密、内部、密码等关键词 |
| **文件指纹** | 基于文件特征 | 特定文件、图纸、源代码 |
| **机器学习** | 基于特征训练 | 文档类型、内容语义识别 |
| **数据指纹** | 哈希匹配 | 特定敏感文件识别 |

### 2.4 主流 DLP 产品

- **Symantec DLP**（博通）：传统企业级DLP，功能全面
- **Forcepoint DLP**：偏重数据安全治理，可视化强
- **Digital Guardian**：终端DLP强，适合数据防泄漏
- **Microsoft Purview**：云原生，集成Microsoft 365/Azure
- **奇安信数据防泄漏系统**、**启明星辰天阗DLP**：国内厂商优势

## 三、数据脱敏

### 3.1 数据脱敏技术类型

| 脱敏方法 | 原理 | 保持格式 | 可逆 | 适用场景 |
|---------|------|---------|------|---------|
| **替换法** | 用虚构数据替换真实数据 | ✅ | ❌ | 测试环境、开发环境 |
| **掩码法** | 部分字符隐藏（如 138****1234） | ✅ | ❌ | 展示场景、日志脱敏 |
| **乱序法** | 打乱数据顺序或字符位置 | ✅ | ❌ | 统计分析、数据共享 |
| **加密法** | 可逆加密算法 | ✅ | ✅ | 需要恢复的场景、内部使用 |
| **合成法** | AI生成假数据（保持格式和分布） | ✅ | ❌ | AI训练、数据共享、外部协作 |
| **空值法** | 直接置空或删除 | ❌ | ❌ | 非必要数据、特殊情况 |

### 3.2 脱敏场景分类

| 场景类型 | 说明 | 脱敏要求 |
|---------|------|---------|
| **静态脱敏（SSD）** | 数据抽取到非生产环境时脱敏 | 一次性批量处理，保持数据关联性 |
| **动态脱敏（DSD）** | 查询访问时实时脱敏 | 不影响数据存储，按权限动态展示 |
| **数据流脱敏** | 数据传输过程中脱敏 | 实时性要求高，低延迟 |

### 3.3 主流数据脱敏产品

- **IBM InfoSphere Optim**：老牌数据脱敏，支持多种数据库
- **Oracle Data Masking and Subsetting**：Oracle生态集成好
- **Delphix**：数据虚拟化+脱敏一体
- **安华金和数据脱敏系统**：国内主流厂商
- **美创数据脱敏平台**：国内厂商，支持多种数据库

## 四、数据加密

### 4.1 加密技术分类

| 加密类型 | 算法 | 特点 | 应用场景 |
|---------|------|------|---------|
| **对称加密** | AES、SM4、ChaCha20 | 速度快，密钥管理重要 | 数据库加密、文件加密、传输加密 |
| **非对称加密** | RSA、SM2、ECC | 公钥私钥分离 | 密钥交换、数字签名 |
| **哈希算法** | SHA-256、SM3、bcrypt | 不可逆 | 完整性校验、密码存储 |

### 4.2 数据加密应用场景

| 加密层级 | 说明 | 实现方式 |
|---------|------|---------|
| **传输层加密** | 网络传输数据加密 | TLS/SSL、HTTPS、IPSec、VPN |
| **存储层加密** | 数据库、文件存储加密 | TDE（透明数据加密）、应用层加密 |
| **应用层加密** | 应用内敏感字段加密 | 业务系统内置加密、加密SDK |
| **端到端加密** | 从发送方到接收方全程加密 | 即时通讯、加密邮件、区块链 |

### 4.3 主流加密产品

- **Thales CipherTrust**（泰雷兹）：密钥管理+加密一体
- **IBM Key Protect**：云密钥管理
- **HashiCorp Vault**：开源密钥管理（企业版功能强）
- **中安网星**、**江南天安**：国内密码厂商

## 五、数据分类分级

### 5.1 数据分级标准

| 分级 | 金融行业（JR/T 0197-2020） | 通用定义 | 典型数据 |
|------|-------------------------|---------|---------|
| L1 | 公开信息 | 完全公开，无风险 | 公司名称、公开联系方式、官网信息 |
| L2 | 内部信息 | 内部使用，泄露有轻微影响 | 内部规章制度、非敏感业务数据 |
| L3 | 敏感信息 | 泄露可能造成损害 | 客户姓名、手机号、一般财务数据 |
| L4 | 高度敏感信息 | 泄露造成严重损害 | 身份证号、银行卡号、交易密码、核心算法 |
| L5 | 核心机密 | 泄露造成重大损害 | 核心商业秘密、国家秘密、系统源代码 |

### 5.2 数据分类分级系统架构

```
数据来源（数据库/文件/API）
    │
    ▼
数据发现与元数据采集
    │
    ├─ [结构化数据] → 字段分析 → 数据采样
    └─ [非结构化数据] → OCR/NLP → 实体提取
    │
    ▼
两阶段分类引擎
    │
    ├─ Stage 1: 混合检索（向量搜索+全文搜索）
    ├─ Stage 2: LLM精选/规则匹配
    └─ 兜底分类引擎
    │
    ▼
分类分级结果（分类路径+安全等级）
    │
    ├─ 数据目录
    ├─ 分级标签
    └─ 安全策略应用
```

### 5.3 技术实现参考

知识库中已有完整实现案例：[knowledge_graph.md](../11_other/knowledge_graph.md)

该系统基于 Neo4j 知识图谱 + LLM + 向量检索，实现了金融数据分类分级的自动化。

核心特点：
- 基于 JR/T 0197-2020 金融行业标准
- 两阶段分类引擎（混合检索 + LLM精选）
- 知识图谱存储分类体系
- 支持结构化和非结构化数据

### 5.4 主流数据分类分级产品

- **IBM InfoSphere Information Governance Catalog**：元数据管理+分类
- **Collibra Data Governance**：数据治理平台，含分类分级
- **Informatica Data Governance**：数据治理+分类
- **安恒信息明御数据分类分级平台**：国内厂商

## 六、数据库审计

### 6.1 核心审计能力

| 能力 | 说明 |
|------|------|
| **操作审计** | 记录登录、查询、修改、删除、DDL等所有操作 |
| **会话审计** | 记录会话信息、源IP、用户、时间、操作内容 |
| **风险识别** | 异常行为检测（如异常时间访问、异常大量查询） |
| **违规告警** | 基于策略的告警（如敏感表访问、高危操作） |
| **报表分析** | 合规报表、行为分析报表、趋势报表 |

### 6.2 部署方式

| 方式 | 原理 | 优势 | 劣势 |
|------|------|------|------|
| **网络审计（镜像流量）** | 交换机镜像流量，解析SQL | 不影响业务，无Agent | 加密流量无法解析，资源消耗大 |
| **Agent审计** | 数据库服务器安装Agent | 支持加密流量，审计更全面 | 需要安装Agent，有一定性能影响 |
| **日志审计** | 采集数据库日志审计 | 部署简单，资源消耗小 | 依赖数据库日志配置，审计粒度有限 |

### 6.3 主流数据库审计产品

- **Imperva Database Security**：老牌数据库安全
- **Oracle Audit Vault**：Oracle生态集成
- **IBM Guardium**：数据安全平台，含审计
- **安华金和数据库审计系统**：国内主流
- **启明星辰数据库安全审计系统**：国内厂商

## 七、隐私计算

### 7.1 隐私计算技术分类

| 技术 | 核心原理 | 特点 | 应用场景 |
|------|---------|------|---------|
| **联邦学习** | 数据不出域，模型在各方本地训练 | 数据可用不可见 | 金融风控、医疗AI、联合营销 |
| **同态加密** | 密文直接计算，结果解密后与明文一致 | 最高隐私保护 | 云端计算、外包数据处理 |
| **安全多方计算（MPC）** | 多方联合计算，无人知晓其他方数据 | 多方协作 | 联合统计、联合建模、拍卖计算 |
| **差分隐私** | 加入噪声，防止个体信息泄露 | 统计场景 | 数据发布、查询服务 |
| **零知识证明** | 证明某命题为真，不泄露其他信息 | 隐私性强 | 身份认证、区块链、合规审计 |

### 7.2 主流隐私计算产品/平台

- **微众银行 FATE**：联邦学习开源框架
- **同盾知识联邦平台**：商业联邦学习平台
- **华控清交 PrivPy**：安全多方计算平台
- **富数科技 Avatar**：隐私计算平台

## 九、数据安全相关法规标准

### 9.1 国内法规

| 法规标准 | 发布单位 | 主要内容 |
|---------|---------|---------|
| 《中华人民共和国数据安全法》 | 全国人大 | 数据分类分级、重要数据保护、数据安全审查 |
| 《中华人民共和国个人信息保护法》 | 全国人大 | 个人信息处理、敏感个人信息保护、跨境传输 |
| 《网络安全等级保护制度》 | 公安部 | 等保2.0，三级以上系统需测评 |
| JR/T 0197-2020《金融数据安全 数据安全分级指南》 | 人民银行 | 金融行业数据分级标准 |
| GB/T 35273-2020《个人信息安全规范》 | 国标委 | 个人信息保护最佳实践 |

## 十、数据安全产品选型建议

### 10.1 选型考虑维度

| 维度 | 考虑点 |
|------|--------|
| **业务需求** | 数据类型、规模、场景（开发/测试/生产） |
| **合规要求** | 行业监管、等保、GDPR等 |
| **技术栈** | 与现有系统集成、数据库类型、云平台 |
| **性能影响** | 对业务系统性能的影响程度 |
| **实施难度** | 部署复杂度、运维成本、人员培训 |
| **厂商能力** | 技术支持、服务水平、安全漏洞响应 |
| **ROI** | 投入产出比、长期维护成本 |

### 10.2 渐进式建设路线

```
阶段一：基础安全建设
  ├─ 数据分类分级（理清家底）
  ├─ 数据库审计（风险可见）
  └─ 基础加密（传输加密、存储加密）
        │
        ▼
阶段二：纵深防御
  ├─ DLP（数据泄露防护）
  ├─ 静态脱敏（开发测试环境）
  └─ 权限治理（最小权限原则）
        │
        ▼
阶段三：数据安全治理平台化
  ├─ 数据安全治理平台（统一管理）
  ├─ 动态脱敏（生产环境查询）
  └─ 高级分析（UEBA、AI异常检测）
        │
        ▼
阶段四：隐私计算与创新
  ├─ 隐私计算（数据可用不可见）
  ├─ 零信任架构
  └─ 持续运营与优化
```

## 十一、总结

数据安全产品体系是一个分层防御的体系：

| 层级 | 核心产品 | 目标 |
|------|---------|------|
| **发现层** | 数据分类分级、数据发现 | 知道数据在哪里，是什么级别 |
| **防御层** | DLP、数据脱敏、数据加密 | 防止数据泄露，保护敏感数据 |
| **监控层** | 数据库审计、访问日志 | 知道数据被谁访问了，做了什么 |
| **治理层** | 数据安全治理平台 | 统一管理，合规运营 |
| **创新层** | 隐私计算 | 数据可用不可见，发挥数据价值 |

企业应根据自身业务规模、数据类型、合规要求，选择适合的产品组合，循序渐进建设数据安全体系。
