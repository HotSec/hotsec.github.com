# 关系数据库原理

---

## 一、事务与 ACID

| 特性 | 说明 | 实现方式 |
|------|------|----------|
| Atomicity (原子性) | 事务要么全部成功，要么全部回滚 | Undo Log |
| Consistency (一致性) | 事务前后数据满足约束规则 | 约束/触发器 |
| Isolation (隔离性) | 并发事务互不干扰 | 锁/MVCC |
| Durability (持久性) | 提交后数据永久保存 | Redo Log |

## 二、隔离级别

### 2.1 并发问题

| 问题 | 说明 |
|------|------|
| 脏读 | 读到未提交的数据 |
| 不可重复读 | 同一事务内两次读同一行结果不同 |
| 幻读 | 同一事务内两次查询行数不同 |

### 2.2 四个隔离级别

| 隔离级别 | 脏读 | 不可重复读 | 幻读 | 性能 |
|----------|------|-----------|------|------|
| READ UNCOMMITTED | ✅ | ✅ | ✅ | 最高 |
| READ COMMITTED | ❌ | ✅ | ✅ | 高 |
| REPEATABLE READ | ❌ | ❌ | ✅ | 中 |
| SERIALIZABLE | ❌ | ❌ | ❌ | 最低 |

> MySQL InnoDB 默认 REPEATABLE READ，通过 MVCC + Next-Key Lock 部分解决幻读。

## 三、MVCC (多版本并发控制)

### 3.1 InnoDB MVCC 实现

```
每行隐藏列:
- DB_TRX_ID: 最后修改的事务 ID
- DB_ROLL_PTR: 回滚指针 → Undo Log
- DB_ROW_ID: 隐藏主键

Read View (快照读):
- 创建时记录当前活跃事务列表
- 判断数据版本是否可见:
  1. 版本事务 ID < 最小活跃事务 ID → 可见
  2. 版本事务 ID 在活跃列表中 → 不可见
  3. 版本事务 ID > 最大活跃事务 ID → 可见
  4. 否则遍历 Undo Log 链找可见版本
```

### 3.2 快照读 vs 当前读

```sql
-- 快照读 (MVCC，不加锁)
SELECT * FROM users WHERE id = 1;

-- 当前读 (加锁)
SELECT * FROM users WHERE id = 1 FOR UPDATE;  -- X 锁
SELECT * FROM users WHERE id = 1 LOCK IN SHARE MODE; -- S 锁
UPDATE users SET name = 'Bob' WHERE id = 1;   -- X 锁
DELETE FROM users WHERE id = 1;                -- X 锁
```

## 四、索引

### 4.1 B+ 树索引

```
                    ┌────────────┐
                    │  Root Page │
                    │ 10 | 20 | 30│
                    └──┬───┬───┬─┘
              ┌────────┘   │   └────────┐
         ┌────┴────┐  ┌────┴────┐  ┌────┴────┐
         │ 5 | 10  │  │15 | 20  │  │25 | 30  │
         └──┬───┬──┘  └──┬───┬──┘  └──┬───┬──┘
           ┌─┘   └─┐     ┌─┘   └─┐     ┌─┘   └─┐
         [1-5]  [6-10] [11-15][16-20] [21-25][26-30]
         叶子节点通过双向链表连接
```

特点：
- 非叶子节点只存键值，不存数据
- 叶子节点存所有数据，双向链表连接
- 范围查询高效

### 4.2 索引类型

| 类型 | 说明 |
|------|------|
| 主键索引 | 聚簇索引，叶子存整行数据 |
| 唯一索引 | 值唯一，允许 NULL |
| 普通索引 | 无约束 |
| 组合索引 | 多列索引，遵循最左前缀 |
| 全文索引 | 全文搜索 |
| 覆盖索引 | 查询字段都在索引中 |

### 4.3 最左前缀原则

```sql
-- 组合索引 (a, b, c)
WHERE a = 1              -- ✅ 用到 a
WHERE a = 1 AND b = 2    -- ✅ 用到 a, b
WHERE a = 1 AND b = 2 AND c = 3 -- ✅ 用到 a, b, c
WHERE b = 2              -- ❌ 无法使用
WHERE a = 1 AND c = 3    -- ✅ 用到 a，c 无法使用
WHERE a > 1 AND b = 2    -- ✅ 用到 a，b 无法使用（范围后失效）
```

## 五、锁

### 5.1 锁类型

| 锁 | 粒度 | 说明 |
|----|------|------|
| 共享锁 (S) | 行 | 读锁，多个事务可同时持有 |
| 排他锁 (X) | 行 | 写锁，独占 |
| 意向共享 (IS) | 表 | 表明有行级 S 锁 |
| 意向排他 (IX) | 表 | 表明有行级 X 锁 |
| 表锁 | 表 | 锁整张表 |

### 5.2 InnoDB 行锁

| 锁类型 | 说明 | 触发条件 |
|--------|------|----------|
| Record Lock | 锁单行 | 精确匹配唯一索引 |
| Gap Lock | 锁间隙 | 非唯一索引范围查询 |
| Next-Key Lock | Record + Gap | 默认行锁类型 |

## 六、SQL 优化

### 6.1 EXPLAIN

```sql
EXPLAIN SELECT * FROM users WHERE age > 20;

-- 关注字段:
-- type: 访问类型 (ALL < index < range < ref < eq_ref < const)
-- key: 使用的索引
-- rows: 预估扫描行数
-- Extra: Using index (覆盖索引), Using filesort (需优化), Using temporary (需优化)
```

### 6.2 优化建议

| 优化项 | 说明 |
|--------|------|
| 避免 SELECT * | 只查需要的列 |
| 建合适索引 | WHERE/ORDER BY/GROUP BY 列 |
| 避免索引失效 | 不在索引列上函数运算 |
| 小表驱动大表 | EXISTS vs IN |
| LIMIT 优化 | 延迟关联 |
| 批量操作 | INSERT 批量插入 |
| 分页优化 | 游标分页替代 OFFSET |

```sql
-- ❌ OFFSET 深分页
SELECT * FROM users ORDER BY id LIMIT 100000, 10;

-- ✅ 游标分页
SELECT * FROM users WHERE id > 100000 ORDER BY id LIMIT 10;

-- ✅ 延迟关联
SELECT * FROM users u
INNER JOIN (SELECT id FROM users ORDER BY id LIMIT 100000, 10) t
ON u.id = t.id;
```
