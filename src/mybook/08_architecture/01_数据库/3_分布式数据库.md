# 分布式数据库

## 概述

分布式数据库将数据分散在多个节点上，提供高可用、高扩展、强一致性的数据服务。

## 分布式存储

### 数据分片 (Sharding)

| 策略 | 描述 | 优缺点 |
|------|------|--------|
| 哈希分片 | hash(key) % N | 分布均匀，扩容困难 |
| 范围分片 | key ∈ [a, m) → Shard1 | 范围查询友好，可能热点 |
| 一致性哈希 | hash(key) → 环上映射 | 扩缩容影响小 |
| 虚拟槽 | Redis Cluster 16384 槽 | 均匀 + 灵活迁移 |

### 一致性哈希

```
        0
       / \
    Node3   Node1
      |      |
    Node2──Node0
        180

key → hash(key) → 顺时针找到第一个节点
```

```go
import "sort"

type ConsistentHash struct {
    ring  []int
    nodes map[int]string
}

func (ch *ConsistentHash) Add(node string) {
    for i := 0; i < 150; i++ {
        h := hash(fmt.Sprintf("%s:%d", node, i))
        ch.ring = append(ch.ring, h)
        ch.nodes[h] = node
    }
    sort.Ints(ch.ring)
}

func (ch *ConsistentHash) Get(key string) string {
    h := hash(key)
    idx := sort.SearchInts(ch.ring, h)
    if idx >= len(ch.ring) {
        idx = 0
    }
    return ch.nodes[ch.ring[idx]]
}
```

### 数据复制

| 模式 | 描述 | 一致性 | 可用性 |
|------|------|--------|--------|
| 主从复制 | 1 主 + N 从 | 最终一致 | 高 |
| 多主复制 | 多主互相同步 | 冲突处理 | 更高 |
| 无主复制 | 任意节点写入 | Quorum | 最高 |

## 分布式事务

### 2PC (Two-Phase Commit)

```
Coordinator          Participant1    Participant2
    │                     │               │
    │─── PREPARE ────────>│               │
    │─── PREPARE ───────────────────────>│
    │<── YES ─────────────│               │
    │<── YES ─────────────────────────────│
    │                     │               │
    │─── COMMIT ─────────>│               │
    │─── COMMIT ─────────────────────────>│
    │<── ACK ─────────────│               │
    │<── ACK ─────────────────────────────│
```

- **Prepare**：协调者询问参与者是否可以提交
- **Commit/Abort**：所有参与者同意则提交，任一拒绝则回滚

**问题**：
- 同步阻塞：参与者持有锁等待
- 单点故障：协调者宕机
- 数据不一致：网络分区导致部分提交

### 3PC (Three-Phase Commit)

```
CanCommit → PreCommit → DoCommit
```

增加 PreCommit 阶段减少阻塞，但仍有网络分区问题。

### TCC (Try-Confirm-Cancel)

```go
type TCCService interface {
    Try(ctx context.Context, req Request) error
    Confirm(ctx context.Context, req Request) error
    Cancel(ctx context.Context, req Request) error
}

func Transfer(from, to string, amount int) error {
    tx := BeginTCC()

    if err := account.TryDeduct(from, amount); err != nil {
        return err
    }
    if err := account.TryAdd(to, amount); err != nil {
        account.CancelDeduct(from, amount)
        return err
    }

    account.ConfirmDeduct(from, amount)
    account.ConfirmAdd(to, amount)
    return nil
}
```

### SAGA

```go
type SagaStep struct {
    Action      func() error
    Compensation func() error
}

func ExecuteSaga(steps []SagaStep) error {
    var completed []int

    for i, step := range steps {
        if err := step.Action(); err != nil {
            for j := len(completed) - 1; j >= 0; j-- {
                steps[completed[j]].Compensation()
            }
            return err
        }
        completed = append(completed, i)
    }
    return nil
}
```

### 对比

| 方案 | 一致性 | 性能 | 复杂度 | 适用场景 |
|------|--------|------|--------|----------|
| 2PC | 强一致 | 低 | 中 | 传统数据库 |
| 3PC | 强一致 | 低 | 高 | 较少使用 |
| TCC | 最终一致 | 中 | 高 | 资金交易 |
| SAGA | 最终一致 | 高 | 中 | 长事务 |
| 本地消息表 | 最终一致 | 高 | 低 | 异步场景 |

## 主流分布式数据库

### TiDB

```sql
CREATE TABLE users (
    id BIGINT PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(255)
);

CREATE INDEX idx_email ON users(email);

ALTER TABLE users ADD COLUMN age INT;
```

- MySQL 兼容
- HTAP（行列混存）
- Raft 共识
- 自动分片 (Region)

### CockroachDB

```sql
CREATE TABLE orders (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id INT,
    amount DECIMAL(10,2),
    created_at TIMESTAMP DEFAULT now()
) PARTITION BY RANGE (created_at);
```

- PostgreSQL 兼容
- 强一致性
- Geo-partitioning
- 分布式 SQL 优化器

### Cassandra

```sql
CREATE KEYSPACE myapp WITH replication = {
    'class': 'NetworkTopologyStrategy',
    'dc1': 3,
    'dc2': 2
};

CREATE TABLE events (
    event_id UUID,
    event_type TEXT,
    created_at TIMESTAMP,
    data TEXT,
    PRIMARY KEY ((event_type), created_at, event_id)
) WITH CLUSTERING ORDER BY (created_at DESC);
```

- 无主架构
- 写优化
- 可调一致性 (ONE / QUORUM / ALL)
- 适合时序和日志数据

### 分布式数据库选型

| 场景 | 推荐 | 原因 |
|------|------|------|
| OLTP + MySQL 迁移 | TiDB | 兼容性好 |
| 全球部署 + 强一致 | CockroachDB | Geo-partition |
| 高写入 + 时序数据 | Cassandra | 写性能优 |
| 文档 + 灵活模式 | MongoDB 分片 | 文档模型 |
| KV + 低延迟 | DynamoDB | 全托管 |

## 分布式共识

### Raft

```
Leader ──── AppendEntries ────> Follower1
   │                              │
   └──── AppendEntries ────> Follower2

选举: 任一 Follower 超时 → Candidate → 请求投票 → 多数同意 → Leader
```

| 角色 | 职责 |
|------|------|
| Leader | 处理写请求，复制日志 |
| Follower | 接收日志，响应投票 |
| Candidate | 发起选举 |

### Paxos

- 最严谨的共识算法
- Multi-Paxos 用于实践
- 实现复杂
