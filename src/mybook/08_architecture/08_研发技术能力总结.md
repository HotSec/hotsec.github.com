### 二、技术架构能力

#### 2.1 分布式与云原生架构

- **分布式系统设计**：
  - **CAP理论**：深刻理解一致性（Consistency）、可用性（Availability）、分区容错性（Partition tolerance）三者的权衡关系，根据业务场景选择CP（ZooKeeper/etcd/HBase）或AP（Cassandra/DynamoDB/Eureka）架构
  - **BASE理论**：基本可用（Basically Available）、软状态（Soft State）、最终一致性（Eventually Consistent）的实践应用
  - **一致性模型**：从强一致性（Linearizability）→ 顺序一致性 → 因果一致性 → 最终一致性的多级策略选择
  - **共识算法**：Raft/Paxos/ZAB共识机制原理与实践（hashicorp/raft、etcd/raft）

- **分布式关键技术**：
  - **分布式ID**：雪花算法（1bit符号位+41bit时间戳+10bit机器ID+12bit序列号，每毫秒4096个ID）、号段模式（批量预分配）、Redis INCR、UUID（无序，但存储空间大）对比选型
  - **分布式事务**：两阶段提交(2PC)（强一致但同步阻塞）、TCC(Try-Confirm-Cancel)（预留资源，确认/取消）、Saga模式（编排式：中心协调器；协同式：事件驱动）、本地消息表（事务消息可靠性）
  - **分布式锁**：Redis SetNX+Lua脚本原子释放、etcd concurrency.Mutex租约机制、脑裂问题解决方案（多数派投票、Fencing Token）

- **微服务架构**：
  - 服务拆分策略（领域驱动设计DDD限界上下文指导拆分，单一职责原则）
  - 服务治理：熔断（Hystrix/Sentinel，错误率/慢调用比例熔断规则）、限流（令牌桶、漏桶、滑动窗口算法）、降级策略
  - 服务网格：Istio（控制面：Istiod；数据面：Envoy Sidecar）、Linkerd）的流量管理、可观测性、安全能力
  - 服务发现：Consul/Eureka的注册与发现机制，健康检查

- **容器化与编排**：
  - Docker容器化（Dockerfile优化：多阶段构建减小镜像体积、.dockerignore优化）
  - Kubernetes集群管理（Pod生命周期、Deployment滚动更新、Service ClusterIP/NodePort/LoadBalancer、Ingress路径路由、ConfigMap配置管理、Secret加密存储）
  - Helm Chart包管理（Chart模板开发、Values.yaml配置模板）

- **云原生技术栈**：
  - Service Mesh微服务网格
  - Sidecar模式（数据面与控制面分离）
  - Serverless无服务器架构（AWS Lambda、阿里云函数计算）
  - GitOps声明式交付（Argo CD、Flux CD）

#### 2.2 AI智能体架构

- **AI Agent核心能力**：LLM + 记忆（短期/工作/长期/语义记忆） + 工具 + 规划的完整架构设计
  - 短期记忆：当前对话上下文
  - 工作记忆：当前任务进度
  - 长期记忆：跨会话知识（向量数据库存储）
  - 语义记忆：领域知识（RAG知识库）

- **Agent架构模式**：
  - **ReAct循环**：观察（Observe）→ 思考（Think）→ 行动（Act）循环
  - **Plan-and-Execute**：先规划再执行，复杂任务分解，规划器+执行器分离
  - **Supervisor调度**：中心调度器管理多个专职Agent（研究员Agent+编写Agent+审查Agent）
  - **Swarm对等协作**：Agent间直接任务交接，去中心化
  - **层级式管理**：多层Agent结构（CEO Agent → Manager Agent → Worker Agent）

- **Agent框架选型**：
  - **LangGraph**：基于图结构的有状态多角色框架，支持循环、分支、持久化（Checkpoint：MemorySaver/SQLite持久化）、人机交互（interrupt_before节点前暂停）、流式输出
  - **AutoGen**：对话驱动的多Agent协作
  - **CrewAI**：角色扮演式的团队协作

- **MCP协议**：
  - Model Context Protocol（模型上下文协议）架构：Host（Claude Desktop/Claude CLI/IDE） → Client → Server三层
  - 三大原语：Tools（工具调用，最常用）、Resources（资源读取，只读）、Prompts（提示模板）
  - 通信方式：stdio（本地Server，最常用）、SSE（远程Server）
  - Server开发能力（TypeScript/Python SDK）

- **Agent安全设计模式**：
  - 零信任工具调用（Tool Proxy安全代理、参数验证、返回Schema校验
  - 渐进式权限授予（按需申请、风险评估、人工审批
  - 工具输出隔离（子Agent处理、安全摘要返回主Agent
  - 双重确认机制（破坏性操作二次确认）

#### 2.3 大模型与AI工程化

- **模型架构理解**：Transformer结构（Encoder-Decoder）、自注意力机制、Tokenizer原理（Byte-Pair Encoding）
- **提示词工程**：提示词注入防护、角色定义与约束、结构化输出（JSON Schema）、Chain-of-Thought思维链、Few-Shot Learning
- **模型安全**：提示词安全、模型防护、Agent安全机制、对抗性攻击防御、输出过滤
- **模型推理优化**：量化加速（INT8/FP16量化）、批量推理、模型缓存（KV Cache）、ONNX Runtime部署、vLLM推理加速
- **RAG系统**：知识库构建（文档分块、Embedding向量化）、向量检索（Cosine相似度）、混合检索（向量+关键词）、检索结果重排（Rerank模型）
- **评估体系**：RAGAS评估（Faithfulness/Answer Relevancy/Context Precision）、LLM-as-a-Judge自动评估

#### 2.4 访问控制与权限模型

| 模型 | 特点 | 适用场景 |
|------|------|----------|
| DAC | 资源所有者自主决定权限 | 灵活共享场景 |
| MAC | 系统强制执行安全策略，标签匹配 | 高安全等级系统 |
| RBAC | 用户→角色→权限，角色继承 | 企业级应用 |
| ABAC | 基于属性动态决策（subject/resource/environment） | 复杂权限场景 |

### 三、安全技术能力

#### 3.1 网络安全

- **威胁检测与防御**：
  - **IDS/IPS**：
    - 入侵检测系统（IDS）：仅检测告警，不阻断流量
    - 入侵防御系统（IPS）：检测并自动阻断恶意流量
    - 检测方法：签名检测（模式匹配已知特征）、异常检测（基线比对偏离告警）、行为分析
    - 工具：Suricata（多线程、IDS/IPS/NSM，支持EVE JSON输出）、Snort（经典老牌）
  - **NDR**：网络检测与响应，融合签名+行为+ML，支持自动化响应、回溯分析
  - **WAF**：Web应用防火墙（ModSecurity、Cloudflare WAF、OWASP Core RuleSet规则）
  - **Anti-DDoS**：分布式拒绝服务攻击防护（流量清洗、CDN防护）
  - **安全审计**：全流量记录与分析

- **MITRE ATT&CK框架应用**：
  - 14个战术矩阵：侦察、资源开发、初始访问、执行、持久化、权限提升、防御规避、凭据访问、发现、横向移动、收集、命令与控制、数据渗出、影响
  - 常见技术检测与检测方法映射
  - 红队攻击模拟与攻击链分析

- **网络分析工具**：
  - **Zeek**：事件驱动的网络分析框架，50+协议解析器，结构化日志输出（conn.log/dns.log/http.log/ssl.log）
  - **Arkime**：开源全流量捕获、索引和检索系统，PCAP存储+Elasticsearch索引，支持会话重放分析

- **渗透测试**：黑盒/白盒/灰盒测试方法论，OWASP Top 10漏洞利用与防护

- **流量分析**：基于AI的恶意流量识别（DGA检测：字符级LSTM检测算法生成的域名）、UEBA用户实体行为分析、异常检测（自编码器、Isolation Forest）

- **威胁情报**：
  - 情报类型：战略情报（宏观趋势）、战术情报（TTPs）、运营情报（具体事件）、技术情报（IOC）
  - IOC（失陷标示）：IP/域名/URL/文件Hash/Email/证书
  - TTP（战术、技术和程序）：比IOC更稳定，检测价值更高
  - 情报源：商业情报（VirusTotal/Recorded Future）、开源情报（OSINT）、社区情报（MISP）、内部情报（蜜罐/沙箱）
  - STIX/TAXII：标准化威胁情报格式与传输协议

- **攻防对抗**：威胁情报收集、ATT&CK框架应用、溯源分析（基础设施关联、恶意样本关联、TTP关联、语言/时区分析）

- **SOC/SIEM**：
  - **SOC**：7×24监控、分析、响应、优化
  - **SIEM**：日志采集、归一化、关联分析、告警、可视化
  - 平台：Splunk、ELK Stack（Elasticsearch+Logstash+Kibana）、QRadar、Wazuh

- **漏洞扫描**：Nuclei基于YAML模板的快速漏洞扫描器

#### 3.2 数据安全

- **加密体系**：
  - 对称加密（AES-256、ChaCha20，性能高，密钥分发问题）
  - 非对称加密（RSA、ECC，加密小数据，用于密钥交换和签名）
  - 哈希算法（SHA-256、bcrypt/scrypt/Argon2，加盐慢哈希防彩虹表）
- **TLS/SSL**：TLS 1.2（ECDHE密钥交换）、TLS 1.3（仅ECDHE，0-RTT支持更快）、数字证书（X.509）、证书链验证、OCSP/CRL证书状态查询
- **数据脱敏**：静态脱敏（批量处理）、动态脱敏（查询时实时脱敏）、脱敏规则引擎（替换、掩码、泛化、加密）
- **隐私计算**：同态加密（密文计算）、安全多方计算（MPC）、联邦学习（数据不出域）、差分隐私（添加噪声防泄露）
- **密钥管理**：AWS KMS、阿里云KMS、HashiCorp Vault

#### 3.3 应用安全

- **漏洞防护**：
  - SQL注入：参数化查询（?占位符）、ORM（自动转义）
  - XSS：html.EscapeString转义、Content-Security-Policy头
  - CSRF：CSRF Token、SameSite Cookie属性（Strict/Lax/None）
  - 路径遍历：filepath.Join+filepath.Clean+路径前缀校验
  - 命令注入：避免拼接命令、白名单验证
  - 敏感信息泄露：错误信息不暴露细节、敏感数据加密
  - 不安全的反序列化：使用强类型结构体
  - 安全头设置：X-Content-Type-Options、X-Frame-Options、X-XSS-Protection、Strict-Transport-Security、CSP
- **身份认证**：OAuth 2.0（授权码模式最安全/隐式/密码/客户端模式）、JWT无状态认证（Header.Payload.Signature）、SSO单点登录
- **API安全**：API网关鉴权、请求签名、限流熔断、OpenAPI安全规范、OAuth 2.0授权、Rate Limiting速率限制

#### 3.4 AI安全

| 威胁类型 | 攻击面 | 防御策略 |
|---------|--------|---------|
| 提示词注入 | 用户输入/工具输出 | 注入检测、输入清理、输出隔离 |
| 工具投毒 | 工具描述/返回值 | 工具白名单、返回值Schema验证 |
| 越权操作 | 权限边界 | RBAC矩阵、最小权限、渐进授权 |
| 级联幻觉 | LLM输出 | 子Agent隔离、结果验证 |
| 越狱攻击 | 系统提示词 | 角色约束强化、输出过滤 |
| 数据泄露 | RAG/记忆 | 数据访问控制、上下文过滤 |

- **AI安全防护架构**：输入安全层→权限控制层→执行控制层→输出安全层的分层防御体系
- **模型安全**：对抗样本防御（对抗训练）、模型加固（水印）、模型审计、模型对齐（RLHF）
- **LLM输出安全**：输出敏感信息检测（PII）、内容过滤

#### 3.5 容器与云安全

- **Docker安全**：容器逃逸防御、安全基线、镜像签名、最小权限原则、非Root用户运行
- **Kubernetes安全**：RBAC权限、NetworkPolicy网络策略、Pod安全策略、Secret加密、PodSecurityPolicy/Pod Security Admission
- **云安全**：CSPM云安全态势管理、云原生应用保护平台（CNAPP）、IAM最小权限原则
