# 安全基础

## 访问控制模型

### DAC（自主访问控制）

- 资源所有者自行决定访问权限
- ACL（访问控制列表）实现
- 灵活但安全性较低

### MAC（强制访问控制）

- 系统强制执行安全策略
- 安全标签（密级/类别）
- 主体许可级别 ≥ 客体密级 → 可读
- 典型：SELinux / AppArmor

### RBAC（基于角色的访问控制）

- 用户 → 角色 → 权限
- 角色继承
- 最小权限原则
- 广泛应用于企业系统

### ABAC（基于属性的访问控制）

- 基于主体/资源/环境属性动态决策
- 策略：`subject.department == resource.department AND environment.time IN work_hours`
- 灵活但复杂

## 数字签名

### RSA 签名

```
签名：s = m^d mod n
验证：m = s^e mod n
```

### ECDSA 签名

- 基于椭圆曲线
- 更短密钥，同等安全强度
- 比特币/以太坊使用

### 数字证书

- X.509 格式
- 包含：公钥、持有者信息、有效期、CA 签名
- 证书链：根 CA → 中间 CA → 终端证书

### CA（证书颁发机构）

- 根 CA：自签名，预装在操作系统/浏览器
- 中间 CA：根 CA 签发，用于日常签发
- OCSP：在线证书状态查询
- CRL：证书吊销列表

## CIA 三元组

- **机密性（Confidentiality）**：数据不被未授权访问
- **完整性（Integrity）**：数据不被未授权修改
- **可用性（Availability）**：服务可正常使用

## 安全评估

### 等级保护

- 五个等级（一级最低，五级最高）
- 二级：一般信息系统
- 三级：重要信息系统
- 测评流程：定级 → 备案 → 建设整改 → 等级测评 → 运营维护

### 风险评估

- 资产识别 → 威胁识别 → 脆弱性识别 → 风险分析
- 风险值 = 可能性 × 影响程度

### 渗透测试

- 黑盒：无内部信息
- 白盒：有完整信息
- 灰盒：部分信息

### 安全审计

- 日志收集与分析
- 合规性检查
- 安全事件追踪

## 常见攻击与防御

| 攻击 | 说明 | 防御 |
|------|------|------|
| SQL 注入 | 拼接 SQL 执行恶意命令 | 参数化查询、ORM |
| XSS | 注入恶意脚本到页面 | 输入过滤、CSP、转义 |
| CSRF | 伪造用户请求 | Token、SameSite Cookie |
| DDoS | 大量请求耗尽资源 | 限流、CDN、WAF |
| 中间人攻击 | 窃听/篡改通信 | HTTPS、证书校验 |
| 暴力破解 | 尝试大量密码 | 限速、验证码、锁定 |

## 加密算法

### 对称加密

- AES-128/256：最常用，速度快
- ChaCha20：移动端友好
- 密钥分发问题

### 非对称加密

- RSA：签名、密钥交换
- ECC：更短密钥，同等安全
- 速度慢，用于小数据

### 哈希

- SHA-256：通用哈希
- bcrypt / scrypt / Argon2：密码哈希（加盐+慢哈希）
- HMAC：消息认证码

## HTTPS

```
客户端 → ServerHello → 证书 → 验证证书 → 协商密钥 → 对称加密通信
```

- TLS 1.2：RSA/ECDHE 密钥交换
- TLS 1.3：仅 ECDHE，0-RTT 支持
- 证书：Let's Encrypt 免费签发

## OAuth 2.0

四种授权模式：

| 模式 | 适用 |
|------|------|
| 授权码模式 | Web 应用（最安全） |
| 隐式模式 | 纯前端（已不推荐） |
| 密码模式 | 高度信任的第一方应用 |
| 客户端模式 | 服务器间通信 |

## JWT

```
Header.Payload.Signature
```

- 无状态，服务端不存储
- 注意：无法主动撤销，需配合黑名单
- 过期时间不宜过长
