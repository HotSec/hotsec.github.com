# 安全与法律法规

## 一、信息安全基础

### 1.1 信息安全五要素

| 要素 | 含义 |
|------|------|
| 机密性（Confidentiality） | 信息不被未授权者获取 |
| 完整性（Integrity） | 信息未被篡改或破坏 |
| 可用性（Availability） | 合法用户可正常访问和使用 |
| 可控性（Controllability） | 对信息及信息系统实施安全监控 |
| 可审查性（Accountability） | 对安全事件可追踪溯源 |

### 1.2 信息安全等级保护（五级）

| 等级 | 名称 | 适用场景 |
|------|------|----------|
| 第一级 | 用户自主保护级 | 一般信息系统，损害限于个人/组织 |
| 第二级 | 系统审计保护级 | 重要信息系统，损害涉及社会秩序 |
| 第三级 | 安全标记保护级 | 涉及国家安全的重要系统 |
| 第四级 | 结构化保护级 | 涉及国家安全的核心系统 |
| 第五级 | 访问验证保护级 | 极端重要的国家核心系统 |

## 二、密码学

### 2.1 对称加密 vs 非对称加密

| 对比项 | 对称加密 | 非对称加密 |
|--------|----------|------------|
| 密钥 | 加解密同一密钥 | 公钥加密、私钥解密 |
| 速度 | 快 | 慢 |
| 密钥管理 | 困难（N人需N(N-1)/2个密钥） | 简单（N人需N对密钥） |
| 典型算法 | DES/3DES/AES/SM4 | RSA/ECC/SM2 |
| 主要用途 | 大量数据加密 | 密钥交换/数字签名 |

### 2.2 对称加密算法

| 算法 | 密钥长度 | 分组长度 | 特点 |
|------|----------|----------|------|
| DES | 56位 | 64位 | 已不安全，易被暴力破解 |
| 3DES | 112/168位 | 64位 | DES三重加密，兼容性好 |
| AES | 128/192/256位 | 128位 | 当前主流，安全高效 |
| SM4 | 128位 | 128位 | 国密对称加密算法 |

### 2.3 非对称加密算法

| 算法 | 安全基础 | 密钥长度 | 特点 |
|------|----------|----------|------|
| RSA | 大整数分解困难 | 1024/2048位 | 最广泛使用，加解密慢 |
| ECC | 椭圆曲线离散对数 | 256位 | 短密钥高强度，移动端友好 |
| SM2 | 椭圆曲线离散对数 | 256位 | 国密非对称加密算法 |

### 2.4 数字签名

| 算法 | 特点 |
|------|------|
| RSA | 基于大整数分解，最通用 |
| DSA | 基于离散对数，仅用于签名 |
| ECDSA | 椭圆曲线DSA，短密钥高强度 |

- 数字签名流程：发送方用**私钥**签名 → 接收方用**公钥**验证
- 数字签名保证：完整性、认证性、不可抵赖性

### 2.5 数字信封

- 发送方用**对称密钥**加密明文
- 发送方用**接收方公钥**加密对称密钥
- 接收方用**私钥**解密得到对称密钥，再解密明文
- 结合了对称加密的高效和非对称加密的密钥管理优势

### 2.6 消息摘要（哈希）

| 算法 | 输出长度 | 特点 |
|------|----------|------|
| MD5 | 128位 | 已发现碰撞，不推荐安全场景 |
| SHA-1 | 160位 | 已发现碰撞，逐步淘汰 |
| SHA-256 | 256位 | SHA-2族，当前主流 |
| SM3 | 256位 | 国密哈希算法 |

- 消息摘要特性：定长输出、单向不可逆、抗碰撞

### 2.7 PKI/CA 体系

| 组件 | 作用 |
|------|------|
| CA（证书机构） | 签发和管理数字证书 |
| RA（注册机构） | 证书申请注册审核 |
| 证书库 | 存储已签发证书 |
| CRL（证书撤销列表） | 列出已撤销证书 |
| 终端实体 | 证书持有者/使用者 |

- X.509 是最广泛的数字证书标准
- 证书链验证：根CA → 中间CA → 终端证书

### 2.8 国密算法体系

| 算法 | 类型 | 对应国际算法 |
|------|------|-------------|
| SM1 | 对称加密 | AES（不公开，硬件实现） |
| SM2 | 非对称加密/签名 | RSA/ECC |
| SM3 | 哈希摘要 | SHA-256 |
| SM4 | 对称加密 | AES |
| SM9 | 标识密码 | 基于身份的加密 |

## 三、访问控制

### 3.1 访问控制模型

| 模型 | 全称 | 特点 |
|------|------|------|
| DAC | 自主访问控制 | 资源所有者自主授权，灵活但安全性低 |
| MAC | 强制访问控制 | 系统强制执行安全策略，安全性高，灵活性低 |
| RBAC | 基于角色的访问控制 | 权限绑定角色，角色分配用户，管理方便 |
| ABAC | 基于属性的访问控制 | 基于主体/客体/环境属性动态决策，最灵活 |

### 3.2 访问控制实现机制

| 机制 | 说明 |
|------|------|
| ACL（访问控制表） | 以客体为中心，列出可访问的主体及权限 |
| 能力表（Capability） | 以主体为中心，列出可访问的客体及权限 |
| 授权关系表 | 主体-客体-权限三元组，适合关系数据库存储 |

## 四、网络安全

### 4.1 防火墙

| 类型 | 工作层 | 特点 |
|------|--------|------|
| 包过滤防火墙 | 网络层 | 基于IP/端口过滤，速度快，无法检测应用层攻击 |
| 状态检测防火墙 | 网络层/传输层 | 跟踪连接状态，安全性高于包过滤 |
| 应用网关（代理防火墙） | 应用层 | 深度检测应用数据，安全性最高，性能开销大 |

- 防火墙局限：无法防内部攻击、无法防绕过防火墙的攻击、无法防病毒

### 4.2 IDS 与 IPS

| 对比项 | IDS（入侵检测） | IPS（入侵防御） |
|--------|-----------------|-----------------|
| 功能 | 检测并告警 | 检测并阻断 |
| 部署方式 | 旁路部署 | 串联部署 |
| 对业务影响 | 无影响 | 可能误阻断正常流量 |
| 检测方式 | 异常检测/误用检测 | 同IDS |

### 4.3 VPN 技术

| 协议 | 工作层 | 加密 | 认证 | 特点 |
|------|--------|------|------|------|
| IPSec | 网络层 | 支持多种 | IKE/预共享密钥 | 站点到站点VPN首选 |
| SSL VPN | 传输层 | SSL/TLS | 数字证书 | 无需客户端，远程接入 |
| L2TP | 数据链路层 | 本身不加密 | PPP认证 | 常与IPSec配合使用 |

- IPSec 两种模式：传输模式（只加密数据）、隧道模式（加密整个IP包）
- IPSec 核心协议：AH（认证头，仅认证）、ESP（封装安全载荷，认证+加密）

### 4.4 网络隔离与网闸

- 网络隔离：物理/逻辑隔离，确保内外网不直接连通
- 网闸：物理隔离设备，通过数据摆渡方式交换信息
- 网闸工作原理：切断网络连接 → 数据暂存 → 反向推送 → 恢复连接

## 五、安全协议对比

| 协议 | 工作层 | 主要用途 | 加密 | 认证 | 特点 |
|------|--------|----------|------|------|------|
| SSL | 传输层 | Web安全通信 | 对称+非对称 | 数字证书 | 已被TLS替代 |
| TLS | 传输层 | Web安全通信 | 对称+非对称 | 数字证书 | SSL升级版，当前主流 |
| IPSec | 网络层 | 网络层安全通信 | 多种算法 | IKE | 站点到站点VPN |
| PGP | 应用层 | 邮件加密/文件加密 | 对称+非对称 | Web of Trust | 去中心化信任模型 |
| SET | 应用层 | 信用卡在线支付 | 对称+非对称 | 双重签名 | 保障支付安全，商家看不到卡号 |

- TLS 握手流程：ClientHello → ServerHello → 证书验证 → 密钥交换 → 加密通信
- HTTPS = HTTP + TLS，默认端口443

## 六、安全审计与风险评估

### 6.1 风险评估要素

| 要素 | 含义 |
|------|------|
| 资产 | 对组织有价值的信息或系统 |
| 威胁 | 可能对资产造成损害的潜在原因 |
| 脆弱性 | 可被威胁利用的弱点 |
| 风险 | 威胁利用脆弱性导致资产损失的可能性 |
| 安全措施 | 降低风险的防护手段 |

- 风险 = 威胁 × 脆弱性 × 资产价值
- 残余风险 = 风险 - 安全措施降低的风险

### 6.2 风险分析方法

| 方法 | 类型 | 特点 |
|------|------|------|
| 专家评审法 | 定性 | 依赖专家经验 |
| DELPHI法 | 定性 | 匿名多轮征询 |
| 故障树分析 | 定性/定量 | 自顶向下演绎分析 |
| 事件树分析 | 定性/定量 | 自底向上归纳分析 |
| 年度预期损失（ALE） | 定量 | ALE = SLE × ARO |

- SLE（单次损失期望）= 资产价值 × 暴露因子
- ARO（年发生概率）：威胁年均发生次数

### 6.3 DLP 与数字水印

| 技术 | 用途 | 特点 |
|------|------|------|
| DLP（数据防泄露） | 防止敏感数据外泄 | 监控终端/网络/存储，识别并阻断泄露 |
| 数字水印 | 版权保护/溯源 | 嵌入隐藏标记，不影响使用，可提取验证 |

## 七、安全体系

### 7.1 深度防御

- 多层安全防护策略，单一防线失效不影响整体安全
- 核心原则：防御多样化、弱点互补、纵深配置
- 典型层次：物理安全 → 网络安全 → 主机安全 → 应用安全 → 数据安全

### 7.2 零信任架构

- 核心原则：永不信任，始终验证
- 关键特征：
    - 以身份为基石
    - 最小权限原则
    - 微隔离
    - 持续评估与动态授权
    - 假设已被入侵

### 7.3 等保2.0 核心要求

| 要求 | 内容 |
|------|------|
| 安全物理环境 | 机房/设备物理保护 |
| 安全通信网络 | 网络架构/传输加密/边界防护 |
| 安全区域边界 | 访问控制/入侵防范/安全审计 |
| 安全计算环境 | 身份鉴别/访问控制/安全审计/入侵防范 |
| 安全管理中心 | 集中管控/审计管理/安全管理 |
| 安全管理制度 | 制度/机构/人员/建设/运维 |

- 等保2.0新增：云计算安全、移动互联安全、物联网安全、工业控制安全、大数据安全

## 十三、招投标法

## 十四、数字签名详解

### 14.1 签名过程

1. 发送方对原文进行哈希运算，得到消息摘要
2. 发送方用自己的**私钥**对消息摘要进行加密，生成数字签名
3. 将数字签名附在原文后面一起发送

### 14.2 验证过程

1. 接收方用发送方的**公钥**解密数字签名，得到消息摘要
2. 接收方对收到的原文进行同样的哈希运算，得到新的消息摘要
3. 比较两个消息摘要，若一致则验证通过

### 14.3 常用签名算法对比

| 算法 | 安全基础 | 密钥长度 | 特点 |
|------|----------|----------|------|
| RSA签名 | 大整数分解困难 | 2048位及以上 | 最通用，加解密慢 |
| DSA | 离散对数问题 | 1024/2048位 | 仅用于签名，不能加密 |
| ECDSA | 椭圆曲线离散对数 | 256位 | 短密钥高强度，移动端友好 |

### 14.4 数字签名 vs 消息认证码MAC

| 对比项 | 数字签名 | 消息认证码MAC |
|--------|----------|---------------|
| 密钥类型 | 非对称（私钥签名/公钥验证） | 对称（共享密钥） |
| 抗抵赖性 | 支持（私钥仅签名方持有） | 不支持（双方共享密钥） |
| 完整性 | 支持 | 支持 |
| 认证性 | 支持 | 支持 |
| 计算效率 | 慢 | 快 |
| 典型算法 | RSA/DSA/ECDSA | HMAC-MD5/HMAC-SHA256 |

## 十五、数字信封详解

### 15.1 工作流程

1. 发送方随机生成对称密钥（会话密钥）
2. 用对称密钥加密明文，得到密文
3. 用接收方的公钥加密对称密钥，得到数字信封
4. 将密文和数字信封一起发送给接收方

### 15.2 解封流程

1. 接收方用自己的私钥解密数字信封，得到对称密钥
2. 用对称密钥解密密文，得到明文

### 15.3 优势分析

| 优势 | 说明 |
|------|------|
| 安全性 | 对称密钥用公钥加密，只有接收方私钥能解密 |
| 效率 | 大量数据用对称加密，速度快 |
| 密钥管理 | 无需预先共享对称密钥 |

## 十六、PKI体系详解

### 16.1 PKI核心组件

| 组件 | 功能 |
|------|------|
| CA（证书机构） | 签发/管理/撤销数字证书，是PKI的信任核心 |
| RA（注册机构） | 证书申请的注册审核，是CA与用户之间的中介 |
| 证书库 | 存储已签发证书，供用户查询获取 |
| CRL（证书撤销列表） | 发布已撤销但未过期的证书列表 |
| OCSP（在线证书状态协议） | 实时查询证书状态，比CRL更及时 |
| 终端实体 | 证书持有者和使用者 |

### 16.2 证书生命周期

| 阶段 | 流程 |
|------|------|
| 申请 | 用户向RA提交证书申请及身份材料 |
| 审核 | RA验证申请人身份和资质 |
| 签发 | CA签发数字证书，包含公钥和CA签名 |
| 使用 | 用户在通信中使用证书进行身份认证和加密 |
| 撤销 | 证书私钥泄露或持有人变更时，CA将证书加入CRL |
| 续期 | 证书到期前申请换发新证书 |

### 16.3 X.509证书结构

| 字段 | 说明 |
|------|------|
| 版本 | V1/V2/V3 |
| 序列号 | CA分配的唯一编号 |
| 签名算法 | CA签发证书使用的签名算法 |
| 颁发者 | 签发证书的CA名称 |
| 有效期 | 起止日期（Not Before / Not After） |
| 主体 | 证书持有者名称 |
| 主体公钥信息 | 公钥算法和公钥值 |
| 扩展 | V3扩展字段（密钥用途、主体别名等） |
| 签名 | CA对以上字段的数字签名 |

### 16.4 证书验证流程

1. 检查证书是否在有效期内
2. 检查证书是否在CRL中或通过OCSP查询状态
3. 验证CA签名是否有效
4. 沿证书链逐级验证至根CA
5. 检查证书用途是否匹配

## 十七、网络安全设备对比

| 设备 | 功能定位 | 部署位置 | 工作层次 | 特点 |
|------|----------|----------|----------|------|
| 防火墙 | 访问控制/隔离 | 网络边界 | 网络层~应用层 | 基于规则过滤，无法检测入侵行为 |

## 二十、专利法详解

### 20.1 先申请原则

- 两个以上申请人分别就同样的发明创造申请专利，专利权授予最先申请的人
- 同日申请的，申请人应在收到通知后自行协商确定申请人
- 申请日的确定：以专利局收到申请文件之日为准

### 20.2 授予专利的三性

| 条件 | 含义 |
|------|------|
| 新颖性 | 不属于现有技术，申请日前无相同技术被公开 |
| 创造性 | 与现有技术相比具有突出的实质性特点和显著的进步 |
| 实用性 | 能够制造或使用，并能产生积极效果 |

### 20.3 专利保护期

| 专利类型 | 保护期 | 审批制度 |
|----------|--------|----------|
| 发明专利 | 20年（自申请日起） | 实质审查 |
| 实用新型专利 | 10年（自申请日起） | 形式审查 |
| 外观设计专利 | 15年（自申请日起） | 形式审查 |

### 20.4 不授予专利权的情形

- 科学发现
- 智力活动的规则和方法
- 疾病的诊断和治疗方法
- 动物和植物品种
- 用原子核变换方法获得的物质
- 对平面印刷品的图案/色彩或二者的结合作出的主要起标识作用的设计

## 二十一、招投标法关键时间节点

### 21.1 招投标全流程

| 阶段 | 事项 | 时间要求 |
|------|------|----------|
| 招标 | 发布招标公告 | — |
| 招标 | 发售招标文件 | — |
| 招标 | 招标文件发售至投标截止 | 不少于20日 |
| 招标 | 对已发出的招标文件澄清/修改 | 投标截止前15日 |
| 投标 | 编制并提交投标文件 | 截止时间前 |
| 投标 | 投标保证金 | ≤招标项目估算价的2% |
| 开标 | 开标时间 | 与投标截止时间为同一时间 |
| 评标 | 评标委员会评审 | 5人以上单数，专家≥2/3 |
| 中标 | 确定中标人 | 评标委员会推荐1~3名候选人 |
| 中标 | 发出中标通知书 | — |
| 签约 | 招标人与中标人签合同 | 中标通知书发出后30日内 |
| 退还 | 退还投标保证金 | 发出中标通知书后5日内 |

### 21.2 投标有效期

- 从投标截止日起计算，保证招标人有足够时间完成评标和定标
- 一般为60~90天，具体在招标文件中明确
- 有效期内投标人不得撤销或修改投标文件

### 21.3 废标情形

| 情形 | 说明 |
|------|------|
| 投标人不足3家 | 符合条件的投标人少于3个 |
| 串通投标 | 投标人之间或与招标人串通 |
| 弄虚作假 | 投标人以他人名义投标或伪造资质 |
| 均不符合要求 | 所有投标均不满足招标文件实质性要求 |
| 评标委员会否决 | 所有投标被评标委员会否决 |
| 重大偏差 | 投标文件存在重大偏差且未按规定修正 |
