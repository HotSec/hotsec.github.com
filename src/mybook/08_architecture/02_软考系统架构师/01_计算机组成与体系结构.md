# 计算机组成与体系结构

## 一、CPU组成

### 1.1 运算器

| 部件 | 功能 |
|------|------|
| ALU（算术逻辑单元） | 执行算术运算和逻辑运算 |
| 累加器（AC） | 存放运算结果和源操作数 |
| 状态寄存器（PSW） | 存放运算状态标志（进位/溢出/零/符号） |
| 通用寄存器组 | 暂存操作数和中间结果 |
| 暂存寄存器 | 对用户透明，暂存从主存取来的数据 |

### 1.2 控制器

| 部件 | 功能 |
|------|------|
| PC（程序计数器） | 存放下一条指令地址，自动+1 |
| IR（指令寄存器） | 存放当前正在执行的指令 |
| AR（地址寄存器） | 存放当前访问的主存地址 |
| ID（指令译码器） | 对指令操作码译码产生控制信号 |
| 时序发生器 | 产生时序脉冲信号 |
| 微操作信号发生器 | 根据译码结果产生微操作控制信号 |

## 二、指令系统

### 2.1 CISC vs RISC

| 对比项 | CISC | RISC |
|--------|------|------|
| 指令数量 | 多（>200） | 少（<100） |
| 指令长度 | 变长 | 定长 |
| 寻址方式 | 多样 | 少（Load/Store） |
| 指令使用频率 | 20/80规则 | 仅高频指令 |
| 各指令执行时间 | 差别大 | 绝大多数1周期 |
| 通用寄存器 | 较少 | 多 |
| 控制方式 | 微程序控制 | 硬布线控制 |
| 流水线 | 难以实现 | 易于实现 |
| 代表 | x86 | ARM/MIPS/RISC-V |

### 2.2 寻址方式

| 寻址方式 | 操作数位置 | 特点 |
|----------|-----------|------|
| 立即寻址 | 指令中直接给出 | 速度最快，操作数范围小 |
| 直接寻址 | 地址码直接指向主存 | 简单，寻址空间受限 |
| 间接寻址 | 地址码指向的主存单元再存地址 | 寻址空间大，速度慢 |
| 寄存器寻址 | 操作数在寄存器中 | 速度快，寄存器数有限 |
| 寄存器间接寻址 | 寄存器中存主存地址 | 速度较快，寻址灵活 |
| 变址寻址 | EA = (IX) + A | 适合数组/循环，IX可变 |
| 基址寻址 | EA = (BR) + A | 适合多道程序重定位，BR由OS设 |
| 相对寻址 | EA = (PC) + 偏移量 | 适合转移指令，程序浮动 |

## 三、流水线技术

### 3.1 基本参数

- **流水线周期** = 各段中执行时间最长的段（瓶颈段）
- **N条指令执行时间** = 一条指令完整时间 + (n-1) × 流水线周期
  - 理论公式：`T = (Δt₁ + Δt₂ + … + Δtₖ) + (n-1) × max(Δt)`
  - 实践公式：`T = k × max(Δt) + (n-1) × max(Δt)`（每段都按最长段对齐）

### 3.2 性能指标

| 指标 | 公式 | 说明 |
|------|------|------|
| 吞吐率 TP | TP = n / T | 单位时间完成指令数 |
| 最大吞吐率 TPₘₐₓ | TPₘₐₓ = 1 / max(Δt) | 瓶颈段决定 |
| 加速比 S | S = T顺序 / T流水 | 流水加速效果 |
| 效率 E | E = n条指令实际占用时空区 / 总时空区 | 流水线利用率 |

### 3.3 高级流水线

| 类型 | 特点 |
|------|------|
| 超标量 | 多个功能部件并行，同时发射多条指令（空间并行） |
| 超流水 | 将一个周期再分段，提高主频（时间并行） |
| 超长指令字（VLIW） | 编译器将多个独立操作打包为一条长指令 |

## 四、存储体系

### 4.1 层次结构

```
寄存器 → Cache → 主存 → 辅存
速度快 ←————————————→ 速度慢
容量小 ←————————————→ 容量大
价格高 ←————————————→ 价格低
```

- Cache-主存：解决速度不匹配（硬件管理，对程序员透明）
- 主存-辅存：解决容量不足（OS管理，虚拟存储器）

### 4.2 Cache

**命中率与平均访问时间：**

- 命中率 h = 命中次数 / 总访问次数
- 平均访问时间 `Ta = h × Tc + (1-h) × Tm`
  - Tc：Cache访问时间，Tm：主存访问时间
- 效率 e = Tc / Ta

**地址映射方式：**

| 映射方式 | 地址结构 | 特点 |
|----------|---------|------|
| 直接映射 | 主存字块标记 + Cache字块地址 + 字块内地址 | 简单，冲突多，每个主存块只能映射到固定Cache行 |
| 全相联映射 | 主存字块标记 + 字块内地址 | 灵活，冲突少，硬件复杂，比较器多 |
| 组相联映射 | 主存字块标记 + 组地址 + 字块内地址 | 折中方案，组间直接映射，组内全相联 |

**替换算法：**

| 算法 | 原理 | 特点 |
|------|------|------|
| OPT | 替换将来最长时间不使用的 | 理论最优，无法实现 |
| FIFO | 替换最早调入的 | 实现简单，可能Belady异常 |
| LRU | 替换最近最少使用的 | 性能好，需硬件计数器 |
| LFU | 替换使用频率最低的 | 需计数器，长期偏好旧数据 |

### 4.3 虚拟存储器与页面置换

| 算法 | 说明 | Belady异常 |
|------|------|-----------|
| FIFO | 先进先出 | 可能发生 |
| OPT | 最优置换 | 不会 |
| LRU | 最近最少使用 | 不会 |
| Clock | 近似LRU，循环检查访问位 | 不会 |

**Belady异常**：FIFO算法中，分配的物理块数增加反而缺页率上升的现象。

**抖动**：频繁缺页导致系统大部分时间用于页面换入换出。

**工作集**：在某段时间间隔（窗口）内进程实际访问的页面集合。

## 五、中断与DMA

### 5.1 中断

| 要点 | 说明 |
|------|------|
| 中断响应时间 | 从发出中断请求到进入中断处理程序的时间 |
| 中断向量 | 中断服务程序入口地址 |
| 中断向量表 | 存放各中断向量的表，通过中断类型号索引 |
| 中断优先级 | 硬件固定，不可屏蔽中断 > 可屏蔽中断 |
| 中断嵌套 | 高优先级可打断低优先级中断处理 |
| 单重中断与多重中断 | 单重：中断期间不响应新中断；多重：高优先级可嵌套 |

### 5.2 DMA

| 方式 | 说明 |
|------|------|
| 停止CPU访存 | DMA期间CPU完全让出总线，最简单 |
| 周期挪用（窃取） | DMA在CPU不用存储器时挪用周期，优先DMA |
| DMA与CPU交替访存 | 适用于CPU工作周期比主存周期长的情况 |

DMA特点：数据不经过CPU，直接在内存与I/O设备间传送；传送前/后需CPU干预；适合大批量数据传送。

## 六、总线

| 总线类型 | 功能 | 宽度决定 |
|----------|------|---------|
| 数据总线 | 传输数据 | 一次传输的数据位数 |
| 地址总线 | 传输地址 | 寻址空间大小（2^n） |
| 控制总线 | 传输控制信号 | — |

**总线带宽计算：**

`总线带宽 = 总线宽度 × 总线工作频率 / 8`（单位：B/s）

若总线宽度32位，频率200MHz：`带宽 = 32/8 × 200M = 800MB/s`

## 七、校验码

### 7.1 奇偶校验

- 只能检奇数位错，不能纠错
- 奇校验：1的个数为奇数
- 偶校验：1的个数为偶数

### 7.2 海明码

- **码距（海明距离）**：两个合法编码之间不同二进制位的最小位数
- 检错能力：码距 d 可检 d-1 位错
- 纠错能力：码距 d 可纠 ⌊(d-1)/2⌋ 位错
- 检错+纠错：d ≥ 2e+1（检e位），d ≥ 2t+1（纠t位）
- **校验位位数**：2^k ≥ n + k + 1（n为数据位，k为校验位）
- 校验位放在 2^i 的位置（第1,2,4,8…位）

### 7.3 CRC循环冗余校验

- 生成多项式 G(x) 的最高次幂为 r，则附加 r 个0
- 用模2除法（异或）计算余数，余数即为校验码
- 能检测所有奇数位错误和所有长度 ≤ r 的突发错误
- 只能检错，不能纠错

## 八、指令流水线冲突

| 冲突类型 | 原因 | 解决方案 |
|----------|------|---------|
| 结构冲突 | 不同指令争用同一硬件资源 | 资源重复配置（分离指令/数据Cache）、指令暂停 |
| 数据冲突 | 后续指令需要前面指令的结果 | 数据旁路（转发/前推）、编译器插入NOP、流水线停顿 |
| 控制冲突 | 转移指令改变PC值，已取指令作废 | 分支预测（静态/动态）、延迟转移、预取两个方向 |

**数据冲突细分：**

| 类型 | 说明 | 示例 |
|------|------|------|
| RAW（写后读） | 真相关，最常见 | 后指令读前指令要写的寄存器 |
| WAR（读后写） | 反相关 | 后指令写前指令要读的寄存器 |
| WAW（写后写） | 输出相关 | 两条指令写同一寄存器 |

## 十、系统性能指标

| 指标 | 含义 | 公式/说明 |
|------|------|----------|
| 主频 | CPU时钟频率 | 主频 = 外频 × 倍频 |
| CPI | 执行一条指令所需平均时钟周期数 | CPI = 总时钟周期数 / 指令条数 |
| MIPS | 每秒百万条指令 | MIPS = 主频 / (CPI × 10⁶) |
| FLOPS | 每秒浮点运算次数 | MFLOPS/GFLOPS/TFLOPS |
| 执行时间 | CPU执行时间 = 指令条数 × CPI × 时钟周期 |
| 响应时间 | 从提交到获得结果的时间 | 包含等待+执行 |
| 吞吐率 | 单位时间处理任务数 | 吞吐率 = 1 / 响应时间 |

**Amdahl定律：**

`加速比 S = 1 / [(1 - Fe) + Fe/Se]`

- Fe：可改进比例，Se：改进后加速倍数
- 最大加速比：当 Se→∞ 时，Sₘₐₓ = 1/(1-Fe)

## 十一、存储器编址计算

### 11.1 按字节编址与按字编址

| 编址方式 | 含义 | 最小寻址单位 | 地址空间 |
|----------|------|-------------|---------|
| 按字节编址 | 每个字节一个地址 | 1B | 地址数 = 容量(B) |
| 按字编址 | 每个字一个地址 | 1个机器字 | 地址数 = 容量(B) / 字长(B) |

- 按字节编址：地址 +1 → 移动1B
- 按字编址：地址 +1 → 移动1个字（如32位机移动4B）

### 11.2 芯片数量计算

`所需芯片数 = 总容量 / 单片容量`

- 位扩展（扩展字长）：数据位数不够，多片并联扩展数据位宽
- 字扩展（扩展容量）：地址空间不够，多片串联扩展地址范围
- 字位同时扩展：先位扩展满足字长，再字扩展满足容量

**示例**：用 4K×4 位芯片组成 16K×8 位存储器

- 位扩展：2片 4K×4 → 4K×8（字长从4位扩到8位）
- 字扩展：4组 4K×8 → 16K×8（容量从4K扩到16K）
- 总芯片数 = 2 × 4 = 8片

### 11.3 地址范围计算

`结束地址 = 起始地址 + 容量 - 1`

**示例**：某存储器容量 4KB，起始地址 2000H

- 结束地址 = 2000H + 4KB - 1 = 2000H + 0FFFH = 2FFFH

**按字编址地址数**：若机器字长16位（2B），容量8KB

- 按字节编址：8K个地址
- 按字编址：8K / 2 = 4K个地址

### 11.4 存储器扩展方式对比

| 扩展方式 | 目的 | 连接方法 | 地址线 | 数据线 |
|----------|------|---------|--------|--------|
| 位扩展 | 扩展字长 | 多片并联 | 各片地址线并联 | 各片数据线分别引出 |
| 字扩展 | 扩展容量 | 多片串联 | 低位地址线并联，高位经译码器选片 | 各片数据线并联 |
| 字位同时扩展 | 同时扩展 | 先位扩展再字扩展 | 同字扩展 | 同位扩展 |

## 十二、磁盘容量与性能计算

### 12.1 磁盘结构

| 术语 | 说明 |
|------|------|
| 磁道 | 磁盘面上的同心圆环 |
| 扇区 | 磁道上的最小寻址单位，通常512B |
| 柱面 | 所有记录面上同一半径的磁道集合 |
| 记录面 | 磁盘的上下两个记录面 |

### 12.2 容量计算

- **磁道容量** = 每扇区字节数 × 每磁道扇区数
- **面容量** = 磁道容量 × 每面磁道数
- **总容量** = 面容量 × 记录面数 = 扇区字节数 × 扇区数 × 磁道数 × 记录面数

**非格式化容量** = 位密度 × 内圈周长 × 磁道数 × 记录面数

**格式化容量** = 每道扇区数 × 扇区字节数 × 磁道数 × 记录面数

格式化容量 < 非格式化容量（格式化需要留出间隔和校验信息）

### 12.3 性能指标

| 指标 | 计算方法 |
|------|---------|
| 平均寻道时间 | 磁头移动到目标磁道的平均时间（通常取最大寻道时间的1/3~1/2） |
| 平均旋转延迟 | 磁头等待目标扇区转到其下方的平均时间 = 磁盘旋转一圈时间 / 2 |
| 数据传输率 | 磁道容量 × 磁盘转速（r/s） |

**存取时间计算：**

`存取时间 = 寻道时间 + 旋转等待时间 + 数据传输时间`

- 旋转等待时间 = 半圈时间 = (1/转速) / 2
- 数据传输时间 = 传输数据量 / 数据传输率

**示例**：磁盘转速 7200rpm，每磁道100个扇区，每扇区512B

- 旋转一圈时间 = 60/7200 ≈ 8.33ms
- 平均旋转延迟 = 8.33/2 ≈ 4.17ms
- 数据传输率 = 100 × 512 × (7200/60) = 6,144,000 B/s ≈ 6MB/s

## 十三、输入输出系统

### 13.1 程序查询方式

| 类型 | 说明 | 特点 |
|------|------|------|
| 无条件传送 | 假设外设始终就绪，直接读写 | 硬件最简单，可靠性低 |
| 条件传送（轮询） | CPU不断查询外设状态，就绪后传送 | 浪费CPU时间，实时性差 |

- CPU全程参与，等待外设就绪期间无法做其他工作
- 优先级由查询顺序决定

### 13.2 程序中断方式

**中断处理流程：**

```
中断请求 → 中断响应 → 保护现场 → 中断服务 → 恢复现场 → 中断返回
```

| 阶段 | 说明 |
|------|------|
| 中断请求 | 外设通过中断线向CPU发请求信号 |
| 中断响应 | CPU完成当前指令后，发中断响应信号，获取中断向量 |
| 保护现场 | 保存断点（PC）和状态（PSW），必要时保存通用寄存器 |
| 中断服务 | 执行中断服务程序，完成I/O操作 |
| 恢复现场 | 恢复通用寄存器和状态寄存器 |
| 中断返回 | 执行中断返回指令，恢复PC，返回断点 |

**单重中断 vs 多重中断：**

| 对比项 | 单重中断 | 多重中断 |
|--------|---------|---------|
| 中断期间 | 关中断，不响应新请求 | 开中断，高优先级可嵌套 |
| 保护现场 | 只保存断点 | 保存断点+屏蔽字 |
| 实时性 | 差 | 好 |

### 13.3 DMA方式与中断方式对比

| 对比项 | 中断方式 | DMA方式 |
|--------|---------|---------|
| 数据传送 | 通过CPU执行程序 | DMA控制器直接控制 |
| CPU参与 | 每次传送需CPU干预 | 仅初始化和结束需CPU |
| 传送单位 | 字或字节 | 数据块 |
| 响应时间 | 指令执行结束后 | 存取周期结束后（总线周期） |
| 适用场景 | 少量数据、低速设备 | 大批量数据、高速设备 |
| 程序中断 | 有 | 传送结束后中断CPU |

### 13.4 通道方式

| 通道类型 | 特点 | 适用场景 |
|----------|------|---------|
| 字节多路通道 | 以字节为单位交叉服务多台低速设备 | 低速设备（打印机、终端） |
| 数组选择通道 | 以块为单位，一次只服务一台设备，传输率高 | 高速设备（磁盘） |
| 数组多路通道 | 以块为单位交叉服务多台高速设备 | 高速设备，兼顾并发与效率 |

- 字节多路通道：分时操作，每台设备轮流传一个字节
- 数组选择通道：独占式，串行工作，利用率低
- 数组多路通道：结合前两者优点，通道程序可切换

## 十四、系统总线详解

### 14.1 总线仲裁

**集中式仲裁：**

| 方式 | 原理 | 优先级 | 速度 | 扩展性 |
|------|------|--------|------|--------|
| 链式查询 | 总线授权信号串行通过各设备，先到先得 | 离仲裁器近的优先级高 | 慢 | 差（对电路故障敏感） |
| 计数器定时查询 | 计数器从某值开始，通过计数找到请求设备 | 计数起始值决定 | 中 | 中 |
| 独立请求方式 | 每个设备有独立的请求线和授权线 | 仲裁器灵活决定 | 最快 | 好（线路多，成本高） |

**分布式仲裁：**

- 不需要中央仲裁器，各设备通过竞争机制自行获得总线控制权
- 常见方式：自举分布式、冲突检测（CSMA/CD）

### 14.2 总线操作周期

```
请求 → 仲裁 → 寻址 → 数据传输 → 结束
```

| 阶段 | 说明 |
|------|------|
| 请求 | 主设备发出总线使用请求 |
| 仲裁 | 总线仲裁器决定哪个设备获得总线控制权 |
| 寻址 | 主设备发出从设备地址和操作命令 |
| 数据传输 | 主从设备之间进行数据交换 |
| 结束 | 撤销总线请求，释放总线 |

### 14.3 总线复用

- 地址/数据复用：同一组线在不同阶段传输地址或数据
- 寻址阶段传地址，数据传输阶段传数据
- 减少总线线数，降低成本，但需要锁存器暂存地址
- 例：PCI总线采用地址/数据复用线 AD[31:0]

## 十五、可靠性计算

### 15.1 串联系统

```
R₁ → R₂ → … → Rₙ
```

`R = R₁ × R₂ × … × Rₙ`

- 任一部件失效则系统失效
- 串联越多，可靠性越低

### 15.2 并联系统

```
R₁ ∥ R₂ ∥ … ∥ Rₙ
```

`R = 1 - (1-R₁)(1-R₂)…(1-Rₙ)`

- 所有部件同时失效系统才失效
- 并联越多，可靠性越高
- 若各部件可靠度相同均为 R₀：`R = 1 - (1-R₀)ⁿ`

### 15.3 混联系统

- 先计算局部并联/串联的等效可靠度，再整体计算
- 方法：化简为纯串联或纯并联

**示例**：R₁与R₂并联后，再与R₃串联

- 并联部分：R₁₂ = 1 - (1-R₁)(1-R₂)
- 整体：R = R₁₂ × R₃

### 15.4 MTBF与失效率

| 指标 | 公式 | 说明 |
|------|------|------|
| MTBF（平均无故障时间） | MTBF = 1/λ | λ为失效率 |
| 串联系统失效率 | λ = λ₁ + λ₂ + … + λₙ | 近似公式（各λ较小时） |
| 并联系统MTBF | MTBF = 1/λ × (1 + 1/2 + … + 1/n) | 各部件失效率相同为λ时 |

- 串联系统：MTBF = 1/(λ₁ + λ₂ + … + λₙ)
- 可靠度与时间关系：R(t) = e^(-λt)

## 十六、计算机体系结构发展

### 16.1 冯·诺依曼体系

| 要点 | 说明 |
|------|------|
| 核心思想 | 存储程序，程序和数据同等对待 |
| 五大部件 | 运算器、控制器、存储器、输入设备、输出设备 |
| 工作方式 | 指令驱动，顺序执行（取指→译码→执行） |
| 存储结构 | 指令和数据共存同一存储器 |
| 特点 | 简单灵活，但存在冯·诺依曼瓶颈（CPU与存储器速度差距） |

**冯·诺依曼瓶颈**：CPU速度远快于主存，单一总线导致指令和数据不能同时访问，限制了性能提升。

### 16.2 哈佛体系

| 要点 | 说明 |
|------|------|
| 核心思想 | 指令和数据分开存储、分开访问 |
| 存储结构 | 独立的指令存储器和数据存储器，各有独立总线 |
| 工作方式 | 可同时取指和取操作数，提高吞吐率 |
| 特点 | 硬件复杂，但消除了存储器访问冲突 |
| 典型应用 | DSP、ARM Cortex-M、微控制器 |

### 16.3 冯·诺依曼体系 vs 哈佛体系

| 对比项 | 冯·诺依曼体系 | 哈佛体系 |
|--------|-------------|---------|
| 存储器 | 统一存储 | 指令/数据分离 |
| 总线 | 共用一套总线 | 独立的两套总线 |
| 取指与取数 | 不能同时 | 可以同时 |
| 硬件复杂度 | 低 | 高 |
| 空间利用率 | 高（灵活分配） | 低（固定分配） |
| 适用场景 | 通用计算机 | 嵌入式、DSP |
| 性能瓶颈 | 存在瓶颈 | 缓解瓶颈 |

**改进型哈佛体系**：在哈佛体系基础上，允许指令存储器和数据存储器之间有通道，既保持并行访问优势，又增加灵活性。现代CPU的L1 Cache分为L1 I-Cache和L1 D-Cache，即为哈佛体系的体现。
