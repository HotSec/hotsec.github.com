# 操作系统

## 一、进程管理

### 1.1 进程状态模型

**三态模型：**

| 状态 | 说明 |
|------|------|
| 运行态 | 正在CPU上执行 |
| 就绪态 | 已获除CPU外所有资源，等待调度 |
| 阻塞态（等待态） | 等待某事件完成 |

**五态模型：**

| 状态 | 说明 |
|------|------|
| 运行态 | 正在CPU上执行 |
| 就绪态 | 等待调度 |
| 阻塞态 | 等待事件 |
| 新建态 | 正在创建，尚未进入就绪队列 |
| 终止态 | 正在回收资源 |

**状态转换要点：**
- 运行→就绪：时间片到/被抢占
- 运行→阻塞：请求I/O/等待事件（主动行为）
- 阻塞→就绪：事件完成（被动行为）
- 就绪→运行：调度程序选中
- 无：就绪→阻塞、阻塞→运行（不存在）

### 1.2 进程与线程

| 对比项 | 进程 | 线程 |
|--------|------|------|
| 资源分配 | 进程是资源分配的基本单位 | 线程不拥有资源，共享进程资源 |
| 调度 | 进程切换开销大 | 线程切换开销小 |
| 地址空间 | 每个进程独立地址空间 | 同进程线程共享地址空间 |
| 通信 | 需IPC机制（管道/消息/共享内存） | 可直接共享全局变量 |
| 并发性 | 进程间可并发 | 线程间可并发 |
| 系统开销 | 创建/撤销/切换开销大 | 开销小 |

**线程分类：**

| 类型 | 说明 |
|------|------|
| 用户级线程 | 内核不可见，线程切换不需内核介入，一个线程阻塞则整个进程阻塞 |
| 内核级线程 | 内核可见，由内核调度，一个线程阻塞不影响其他线程 |
| 组合方式 | 多对一/一对一/多对多模型 |

### 1.3 进程同步与互斥

- **互斥**：对共享资源的排他性访问
- **同步**：进程间的协调执行顺序
- **临界区**：访问共享资源的代码段，需满足：空闲让进、忙则等待、有限等待、让权等待

### 1.4 PV操作

**信号量：** 整型变量，P操作减1（可能阻塞），V操作加1（可能唤醒）

**生产者-消费者问题：**

| 操作 | P/V顺序 |
|------|---------|
| 生产者 | P(空闲) → P(互斥) → 放产品 → V(互斥) → V(满) |
| 消费者 | P(满) → P(互斥) → 取产品 → V(互斥) → V(空闲) |

要点：P(互斥)必须在P(资源)之后，否则可能死锁

**读者-写者问题：**

| 角色 | 操作 |
|------|------|
| 读者 | P(rw)仅第一个读者 → V(rw)；最后一个读者 → V(w) |
| 写者 | P(w) → 写 → V(w) |
| 读计数 | P(mutex)保护readcount变量 |

**哲学家进餐问题：**

- 死锁原因：5人同时拿左边筷子
- 解决方案：最多允许4人同时进餐；奇数号先拿左偶数号先拿右；仅当左右筷子都可用时才拿

### 1.5 死锁

**四个必要条件：**

| 条件 | 说明 | 预防方法 |
|------|------|---------|
| 互斥 | 资源排他使用 | 无法破坏 |
| 不可剥夺 | 已获资源不能被强行收回 | 允许抢占 |
| 请求与保持 | 持有资源又请求新资源 | 一次性申请所有资源 |
| 循环等待 | 存在进程循环等待链 | 资源有序分配 |

**死锁处理策略：**

| 策略 | 说明 |
|------|------|
| 预防 | 破坏四个必要条件之一 |
| 避免 | 银行家算法，动态检查资源分配安全性 |
| 检测 | 资源分配图检测环路 |
| 解除 | 资源剥夺、进程撤销、进程回退 |

**银行家算法：**

- Available：可用资源向量
- Max：最大需求矩阵
- Allocation：已分配矩阵
- Need = Max - Allocation
- 安全性检查：寻找 Need ≤ Available 的进程，完成后释放资源，重复直至所有进程完成

**资源分配图：**
- 进程→资源：请求边（进程请求资源）
- 资源→进程：分配边（资源已分配给进程）
- 图中有环路且每类资源仅一个实例 → 死锁
- 图中有环路但每类资源多个实例 → 可能死锁

## 二、存储管理

### 2.1 管理方式对比

| 方式 | 地址空间 | 碎片 | 分配 | 优缺点 |
|------|---------|------|------|--------|
| 固定分区 | 一维 | 内部碎片 | 静态 | 简单但浪费空间 |
| 可变分区 | 一维 | 外部碎片 | 动态 | 灵活但需紧凑 |
| 页式 | 一维 | 内部碎片（页内） | 动态 | 无外部碎片，需页表 |
| 段式 | 二维 | 外部碎片 | 动态 | 便于共享和保护 |
| 段页式 | 二维 | 内部碎片 | 动态 | 结合段式页式优点，两次查表 |

### 2.2 页式存储

**地址结构：** 页号 + 页内偏移

**地址变换：** 逻辑地址 → 查页表 → 物理页框号 + 页内偏移 → 物理地址

**快表TLB：**
- 高速缓存，存放最近访问的页表项
- 命中时无需访问主存中的页表
- 平均访问时间 = 命中率 × TLB访问时间 + (1-命中率) × (TLB访问时间 + 主存访问时间)

**多级页表：** 解决页表占用连续主存空间的问题，将页表再分页

### 2.3 缺页中断

- 访问的页面不在主存时产生
- 属于内中断（异常）
- 指令执行期间产生（不同于一般中断在指令结束后检测）
- 一条指令可能产生多次缺页中断

### 2.4 页面置换算法

| 算法 | 原理 | Belady异常 |
|------|------|-----------|
| OPT | 置换将来最久不使用的页面 | 不会 |
| FIFO | 置换最早进入内存的页面 | 可能 |
| LRU | 置换最近最久未使用的页面 | 不会 |
| Clock | 近似LRU，访问位为0则置换，为1则置0继续扫描 | 不会 |

**Belady异常**：FIFO算法中增加物理块数反而缺页次数增加。

**抖动**：频繁发生缺页中断，系统大部分时间用于页面置换。

**工作集**：在某时间窗口Δ内进程实际访问的页面集合，分配的物理块数应≥工作集大小。

## 三、设备管理

### 3.1 SPOOLing技术

- **假脱机技术**，将独占设备改造为共享设备
- 组成：输入井/输出井（磁盘）、输入缓冲区/输出缓冲区（内存）、输入进程SPi/输出进程SPo
- 应用：共享打印机
- 特点：提高了I/O速度，将独占设备虚拟为共享设备

### 3.2 缓冲技术

| 缓冲方式 | 说明 |
|----------|------|
| 单缓冲 | 设备→缓冲区→工作区，处理时间和传送时间重叠 |
| 双缓冲 | 设备→缓冲区1的同时，缓冲区2→工作区，速度匹配时可并行 |
| 循环缓冲 | 多个缓冲区组成环形队列 |

**单缓冲平均时间：** max(T, C) + M（T：输入，C：处理，M：传送）
**双缓冲平均时间：** max(T, C+M)（当T > C+M时）

### 3.3 磁盘调度

| 算法 | 原理 | 特点 |
|------|------|------|
| FCFS | 按请求顺序服务 | 公平，寻道距离长 |
| SSTF | 选择距当前磁头最近的请求 | 局部最优，可能饥饿 |
| SCAN（电梯算法） | 单向扫描到头再反向 | 不会饥饿，对两端不公平 |
| C-SCAN | 单向扫描到头后直接跳回起始端 | 均匀响应时间 |
| LOOK | SCAN的改进，到最远请求即反向，不到端 | 减少不必要的移动 |

## 四、文件管理

### 4.1 索引节点

- 将文件名与文件描述信息分离
- 目录项仅含文件名+索引节点号
- 索引节点存放文件元数据（大小/权限/地址等）

### 4.2 文件物理结构

| 结构 | 说明 | 优缺点 |
|------|------|--------|
| 连续分配 | 文件占连续磁盘块 | 顺序读快，外部碎片，难以扩展 |
| 链接分配 | 每块含指向下一块的指针 | 无外部碎片，顺序访问慢，指针占空间 |
| FAT | 文件分配表，链式结构在表中 | 随机访问较快，FAT表占内存 |
| 索引分配 | 索引块存放所有数据块指针 | 支持随机访问，小文件浪费索引块 |

**索引分配扩展：**

| 方式 | 说明 |
|------|------|
| 直接索引 | 索引块直接指向数据块 |
| 一级间接 | 索引块指向间接索引块 |
| 二级间接 | 两级间接索引 |
| 三级间接 | 三级间接索引 |

### 4.3 空闲空间管理

| 方法 | 原理 | 特点 |
|------|------|------|
| 位图法 | 每个磁盘块用1位表示空闲/占用 | 空间固定，查找快，常用 |
| 空闲链表 | 空闲块链成链表 | 灵活，遍历慢 |
| 成组链接 | 空闲块分组，组间链表连接 | UNIX采用，兼顾效率 |

### 4.4 目录结构

| 结构 | 说明 |
|------|------|
| 单级目录 | 所有文件同一目录，不允许重名 |
| 两级目录 | 主目录+用户目录，用户间可重名 |
| 树形目录 | 层次结构，路径名唯一标识 |
| 无环图目录 | 支持文件共享，需处理共享计数 |

## 五、作业管理

### 5.1 性能指标

| 指标 | 公式 |
|------|------|
| 周转时间 | 完成时间 - 提交时间 |
| 带权周转时间 | 周转时间 / 实际运行时间 ≥ 1 |
| 平均周转时间 | Σ周转时间 / 作业数 |
| 平均带权周转时间 | Σ带权周转时间 / 作业数 |

### 5.2 调度算法

| 算法 | 原理 | 特点 |
|------|------|------|
| FCFS | 按提交顺序 | 公平，短作业不利 |
| SJF/SPF | 选运行时间最短的 | 平均周转时间最优，长作业可能饥饿 |
| HRN（高响应比优先） | RP = (等待时间+运行时间)/运行时间 | 兼顾长短作业，不会饥饿 |
| RR（时间片轮转） | 就绪队列轮转，时间片到则换 | 响应快，适合交互式系统 |

**HRN响应比：** RP = 1 + 等待时间/运行时间，等待时间越长优先级越高

## 六、操作系统结构

| 结构 | 说明 | 特点 |
|------|------|------|
| 宏内核（单体内核） | 所有OS功能在内核态运行 | 性能高，可靠性差，规模大 |
| 微内核 | 仅保留最基本功能在内核（进程调度/通信/中断） | 可靠性好，可扩展，性能略低（用户态/内核态切换多） |
| 混合内核 | 宏内核+微内核折中 | 兼顾性能与可靠性 |

**微内核基本功能：** 进程管理、低级存储管理、进程间通信、I/O管理

| 特点 | 说明 |
|------|------|
| 实时性 | 硬实时（必须满足截止时间）/软实时（尽量满足） |

## 八、进程通信方式（IPC）

### 8.1 共享存储

- 低级共享：共享某些数据区（变量/数组），需程序员控制同步
- 高级共享：共享存储区，进程可读写整个共享区，需配合信号量同步

### 8.2 消息传递

| 方式 | 说明 |
|------|------|
| 直接通信 | 发送进程直接指明接收进程ID，消息直接挂到接收进程的消息队列 |
| 间接通信（信箱） | 通过信箱（邮箱）中转，发送方放信箱、接收方从信箱取，解耦收发双方 |

### 8.3 管道通信

- 管道（Pipe）是连接读写进程的共享文件（pipe文件）
- 半双工通信：同一时刻只能单向传输，要双向需建立两个管道
- 无名管道：父子进程间使用，随进程消失
- 有名管道（FIFO）：存在于文件系统中，无亲缘关系进程也可通信
- 管道满时写阻塞，管道空时读阻塞

### 8.4 信号量

- 用于进程间同步与互斥，不属于数据传输型通信
- 详见1.4节PV操作

### 8.5 套接字Socket

- 可用于同一主机或跨网络的不同主机间通信
- 基于网络协议（TCP/UDP），是分布式系统进程通信的基础

### 8.6 IPC方式对比

| 方式 | 通信方向 | 通信范围 | 同步机制 | 特点 |
|------|---------|---------|---------|------|
| 共享存储 | 双向 | 同一主机 | 需外部同步 | 速度快，需处理互斥 |
| 消息传递 | 双向 | 同一主机 | 系统自动同步 | 解耦，消息缓冲 |
| 管道 | 半双工 | 同一主机 | 自动阻塞 | 简单，单向限制 |
| 信号量 | — | 同一主机 | 自身即同步 | 仅同步互斥，不传数据 |
| Socket | 双向 | 跨网络 | 应用层控制 | 跨主机，开销较大 |

## 九、段式存储管理

### 9.1 基本概念

- 按程序逻辑将地址空间划分为若干段，每段有段名和段长
- 逻辑地址结构：**段号 + 段内偏移**
- 每段从0开始编址，段长可变

### 9.2 段表

| 段表项 | 说明 |
|--------|------|
| 段号 | 逻辑段编号 |
| 段起始地址（基址） | 该段在主存中的起始物理地址 |
| 段长度 | 该段的长度，用于越界检查 |

### 9.3 地址变换过程

1. 从逻辑地址取出段号和段内偏移
2. 用段号查段表，得到段起始地址和段长度
3. 越界检查：段内偏移 < 段长度，否则产生越界中断
4. 物理地址 = 段起始地址 + 段内偏移

### 9.4 段的共享与保护

- **共享**：不同进程段表中指向同一物理段即可实现共享（如共享代码段）
- **保护**：越界检查（段内偏移 ≥ 段长度则越界）；访问权限检查（读/写/执行）

### 9.5 段式 vs 页式对比

| 对比项 | 页式 | 段式 |
|--------|------|------|
| 划分依据 | 物理大小固定分页 | 逻辑模块分页 |
| 地址空间 | 一维（页号自动计算） | 二维（需给出段号+偏移） |
| 大小 | 页大小固定 | 段大小可变 |
| 碎片 | 内部碎片（页内碎片） | 外部碎片 |
| 共享与保护 | 不便共享和保护 | 便于按段共享和保护 |
| 地址变换 | 查页表 | 查段表 |

## 十、段页式存储管理

### 10.1 基本思想

- 先将程序按逻辑分段，再将每段按固定大小分页
- 结合段式的逻辑优势和页式的内存管理优势

### 10.2 逻辑地址结构

**段号 + 页号 + 页内偏移**

### 10.3 地址变换过程

1. 用段号查段表，得到该段对应的页表起始地址和页表长度
2. 越界检查：页号 < 页表长度
3. 用页号查页表，得到物理页框号
4. 物理地址 = 页框号 × 页面大小 + 页内偏移

### 10.4 性能开销

- 每次访存需两次查表（段表→页表），再访问主存取数据，共三次访存
- 可引入TLB加速，将最近使用的段表项/页表项缓存

## 十一、磁盘结构参数计算

### 11.1 磁盘存取时间

**存取时间 = 寻道时间 + 旋转等待时间 + 传输时间**

| 组成 | 说明 |
|------|------|
| 寻道时间 | 磁头移动到目标磁道所需时间，主要开销 |
| 旋转等待时间 | 目标扇区旋转到磁头下方所需时间 |
| 传输时间 | 读写数据的时间 |

### 11.2 旋转等待时间

- 平均旋转等待时间 = 磁盘旋转一周时间的一半
- **平均旋转等待时间 = 1/(2r)**（r为转速，单位rps）
- 例：转速7200 RPM = 120 rps，平均旋转等待 = 1/(2×120) ≈ 4.17ms

### 11.3 数据传输率

**数据传输率 = 扇区字节数 × 每道扇区数 × 转速**

- 例：每扇区512B，每道100个扇区，转速7200RPM
- 传输率 = 512 × 100 × 120 = 6,144,000 B/s ≈ 6MB/s

### 11.4 常见计算题型

| 题型 | 方法 |
|------|------|
| 求存取时间 | 三部分相加 |
| 求平均旋转等待 | 1/(2r) |
| 求传输率 | 扇区字节数×每道扇区数×转速 |
| 求磁盘容量 | 磁头数×柱面数×每道扇区数×每扇区字节数 |

## 十二、文件系统实例

### 12.1 FAT文件系统

| 特性 | FAT12 | FAT16 | FAT32 |
|------|-------|-------|-------|
| FAT表项 | 12位 | 16位 | 28位（保留4位） |
| 最大分区 | 8MB | 2GB | 2TB（默认） |
| 簇大小 | — | — | 4KB~32KB |
| 根目录 | 固定扇区数 | 固定扇区数 | 可变，普通目录 |
| 文件名 | 8.3格式 | 8.3格式 | 长文件名支持 |

- FAT表：链式结构，每个表项指向下一个簇号，末项为特殊标记
- 优点：简单、兼容性好
- 缺点：不支持日志、碎片多、单文件最大4GB（FAT32）

### 12.2 ext2/ext3/ext4

| 特性 | ext2 | ext3 | ext4 |
|------|------|------|------|
| 日志 | 无 | 有（日志模式可选） | 有 |

## 十三、操作系统安全

### 13.1 安全层次

| 层次 | 说明 | 措施 |
|------|------|------|
| 系统级安全 | 防止未授权用户进入系统 | 注册与登录、身份认证（密码/生物特征/令牌） |
| 用户级安全 | 控制用户权限范围 | 用户权限分组、用户组管理、权限隔离 |
| 文件级安全 | 控制文件访问权限 | 访问控制列表ACL、文件权限位（rwx） |

### 13.2 访问控制列表ACL

- 每个文件/资源关联一个ACL，列出各用户/组的访问权限
- 比传统rwx权限更精细，可针对单个用户设置不同权限

### 13.3 安全操作系统等级

| 等级 | 名称 | 说明 |
|------|------|------|
| D | 最低保护 | 无安全要求，如MS-DOS |
| C1 | 自主安全保护 | 用户与数据分离，基本访问控制 |
| C2 | 受控访问保护 | 更细粒度访问控制，审计 |
| B1 | 标签安全保护 | 强制访问控制（MAC），安全标签 |
| B2 | 结构化保护 | 形式化安全策略模型，隐蔽通道分析 |
| B3 | 安全域 | 参考监视器，安全事件审计 |
| A1 | 验证设计 | 形式化验证，最高安全等级 |

- C级：自主访问控制（DAC），用户自行决定权限
- B级以上：强制访问控制（MAC），系统强制执行安全策略

## 十四、进程调度算法补充

### 14.1 优先级调度

| 类型 | 说明 |
|------|------|
| 静态优先级 | 创建时确定，运行期间不变，实现简单但不灵活 |
| 动态优先级 | 运行期间可调整，更灵活，如等待时间越长优先级越高 |

- 就绪队列按优先级排列，选优先级最高者运行
- 可抢占式：高优先级进程可抢占低优先级进程
- 非抢占式：当前进程运行完毕或阻塞后才调度

### 14.2 多级反馈队列调度

- 设置多个就绪队列，优先级从高到低，时间片从小到大
- 新进程进入第1级队列，时间片到未完成则降入下一级队列
- 仅当高优先级队列为空时，才调度低优先级队列
- 高优先级队列到达新进程时，可抢占当前低优先级进程
- 特点：兼顾短作业（快速完成）和长作业（逐渐获得更长CPU时间），无需预知运行时间

### 14.3 实时调度算法

| 算法 | 原理 | 特点 |
|------|------|------|
| RM（速率单调） | 周期越短优先级越高（静态优先级） | 最优静态调度，CPU利用率上限 ≤ n(2^(1/n)-1) |
| DM（截止期单调） | 相对截止期越短优先级越高 | RM的推广，适用于截止期≠周期 |
| EDF（最早截止期优先） | 绝对截止期越近优先级越高（动态优先级） | 最优动态调度，CPU利用率可达100% |

- RM/DM为静态优先级算法，EDF为动态优先级算法
- EDF理论上最优但实现复杂，RM实现简单但利用率有上限
