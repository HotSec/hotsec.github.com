# 数据库系统

## 数据库三级模式两级映像

### 三级模式

| 模式层次 | 别称 | 描述 | 对应 |
|---------|------|------|------|
| 外模式 | 用户模式/子模式 | 用户可见的数据视图，一个数据库可有多个外模式 | 视图 |
| 概念模式 | 逻辑模式/模式 | 全体数据的逻辑结构和特征描述，一个数据库只有一个概念模式 | 基本表 |
| 内模式 | 存储模式/物理模式 | 数据在数据库内部的存储方式和物理结构，一个数据库只有一个内模式 | 存储文件 |

### 两级映像与数据独立性

| 映像 | 定义 | 保证的独立性 | 效果 |
|------|------|-------------|------|
| 外模式-概念模式映像 | 外模式与概念模式之间的对应关系 | 逻辑独立性 | 概念模式改变时修改映像，外模式不变，应用程序不变 |
| 概念模式-内模式映像 | 概念模式与内模式之间的对应关系 | 物理独立性 | 内模式改变时修改映像，概念模式不变，外模式不变，应用程序不变 |

- 逻辑独立性：修改概念模式（如增加新关系/属性），只需调整外模式-概念模式映像
- 物理独立性：修改内模式（如更换存储设备/改变存储结构），只需调整概念模式-内模式映像

## 数据模型

### 数据模型分类

| 层次 | 模型类型 | 特点 | 典型代表 |
|------|---------|------|---------|
| 概念模型 | E-R模型 | 面向用户，独立于DBMS | E-R图 |
| 逻辑模型 | 层次模型 | 树形结构，一对多关系 | IMS |
| 逻辑模型 | 网状模型 | 图形结构，多对多关系 | DBTG |
| 逻辑模型 | 关系模型 | 二维表格，数学基础严格 | Oracle/MySQL |
| 物理模型 | 物理模型 | 面向DBMS，描述存储细节 | 存储结构/存取路径 |

### E-R图要素

| 要素 | 表示方式 | 含义 |
|------|---------|------|
| 实体 | 矩形 | 客观存在并可相互区分的事物 |
| 属性 | 椭圆 | 实体所具有的某一特性 |
| 联系 | 菱形 | 实体之间的关联关系 |

- 联系类型：1:1、1:N、M:N
- E-R图转换为关系模式规则：
  - 实体→关系模式
  - 1:1联系→合并到任一端实体
  - 1:N联系→合并到N端实体
  - M:N联系→独立成关系模式

## 关系代数

### 基本运算

| 运算 | 符号 | 含义 | 示例 |
|------|------|------|------|
| 选择 | σ | 从关系中选取满足条件的元组 | σ_{age>20}(R) |
| 投影 | π | 从关系中选取若干属性列 | π_{name,age}(R) |
| 连接 | ⋈ | 两个关系中满足条件的元组拼接 | R ⋈_{R.A=S.A} S |
| 自然连接 | ⋈ | 在公共属性上等值连接并去重 | R ⋈ S |
| 除 | ÷ | R中包含S全部属性的元组 | R ÷ S |
| 并 | ∪ | 两个关系元组合并（去重） | R ∪ S |
| 差 | - | 在R但不在S中的元组 | R - S |
| 交 | ∩ | 同时在R和S中的元组 | R ∩ S |
| 笛卡尔积 | × | 两个关系元组的所有组合 | R × S |

### 运算要点

- 并、差、交要求两个关系具有相同的属性个数和属性域（并相容性）
- 交可用差表示：R ∩ S = R - (R - S)
- 自然连接 = 在所有公共属性上等值连接 + 去除重复属性列
- 除运算常用于"全部"语义查询（如"选修了所有课程的学生"）

## 关系数据库理论

### 函数依赖

| 依赖类型 | 定义 | 示例 |
|---------|------|------|
| 函数依赖 | X→Y，X唯一确定Y | 学号→姓名 |
| 部分函数依赖 | X→Y且X的某个真子集也能确定Y | (学号,课程号)→姓名（学号即可确定） |
| 传递函数依赖 | X→Y，Y→Z，Y不→X | 学号→系名→系主任 |
| 多值依赖 | X↠Y，X的一个值对应Y的多个值 | 课程↠教师 |

### Armstrong公理体系

| 规则 | 描述 |
|------|------|
| 自反律 | 若Y⊆X，则X→Y |
| 增广律 | 若X→Y，则XZ→YZ |
| 传递律 | 若X→Y且Y→Z，则X→Z |

**导出规则**：

| 规则 | 描述 |
|------|------|
| 合并律 | X→Y且X→Z，则X→YZ |
| 分解律 | X→YZ，则X→Y且X→Z |
| 伪传递律 | X→Y且WY→Z，则XW→Z |

### 候选键求解方法

1. 属性分类：
   - L类：仅出现在函数依赖左部 → 必为候选键成员
   - R类：仅出现在函数依赖右部 → 必不在候选键中
   - N类：未出现在函数依赖中 → 必为候选键成员
   - LR类：出现在函数依赖左右两部 → 待定
2. 求键步骤：
   - 取L类+N类属性集X，求X的闭包X⁺
   - 若X⁺包含所有属性，则X为候选键
   - 否则，逐个添加LR类属性，再求闭包，直到包含所有属性

### 范式

| 范式 | 要求 | 消除的依赖 | 关键判断 |
|------|------|-----------|---------|
| 1NF | 属性不可再分（原子性） | — | 每个属性都是原子的 |
| 2NF | 消除非主属性对候选键的部分函数依赖 | 部分函数依赖 | 非主属性完全依赖于候选键 |
| 3NF | 消除非主属性对候选键的传递函数依赖 | 传递函数依赖 | 非主属性不传递依赖于候选键 |
| BCNF | 消除主属性对候选键的部分和传递函数依赖 | 主属性的部分/传递依赖 | 每个决定因素都是候选键 |
| 4NF | 消除非平凡的多值依赖 | 多值依赖 | 不存在非平凡多值依赖 |

- 范式级别：1NF ⊂ 2NF ⊂ 3NF ⊂ BCNF ⊂ 4NF
- 3NF放宽条件：允许主属性对候选键的传递依赖
- BCNF强化条件：所有决定因素都必须是候选键

### 模式分解

| 分解性质 | 定义 | 判定方法 |
|---------|------|---------|
| 无损连接 | 分解后自然连接等于原关系 | R₁∩R₂→(R₁-R₂)或(R₂-R₁)在F⁺中 |
| 保持函数依赖 | F在分解上的投影逻辑蕴含F | ⋃π_{Rᵢ}(F)逻辑蕴含F |

- 无损连接判定（两个关系模式）：R₁∩R₂ → (R₁-R₂) ∈ F⁺ 或 R₁∩R₂ → (R₂-R₁) ∈ F⁺
- 无损连接判定（多个关系模式）：构造表格法（Chase算法）
- 分解目标：既无损连接又保持函数依赖
- 3NF分解：可同时满足无损连接和保持函数依赖
- BCNF分解：可保证无损连接，但不一定能保持函数依赖

## SQL语言

### SQL分类

| 类型 | 全称 | 功能 | 关键字 |
|------|------|------|--------|
| DDL | Data Definition Language | 定义/修改/删除数据库对象 | CREATE/ALTER/DROP |
| DML | Data Manipulation Language | 操作数据 | INSERT/UPDATE/DELETE |
| DQL | Data Query Language | 查询数据 | SELECT |
| DCL | Data Control Language | 授权与权限控制 | GRANT/REVOKE |

### 视图

- 虚表，不存储实际数据，存储的是查询定义
- 简化查询、提供逻辑数据独立性、提供安全保护
- 视图更新限制：含聚合函数/GROUP BY/DISTINCT/多表连接的视图不可更新

### 索引

| 索引类型 | 特点 | 适用场景 |
|---------|------|---------|
| 聚簇索引 | 物理顺序与索引顺序一致，每表仅一个 | 范围查询、排序 |
| 非聚簇索引 | 物理顺序与索引顺序不一致，每表可有多个 | 等值查询 |
| 唯一索引 | 索引列值唯一 | 主键/唯一约束 |
| 复合索引 | 多列组合索引 | 多条件查询 |
| 全文索引 | 对文本内容索引 | 文本搜索 |

### 存储过程与触发器

| 对象 | 定义 | 特点 |
|------|------|------|
| 存储过程 | 预编译的SQL语句集合 | 减少网络流量、提高性能、可复用、可带参数 |
| 触发器 | 特定事件自动执行的存储过程 | 事件驱动（INSERT/UPDATE/DELETE）、BEFORE/AFTER |

### SQL查询优化

- 选择运算尽早执行（减少中间结果）
- 投影运算尽早执行（减少属性列数）
- 笛卡尔积与选择合并为连接运算
- 索引使用：WHERE条件列建立索引
- 避免全表扫描：避免在索引列上使用函数/计算/NOT操作

| 冲突类型 | 描述 | 示例 |

## 数据库安全

| 安全机制 | 说明 |
|---------|------|
| GRANT/REVOKE | 授予/撤销用户权限，GRANT SELECT ON T TO U1 |
| 视图机制 | 通过视图限制用户访问的数据范围 |
| 审计 | 记录用户操作日志，追踪安全事件 |
| 加密 | 对存储和传输的数据进行加密保护 |

- GRANT语法：GRANT 权限 ON 对象 TO 用户 [WITH GRANT OPTION]
- WITH GRANT OPTION：允许被授权者将权限再授予他人
- REVOKE语法：REVOKE 权限 ON 对象 FROM 用户 [CASCADE]

## 数据库恢复与并发控制

### 事务ACID特性

| 特性 | 含义 |
|------|------|
| 原子性（Atomicity） | 事务是不可分割的最小执行单位，要么全做要么全不做 |
| 一致性（Consistency） | 事务执行使数据库从一个一致状态转到另一个一致状态 |
| 隔离性（Isolation） | 并发事务之间互不干扰 |
| 持久性（Durability） | 事务提交后对数据库的修改是永久的 |

### 故障类型

| 故障类型 | 原因 | 恢复方法 |
|---------|------|---------|
| 事务故障 | 事务内部错误（如运算溢出/死锁被撤销） | 反向扫描日志，UNDO未完成事务 |
| 系统故障 | 硬件故障/软件错误/断电，内存数据丢失 | REDO已提交事务 + UNDO未提交事务 |
| 介质故障 | 磁盘损坏，外存数据丢失 | 利用备份恢复 + 日志重做 |

### 恢复技术

| 技术 | 原理 | 特点 |
|------|------|------|
| 日志（WAL） | 先写日志再写数据库，记录修改前后的值 | 基本恢复手段 |
| 检查点 | 定期将内存中的脏页写入磁盘，记录检查点 | 缩短恢复时间，只需从最近检查点开始恢复 |
| 镜像 | 自动将数据库复制到镜像服务器 | 实时备份，故障时快速切换 |

- 日志记录内容：事务标识、操作类型、修改前值（前像）、修改后值（后像）
- REDO：重做已提交事务的修改（使用后像）
- UNDO：撤销未提交事务的修改（使用前像）

### 并发问题

| 问题 | 描述 |
|------|------|
| 丢失修改 | 两个事务同时修改同一数据，一个修改覆盖另一个 |
| 不可重复读 | 事务两次读同一数据，中间被其他事务修改，结果不同 |
| 读脏数据 | 事务读取了另一个未提交事务修改的数据 |

### 封锁协议

| 锁类型 | 名称 | 特点 |
|--------|------|------|
| S锁（共享锁） | 读锁 | 多个事务可同时持有S锁，与X锁互斥 |
| X锁（排他锁） | 写锁 | 仅一个事务持有，与S锁和X锁都互斥 |

| 封锁协议 | 规则 | 防止的问题 |
|---------|------|-----------|
| 一级封锁协议 | 写前加X锁，事务结束释放 | 丢失修改 |
| 二级封锁协议 | 一级 + 读前加S锁，读完释放 | 丢失修改 + 读脏数据 |
| 三级封锁协议 | 一级 + 读前加S锁，事务结束释放 | 丢失修改 + 读脏数据 + 不可重复读 |

### 两阶段锁协议（2PL）

- 扩展阶段：只加锁，不释放锁
- 收缩阶段：只释放锁，不加锁
- 两阶段锁协议可保证串行化调度，但可能发生死锁

### 死锁处理

| 方法 | 说明 |
|------|------|
| 预防 | 一次性申请所有锁/按序加锁 |
| 超时 | 等锁超时则回滚 |
| 检测与恢复 | 等待图检测环路，选择牺牲者回滚 |

### 隔离级别

| 隔离级别 | 脏读 | 不可重复读 | 幻读 |
|---------|------|-----------|------|
| 读未提交（Read Uncommitted） | 可能 | 可能 | 可能 |
| 读已提交（Read Committed） | 不可能 | 可能 | 可能 |
| 可重复读（Repeatable Read） | 不可能 | 不可能 | 可能 |
| 串行化（Serializable） | 不可能 | 不可能 | 不可能 |

## 分布式数据库

### 透明性层次

| 透明性 | 含义 |
|--------|------|
| 分片透明性 | 用户不知道数据被分片，最高级别透明性 |
| 位置透明性 | 用户不知道数据存储在哪个场地 |
| 复制透明性 | 用户不知道数据被复制了多少副本 |
| 局部映射透明性 | 用户不知道局部DBMS的数据模型和语言 |

### 分布式事务提交协议

| 协议 | 过程 | 优缺点 |
|------|------|--------|
| 2PC | 1.协调者发Prepare 2.参与者回复Yes/No 3.协调者发Commit/Abort | 简单但有阻塞问题（协调者故障时参与者阻塞） |
| 3PC | 1.CanCommit 2.PreCommit 3.DoCommit | 消除阻塞但增加消息轮次，网络开销大 |

### CAP定理与BASE理论

| CAP属性 | 含义 |
|---------|------|
| 一致性（Consistency） | 所有节点看到相同的数据 |
| 可用性（Availability） | 每个请求都能得到非错误响应 |
| 分区容错性（Partition tolerance） | 网络分区时系统仍能运行 |

- CAP三者不可同时满足，分布式系统必须选择P，在C和A之间权衡
- CP系统：优先一致性（如ZooKeeper）
- AP系统：优先可用性（如Cassandra）

| BASE属性 | 含义 |
|----------|------|
| 基本可用（Basically Available） | 允许响应时间增加或功能降级 |
| 软状态（Soft State） | 允许中间状态 |
| 最终一致性（Eventual Consistency） | 一段时间后数据最终一致 |

### 分片与复制

| 策略 | 方式 | 特点 |
|------|------|------|
| 水平分片 | 按行将表拆分到不同节点 | 每个分片结构相同，数据不同 |
| 垂直分片 | 按列将表拆分到不同节点 | 每个分片包含不同列 |
| 主从复制 | 一个主节点写，多个从节点读 | 读扩展，主节点单点 |
| 多主复制 | 多个主节点均可写 | 写扩展，冲突解决复杂 |

## 数据仓库与数据挖掘

### OLTP vs OLAP

| 对比项 | OLTP | OLAP |
|--------|------|------|
| 全称 | 联机事务处理 | 联机分析处理 |
| 用户 | 操作人员/DBA | 决策人员/分析师 |
| 操作 | 增删改查 | 复杂查询/聚合分析 |
| 数据量 | 当前数据，量小 | 历史数据，量大 |
| 设计 | 面向应用，规范化 | 面向主题，反规范化 |
| 性能指标 | 事务吞吐量 | 查询响应时间 |

### 数据仓库模型

| 模型 | 结构 | 特点 |
|------|------|------|
| 星型模型 | 一个事实表 + 多个维度表（不规范化） | 查询快，冗余大 |
| 雪花模型 | 一个事实表 + 多个维度表（规范化） | 冗余小，查询需多表连接 |
| 星座模型 | 多个事实表 + 共享维度表 | 多主题分析 |

### ETL

| 阶段 | 功能 |
|------|------|
| Extract（抽取） | 从多个数据源抽取数据 |
| Transform（转换） | 清洗、格式转换、聚合、计算派生属性 |
| Load（加载） | 将转换后的数据装入数据仓库 |

### 数据挖掘方法

| 方法 | 目的 | 典型算法 |
|------|------|---------|
| 分类 | 预测离散类别标签 | 决策树/朴素贝叶斯/SVM/神经网络 |
| 聚类 | 无监督分组，发现自然簇 | K-Means/DBSCAN/层次聚类 |
| 关联规则 | 发现项之间的关联关系 | Apriori/FP-Growth |
| 回归 | 预测连续值 | 线性回归/逻辑回归 |
| 时间序列 | 分析时间趋势和周期 | ARIMA/指数平滑 |

- 关联规则关键指标：支持度（Support）、置信度（Confidence）、提升度（Lift）
- Apriori性质：频繁项集的所有子集也是频繁的

## 数据库性能优化

### 优化层次

| 层次 | 方法 | 说明 |
|------|------|------|
| 索引优化 | 选择合适索引类型、复合索引列顺序、避免过度索引 | 查询列与条件列建索引，高选择性列优先 |
| 查询优化 | 重写SQL、避免全表扫描、减少子查询 | EXISTS替代IN、UNION ALL替代UNION |
| 物理优化 | 分区表、表空间规划、存储引擎选择 | 按范围/列表/哈希分区 |
| 配置优化 | 缓冲池大小、连接池、日志配置 | 根据硬件资源和负载调整参数 |

### 索引优化要点

- 高选择性列（区分度高）优先建索引
- 复合索引遵循最左前缀原则
- 频繁更新的表避免过多索引（索引维护开销）
- 覆盖索引：索引包含查询所需全部列，避免回表

### 查询优化要点

- WHERE条件中使用索引列
- 避免在索引列上使用函数或计算
- 避免SELECT *，只查需要的列
- 大表连接优先使用索引列连接
- 分页查询优化：使用游标分页代替OFFSET

## 关系代数运算详解

### 选择运算（σ）

- 符号：σ
- 含义：从关系中选取满足给定条件的元组（行选择）
- 语法：σ_{条件}(R)
- 示例

| 运算 | 含义 |
|------|------|
| σ_{age>20}(Student) | 选取年龄大于20的学生 |
| σ_{dept='CS' ∧ age>20}(Student) | 选取计算机系且年龄大于20的学生 |
| σ_{salary>5000 ∨ dept='HR'}(Emp) | 选取工资大于5000或HR部门的员工 |

### 投影运算（π）

- 符号：π
- 含义：从关系中选取若干属性列（列选择），自动去除重复行
- 语法：π_{属性列表}(R)
- 示例

| 运算 | 含义 |
|------|------|
| π_{name,age}(Student) | 选取姓名和年龄两列 |
| π_{dept}(Student) | 选取系别列（自动去重） |
| π_{name,salary}(σ_{dept='CS'}(Emp)) | 先选CS部门，再取姓名和工资 |

### 连接运算（⋈）

- 符号：⋈
- 含义：从两个关系的笛卡尔积中选取满足条件的元组
- 语法：R ⋈_{条件} S

| 连接类型 | 符号 | 含义 | 示例 |
|---------|------|------|------|
| θ连接 | R ⋈_{θ} S | 选取满足θ条件的元组 | R ⋈_{R.A>S.B} S |
| 等值连接 | R ⋈_{R.A=S.A} S | θ为等号时的连接 | R ⋈_{R.id=S.id} S |
| 自然连接 | R ⋈ S | 在所有公共属性上等值连接并去重 | R ⋈ S |

### 自然连接详解

- 符号：⋈（无下标）
- 规则
    - 在所有公共属性上做等值比较
    - 结果中去除重复的公共属性列
    - 若无公共属性，则退化为笛卡尔积
- 示例

```
R(A, B)      S(B, C)
  a1  b1       b1  c1
  a2  b2       b2  c2
  a3  b3       b1  c3

R ⋈ S =
  A   B   C
  a1  b1  c1
  a1  b1  c3
  a2  b2  c2
```

### 除运算（÷）

- 符号：÷
- 含义：R中包含S全部属性的元组，常用于"全部"语义
- 语法：R ÷ S
- 示例：选课关系SC(学号,课程号)，课程关系C(课程号)
    - SC ÷ C = 选修了C中所有课程的学生学号
- 运算规则
    - 结果属性 = R的属性 - S的属性
    - 结果元组 = R中与S的每条元组都能匹配的元组在结果属性上的投影

### 集合运算

| 运算 | 符号 | 含义 | 条件 |
|------|------|------|------|
| 并 | ∪ | 两个关系元组合并去重 | 并相容 |
| 差 | - | 在R但不在S中的元组 | 并相容 |
| 交 | ∩ | 同时在R和S中的元组 | 并相容 |
| 笛卡尔积 | × | 两个关系元组的所有组合 | 无 |

- 并相容性：两个关系的属性个数相同、对应属性域相同
- 交可用差表示：R ∩ S = R - (R - S)

### 更名运算（ρ）

- 符号：ρ
- 含义：给关系或属性重新命名
- 语法：ρ_{新名}(R) 或 ρ_{新名(属性列表)}(R)
- 用途
    - 同一关系自身连接时区分不同实例
    - 使查询结果更易读
- 示例

| 运算 | 含义 |
|------|------|
| ρ_{Emp2}(Employee) | 将Employee重命名为Emp2 |
| ρ_{S(name,sal)}(π_{ename,salary}(Emp)) | 投影后重命名属性 |

## 候选键求解方法（图示法）

### 图示法步骤

1. 画出函数依赖图
    - 节点表示属性
    - 箭头表示函数依赖（X→Y画从X到Y的箭头）
2. 识别入度为0的属性
    - 入度为0的属性（无箭头指向）必在候选键中
3. 识别出度为0的属性
    - 出度为0的属性（无箭头指出）必不在候选键中
4. 逐步闭包求候选键
    - 将入度为0的属性集X求闭包X⁺
    - 若X⁺包含所有属性，X即为候选键
    - 否则逐个添加LR类属性，再求闭包

### 图示法示例

设有关系模式R(A,B,C,D,E)，函数依赖集F={A→B, B→C, C→D, D→E}

```
依赖图：
A → B → C → D → E
```

- 入度为0的属性：A（无箭头指向A）
- A的闭包：A⁺ = {A,B,C,D,E} = U
- 候选键：A

### 多候选键示例

设有R(A,B,C,D)，F={AB→C, C→D, D→A}

```
依赖图：
AB → C → D → A
```

- 入度为0的属性：B（只有B没有箭头指向）
- B⁺ = {B} ≠ U
- 尝试B+A：{A,B}⁺ = {A,B,C,D} = U → AB是候选键
- 尝试B+C：{B,C}⁺ = {A,B,C,D} = U → BC是候选键
- 尝试B+D：{B,D}⁺ = {A,B,C,D} = U → BD是候选键
- 候选键：AB、BC、BD

## 无损连接判定

### 方法一：Chase算法（表格法）

- 步骤
    1. 构造初始表格：行为分解的关系模式，列为全部属性
    2. 填写表格：若属性在关系模式中，填aᵢ；否则填bᵢⱼ
    3. 逐个应用函数依赖：若同一函数依赖左部相同的行，则右部也改为相同符号
    4. 判断：若某一行全部为a，则为无损连接

- 示例：R(A,B,C,D)，F={A→B, B→C}，分解为R₁(A,B)、R₂(B,C,D)

| | A | B | C | D |
|------|------|------|------|------|
| R₁(AB) | a₁ | a₂ | b₁₃ | b₁₄ |
| R₂(BCD) | b₂₁ | a₂ | a₃ | a₄ |

应用A→B：R₁和R₂的A列不同，无法修改
应用B→C：R₁和R₂的B列相同（都是a₂），将C列统一→b₁₃改为a₃

| | A | B | C | D |
|------|------|------|------|------|
| R₁(AB) | a₁ | a₂ | a₃ | b₁₄ |
| R₂(BCD) | b₂₁ | a₂ | a₃ | a₄ |

R₂行全为a → 无损连接 ✓

### 方法二：交集法（仅适用于两个关系模式的分解）

- 判定条件：R₁∩R₂ → (R₁-R₂) ∈ F⁺ 或 R₁∩R₂ → (R₂-R₁) ∈ F⁺
- 步骤
    1. 计算R₁和R₂的交集属性集 X = R₁∩R₂
    2. 计算R₁-R₂ 和 R₂-R₁
    3. 判断X→(R₁-R₂)或X→(R₂-R₁)是否在F的闭包F⁺中
    4. 若任一成立，则为无损连接

- 示例：R(A,B,C,D)，F={A→B, B→C}，R₁(A,B)、R₂(B,C,D)
    - R₁∩R₂ = {B}
    - R₁-R₂ = {A}
    - R₂-R₁ = {C,D}
    - B→A？不在F⁺中
    - B→{C,D}？B⁺={B,C}，不包含D，不在F⁺中
    - 结论：不是无损连接

## 保持函数依赖判定

### 判定方法

1. 计算F在每个Rᵢ上的投影π_{Rᵢ}(F)
    - π_{Rᵢ}(F) = {X→Y ∈ F⁺ | XY ⊆ Rᵢ}
2. 计算所有投影的并集 G = ⋃π_{Rᵢ}(F)
3. 判断G是否覆盖F，即F⁺ = G⁺
    - 等价判断：对F中每个函数依赖X→Y，验证Y ⊆ X_{G}⁺（X在G下的闭包）

### 判定步骤

1. 对F中的每个函数依赖X→Y
2. 在G下求X的闭包X_{G}⁺
3. 若Y ⊆ X_{G}⁺，则该依赖被G保持
4. 若所有依赖都被保持，则分解保持函数依赖

### 示例

R(A,B,C)，F={A→B, B→C}，分解为R₁(A,B)、R₂(A,C)

- π_{R₁}(F)：A→B（AB⊆R₁）→ {A→B}
- π_{R₂}(F)：无（AC上没有非平凡函数依赖）→ ∅
- G = {A→B}
- 验证B→C：B_{G}⁺ = {B}，C ⊄ {B} → 不保持
- 结论：该分解不保持函数依赖

### 分解性质总结

| 分解目标 | 3NF分解 | BCNF分解 |
|---------|---------|---------|
| 无损连接 | 可保证 | 可保证 |
| 保持函数依赖 | 可保证 | 不一定保证 |
| 同时满足两者 | 可保证 | 不一定 |

## SQL高级用法

### WITH递归CTE

- CTE（Common Table Expression）公用表表达式
- 语法

```sql
WITH 递归CTE名称(列名列表) AS (
    基础查询（锚点成员）
    UNION ALL
    递归查询（引用CTE自身）
)
SELECT * FROM 递归CTE名称;
```

- 示例：查询员工及其所有下属

```sql
WITH EmpCTE(id, name, manager_id, level) AS (
    SELECT id, name, manager_id, 0
    FROM Employee
    WHERE manager_id IS NULL
    UNION ALL
    SELECT e.id, e.name, e.manager_id, c.level + 1
    FROM Employee e
    JOIN EmpCTE c ON e.manager_id = c.id
)
SELECT * FROM EmpCTE;
```

- 注意事项
    - 必须有锚点成员（终止条件）
    - 递归成员不能包含GROUP BY、HAVING、聚合函数
    - 可用OPTION(MAXRECURSION n)限制递归深度

### 窗口函数

| 函数 | 说明 | 示例 |
|------|------|------|
| ROW_NUMBER() | 连续编号，无并列 | ROW_NUMBER() OVER(ORDER BY score DESC) |
| RANK() | 并列同号，跳号 | RANK() OVER(ORDER BY score DESC) |
| DENSE_RANK() | 并列同号，不跳号 | DENSE_RANK() OVER(ORDER BY score DESC) |
| LEAD() | 访问后续行的值 | LEAD(salary, 1) OVER(ORDER BY hire_date) |
| LAG() | 访问前序行的值 | LAG(salary, 1) OVER(ORDER BY hire_date) |

- 排名函数对比

| score | ROW_NUMBER | RANK | DENSE_RANK |
|-------|-----------|------|------------|
| 95 | 1 | 1 | 1 |
| 95 | 2 | 1 | 1 |
| 90 | 3 | 3 | 2 |
| 85 | 4 | 4 | 3 |

- 窗口函数语法

```sql
函数名() OVER(
    [PARTITION BY 分组列]
    [ORDER BY 排序列]
    [ROWS/RANGE 窗口范围]
)
```

- PARTITION BY：分区后在每个分区内独立计算
- ROWS BETWEEN ... AND ...：指定窗口范围

### CASE WHEN

```sql
SELECT name,
    CASE
        WHEN score >= 90 THEN 'A'
        WHEN score >= 80 THEN 'B'
        WHEN score >= 70 THEN 'C'
        ELSE 'D'
    END AS grade
FROM Student;
```

- 简单CASE

```sql
SELECT name,
    CASE dept
        WHEN 'CS' THEN '计算机'
        WHEN 'EE' THEN '电子'
        ELSE '其他'
    END AS dept_name
FROM Student;
```

- CASE WHEN在聚合中使用

```sql
SELECT dept,
    COUNT(*) AS total,
    SUM(CASE WHEN score >= 60 THEN 1 ELSE 0 END) AS pass,
    SUM(CASE WHEN score >= 90 THEN 1 ELSE 0 END) AS excellent
FROM Student
GROUP BY dept;
```

### EXISTS / NOT EXISTS

- EXISTS：子查询返回至少一行则为真
- NOT EXISTS：子查询返回零行则为真

```sql
SELECT s.name
FROM Student s
WHERE EXISTS (
    SELECT 1 FROM SC sc
    WHERE sc.sno = s.sno AND sc.cno = 'C001'
);
```

- NOT EXISTS实现"全部"语义（双重否定）

```sql
SELECT s.name
FROM Student s
WHERE NOT EXISTS (
    SELECT c.cno FROM Course c
    WHERE NOT EXISTS (
        SELECT 1 FROM SC sc
        WHERE sc.sno = s.sno AND sc.cno = c.cno
    )
);
```

- 含义：不存在一门课程该学生没有选修 → 选修了所有课程的学生

## 数据库性能优化详解

### 索引类型详解

| 索引类型 | 数据结构 | 特点 | 适用场景 | 不适用场景 |
|---------|---------|------|---------|-----------|
| B+树索引 | 平衡多路搜索树 | 范围查询高效、有序存储、最常用 | 等值查询、范围查询、排序 | 频繁大量更新的列 |
| 哈希索引 | 哈希表 | 等值查询O(1)、不支持范围 | 等值查询、内存表 | 范围查询、排序 |
| 位图索引 | 位图 | 低基数列高效、节省空间 | 性别、状态等低区分度列 | 高并发OLTP更新 |
| 全文索引 | 倒排索引 | 支持关键词搜索、分词 | 文本搜索、内容检索 | 精确等值查询 |

### 索引设计原则

| 原则 | 说明 |
|------|------|
| 选择性高的列优先 | 区分度高的列建索引效果好，如唯一键 |
| 遵循最左前缀 | 复合索引(A,B,C)可支持A、A,B、A,B,C的查询 |
| 覆盖索引 | 索引包含查询所需全部列，避免回表 |
| 避免过度索引 | 每个索引增加写开销和存储空间 |
| 频繁查询条件建索引 | WHERE、JOIN、ORDER BY中的列 |
| 避免在低选择性列建索引 | 如性别列（只有2个值） |
| 使用前缀索引 | 长字符串列只索引前N个字符 |

### 查询优化策略

**选择下推**

- 将选择运算尽可能下推到叶子节点执行
- 减少中间结果集大小
- 示例：σ_{age>20}(R ⋈ S) → (σ_{age>20}(R)) ⋈ S

**投影下推**

- 将投影运算尽可能下推，尽早去除不需要的列
- 减少数据传输量
- 示例：π_{name}(R ⋈ S) → π_{name}(π_{name,id}(R) ⋈ π_{id}(S))

**连接顺序优化**

- 小表驱动大表：小表作为外层循环
- 先做选择再连接：减少参与连接的元组数
- 多表连接时选择产生最小中间结果的顺序

| 策略 | 说明 | 效果 |
|------|------|------|
| 小表驱动大表 | 小表作为驱动表 | 减少循环次数 |
| 索引连接 | 在连接列上使用索引 | 避免全表扫描 |
| 哈希连接 | 构建哈希表进行连接 | 适合等值连接的大表 |
| 排序归并连接 | 两表排序后归并 | 适合已排序或需排序的数据 |

### 执行计划Explain分析

- 使用EXPLAIN查看查询执行计划

```sql
EXPLAIN SELECT s.name, sc.score
FROM Student s
JOIN SC sc ON s.sno = sc.sno
WHERE s.dept = 'CS' AND sc.score > 80;
```

- 关键指标

| 指标 | 含义 | 优化关注点 |
|------|------|-----------|
| type | 访问类型 | 从好到差：system > const > eq_ref > ref > range > index > ALL |
| key | 实际使用的索引 | 是否使用了预期索引 |
| rows | 预估扫描行数 | 越小越好 |
| Extra | 额外信息 | Using index（覆盖索引）、Using filesort（需优化）、Using temporary（需优化） |
| filtered | 过滤比例 | 越高越好 |

- 访问类型优化目标：避免ALL（全表扫描），争取达到ref及以上
- Using filesort：额外排序操作，考虑优化ORDER BY的索引使用
- Using temporary：使用临时表，考虑优化GROUP BY的索引使用
