# AI Coding — CLI 工具与插件生态

本文重点关注三类终端 Agent：**Claude Code、OpenAI Codex、OpenCode**。它们的共同点是：直接运行在项目目录中，能读代码、改文件、执行命令、调用 MCP 工具，并把结果沉淀为可审查的 diff。

IDE 类工具（Cursor、Trae、Copilot）更适合日常补全和局部编辑；CLI Agent 更适合跨文件任务、代码审查、重构、测试修复、文档整理和长流程执行。

## 一、快速选型

| 工具 | 定位 | 优势 | 推荐场景 |
|------|------|------|----------|
| Claude Code | Anthropic 官方 CLI Agent | 生态成熟，Subagents、Hooks、MCP、Skills、插件生态完整 | 复杂代码库、深度重构、多 Agent 编排、团队规范落地 |
| OpenAI Codex | OpenAI 官方 CLI / IDE Agent | 本地 CLI、IDE、Cloud、Subagents、MCP、AGENTS.md、代码审查闭环 | 本地实现、代码审查、文档迁移、并行子任务、OpenAI 生态 |
| OpenCode | 开源多模型 CLI / TUI Agent | 开源、模型无关、配置透明，支持 Agents、MCP、Plugins、LSP | 多模型切换、本地模型、低成本团队工作流、可控私有化 |

### 使用建议

| 场景 | 首选 |
|------|------|
| 想要开箱即用和成熟 Agent 体验 | Claude Code |
| 已经使用 ChatGPT / OpenAI 账号和 Codex IDE | Codex |
| 想要开源、可换模型、可自定义运行时 | OpenCode |
| 需要多 Agent 编排 | Claude Code + OMC / OpenCode + OmO / Codex Subagents |
| 需要接外部系统和文档 | MCP（Context7、GitHub、Figma、Playwright、Sentry、Linear 等） |
| 需要团队统一规则 | AGENTS.md / CLAUDE.md + Skills / Hooks |

## 二、核心能力对比

| 能力 | Claude Code | Codex | OpenCode |
|------|-------------|-------|----------|
| 运行形态 | CLI | CLI / IDE / Cloud | CLI / TUI |
| 项目规则 | CLAUDE.md，可兼容 AGENTS.md | AGENTS.md / `.codex/config.toml` | `opencode.json` / instructions / AGENTS.md |
| 子代理 | 内置 Subagents、Background agents、Agent teams | Subagents、Cloud tasks、可配置 `.codex/agents` | Primary agents / Subagents |
| MCP | 支持 HTTP / stdio 等 MCP | CLI 和 IDE 共用 MCP 配置 | 支持 MCP 配置 |
| Hooks | 原生支持 | 支持 hooks 配置 | 通过插件和配置扩展 |
| Skills | 原生 / 插件生态 | 支持 Skills | 支持 Skill 权限与社区移植 |
| 插件 | Claude Code Plugins / OMC 等 | Codex Plugins / Skills / MCP | `.opencode/plugins` / npm 插件 / OmO |
| 模型选择 | Anthropic 模型 | OpenAI 模型 | 75+ provider，可接 OpenAI、Anthropic、Gemini、Ollama 等 |
| 最适合 | 高质量代理式开发 | 本地/云端 Codex 工作流 | 开源可控、多模型工作流 |

## 三、Claude Code

Claude Code 是 Anthropic 官方终端 AI 编程工具。它适合让 Agent 长时间工作在真实项目中：读代码、改文件、运行测试、调用 MCP、生成计划，并通过 Subagents 和 Hooks 把复杂任务拆开。

### 安装与启动

```bash
npm install -g @anthropic-ai/claude-code
cd your-project
claude
```

### 项目约束文件

Claude Code 默认读取 `CLAUDE.md`。如果团队同时使用 Codex、OpenCode、Cursor，可以用 `AGENTS.md` 作为通用规则，再让 `CLAUDE.md` 链接或引用它。

```markdown
# Project Instructions

## 项目概述
Go 1.22 / Gin / PostgreSQL / Redis，采用 handler -> service -> repo 分层。

## 常用命令
- 测试：make test
- Lint：make lint
- 构建：make build

## 编码规范
- Context 作为第一个参数
- 错误使用 fmt.Errorf("module: %w", err)
- Handler 不直接访问 Repo

## Agent 规则
- 修改前先阅读相关代码和测试
- 不要回滚用户未要求回滚的改动
- 完成后报告实际运行过的验证命令
```

### 原生能力

| 能力 | 用法 | 适合场景 |
|------|------|----------|
| Plan Mode | 先规划再执行 | 中大型任务、架构变更 |
| Subagents | `/agents` 创建或配置专用 Agent | 探索、审查、测试、文档等边车任务 |
| Hooks | 在工具调用、提交、退出等节点触发脚本 | 质量门禁、禁止危险命令、自动格式检查 |
| MCP | `claude mcp add ...` | 连接 GitHub、Figma、Notion、Sentry、Linear、Vercel 等外部系统 |
| Skills / Plugins | 安装或自定义技能包 | 固化 TDD、调试、代码审查、发布流程 |

### 推荐插件与扩展

| 扩展 | 类型 | 推荐用途 |
|------|------|----------|
| Oh My ClaudeCode（OMC） | 多 Agent 编排插件 | Team、Ralph、Ultrawork、Code Review、Security Review 等复杂流程 |
| Claude Code GitHub Actions | 官方 GitHub 集成 | 在 issue / PR 中触发 Claude Code 工作流 |
| Context7 MCP | MCP 文档检索 | 查询框架和库的当前文档，减少 API 幻觉 |
| Playwright MCP | MCP 浏览器自动化 | 前端页面验证、截图、交互回归 |
| Figma MCP | MCP 设计上下文 | UI 还原、设计稿分析、视觉对齐 |
| GitHub / Linear / Sentry MCP | MCP 工程系统集成 | 读取 issue、PR、错误事件、任务状态 |
| Superpowers | Skill / 工作流集合 | TDD、系统化调试、计划执行、收尾验证 |

### OMC 适用场景

OMC 适合 Claude Code 原生能力不够“流程化”的任务：

- 多模块功能，需要 planner / architect / executor / verifier 分工
- 复杂重构，需要 critic 或 reviewer 专门找风险
- 长时间任务，需要 Ralph / UltraQA 做验证-修复循环
- 团队希望把常用流程封装成 slash command、Skill、Hook、Agent

不建议一上来就给小任务套 OMC。单文件修复、简单文档调整、局部测试补充，直接 Claude Code 会更快。

## 四、OpenAI Codex

Codex 是 OpenAI 的编码 Agent。Codex CLI 可以在本地终端运行，读取仓库、修改文件、执行命令；Codex IDE / Cloud 可以把同一套工作流延伸到编辑器和云端任务。

### 安装与启动

```bash
npm i -g @openai/codex
cd your-project
codex
```

常用入口：

```bash
# 交互式 TUI
codex

# 一次性任务
codex "阅读 AGENTS.md，分析 auth 模块的测试缺口"

# 恢复历史会话
codex resume

# 本地代码审查
codex review

# 非交互自动化
codex exec "分析当前分支相对 main 的测试缺口"
```

### 项目配置

Codex 的核心配置通常是：

| 文件 | 用途 |
|------|------|
| `AGENTS.md` | 项目规则、命令、边界、验证要求 |
| `.codex/config.toml` | 项目级 Codex 配置，适合可信项目 |
| `.codex/agents/*.toml` | 自定义子代理 |
| `~/.codex/config.toml` | 用户级 MCP、模型、权限等配置 |

### 原生能力

| 能力 | 推荐用途 |
|------|----------|
| 本地 TUI | 日常实现、重构、调试、代码解释 |
| Local code review | 提交前让独立 Codex Agent 审查 diff |
| Subagents | 并行探索、审查、文档查证、UI 调试 |
| MCP | 连接第三方文档、浏览器、Figma、GitHub 等工具 |
| Skills / Plugins | 复用团队工作流和工具扩展 |
| Cloud tasks | 把较长任务放到云端环境执行，再应用 diff |
| Image inputs | UI 截图、设计稿、错误截图辅助分析 |

### 推荐搭配

| 扩展 | 类型 | 推荐用途 |
|------|------|----------|
| AGENTS.md | 项目规则 | 所有 Codex 项目的最低配置 |
| Codex Subagents | 原生子代理 | PR review、文档查证、前端调试、批量审计 |
| OpenAI Developer Docs MCP | MCP | 查询 OpenAI API / Codex 官方文档 |
| Context7 MCP | MCP | 查询第三方库文档 |
| Playwright MCP | MCP | 浏览器复现、截图和前端回归验证 |
| Figma MCP | MCP | 从设计稿提取 UI 上下文 |
| GitHub / Linear MCP | MCP | 读取 issue、PR、需求上下文 |
| 自定义 Codex Plugin / Skill | 插件 / Skill | 封装团队代码审查、发布、迁移、文档流程 |

### 子代理示例

适合 PR review 的三代理配置：

| Agent | 权限 | 职责 |
|-------|------|------|
| `pr_explorer` | read-only | 映射代码路径、查找相关测试和调用链 |
| `reviewer` | read-only | 找 correctness、安全、回归和缺失测试 |
| `docs_researcher` | read-only + MCP | 查官方文档，确认 API 和版本行为 |

提示模板：

```text
Review this branch against main.
Have pr_explorer map affected code paths,
reviewer find real risks,
and docs_researcher verify framework APIs through MCP.
Return findings ordered by severity with file references.
```

### 使用建议

1. **把 AGENTS.md 写具体**：命令、分层、禁止项、验证要求要可执行。
2. **审查和实现分离**：实现任务后，用 local code review 或 reviewer subagent 做独立审查。
3. **MCP 只接必要工具**：文档、浏览器、Figma、GitHub 是高价值；低频工具按项目需要再加。
4. **权限按任务收紧**：探索和 review 用 read-only；实现才给 workspace-write。
5. **长任务用 Cloud 或 exec**：需要后台跑的任务不要阻塞本地交互会话。

## 五、OpenCode

OpenCode 是开源的终端 AI 编程 Agent，适合希望控制模型、配置、插件和运行环境的团队。它的核心优势是模型无关和配置透明。

### 安装与启动

```bash
curl -fsSL https://opencode.ai/install | bash
cd your-project
opencode
```

### 配置入口

OpenCode 常用 `opencode.json`：

```json
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": ["AGENTS.md", "docs/guidelines.md", ".cursor/rules/*.md"],
  "permission": {
    "edit": "ask",
    "bash": "ask"
  },
  "lsp": true,
  "mcp": {},
  "plugin": ["opencode-helicone-session"]
}
```

### 原生能力

| 能力 | 推荐用途 |
|------|----------|
| Plan / Build agents | 规划与执行分离 |
| Custom agents | 为 review、docs、debug、frontend 等任务配置专用 Agent |
| Permissions | 控制 edit、bash、websearch、MCP 等工具权限 |
| MCP | 接入外部文档、浏览器、设计和工程系统 |
| LSP | 代码跳转、引用、诊断等语言服务能力 |
| Plugins | 自定义工具、Hooks、集成和 npm 插件 |
| Instructions | 复用 AGENTS.md、CONTRIBUTING.md、Cursor rules 等项目规则 |

### 推荐插件与扩展

| 扩展 | 类型 | 推荐用途 |
|------|------|----------|
| Oh My OpenCode（OmO） | 多 Agent 编排插件 | Sisyphus、Prometheus、Atlas 等规划/执行/审查流程 |
| Context7 MCP | MCP 文档检索 | 查第三方库文档 |
| Playwright MCP | MCP 浏览器自动化 | 前端回归和页面验证 |
| GitHub / Linear MCP | MCP 工程系统集成 | 读取 issue、PR、任务上下文 |
| LSP servers | 语言服务 | TypeScript、Go、Python 等项目的跳转和诊断 |
| Helicone / 观测插件 | Plugin | 追踪请求、成本和模型表现 |
| Superpowers / Skill 移植 | Skill 工作流 | TDD、调试、审查、验证等流程规范 |

### OmO 适用场景

OmO 可以理解为 OpenCode 的“带电池发行版”：在 OpenCode 之上预置 Agent、Hooks、MCP、LSP 和任务路由。

推荐使用：

- 多步骤任务，需要先采访需求、再生成计划、再执行
- 希望不同任务路由到不同模型
- 希望把 review、debug、docs、frontend 等职责拆给不同 Agent
- 团队需要统一 OpenCode 的默认配置和流程

谨慎使用：

- 非常小的修改
- 对第三方插件供应链敏感的生产环境
- 团队尚未明确权限、MCP、模型成本边界

## 六、插件选择原则

CLI Agent 的插件不要越多越好。推荐按以下顺序逐步启用：

1. **项目规则**：AGENTS.md / CLAUDE.md / instructions。
2. **文档 MCP**：Context7、OpenAI Developer Docs、框架官方 MCP。
3. **工程 MCP**：GitHub、Linear、Sentry、Vercel、数据库只读查询。
4. **浏览器 / 设计 MCP**：Playwright、Figma。
5. **流程插件**：OMC、OmO、Superpowers、团队自定义 Skills。
6. **观测和安全**：请求追踪、MCP 审计、权限收敛、密钥扫描。

### 高价值组合

| 组合 | 适合场景 |
|------|----------|
| Claude Code + CLAUDE.md + Context7 MCP + Playwright MCP | 全栈功能开发和前端验证 |
| Claude Code + OMC + Superpowers | 大任务规划、并行执行、审查和验证闭环 |
| Codex + AGENTS.md + Subagents + OpenAI Docs MCP | OpenAI/API 项目、PR review、文档查证 |
| Codex + Playwright MCP + Figma MCP | UI 修复、设计稿还原、截图驱动调试 |
| OpenCode + AGENTS.md + OmO + LSP | 开源多模型团队工作流 |
| OpenCode + Ollama + Context7 MCP | 本地模型、低成本探索和文档辅助 |

### 风险控制

- MCP 会扩大 Agent 的外部权限，只连接当前任务真正需要的服务器。
- 插件可能包含 Hooks、脚本或工具定义，安装前检查来源、权限和更新频率。
- Review / Explore Agent 默认用 read-only 权限。
- 涉及数据库、云平台、生产日志时优先只读，敏感字段脱敏。
- 团队统一配置版本，避免每个人的 Agent 行为不一致。

## 七、其他工具简表

| 工具 | 类型 | 适合场景 |
|------|------|----------|
| GitHub Copilot | IDE 插件 | 日常补全、短函数、样板代码 |
| Cursor | AI IDE | IDE 内 Chat、Composer、多文件编辑 |
| Trae | AI IDE | IDE 工作流、Rules、Skills、Builder |
| Aider | CLI | Git 驱动的轻量终端改代码 |
| Continue | IDE 插件 | 开源 IDE 助手、私有模型接入 |

这些工具仍然有价值，但本文的主线是 CLI Agent。团队实践中常见搭配是：IDE 工具负责日常补全，CLI Agent 负责复杂任务和验证闭环。
