# AI Coding — 最佳实践总结

## AI Coding 最佳实践总结

### 1. 项目配置

- 始终配置项目约束文档（AGENTS.md / CLAUDE.md / Rules）
- 约束文档保持更新，与项目同步
- 分主题管理规则，避免单文件过长
- 提供具体的代码示例、命令、验证方式和禁止事项
- 大型仓库用子目录级约束文件覆盖局部规则

### 2. 任务交互

- 精确描述任务，包含文件路径、函数名、当前问题和期望行为
- 复杂任务先要求 Agent 只读探索，再输出计划，不要立即改代码
- 提示词包含目标、边界、验收标准、允许改动范围和测试要求
- 原样提供错误日志、堆栈、截图和复现步骤，不要过度转述
- 让 Agent 小步交付，保持 diff 可审查

### 3. 上下文管理

- 把长期稳定信息写入 AGENTS.md / CLAUDE.md，把临时需求写进当前任务
- 大任务分阶段执行，阶段之间总结当前状态、剩余任务和验证结果
- 当 Agent 连续两次犯同类错误，优先更新项目约束文档，而不是继续口头提醒
- 对大型文件或复杂模块，先让 Agent 建立文件地图，再指定具体改动点
- 保留关键决策：为什么这么做、哪些方案被排除、兼容性要求是什么

### 4. 工作流

推荐顺序：

1. **Explore**：只读搜索代码、测试、配置、文档。
2. **Plan**：形成任务清单、接口变化、风险和验证方式。
3. **Implement**：小范围修改，优先复用现有模式。
4. **Verify**：运行测试、lint、构建或手工场景。
5. **Review**：审查 diff，检查无关改动、重复代码、遗漏测试。
6. **Document**：需要时同步 AGENTS.md、README、接口文档或迁移说明。

Claude Code 可用 Plan Mode、feature-dev、ralph-loop、OMC Team 等强化这个流程；Codex 可用 AGENTS.md、权限模式、本地 code review 和明确验收标准强化这个流程。

### 5. 代码质量

- AI 生成的代码必须通过项目指定的 lint、测试和构建
- 修改公共行为时补充回归测试；修 bug 时优先写能复现问题的测试
- 安全审查重点检查注入、认证、授权、敏感数据、路径遍历和依赖风险
- 性能审查重点检查 N+1 查询、无界循环、重复 IO、大对象复制和内存泄漏
- 保持代码风格一致，不为了 AI 生成方便引入新抽象或新依赖

### 6. 验证策略

验证要求要写具体命令，不写“运行相关测试”这种模糊描述。

```markdown
## 验证要求
- 单文件工具函数改动：go test ./internal/pkg/foo
- HTTP Handler 改动：go test ./internal/handler ./internal/service
- 数据库迁移：make test-integration
- 前端交互：npm test -- UserForm && npm run build
```

推荐让 Agent 在最终回复中报告：

- 运行了哪些命令
- 命令是否通过
- 未运行的验证及原因
- 手工检查了哪些关键场景

### 7. 权限与安全

- 只读分析用只读权限；写文件、安装依赖、联网或执行危险命令时单独授权
- 不要把 API Key、密码、私钥、生产 Token 写入约束文档或 Prompt
- 不要让 Agent 自动提交或推送到生产分支，除非团队流程明确允许
- 不要要求 Agent 回滚未明确属于本任务的用户改动
- 对依赖升级、迁移脚本、权限配置、认证授权代码做额外人工审查

### 8. 代码审查

让 AI 做 review 时要指定角色和优先级：

```markdown
请以代码审查者身份审查当前 git diff。
优先级：
1. 行为回归和 bug
2. 安全问题
3. 兼容性和数据迁移风险
4. 缺失测试
5. 可维护性问题
请按严重程度排序，给出文件和行号。
```

不要只让 AI 总结“代码看起来怎么样”。审查目标应是找缺陷，而不是复述改了什么。

### 9. 效率提升

- 将常见开发模式定义为 Skill、命令模板或任务清单
- 使用 AGENTS.md 减少每次对话重复说明
- 善用 Builder / Composer / Plan Mode / OpenSpec 处理多文件变更
- 用 Git diff 作为协作边界，让 Agent 围绕当前变更解释、审查和修复
- 把成功的 Prompt 模板沉淀为团队文档

### 10. 团队落地

- 统一项目约束文档入口：AGENTS.md 为主，CLAUDE.md 可作为兼容入口或软链接
- 统一验证命令：测试、lint、构建、架构检查都写成固定命令
- 统一 AI 使用披露规则：是否允许 commit message 出现 AI 工具、是否需要 trailer
- 统一高风险改动流程：权限、数据、安全、依赖升级需要人工复核
- 定期审查约束文档，删除过时规则，补充重复踩坑经验
