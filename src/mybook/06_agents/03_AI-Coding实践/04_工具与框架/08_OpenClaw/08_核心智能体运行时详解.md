
# OpenClaw 核心智能体运行时详解

## 一、嵌入模式智能体 (`pi-embedded-runner`)

### 核心功能概述

[`pi-embedded-runner`](file:///Volumes/SN740/code/notebook/third/openclaw/src/agents/pi-embedded-runner/) 是 OpenClaw 的主要运行时引擎，它基于 `@earendil-works/pi-agent-core` 包提供完整的智能体执行环境。它负责：

- 会话管理
- 工具调用编排
- 模型请求处理
- 历史记录管理
- 上下文压缩 (`compaction`)

### 主要文件结构

```
pi-embedded-runner/
├── run/                  # 单次运行 (attempt) 实现
│   ├── attempt.ts        # 单次完整运行尝试
│   ├── helpers.ts        # 辅助方法
│   ├── setup.ts          # 准备阶段
│   └── types.ts          # 类型定义
├── abort.ts              # 中止控制
├── history.ts            # 历史管理
├── lanes.ts              # 执行通道隔离
├── logger.ts             # 运行日志
└── runtime.ts            # 主运行时
```

### 单次运行执行流程 (`runEmbeddedAttempt`)

[`runEmbeddedAttempt`](file:///Volumes/SN740/code/notebook/third/openclaw/src/agents/pi-embedded-runner/run/attempt.ts) 是一次完整的运行尝试（一次用户消息处理周期），核心步骤如下：

1. **准备阶段 (`setup`)**
   - 解析参数和配置
   - 初始化 Sandbox（如果启用）
   - 加载 Skills
   - 准备上下文注入（Bootstrap files）

2. **工具构建 (`construct tools`)**
   - 使用 `createOpenClawCodingTools`（见下文）
   - 应用工具策略（Tool Policy）
   - 过滤工具可见性

3. **历史记录准备 (`history preparation`)**
   - 加载历史记录
   - 进行上下文压缩 (如果需要)
   - 应用策略过滤

4. **请求/响应循环 (`request/response loop`)**
   - 调用模型（通过 Provider Transport）
   - 处理工具调用请求
   - 执行工具
   - 记录结果到历史
   - 重复直到模型生成最终消息

5. **结果输出 (`output result`)**
   - 生成 Assistant 可见内容
   - 保存会话文件
   - 发送事件通知

## 二、工具系统 (`pi-tools`)

### 核心工具创建函数

[`createOpenClawCodingTools`](file:///Volumes/SN740/code/notebook/third/openclaw/src/agents/pi-tools.ts) 是构建所有 OpenClaw 工具的工厂函数，负责根据配置、策略、沙箱环境等因素组装完整工具集。

### 工具分类

#### 1. 基础编码工具 (Base Coding Tools)

基于 `@earendil-works/pi-coding-agent` 提供：
- `read` - 读取文件
- `write` - 写入文件
- `edit` - 编辑文件
- `apply_patch` - 应用补丁 (OpenAI 模型专用)

#### 2. 执行工具 (Shell Tools)

- `exec` - 执行 shell 命令
- `process` - 管理后台进程 (查看/终止)

#### 3. 内置 OpenClaw 工具

- `session_*` - 会话管理工具
- `memory` - 记忆管理
- `cron` - 定时任务
- `browser` - 浏览器控制 (如果启用)
- `message` - 消息发送工具 (用于多渠道)
- `camera` - 摄像头功能
- 等等 (详见 `openclaw-tools.ts`)

#### 4. 插件工具 (Plugin Tools)

从配置的插件目录加载的自定义工具。

#### 5. 工具搜索控制 (Tool Search Controls)

当工具搜索启用时提供：
- `tool_search` - 工具搜索
- `tool_call_raw` - 原始工具调用
- `tool_describe_raw` - 工具描述

### 工具策略管道 (`Tool Policy Pipeline`)

为了安全和功能控制，工具经过复杂的策略管道处理：

1. **显式允许列表 (`Explicit Allowlist`)** - 全局/代理/提供者/会话级的工具白名单
2. **显式拒绝列表 (`Explicit Denylist`)** - 全局/代理/提供者/会话级的工具黑名单
3. **组级别策略 (`Group Policy`)** - 群组/频道/空间级别的工具策略
4. **发送者策略 (`Sender Policy`)** - 发送者权限控制
5. **沙箱策略 (`Sandbox Policy`)** - 沙箱环境的工具限制
6. **子代理策略 (`Subagent Policy`)** - 子代理继承的工具策略

```typescript
// 示意性流程
applyToolPolicyPipeline({
  steps: [
    profilePolicy,
    providerProfilePolicy,
    globalPolicy,
    agentPolicy,
    groupPolicy,
    senderPolicy,
    sandboxPolicy,
    subagentPolicy,
    inheritedPolicy,
  ]
})
```

## 三、会话管理系统

### 会话存储格式

OpenClaw 的会话存储是一个包含完整对话历史的 JSON 或 JSONL 文件，通常位于 `~/.openclaw/sessions/`。

### 会话管理器 (`Session Manager`)

会话管理器负责：
- 读写会话文件
- 应用更改
- 处理并发写入锁
- 保持一致性

```typescript
// 会话写入锁相关
acquireSessionWriteLock()
resolveSessionLockMaxHoldFromTimeout()
```

### 会话密钥 (`Session Key`)

会话密钥用于安全地标识和访问会话，格式示例：
- `agent:myagent:main` (主会话)
- `agent:myagent:sub-<uuid>` (子代理会话)
- `sandbox:agent:myagent:main` (沙箱会话)

## 四、子代理系统 (`Subagents`)

### 子代理特性

OpenClaw 支持创建子代理，它们有以下特性：
- 可以继承父代理的工具和策略
- 可以有自己的工作区
- 可以通过 `subagent_session` 工具创建
- 可以通过 `session_switch` 工具切换

### 子代理运行时

子代理的能力存储在：
- `subagentCapabilitiesStore`
- `resolveSubagentCapabilityStore`

## 五、沙箱模式 (`Sandbox Mode`)

### 沙箱安全措施

当沙箱启用时：
- 文件读写限制在沙箱目录内
- Shell 执行在容器内
- 工具访问受限
- 网络访问受限 (取决于配置)

### 沙箱上下文

```typescript
type SandboxContext = {
  enabled: boolean;
  workspaceDir: string;
  workspaceAccess: "ro" | "rw" | "none";
  fsBridge?: FileSystemBridge;
  containerWorkdir?: string;
  containerName?: string;
  backend?: SandboxBackend;
  docker?: DockerSandboxConfig;
};
```

## 六、上下文压缩机制 (`Compaction`)

### 上下文压缩时机

当会话大小超出模型的上下文窗口限制时触发压缩。

### 压缩策略

- 智能地总结旧的对话回合
- 保持关键信息不变
- 保留完整的工具调用记录
- 生成压缩报告

### 压缩钩子

有 `before_compaction` 和 `after_compaction` 钩子可以自定义压缩行为。

## 七、Bootstrap 文件系统

### 功能概述

Bootstrap 文件系统允许将相关上下文文件自动注入到每个运行的系统提示词中，使智能体能够立即了解相关项目信息。

### 配置示例

```json5
{
  "bootstrap": {
    "files": [
      "README.md",
      "package.json",
      "tsconfig.json"
    ],
    "autoDiscover": true,
    "autoDiscoverMaxFiles": 10
  }
}
```

## 八、技能系统 (`Skills`)

### 技能加载

技能可以从以下位置加载：
- 项目本地 `./skills/`
- 用户全局 `~/.openclaw/skills/`
- ClawHub (官方技能库)

### 技能执行流程

1. 解析技能定义 (skill.yml 或 skill.json)
2. 加载技能的工具和提示词
3. 将技能工具注入到工具列表
4. 在系统提示词中添加技能引导

## 九、模型和提供者系统

### 模型发现

`resolveModelAsync` 函数负责模型发现和解析，流程：

1. 检查插件覆盖 (`plugin harness`)
2. 尝试动态发现 (`model discovery`)
3. 加载 `~/.openclaw/models.json` 配置
4. 应用配置覆盖

### 提供者认证

支持多种认证模式：
- API keys
- OAuth (支持刷新)
- 环境变量
- 密码存储 (系统 keyring)

## 十、错误处理和重试机制

### 重试策略

OpenClaw 具有多层次的重试机制：
1. 同模型重试 (`same model retry`)
2. 模型降级/升级 (`model fallback`)
3. 认证配置轮换 (`auth profile rotation`)
4. 错误类型分类处理

### 常见错误类型和处理

| 错误类型 | 处理策略 |
|----------|----------|
| Context Overflow | 触发上下文压缩 |
| Auth Failure | 尝试其他认证配置 |
| Rate Limit | 应用退避策略或降级 |
| Timeout | 扩展超时或重试 |

## 十一、关键设计模式

### 懒加载工具 (`Lazy Tools`)

`exec` 和 `process` 工具使用懒加载 (`createLazyExecTool`, `createLazyProcessTool`) 避免在不需要时加载大型依赖。

### 策略模式 (`Policy Pattern`)

工具权限使用多级策略模式，从全局到会话级逐步限制。

### 观察者模式 (`Observer Pattern`)

工具执行、会话更新、事件发送都支持钩子系统，允许插件监听和修改行为。

### 重试模式 (`Retry Pattern`)

内置多层重试机制，包括认证、模型降级、超时处理。
