# OpenClaw 面试题

> 来源：[面试官：简历写着用过 OpenClaw，那这些题你能答上来吗？](https://mp.weixin.qq.com/s/1RkWpmZBT11sXJYtv93NHA)

OpenClaw 是当下最火的开源个人 AI 助手（GitHub Star 霸榜第一），各大互联网大厂连夜跟进推出自家版本，面试官已经开始拿 OpenClaw 拷打候选人。本文整理了 9 道高频面试题。

## 1、什么是 OpenClaw？

大语言模型本质是一个「无状态」的对话系统，你给它什么上下文，它就在这个上下文里回答你，一旦对话结束，什么都不会留下来。

**OpenClaw 要解决的正是这个问题。**

用一句话概括：**OpenClaw 是一个可以 7×24 小时运行在你个人设备上的自主 AI Agent，能接管你的电脑帮你干活。**

大语言模型就像一个「有超级大脑但没有身体的人」——思维敏锐，什么都懂，但没有手、没有脚、没有眼睛、也没有记忆，唯一能做的就是「说话」。

OpenClaw 做的事情，就是给这个大脑配上一副完整的「身体」：有手脚去操作电脑和设备，有记忆去记住偏好和历史，有眼睛去感知周围的环境，有通讯工具去接入日常用的各种消息平台。

### OpenClaw 的架构组件

| 组件 | 类比 | 职责 |
|------|------|------|
| Gateway（网关） | 大楼的门卫加总机 | 身份鉴权、会话状态管理、请求路由 |
| Agent（智能体） | 大脑 + 调度中心 | 调用大模型、拆解执行计划、协调模块、跟踪进度 |
| Tools & Skills（工具和技能） | 万能工具箱 | Tools 是单件工具（开文件、发邮件），Skills 是串起来的完整流程（整理周报） |
| Channels（通道） | 万能翻译官 | 把各平台消息转成 AI 能懂的统一格式，保持连线不断开 |
| Nodes（节点） | 传感器终端 | 运行在各类设备上的小节点，提供摄像头、地理位置、屏幕渲染等本地能力 |

## 2、OpenClaw 核心亮点是什么？

### 亮点一：多平台一键打通

通过网关组件直接连飞书、钉钉、微信等通讯软件。手机发条语音，远在家里的 OpenClaw 就会立刻接收指令干活。

### 亮点二：啥都能干权限超大

配合底层终端节点，权限比市面上任何智能体都高：直接操作文件、运行命令行、控制浏览器、操作桌面应用。

### 亮点三：技能生态超庞大

一句话装上新插件，不用复杂配置。装上对应技能包，瞬间掌握读写邮件或查阅全网资讯的能力。

### 亮点四：7×24 小时主动干活

每 30 分钟自动跑一次心跳文档，主动自检、主动做事，还支持自定义定时任务。

### 亮点五：自我净化越用越稳

当告诉它某个操作出错了，它不仅会调整方案重试，还会启动反思环节，把失败原因、正确逻辑、需要规避的问题总结成可复用的避坑经验，写入本地长期记忆文件。

### 亮点六：真正的永久记忆

记忆不是依赖临时上下文，而是以文件总结的形式存在本地。每当系统发现聊天内容有价值，就会主动提炼核心事实写进本地文件。

## 3、OpenClaw 文件目录结构是怎样的？

OpenClaw 的智能体本质上就是一个普通的文件夹：

```
openclaw-workspace/
├── SOUL.md          # 灵魂与人设
├── AGENTS.md        # 员工操作手册
├── TOOLS.md         # 武器库
├── HEARTBEAT.md     # 日常巡检大纲
├── MEMORY.md        # 长期记忆
└── sessions/
    ├── 2026-03-23.md  # 短期对话流水账
    └── 2026-03-24.md
```

### SOUL.md — 灵魂与人设

定义智能体的价值观、语气甚至幽默感。官方模板核心准则：

- **真帮忙，不表演**：跳过废话，直接帮
- **要有观点**：没有个性的助手只是多绕几步的搜索引擎
- **先想办法，再提问**：先自己搞清楚，卡住时再问
- **用能力赢得信任**：对外部动作谨慎，对内部动作果断
- **记住你是客人**：你接触的是别人的生活，务必尊重

### AGENTS.md — 员工操作手册

决定它怎么做事的标准化流程，如代码规范、系统运维规范等。

### TOOLS.md — 武器库

注册当前智能体可以使用的所有本地工具和技能生态。

### HEARTBEAT.md — 日常巡检大纲

实现 7×24 小时主动干活的核心，每次心跳时间一到，系统优先读取里面的任务清单。

### MEMORY.md + sessions/ — 大脑记忆区

MEMORY.md 存放提炼后的长期记忆和事实偏好，sessions 文件夹按天存放短期对话流水账。

**文件即 Agent**：想分享一个调教好的智能体，直接把文件夹打包发过去就行。

## 4、OpenClaw 与传统 Agent 有什么区别？

| 区别点 | 传统 Agent | OpenClaw |
|--------|-----------|---------|
| 运行模式 | 被动响应（拨一下动一下） | 主动值守（心跳机制，全天候无人值守） |
| 权限边界 | 云端沙盒（碰不到本地文件） | 本地直连（系统级最高读写权限） |
| 记忆机制 | 云端黑盒（跨会话易失忆） | 本地透明（纯文本 Markdown，全可控） |
| 产品定位 | 单一工具（特定场景） | 通用基建（大模型随你切换，能力无限扩展） |

## 5、OpenClaw 的记忆机制是怎么实现的？

OpenClaw 放弃了重型的外部向量数据库，使用**纯文本 Markdown 文件 + 轻量级 SQLite** 的混合记忆流。

### 短期记忆

存放在 `sessions/` 目录下按天生成的日志文件。系统启动时只把最近一两天的日志加载到提示词里，保证短期对话连贯性又不浪费资源。

### 长期记忆

当聊天记录越来越长，快要触发上下文压缩时，系统会在后台偷偷拦截，强制大模型做阅读理解，把最重要的信息提炼出来写入 MEMORY.md。

### SQLite 向量索引

当 MEMORY.md 变得庞大时，OpenClaw 在底层内嵌了带有向量搜索扩展的 SQLite 数据库：

1. 新增文本切分成小块，转换成向量存进 SQLite
2. 下次聊相关话题时，当前问题也转换成向量
3. 在 SQLite 里做**向量相似度比对 + BM25 关键词匹配**的双路召回
4. 精准捞出最相关的几句话，塞回给大模型

**底层复杂的数据检索交给 SQLite，人类可读的数据留在纯文本文件里。** 记错了直接用记事本打开 MEMORY.md 删掉那行即可——大道至简。

## 6、OpenClaw 到底解决了什么痛点？

### 痛点一：云端智能体无法落地执行的割裂感

以前大模型写完代码，还得自己复制到本地运行，报错了再贴回去。OpenClaw 直接把大脑装在电脑里，写完代码自己运行测试，遇到 Bug 自己修复，真正完成最后一公里闭环。

### 痛点二：长期使用的失忆问题

每次新建对话都得重新调教。OpenClaw 把偏好永久刻在本地硬盘上，越用越懂你。

### 痛点三：工具切换的繁琐体验

通过网关把 AI 直接塞进即时通讯软件，在聊天框发条语音就能指挥它干活。

## 7、OpenClaw 有什么缺点？

### 缺点一：安全风险极高

权限拉满是一把双刃剑。一旦底层大模型产生幻觉或遭遇提示词注入攻击，后果不堪设想。生产环境必须极其谨慎地设置沙箱隔离和工具使用边界。

### 缺点二：极其烧 Token 导致成本飙升

四个核心原因：

1. **心跳保活机制**：每半小时唤醒一次，每次都要把人物设定、操作规范、工具清单全部组装成巨大提示词
2. **自主反思与试错闭环**：报错后读日志、分析、修复、重试，循环往复累积上下文
3. **永久记忆机制**：后台偷偷拉起总结任务，把上万字文本交给大模型压缩
4. **全透明文件配置**：灵魂文件、操作手册、工具清单每次都必须全文带上

### 缺点三：对设备在线状态的强依赖

装在笔记本上，合上电脑心跳就失效。想要完美发挥全天候值守能力，通常需要专门配备一台永远不关机的设备。

## 8、Coze、n8n 和 OpenClaw 的区别在哪里？

| 工具 | 类比 | 特点 | 局限 |
|------|------|------|------|
| Coze | 云端的精装修商铺 | 图形化界面，拖拽快速捏出智能客服，一键发布 | 数据和权限全在云端，摸不到本地代码 |
| n8n | 极其严谨的工厂流水线 | 基于触发器和条件判断，确定性极强 | 没有自主思考能力，不按预设条件就报错罢工 |
| OpenClaw | 拥有自主意识的本地操作系统 | 懂得灵活变通，模糊指令也能自主思考 + 本地最高权限 | 安全风险高、烧 Token、依赖设备在线 |

## 9、为什么 OpenClaw 那么烧 Token？

Token 是大模型的「计费单位」，1 个 token 差不多就是半个汉字。

### 四个核心原因

**原因一：心跳保活机制**

传统交互是你问一句它答一句，不发消息就不消耗资源。OpenClaw 每半小时唤醒一次，一天 48 次。每次唤醒都要把人物设定、操作规范、工具清单、心跳任务大纲全部组装成巨大提示词发给大模型。

**原因二：自主反思与试错闭环**

传统大模型输出文本就完事了。OpenClaw 是行动派，要真刀真枪执行。报错后读日志、分析、修复、重试，循环往复不断累积上下文。遇到难搞的依赖问题，可能后台不声不响尝试几十次。

**原因三：永久记忆机制**

当短期对话日志快触碰上下文极限时，系统后台拉起独立总结任务，强制大模型阅读海量聊天记录并提炼核心事实。后续对话又频繁把召回的历史记忆塞回提示词，每次对话底座都很厚重。

**原因四：全透明文件配置的基础包袱**

灵魂文件、员工操作手册、工具清单——这套沉重的包袱每次处理任务时都必须全文带上。基础系统提示词越长，单次交互成本越高。
