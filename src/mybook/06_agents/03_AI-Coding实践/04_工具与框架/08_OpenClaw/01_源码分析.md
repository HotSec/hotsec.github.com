# OpenClaw 源码分析

> 来源：[万字拆解OpenClaw源码！十大步骤+四个反共识，看完直接吃透](http://m.toutiao.com/group/7615570013772939785/)

OpenClaw 是当下最火的开源个人 AI 助手（GitHub 10万+ Star），其核心架构不是"套壳 AI"，而是完整的 Agent 操作系统。本文基于 2026 年最新稳定版源码，深度拆解其核心执行流程与架构设计。

---

## 一、OpenClaw 源码十大核心步骤

### 步骤1：配置加载与环境自检

启动第一件事不是"聊天"，而是读配置：

- 加载 model、device、prompt 模板
- 检查插件是否损坏
- 确认 Memory、Skills 路径是否存在
- 做权限与环境变量校验

启动报错 90% 死在这一步。

### 步骤2：插件系统初始化

插件安装、排序、依赖检查。关键点：

- **Memory 不是后加载，而是第二顺位就启动**
- Skills 系统会提前做语法树解析
- Tool 工具做签名与白名单校验

反常识：**插件不是"用到才加载"，是启动就全加载**，保证运行时不卡。

### 步骤3：Agent 核心对象创建

智能体本体诞生：

- 绑定 LLM
- 绑定记忆实例
- 绑定技能池
- 绑定状态机

AI 的"大脑"在这里被组装完成。

### 步骤4：历史对话重建

Memory 真正发挥作用的地方：

- 不是简单拼接聊天记录
- Memory 会做**摘要、关键词提取、向量检索**
- 只把关键信息喂给模型，而不是全量塞

正确配置 Memory 能省 50% Token。

### 步骤5：用户意图解析

收到问题后不会直接回答：

- **分类**：聊天 / 任务 / 工具调用 / 技能执行
- **提取**：槽位信息、约束、目标
- **判断**：是否需要多轮、是否需要查记忆、是否要跑技能

这一步决定了后面所有行为。

### 步骤6：技能匹配与路由

OpenClaw 最值钱的模块：

- 根据意图自动匹配 Skills
- 做参数校验
- 决定：直接执行 / 追问补全 / 拒绝执行

### 步骤7：工具调用决策

如果判断需要工具：

- 选择可用工具
- 构造参数
- 调用外部能力（搜索、文件、浏览器、API）
- 拿回结果做结构化整理

源码里有非常严格的安全沙箱。

### 步骤8：多轮思考循环（Think Loop）

真正的智能在这里：

- **思考**：结果够不够？
- **判断**：要不要继续调用工具？
- **记忆**：把中间结果写入短期记忆
- **循环**直到任务完成或达到最大步数

不是一次回答，是一整段推理链。

### 步骤9：结果生成与格式美化

LLM 生成内容后还会经过：

- 格式清洗
- 排版优化
- 代码高亮
- 超长内容分段

### 步骤10：记忆持久化 & 任务归档

- 把关键对话写入长期记忆
- 生成任务总结
- 记录技能调用日志
- 清理临时状态

重启后依然记得你。

## 二、四个反共识真相

### 反共识1：Memory 不是"上下文加长"，而是"知识检索系统"

| 维度 | 错误理解 | 源码真相 |
|------|---------|---------|
| 本质 | 把历史聊天记录拉得更长 | 向量数据库 + 摘要系统 + 遗忘机制 |
| 效果 | 越用越卡 | 越用越快（主动忘掉废话，只存关键信息） |

### 反共识2：Skills 不是"提示词模板"，而是"微型程序"

| 维度 | 错误理解 | 源码真相 |
|------|---------|---------|
| 本质 | 一段固定提示词 | 带参数、校验、流程、返回值的可执行单元 |
| 能力 | 静态文本 | 条件判断、循环、多步骤、调用其他技能 |
| 类比 | 提示词收藏夹 | 低代码智能体脚本 |

### 反共识3：OpenClaw 不是"套壳AI"，而是完整的"Agent 操作系统"

| 维度 | 错误理解 | 源码真相 |
|------|---------|---------|
| 本质 | 包装了一层 LLM | 调度系统 + 插件系统 + 记忆系统 + 技能系统 + 工具系统 + 安全系统 |
| LLM 角色 | 全部 | 只是"CPU"，不是全部 |

### 反共识4：越复杂的任务，越不应该靠"加长提示词"

| 维度 | 错误理解 | 源码真相 |
|------|---------|---------|
| 复杂任务 | 提示词写得越长越厉害 | 复杂任务 = 拆步骤 = 用 Skills |
| 记信息 | 全塞进提示词 | 用 Memory |
| 提示词职责 | 规则 + 流程 | 只负责"规则"，不负责"流程" |

**高手都是提示词极简 + 技能极复杂。**

## 三、OpenClaw 核心架构

### 3.1 架构全景

```
┌─────────────────────────────────────────────┐
│                  用户输入                      │
├─────────────────────────────────────────────┤
│              意图解析 & 路由                   │
├──────────┬──────────┬──────────┬────────────┤
│  Memory  │  Skills  │  Tools   │  安全沙箱   │
│ 知识检索  │ 微型程序  │ 外部能力  │  权限校验   │
├──────────┴──────────┴──────────┴────────────┤
│            Think Loop（多轮思考循环）           │
├─────────────────────────────────────────────┤
│              LLM（"CPU"）                     │
├─────────────────────────────────────────────┤
│          记忆持久化 & 任务归档                  │
└─────────────────────────────────────────────┘
```

### 3.2 Memory 系统

- **向量数据库**：存储语义化记忆
- **摘要系统**：自动压缩冗余信息
- **遗忘机制**：主动丢弃废话，只保留关键信息
- **检索策略**：关键词提取 + 向量检索，只喂关键信息给模型

### 3.3 Skills 系统

Skills 是带参数、校验、流程、返回值的可执行单元：

- 支持：条件判断、循环、多步骤、调用其他技能
- 本质：低代码智能体脚本
- 加载：启动时全加载，运行时按需匹配路由

### 3.4 Tool 工具系统

- 选择可用工具
- 构造参数
- 调用外部能力（搜索、文件、浏览器、API）
- 安全沙箱：严格的安全验证

### 3.5 Think Loop

多轮思考循环是 OpenClaw 智能的核心：

1. 思考：结果够不够？
2. 判断：要不要继续调用工具？
3. 记忆：把中间结果写入短期记忆
4. 循环直到任务完成或达到最大步数

## 五、核心洞察

**OpenClaw 强，不是强在模型，是强在架构。**

懂源码的人能做到：

- 只加载需要的插件，速度提升 2~3 倍
- 精准控制记忆，Token 省 50%+
- 自己写 Skills，把重复工作全自动跑
- 私有化部署，完全本地运行，不泄露数据
- 排查问题 1 分钟定位，不用瞎试

AI 时代，真正的壁垒是"理解底层"。OpenClaw 不只是一个工具，它是现代 AI 智能体的标准教科书。把它的源码吃透，等于看懂了未来 3 年所有智能体的架构。
