# K8s 持久化存储

## 1. Volume 基础

### 1.1 临时 Volume

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: emptydir-pod
spec:
  containers:
  - name: writer
    image: busybox
    command: ["/bin/sh", "-c", "echo hello > /data/hello"]
    volumeMounts:
    - name: shared-data
      mountPath: /data
  - name: reader
    image: busybox
    command: ["/bin/sh", "-c", "cat /data/hello"]
    volumeMounts:
    - name: shared-data
      mountPath: /data
  volumes:
  - name: shared-data
    emptyDir: {}
```

### 1.2 常用 Volume 类型

| 类型 | 用途 | 持久性 |
|------|------|--------|
| emptyDir | Pod 内容器共享 | 随 Pod 删除 |
| hostPath | 节点本地路径 | 节点级持久 |
| nfs | NFS 网络存储 | 持久 |
| configMap | 配置文件 | 随 ConfigMap |
| secret | 敏感数据 | 随 Secret |
| persistentVolumeClaim | 持久化存储 | 持久 |

## 2. PV 与 PVC

### 2.1 生命周期

```
Provisioning → Binding → Using → Reclaiming
```

### 2.2 PV（PersistentVolume）

```yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: nfs-pv
spec:
  capacity:
    storage: 10Gi
  accessModes:
  - ReadWriteMany
  persistentVolumeReclaimPolicy: Retain
  storageClassName: nfs
  nfs:
    server: 192.168.1.100
    path: /data/share
```

**访问模式**：

| 模式 | 缩写 | 说明 |
|------|------|------|
| ReadWriteOnce | RWO | 单节点读写 |
| ReadOnlyMany | ROX | 多节点只读 |
| ReadWriteMany | RWX | 多节点读写 |
| ReadWriteOncePod | RWOP | 单 Pod 读写（K8s 1.27+） |

**回收策略**：

| 策略 | 说明 |
|------|------|
| Retain | 保留数据，需手动清理 |
| Delete | 删除 PV 和底层存储 |
| Recycle | 已弃用，用动态供给替代 |

### 2.3 PVC（PersistentVolumeClaim）

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-pvc
spec:
  accessModes:
  - ReadWriteOnce
  resources:
    requests:
      storage: 5Gi
  storageClassName: nfs
```

### 2.4 Pod 使用 PVC

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: app-pod
spec:
  containers:
  - name: app
    image: nginx
    volumeMounts:
    - name: data
      mountPath: /usr/share/nginx/html
  volumes:
  - name: data
    persistentVolumeClaim:
      claimName: my-pvc
```

## 3. StorageClass

### 3.1 动态供给

```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: local-storage
provisioner: kubernetes.io/no-provisioner
reclaimPolicy: Delete
volumeBindingMode: WaitForFirstConsumer
```

```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: nfs-client
provisioner: nfs.csi.k8s.io
parameters:
  server: 192.168.1.100
  share: /data/nfs
reclaimPolicy: Delete
volumeBindingMode: Immediate
allowVolumeExpansion: true
```

### 3.2 默认 StorageClass

```bash
kubectl annotate storageclass local-storage \
  storageclass.kubernetes.io/is-default-class=true
```

### 3.3 卷扩展

```yaml
# StorageClass 需设置 allowVolumeExpansion: true
# 扩展 PVC
spec:
  resources:
    requests:
      storage: 20Gi  # 从 10Gi 扩展到 20Gi
```

## 4. CSI（Container Storage Interface）

### 4.1 架构

```
K8s Controller → CSI Controller（Provisioner/Attacher/Resizer）
K8s kubelet   → CSI Node Plugin（Stage/Unstage/Publish/Unpublish）
```

### 4.2 常用 CSI 驱动

| CSI 驱动 | 存储类型 | 说明 |
|----------|----------|------|
| csi-driver-nfs | NFS | 通用 NFS 存储 |
| csi-hostpath | 本地 | 测试用 |
| rook-ceph | Ceph | 分布式存储 |
| csi-aws-ebs | AWS EBS | AWS 云盘 |
| csi-azure-disk | Azure Disk | Azure 云盘 |
| csi-alibaba-cloud | 阿里云云盘 | 阿里云 |
| longhorn | Longhorn | 分布式块存储 |
| local-path-provisioner | 本地 | 本地路径供给 |

## 5. StatefulSet + PVC

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: mysql
spec:
  serviceName: mysql
  replicas: 3
  selector:
    matchLabels:
      app: mysql
  template:
    metadata:
      labels:
        app: mysql
    spec:
      containers:
      - name: mysql
        image: mysql:8.0
        env:
        - name: MYSQL_ROOT_PASSWORD
          value: "password"
        volumeMounts:
        - name: mysql-data
          mountPath: /var/lib/mysql
  volumeClaimTemplates:
  - metadata:
      name: mysql-data
    spec:
      accessModes: ["ReadWriteOnce"]
      storageClassName: local-storage
      resources:
        requests:
          storage: 10Gi
```

每个 Pod 自动创建 `mysql-data-mysql-0/1/2` 的 PVC。

## 6. 常见存储方案

### 6.1 本地存储

```yaml
# local-path-provisioner
apiVersion: storage.k8s.io/v1
kind: StorageClass

  name: local-path

```

```bash

  --namespace kube-system
```

```bash
helm repo add rook-release https://charts.rook.io/release
helm install rook-ceph rook-release/rook-ceph --namespace rook-ceph --create-namespace
helm install rook-ceph-cluster rook-release/rook-ceph-cluster --namespace rook-ceph
```

### 6.4 Longhorn

```bash
helm repo add longhorn https://charts.longhorn.io
helm install longhorn longhorn/longhorn --namespace longhorn-system --create-namespace
```

## 7. 面试题

### 1. PV 和 PVC 的关系？

PV 是集群级资源（管理员创建），PVC 是命名空间级资源（用户创建）。PVC 通过容量、访问模式、StorageClass 匹配 PV，一对一绑定。

### 2. 动态供给和静态供给的区别？

- 静态供给：管理员预先创建 PV，PVC 手动绑定
- 动态供给：PVC 创建时 StorageClass 自动创建 PV 并绑定

### 3. WaitForFirstConsumer 的作用？

延迟 PV 绑定，直到 Pod 被调度到具体 Node 后才绑定。避免 PVC 绑定到与 Pod 不在同一节点的 PV，常用于本地存储场景。
