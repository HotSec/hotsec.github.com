# 网络基础

## 网络模型

### OSI 七层模型

| 层 | 名称 | 功能 | 协议/设备 |
|---|------|------|-----------|
| 7 | 应用层 | 用户接口 | HTTP, FTP, DNS, SMTP |
| 6 | 表示层 | 数据格式/加密 | SSL/TLS, JPEG |
| 5 | 会话层 | 会话管理 | RPC, NetBIOS |
| 4 | 传输层 | 端到端通信 | TCP, UDP |
| 3 | 网络层 | 路由寻址 | IP, ICMP, 路由器 |
| 2 | 数据链路层 | 帧传输 | Ethernet, 交换机 |
| 1 | 物理层 | 比特传输 | 光纤, 网线 |

### TCP/IP 四层模型

| 层 | 对应 OSI | 协议 |
|---|---------|------|
| 应用层 | 5-7 | HTTP, DNS, SSH |
| 传输层 | 4 | TCP, UDP |
| 网络层 | 3 | IP, ICMP |
| 网络接口层 | 1-2 | Ethernet, WiFi |

## TCP 协议

### 三次握手

```
Client                    Server
  |---- SYN (seq=x) ------->|
  |<-- SYN+ACK (seq=y,ack=x+1) --|
  |---- ACK (ack=y+1) ----->|
```

### 四次挥手

```
Client                    Server
  |---- FIN (seq=u) ------->|     Client 请求关闭
  |<---- ACK (ack=u+1) -----|     Server 确认
  |<---- FIN (seq=w) -------|     Server 请求关闭
  |---- ACK (ack=w+1) ----->|     Client 确认
  |     TIME_WAIT (2MSL)    |
```

### TCP 状态机

| 状态 | 描述 |
|------|------|
| LISTEN | 等待连接 |
| SYN_SENT | 发送 SYN 后等待 |
| SYN_RCVD | 收到 SYN 后发送 SYN+ACK |
| ESTABLISHED | 连接建立 |
| FIN_WAIT_1 | 发送 FIN 后等待 ACK |
| FIN_WAIT_2 | 收到 FIN 的 ACK，等待对方 FIN |
| CLOSE_WAIT | 收到 FIN，等待本端关闭 |
| LAST_ACK | 发送 FIN 后等待最终 ACK |
| TIME_WAIT | 等待 2MSL 后关闭 |

### 拥塞控制

- **慢启动**：cwnd 从 1 开始指数增长
- **拥塞避免**：cwnd 线性增长
- **快重传**：收到 3 个重复 ACK 立即重传
- **快恢复**：cwnd 减半而非回到 1

## 负载均衡

### 四层负载均衡 (L4)

基于 IP + 端口转发，不解析应用层内容。

```
Client → L4 LB → Backend1 (IP:Port)
                → Backend2 (IP:Port)
                → Backend3 (IP:Port)
```

常用软件：LVS、HAProxy (TCP mode)、iptables

### 七层负载均衡 (L7)

基于 HTTP 头/URL/Cookie 等应用层信息转发。

```
Client → L7 LB → /api/* → API Servers
                → /web/* → Web Servers
                → /img/* → CDN Origin
```

常用软件：Nginx、HAProxy (HTTP mode)、Envoy

### 调度算法

| 算法 | 描述 |
|------|------|
| Round Robin | 轮询 |
| Weighted RR | 加权轮询 |
| Least Connections | 最少连接数 |
| Source Hash | 源地址哈希 |
| IP Hash | IP 哈希（会话保持） |
| Random | 随机 |
| Consistent Hash | 一致性哈希 |

### Nginx 负载均衡

```nginx
upstream backend {
    least_conn;
    server 10.0.0.1:8080 weight=3;
    server 10.0.0.2:8080 weight=2;
    server 10.0.0.3:8080 backup;

    keepalive 32;
}

server {
    listen 80;

    location /api/ {
        proxy_pass http://backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_connect_timeout 5s;
        proxy_read_timeout 30s;
        proxy_send_timeout 30s;

        proxy_next_upstream error timeout http_502 http_503;
    }
}
```

### 健康检查

```nginx
upstream backend {
    server 10.0.0.1:8080 max_fails=3 fail_timeout=30s;
    server 10.0.0.2:8080 max_fails=3 fail_timeout=30s;
}
```

## OVS/OVN

### Open vSwitch

OVS 是生产级虚拟交换机，支持 VLAN、VxLAN、OpenFlow 等。

```bash
ovs-vsctl add-br br-int
ovs-vsctl add-port br-int vnet0
ovs-vsctl set port vnet0 tag=100

ovs-vsctl add-br br-tun
ovs-vsctl add-port br-tun vxlan0 \
    -- set interface vxlan0 type=vxlan \
    options:remote_ip=10.0.0.2 \
    options:key=flow

ovs-ofctl dump-flows br-int
ovs-vsctl show
```

### OVN

OVN 是基于 OVS 的网络虚拟化解决方案。

```
OVN Architecture:
┌─────────────────────────────────────┐
│           OVN Northbound DB         │  逻辑交换机/路由器定义
├─────────────────────────────────────┤
│           ovn-northd                │  逻辑→物理转换
├─────────────────────────────────────┤
│           OVN Southbound DB         │  物理流表
├──────────┬──────────────────────────┤
│ ovn-controller  │  ovn-controller   │  各节点本地控制
│ (Node A)        │  (Node B)         │
├──────────┬──────────────────────────┤
│   OVS    │        OVS              │  数据面
└──────────┴──────────────────────────┘
```

## DNS

### 记录类型

| 类型 | 描述 | 示例 |
|------|------|------|
| A | IPv4 地址 | `example.com. A 1.2.3.4` |
| AAAA | IPv6 地址 | `example.com. AAAA ::1` |
| CNAME | 别名 | `www CNAME example.com` |
| MX | 邮件 | `example.com. MX 10 mail.example.com` |
| NS | 名称服务器 | `example.com. NS ns1.example.com` |
| TXT | 文本 | `example.com. TXT "v=spf1 include:..."` |
| SRV | 服务 | `_http._tcp SRV 10 5 80 target.example.com` |

### 解析流程

```
浏览器缓存 → OS 缓存 → 本地 DNS → 根 DNS → 顶级域 DNS → 权威 DNS
```

### dig 命令

```bash
dig example.com
dig example.com A
dig example.com AAAA
dig example.com CNAME
dig example.com +short
dig example.com +trace
dig @8.8.8.8 example.com
dig -x 1.2.3.4
```

## CDN

### 工作原理

```
用户请求 → DNS 解析 → CDN 调度 → 最近边缘节点
                                    ↓ (缓存命中)
                                  返回内容
                                    ↓ (缓存未命中)
                                  回源站 → 缓存 → 返回
```

### 缓存策略

| 策略 | 适用场景 |
|------|----------|
| 强缓存 (max-age) | 静态资源（JS/CSS/图片） |
| 协商缓存 (ETag) | 频繁更新的内容 |
| 不缓存 (no-store) | 敏感数据 |
| 短缓存 + 异步刷新 | HTML 页面 |

### 关键指标

| 指标 | 目标 |
|------|------|
| 命中率 | > 95% |
| 首字节时间 | < 50ms |
| 下载速度 | > 10MB/s |
| 可用性 | > 99.9% |
