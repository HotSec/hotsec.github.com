# Go 运行时概览

> 主要参考：《Go语言高级编程（第2版）》第4章 — 柴树杉、曹春晖 著

Go 运行时（runtime）是 Go 语言的核心组件，负责管理程序执行过程中的各种底层操作。它实现了调度器、内存分配器、垃圾收集器和网络轮询器等关键功能，使 Go 语言具备了原生并发、自动内存管理和高效网络处理的能力。

---

## 一、运行时架构

### 1.1 运行时的组成

Go 运行时主要由以下四个核心组件构成：

```
┌─────────────────────────────────────────────────────────────┐
│                      Go Runtime                              │
├──────────────┬──────────────┬──────────────┬────────────────┤
│   Scheduler  │   Allocator  │      GC      │   Netpoller    │
│    调度器     │   内存分配器  │   垃圾收集器  │   网络轮询器    │
└──────────────┴──────────────┴──────────────┴────────────────┘
```

| 组件 | 职责 | 关键数据结构 |
|------|------|-------------|
| **调度器** | Goroutine 调度、M/P/G 管理 | g、m、p、schedt |
| **内存分配器** | 对象内存分配、内存管理 | mcache、mcentral、mheap、mspan |
| **垃圾收集器** | 自动内存回收、内存整理 | gcWork、gcBgMarkWorker、markBits |
| **网络轮询器** | 异步 I/O、文件/网络事件 | pollDesc、pollCache、epoll/kqueue |

### 1.2 运行时与用户代码的关系

```go
package main

import (
    "fmt"
    "runtime"
)

func main() {
    fmt.Printf("GOMAXPROCS: %d\n", runtime.GOMAXPROCS(0))
    fmt.Printf("NumCPU: %d\n", runtime.NumCPU())
    fmt.Printf("NumGoroutine: %d\n", runtime.NumGoroutine())
    fmt.Printf("Version: %s\n", runtime.Version())
}
```

运行时通过以下方式与用户代码交互：
- **隐式调用**：go 关键字创建 goroutine、内存分配、channel 操作等
- **显式调用**：runtime 包提供的 API（GOMAXPROCS、GC、NumGoroutine 等）
- **信号处理**：SIGURG 用于抢占式调度、SIGPIPE 处理等

### 1.3 运行时启动流程

Go 程序的启动流程（简化版）：

```
_rt0_amd64_linux
    └── runtime·rt0_go
        └── runtime·schedinit          // 初始化调度器
            ├── runtime·mallocinit     // 初始化内存分配器
            ├── runtime·gcinit         // 初始化 GC
            ├── runtime·schedinit      // 初始化调度器
            └── runtime·newproc        // 创建 main goroutine
                └── runtime·mstart     // 启动 M 执行
                    └── main.main      // 用户代码入口
```

关键初始化步骤：
1. **args 初始化**：命令行参数、环境变量
2. **os 初始化**：操作系统相关设置
3. **sched 初始化**：调度器初始化（创建 P、M 等）
4. **malloc 初始化**：内存分配器初始化
5. **gc 初始化**：垃圾收集器初始化
6. **创建 main goroutine**：执行用户的 main 函数

## 二、调度器（Scheduler）

### 2.1 GMP 模型

调度器采用 GMP 模型：

```
┌─────────────────────────────────────────────────────────────┐
│                      Sched (全局调度器)                       │
│  ┌─────────────────────────────────────────────────────┐   │
│  │                    Global Run Queue                   │   │
│  │    G1 → G2 → G3 → G4 → G5 → ...                     │   │
│  └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
         ↓ steal                    ↓ steal
┌─────────────┐           ┌─────────────┐           ┌─────────────┐
│      P0     │           │      P1     │           │      P2     │
│  Local RunQ │           │  Local RunQ │           │  Local RunQ │
│  G1→G2→G3   │           │  G4→G5      │           │  G6→G7→G8   │
├─────────────┤           ├─────────────┤           ├─────────────┤
│      M0     │           │      M1     │           │      M2     │
│  (OS Thread)│           │  (OS Thread)│           │  (OS Thread)│
└─────────────┘           └─────────────┘           └─────────────┘
```

- **G (Goroutine)**：轻量级线程，包含栈、指令指针等信息
- **M (Machine)**：操作系统线程，执行 G
- **P (Processor)**：逻辑处理器，持有本地运行队列和资源

### 2.2 调度策略

```go
// 调度策略核心逻辑（简化版）
func schedule() {
    // 1. 检查是否需要 GC
    if gcwaiting {
        gcstopm()
        return
    }
    
    // 2. 尝试从本地队列获取 G
    gp := runqget(_p_)
    
    // 3. 本地队列空，从全局队列获取
    if gp == nil {
        gp = globrunqget(_p_, 0)
    }
    
    // 4. 从网络轮询器获取
    if gp == nil {
        gp = netpoll(false)
    }
    
    // 5. 工作窃取
    if gp == nil {
        gp = stealWork()
    }
    
    execute(gp)
}
```

调度策略优先级：
1. 本地运行队列（P 的本地队列）
2. 全局运行队列
3. 网络轮询器（就绪的 goroutine）
4. 工作窃取（从其他 P 窃取）

### 2.3 抢占式调度

Go 1.14+ 实现了基于信号的异步抢占：

```go
// 抢占信号处理
func sigurgHandler(sig uint32) {
    // 设置抢占标志
    gp := getg()
    gp.preempt = true
    
    // 在安全点触发调度
    if gp.stackguard0 == stackPreempt {
        gp.stackguard0 = stackPreempt
    }
}
```

抢占触发场景：
- **系统调用**：进入/退出系统调用时检查
- **函数调用**：栈增长时检查抢占标志
- **信号抢占**：SIGURG 信号触发异步抢占
- **GC 辅助**：GC 需要协助时抢占

## 三、内存分配器（Memory Allocator）

### 3.1 分配器架构

Go 内存分配器采用多级缓存设计：

```
                    ┌─────────────────┐
                    │     mheap       │  ← 堆内存管理
                    │   (heapArena)   │
                    └────────┬────────┘
                             │
         ┌───────────────────┼───────────────────┐
         │                   │                   │
    ┌────▼────┐         ┌────▼────┐         ┌────▼────┐
    │mcentral │         │mcentral │         │mcentral │  ← 中心缓存
    │ (span类)│         │ (span类)│         │ (span类)│
    └────┬────┘         └────┬────┘         └────┬────┘
         │                   │                   │
    ┌────▼────┐         ┌────▼────┐         ┌────▼────┐
    │ mcache  │         │ mcache  │         │ mcache  │  ← 本地缓存
    │  (P0)   │         │  (P1)   │         │  (P2)   │
    └─────────┘         └─────────┘         └─────────┘
```

### 3.2 对象大小分类

| 大小类别 | 范围 | 分配路径 |
|---------|------|---------|
| **微对象** | < 16B | 微分配器（tiny allocator） |
| **小对象** | 16B ~ 32KB | mcache → mcentral → mheap |
| **大对象** | > 32KB | 直接从 mheap 分配 |

### 3.3 mspan 结构

```go
type mspan struct {
    next *mspan          // 链表下一个
    prev *mspan          // 链表前一个
    startAddr uintptr    // 起始地址
    npages    uintptr    // 页数
    nelems    uintptr    // 对象数量
    allocCount uint16    // 已分配数量
    spanclass   spanClass // 大小类别
    gcmarkBits  *gcBits  // GC 标记位图
    allocBits   *gcBits  // 分配位图
}
```

## 四、垃圾收集器（Garbage Collector）

### 4.1 GC 演进

| 版本 | GC 算法 | 特点 |
|------|---------|------|
| Go 1.0 | 标记-清除 | STW，暂停时间长 |
| Go 1.3 | 并发标记 | 减少标记阶段 STW |
| Go 1.5 | 三色并发标记 | 大幅减少 STW |
| Go 1.8 | 混合写屏障 | 删除栈扫描 STW |
| Go 1.19 | Pacer 优化 | 更平滑的 GC 触发 |
| Go 1.25+ | GreenTea GC | 实验性分代 GC |

### 4.2 三色标记算法

```
初始状态：
┌─────┐     ┌─────┐     ┌─────┐
│ 白  │ ──→ │ 白  │ ──→ │ 白  │
└─────┘     └─────┘     └─────┘

标记过程：
┌─────┐     ┌─────┐     ┌─────┐
│ 灰  │ ──→ │ 白  │ ──→ │ 白  │  ← 灰色对象引用的白色对象变灰
└─────┘     └─────┘     └─────┘
    │
    ▼
┌─────┐     ┌─────┐     ┌─────┐
│ 黑  │     │ 灰  │ ──→ │ 白  │  ← 灰色对象处理完变黑
└─────┘     └─────┘     └─────┘

最终状态：
┌─────┐     ┌─────┐     ┌─────┐
│ 黑  │     │ 黑  │     │ 白  │  ← 黑色存活，白色回收
└─────┘     └─────┘     └─────┘
```

三色不变式：
- **强三色不变式**：黑色对象不会直接指向白色对象
- **弱三色不变式**：所有被黑色对象引用的白色对象都处于灰色保护中

### 4.3 GC 阶段

```
┌─────────────────────────────────────────────────────────────┐
│                      GC 周期                                 │
├──────────┬──────────────────────┬───────────────────────────┤
│ 标记准备  │      并发标记         │        标记终止           │
│ (STW)    │   (Concurrent Mark)  │         (STW)             │
├──────────┼──────────────────────┼───────────────────────────┤
│ 设置控制 │ 扫描根对象           │ 关闭写屏障               │
│ 启动后台 │ 并发扫描堆对象       │ 刷新缓存                 │
│ 标记器   │ 写屏障记录指针更新   │ 统计统计                 │
│          │ 辅助标记             │ 下一周期准备             │
└──────────┴──────────────────────┴───────────────────────────┘
```

## 五、网络轮询器（Netpoller）

### 5.1 设计目标

网络轮询器实现了 Go 的异步 I/O 模型：

```go
// 传统阻塞 I/O
conn.Read(buf)  // 阻塞等待数据

// Go 的非阻塞模型
conn.Read(buf)  // goroutine 挂起，M 继续执行其他 G
                 // 数据就绪后，goroutine 被唤醒
```

### 5.2 实现原理

```
┌─────────────────────────────────────────────────────────────┐
│                      Netpoller                              │
├─────────────────────────────────────────────────────────────┤
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐     │
│  │ pollDesc   │    │ pollDesc   │    │ pollDesc   │     │
│  │  (fd=3)    │    │  (fd=4)    │    │  (fd=5)    │     │
│  │  G=gp1     │    │  G=gp2     │    │  G=gp3     │     │
│  └──────┬─────┘    └──────┬─────┘    └──────┬─────┘     │
│         │                 │                 │            │
│         ▼                 ▼                 ▼            │
│  ┌──────────────────────────────────────────────────┐   │
│  │              epoll/kqueue/IOCP                   │   │
│  │           (操作系统 I/O 多路复用)                 │   │
│  └──────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

### 5.3 工作流程

```go
// 网络读取流程
func netpollRead(fd *netFD, p []byte) (n int, err error) {
    // 1. 非阻塞读取
    n, err = syscall.Read(fd.Sysfd, p)
    if err == syscall.EAGAIN {
        // 2. 数据未就绪，挂起 goroutine
        park goroutine
        
        // 3. 将 fd 加入 epoll 监听
        netpollopen(fd, pd)
        
        // 4. 等待唤醒
        gopark(...)
    }
    return n, err
}

// epoll 事件处理
func netpoll(block bool) *g {
    // 1. 调用 epoll_wait
    n := epollwait(epfd, events, maxevents, timeout)
    
    // 2. 处理就绪事件
    for i := 0; i < n; i++ {
        pd := events[i].data
        // 3. 唤醒对应的 goroutine
        goready(pd.g)
    }
}
```

## 六、运行时监控

### 6.1 sysmon 系统监控

Go 运行时有一个特殊的 M（sysmon），不需要 P 即可运行：

```go
func sysmon() {
    for {
        // 1. 释放闲置内存
        if t := now - lastgc; t > forcegcperiod {
            forcegc.idle = 0
            forcegc.g.schedlink = nil
            injectglist(forcegc.g)
        }
        
        // 2. 检查死锁
        checkdead()
        
        // 3. 抢占长时间运行的 G
        retake(now)
        
        // 4. 检查是否需要强制 GC
        if t := now - lastgc; t > forcegcperiod {
            forceGC()
        }
        
        // 5. 动态调整 P 的数量
        if hz := gcTrigger; hz != 0 {
            gcTrigger = 0
            startm(nil, true)
        }
        
        usleep(delay)
    }
}
```

sysmon 职责：
- **死锁检测**：检查程序是否死锁
- **强制 GC**：超过 2 分钟未 GC 则强制触发
- **抢占调度**：抢占运行超过 10ms 的 G
- **网络轮询**：定期检查网络事件
- **动态调整**：根据负载调整 P 数量

## 八、最佳实践

### 8.1 调度器优化

```go
// 1. 避免创建过多 goroutine
// Bad
for i := 0; i < 1000000; i++ {
    go process(i)
}

// Good: 使用 worker pool
pool := make(chan struct{}, runtime.NumCPU()*10)
for i := 0; i < 1000000; i++ {
    pool <- struct{}{}
    go func(i int) {
        defer func() { <-pool }()
        process(i)
    }(i)
}

// 2. 让出 CPU
for {
    select {
    case <-ch:
        // 处理
    default:
        runtime.Gosched() // 让出 CPU
    }
}
```

### 8.2 内存优化

```go
// 1. 预分配切片
s := make([]int, 0, expectedSize)

// 2. 复用对象
var pool = sync.Pool{
    New: func() interface{} {
        return new(MyStruct)
    },
}

obj := pool.Get().(*MyStruct)
// 使用 obj
pool.Put(obj)

// 3. 避免逃逸
func process() {
    // Bad: 返回局部变量指针，导致逃逸
    // return &MyStruct{}
    
    // Good: 使用值类型
    return MyStruct{}
}
```

### 8.3 GC 优化

```go
// 1. 减少 GC 压力
// Bad: 频繁创建临时对象
for {
    _ = make([]byte, 1024)
}

// Good: 复用缓冲区
buf := make([]byte, 1024)
for {
    // 使用 buf
}

// 2. 设置 GC 目标
debug.SetGCPercent(100) // 默认值，堆增长 100% 触发 GC

// 3. 手动触发 GC（谨慎使用）
runtime.GC()
```
