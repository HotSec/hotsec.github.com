# 并发安全与竞态检测

并发安全是指多个 goroutine 并发访问共享资源时，不会产生不正确的结果。Go 提供了竞态检测器来帮助发现并发问题。

---

## 一、竞态条件（Race Condition）

### 1.1 什么是竞态条件

```go
var counter int

func increment() {
    for i := 0; i < 1000; i++ {
        counter++
    }
}

func main() {
    go increment()
    go increment()
    time.Sleep(time.Second)
    fmt.Println(counter)
}
```

- `counter++` 不是原子操作（读取→加1→写入）
- 两个 goroutine 可能同时读取相同的值
- 最终结果可能小于 2000

### 1.2 数据竞争定义

当满足以下条件时发生数据竞争：

1. 两个或多个 goroutine 并发访问同一内存
2. 至少有一个是写操作
3. 没有同步机制

## 二、竞态检测器

### 2.1 使用方法

```bash
go run -race main.go
go build -race -o app main.go
go test -race ./...
```

### 2.2 检测输出示例

```
==================
WARNING: DATA RACE
Write at 0x00c0000b4008 by goroutine 8:
  main.increment()
      /path/main.go:8 +0x4e

Previous read at 0x00c0000b4008 by goroutine 7:
  main.increment()
      /path/main.go:8 +0x3a

Goroutine 8 (running) created at:
  main.main()
      /path/main.go:14 +0x85

Goroutine 7 (finished) created at:
  main.main()
      /path/main.go:13 +0x67
==================
```

### 2.3 性能影响

- 竞态检测会降低性能 5-10 倍
- 内存使用增加 2-10 倍
- 仅用于开发和测试，不要用于生产

## 三、Go 内存模型

### 3.1 Happens-Before 关系

如果操作 A happens-before 操作 B，那么 A 的结果对 B 可见。

### 3.2 同步规则

```go
var a string
var done bool

func setup() {
    a = "hello"
    done = true
}

func main() {
    go setup()
    for !done {
    }
    fmt.Println(a)
}
```

- 上述代码可能有竞态问题
- `done = true` 不保证 `a = "hello"` 对主 goroutine 可见

### 3.3 正确同步方式

```go
var a string
var done = make(chan struct{})

func setup() {
    a = "hello"
    close(done)
}

func main() {
    go setup()
    <-done
    fmt.Println(a)
}
```

## 四、并发安全解决方案

### 4.1 互斥锁

```go
var (
    counter int
    mu      sync.Mutex
)

func increment() {
    mu.Lock()
    defer mu.Unlock()
    counter++
}
```

### 4.2 读写锁

```go
var (
    data map[string]string
    mu   sync.RWMutex
)

func read(key string) string {
    mu.RLock()
    defer mu.RUnlock()
    return data[key]
}

func write(key, value string) {
    mu.Lock()
    defer mu.Unlock()
    data[key] = value
}
```

### 4.3 原子操作

```go
var counter int64

func increment() {
    atomic.AddInt64(&counter, 1)
}
```

### 4.4 Channel

```go
func main() {
    ch := make(chan int)

    go func() {
        ch <- 42
    }()

    value := <-ch
    fmt.Println(value)
}
```

## 五、常见并发安全问题

### 5.1 循环变量捕获

```go
for _, v := range values {
    go func() {
        fmt.Println(v)
    }()
}
```

修复：

```go
for _, v := range values {
    v := v
    go func() {
        fmt.Println(v)
    }()
}
```

### 5.2 非线程安全类型

```go
var m = make(map[string]int)

func concurrentWrite() {
    m["key"] = 1
}
```

- map 不是并发安全的
- 并发读写会 panic

修复：

```go
var m sync.Map

func concurrentWrite() {
    m.Store("key", 1)
}
```

### 5.3 检查-执行竞态

```go
if !exists(key) {
    create(key)
}
```

- 检查和执行之间存在竞态
- 使用原子操作或锁保护整个操作

---

## 六、最佳实践

1. **优先使用 channel**：不要通过共享内存来通信，而要通过通信来共享内存
2. **明确所有权**：每个资源有明确的 goroutine 负责
3. **最小化临界区**：锁的范围尽可能小
4. **使用 -race 检测**：开发和测试阶段开启竞态检测
5. **代码审查**：并发代码需要仔细审查
