# 网络IO并发模型

## select

1. 一次可以处理1024个fd
2. loop thread 通过 select 将一组 fd 提交到内核做监听
3. 当 fd 中无 io event 就绪时，loop thread 会陷入阻塞
4. 每当这组 fd 中有 io event 到达时，内核会唤醒 loop thread
5. loop thread 无法精准感知到哪些 fd 就绪，需要遍历一轮 fd 列表，时间复杂度 O(N)
6. 托付给内核的 fd 列表只具有一轮交互的时效. 新的轮次中，loop thread 需要重新将监听的 fd 列表再传递给内核一次

## epoll

1. 每次处理的fd数量无上限
2. loop thread通过epoll_create操作创建一个epoll池子
3. loop thread通过epoll_ctl每次将一个待监听的fd添加到池子中
4. 每当fd列表中有fd就绪事件到达时，就会唤醒loop thread。同时内核会将处于就绪状态的fd列表返回给loop thread
5. loop thread只需要遍历就绪的fd列表，时间复杂度O(1)

- 水平触发LT
  - fd就绪后，内核会通知loop thread，loop thread可以不立即处理，下次再处理
- 边缘触发ET
  - fd就绪后，内核会通知loop thread，loop thread必须立即处理，否则下次无法再通知
