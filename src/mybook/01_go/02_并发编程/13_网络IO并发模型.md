# 网络IO并发模型

## select

1. 一次可以处理1024个fd
2. loop thread 通过 select 将一组 fd 提交到内核做监听
3. 当 fd 中无 io event 就绪时，loop thread 会陷入阻塞
4. 每当这组 fd 中有 io event 到达时，内核会唤醒 loop thread
5. loop thread 无法精准感知到哪些 fd 就绪，需要遍历一轮 fd 列表，时间复杂度 O(N)
6. 托付给内核的 fd 列表只具有一轮交互的时效. 新的轮次中，loop thread 需要重新将监听的 fd 列表再传递给内核一次

**缺点**：
- fd 数量限制（1024）
- 每次调用需要复制 fd 集合到内核
- 返回后需要遍历所有 fd 找就绪者

## poll

与 select 类似，但使用链表代替位数组，没有 1024 的 fd 数量限制。

**缺点**：
- 仍然需要遍历所有 fd
- 每次调用仍需复制数据到内核

## epoll

1. 每次处理的fd数量无上限
2. loop thread通过epoll_create操作创建一个epoll池子
3. loop thread通过epoll_ctl每次将一个待监听的fd添加到池子中
4. 每当fd列表中有fd就绪事件到达时，就会唤醒loop thread。同时内核会将处于就绪状态的fd列表返回给loop thread
5. loop thread只需要遍历就绪的fd列表，时间复杂度O(1)

### 触发模式

- **水平触发 LT**：fd就绪后，内核会通知loop thread，loop thread可以不立即处理，下次再处理
- **边缘触发 ET**：fd就绪后，内核会通知loop thread，loop thread必须立即处理，否则下次无法再通知

### epoll 优势

| 对比 | select | poll | epoll |
|------|--------|------|-------|
| fd 上限 | 1024 | 无限制 | 无限制 |
| 就绪检测 | 遍历 O(N) | 遍历 O(N) | 回调 O(1) |
| 内存拷贝 | 每次复制 | 每次复制 | mmap 共享 |
| 触发模式 | LT | LT | LT/ET |

## IO 模型

### 阻塞 IO

```
应用调用 read() → 阻塞等待 → 数据就绪 → 拷贝到用户空间 → 返回
```

- 简单但效率低
- 一个连接需要一个线程

### 非阻塞 IO

```
应用调用 read() → 立即返回 EAGAIN → 轮询 → 数据就绪 → 拷贝 → 返回
```

- 避免阻塞但轮询消耗 CPU
- 通常配合 IO 多路复用使用

### IO 多路复用

```
应用调用 epoll_wait() → 阻塞等待就绪事件 → 返回就绪 fd → read/write
```

- 一个线程管理多个连接
- epoll 是 Linux 最优方案

### 异步 IO

```
应用调用 aio_read() → 立即返回 → 内核完成操作 → 通知应用
```

- 真正的非阻塞
- Linux aio 不够成熟，io_uring 是新方向

## Reactor 模式

### 单 Reactor 单线程

```
Reactor → accept → read → decode → compute → encode → send
```

- 简单，无法利用多核
- Redis 使用此模型

### 单 Reactor 多线程

```
Reactor → accept + read/send
              ↓
         Worker 线程池 → decode → compute → encode
```

- IO 和计算分离
- Reactor 仍是瓶颈

### 主从 Reactor 多线程

```
Main Reactor → accept → 分配给 Sub Reactor
Sub Reactor1 → read/write (连接组1)
Sub Reactor2 → read/write (连接组2)
Worker 线程池 → compute
```

- Netty / Nginx / Memcached 使用此模型
- 充分利用多核

## Go netpoll

Go 运行时内置的网络轮询器，将网络 IO 与 Goroutine 调度结合：

```
Goroutine 调用网络 IO → runtime 将 G 挂起 → netpoll (epoll) 监听
→ fd 就绪 → runtime 唤醒 G → 继续执行
```

### 工作流程

1. Goroutine 发起网络读写
2. 如果 fd 未就绪，将 Goroutine 挂起（gopark）
3. 将 fd 注册到 netpoll（epoll_ctl）
4. sysmon 后台线程定期调用 epoll_wait
5. fd 就绪后，将对应 Goroutine 放回运行队列
6. Goroutine 被调度执行，继续网络操作

### 优势

- **对开发者透明**：写同步代码，享受异步性能
- **与调度器集成**：IO 阻塞不占用线程
- **自动管理**：无需手动管理 epoll

### 源码关键

- `runtime/netpoll.go`：netpoll 核心逻辑
- `runtime/netpoll_epoll.go`：Linux epoll 实现
- `runtime/netpoll_kqueue.go`：macOS kqueue 实现
- `internal/poll/fd_poll_runtime.go`：标准库集成

## C10K 问题

如何让一台服务器同时处理 10000 个并发连接：

| 方案 | 问题 |
|------|------|
| 线程/进程模型 | 10000 线程 → 栈内存 80GB，调度开销大 |
| select | fd 上限 1024 |
| poll | 遍历 O(N)，性能差 |
| epoll | 最优解，O(1) 就绪检测 |
| Go netpoll | 更高抽象，开发效率高 |
