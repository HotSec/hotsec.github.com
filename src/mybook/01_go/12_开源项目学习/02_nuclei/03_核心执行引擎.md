
# Nuclei 核心执行引擎

## 1. 工作池设计

### 1.1 WorkPool 结构

[WorkPool](file:///Volumes/SN740/code/notebook/third/nuclei/pkg/core/workpool.go) 是 Nuclei 实现双层并发的核心组件：

```go
type WorkPool struct {
	InputPool     chan MetaInput
	TemplatePool  chan *templates.Template
	Default        *syncutil.AdaptiveWaitGroup
	Headless      *syncutil.AdaptiveWaitGroup
	config        *WorkPoolConfig
}

type WorkPoolConfig struct {
	TypeConcurrency      int
	InputConcurrency    int
	HeadlessConcurrency int
	BulkSize            int
}
```

### 1.2 双层并发模型

```
┌─────────────────────────────────────────┐
│      模板级并发 (TypeConcurrency)    │
│   (同时执行多个不同类型的模板)         │
└─────────────────────────────────────────┘
              ↓ 并行
┌─────────────────────────────────────────┐
│    目标级并发 (InputConcurrency)      │
│ (每个模板同时扫描多个目标)          │
└─────────────────────────────────────────┘
```

- **TypeConcurrency**: 控制同时执行的模板数量，默认为 25
- **InputConcurrency**: 控制每个模板同时扫描的目标数量，默认为 25
- **BulkSize**: 批量处理大小，与 InputConcurrency 配合使用
- **HeadlessConcurrency**: 针对 Headless 协议的单独并发控制，资源消耗大

### 2.2 执行流程

[executeScanWithTemplates](file:///Volumes/SN740/code/notebook/third/nuclei/pkg/core/executors.go) 是主执行函数：

```go
func (e *Engine) executeScanWithTemplates(ctx context.Context, templates []*templates.Template, callback func(*output.ResultEvent)) (bool, error) {
	// 1. 初始化扫描上下文
	scanCtx := scan.NewScanContext(ctx, nil)

	// 2. 获取工作池
	workPool := e.GetWorkPool()

	// 3. 遍历所有模板
	for _, template := range templates {
		select {
		case <-ctx.Done():
			return false, ctx.Err()
		default:
		}

		// 4. 获取模板执行
		matched, err := e.executeTemplate(template, workPool, callback)
		if err != nil {
			e.options.Logger.Warning().Msgf("[%s] 执行失败: %s", template.ID, err)
		}
	}

	// 5. 等待所有任务完成
	workPool.Wait()
	return matched, nil
}
```

## 3. 请求聚类

### 3.1 聚类原理

[Cluster](file:///Volumes/SN740/code/notebook/third/nuclei/pkg/templates/cluster.go) 是 Nuclei 优化扫描效率的关键技术，将多个向同一目标发送相同请求的模板聚类为一个请求，然后用多个匹配器检查响应。

### 3.2 聚类条件

模板可聚类的条件：

1. 只包含单一协议请求
2. 请求方法、路径、头等完全相同
3. 不包含 Payload、raw、unsafe 等特殊字段
4. 不是多协议或 Workflow

### 3.3 聚类实现

```go
func Cluster(list []*Template) [][]*Template {
	http := make(map[uint64][]*Template)
	dns := make(map[uint64][]*Template)
	ssl := make(map[uint64][]*Template)

	final := [][]*Template{}

	for _, template := range list {
		if template.Flow != "" || template.Options.IsMultiProtocol {
			final = append(final, []*Template{template})
			continue
		}

		switch {
		case len(template.RequestsDNS) == 1:
			if template.RequestsDNS[0].IsClusterable() {
				hash := template.RequestsDNS[0].TmplClusterKey()
				dns[hash] = append(dns[hash], template)
			} else {
				final = append(final, []*Template{template})
			}
		// ... 其他协议
		}
	}

	// 添加聚类后的结果
	for _, templates := range http {
		final = append(final, templates)
	}
	// ...
	return final
}
```

### 3.4 ClusterExecuter

[ClusterExecuter](file:///Volumes/SN740/code/notebook/third/nuclei/pkg/templates/cluster.go) 负责执行聚类后的请求：

```go
type ClusterExecuter struct {
	requests     protocols.Request
	operators    []*clusteredOperator
	templateType types.ProtocolType
	options      *protocols.ExecutorOptions
}

func (e *ClusterExecuter) Execute(ctx *scan.ScanContext) (bool, error) {
	var results bool

	inputItem := ctx.Input.Clone()
	previous := make(map[string]interface{})
	dynamicValues := make(map[string]interface{})
	callbackCalled := &atomic.Bool{}

	// 执行一次请求，然后用所有聚类的匹配器去检查
	err := e.requests.ExecuteWithResults(inputItem, dynamicValues, previous, func(event *output.InternalWrappedEvent) {
		callbackCalled.Store(true)
		if event == nil {
			return
		}
		if event.InternalEvent == nil {
			event.InternalEvent = make(map[string]interface{})
		}
		// 对每个聚类的模板执行匹配
		for _, operator := range e.operators {
			clonedEvent := event.CloneShallow()
			result, matched := operator.operator.Execute(...)
			if matched && result != nil {
				clonedEvent.OperatorsResult = result
				clonedEvent.Results = e.requests.MakeResultEvent(clonedEvent)
				results = true
				_ = writer.WriteResult(...)
			}
		}
	})
	return results, err
}
```

## 4. 协议接口设计

### 4.1 Executer 接口

所有协议都实现了统一的 [Executer](file:///Volumes/SN740/code/notebook/third/nuclei/pkg/protocols/protocols.go) 接口：

```go
type Executer interface {
	Compile() error
	Execute(*scan.ScanContext) (bool, error)
	ExecuteWithResults(*scan.ScanContext) ([]*output.ResultEvent, error)
	Requests() int
}
```

### 4.2 Request 接口

协议请求实现 [Request](file:///Volumes/SN740/code/notebook/third/nuclei/pkg/protocols/protocols.go) 接口：

```go
type Request interface {
	Compile(*ExecutorOptions) error
	ExecuteWithResults(*contextargs.MetaInput, map[string]interface{}, map[string]interface{}, func(*InternalWrappedEvent)) error
	Match(map[string]interface{}, bool) (*operators.Result, bool, error)
	Extract(map[string]interface{},) map[string]struct{}
	MakeResultEvent(*InternalWrappedEvent) []*ResultEvent
}
```

## 6. 执行流程完整图

```
main.go
  ↓
runner.RunEnumeration()
  ↓
Engine.executeScanWithTemplates()
  ↓
  ├─ 加载模板
  ├─ 聚类模板
  ├─ 对每个模板
  │  │
  │  ├─ WorkPool（双层并发
  │  │
  │  └─ Template.Executer.Execute()
  │      ├─ Request.ExecuteWithResults()
  │      │   ├─ 发送请求
  │      │   ├─ 接收响应
  │      │   ├─ Operators.Execute()
  │      │   │   ├─ Matchers 匹配
  │      │   │   └─ Extractors 提取
  │      │   └─ 回调输出结果
  │      │
  │      └─ 返回是否匹配
  │
  └─ Wait 等待所有任务完成
```

## 7. 小结

Nuclei 执行引擎的设计亮点：

1. **双层并发**: 模板级 + 目标级并发，最大化利用资源
2. **请求聚类**: 大幅减少重复请求，提升效率
3. **统一接口**: 多协议通过统一 Executer/Request 接口抽象
4. **自适应并发**: AdaptiveWaitGroup 动态调整并发度
5. **错误容忍**: HostErrorsCache 跳过错误主机，避免浪费时间

主要问题：
- ExecutorOptions 耦合度过高，包含 40+ 字段
- RateLimiter 存在竞态条件未修复
- 部分代码中大量使用 _ = err 忽略错误
