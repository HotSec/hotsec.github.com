# Go 汇编语言

> 主要参考：《Go语言高级编程（第2版）》第3章 — 柴树杉、曹春晖 著

Go 语言的很多设计思想和工具传承自 Plan 9 操作系统，Go 汇编语言也是基于 Plan 9 汇编演化而来。Go 汇编不是对底层硬件的简单映射，而是一种经过抽象的半虚拟化汇编语言，不同架构的 CPU 共享大部分汇编语法。

---

## 一、快速入门

### 1.1 从 Go 代码看汇编

理解 Go 汇编最好的方式是从 Go 代码的汇编输出入手：

```go
func Add(a, b int) int {
    return a + b
}
```

```bash
# 查看编译器生成的汇编
go build -gcflags="-S" main.go 2>&1 | grep -A 10 "func Add"
# 或使用 go tool compile
go tool compile -S main.go
```

输出类似：
```
"".Add STEXT nosplit size=24 args=0x18 locals=0x0
    0x0000  MOVQ    "".b+16(SP), AX
    0x0005  MOVQ    "".a+8(SP), CX
    0x000a  ADDQ    CX, AX
    0x000d  MOVQ    AX, "".~r2+24(SP)
    0x0012  RET
```

### 1.2 用汇编实现函数

**add.go**
```go
package main

func Add(a, b int) int

func main() {
    println(Add(10, 20))
}
```

**add_amd64.s**
```asm
TEXT ·Add(SB), NOSPLIT, $0-24
    MOVQ a+0(FP), AX
    MOVQ b+8(FP), BX
    ADDQ BX, AX
    MOVQ AX, ret+16(FP)
    RET
```

### 1.3 编译与运行

```bash
go build
./main

# 查看目标文件中的符号
go tool nm main | grep Add

# 反汇编查看
go tool objdump -s 'main\.Add' main
```

## 二、计算机结构

> 参考《Go语言高级编程》3.2 节

汇编语言是直面计算机的编程语言，理解计算机结构是掌握汇编语言的前提。

### 2.1 冯·诺伊曼体系结构

当前主流计算机采用冯·诺伊曼体系结构（普林斯顿结构），核心思想是**程序指令和数据共用同一存储器**：

```
┌─────────────────────────────────────┐
│              CPU                     │
│  ┌─────────┐  ┌──────────────────┐  │
│  │  ALU     │  │  控制器           │  │
│  │(算术逻辑)│  │(指令译码/执行)    │  │
│  └────┬────┘  └────────┬─────────┘  │
│       │                │             │
│  ┌────┴────────────────┴─────────┐  │
│  │         寄存器组               │  │
│  └──────────────┬────────────────┘  │
└─────────────────┼───────────────────┘
                  │
          ┌───────┴───────┐
          │    存储器       │
          │ (指令 + 数据)   │
          └───────────────┘
```

### 2.2 指令执行流程

```
取指(Fetch) → 译码(Decode) → 执行(Execute) → 写回(WriteBack)
```

- **取指**：从存储器读取指令
- **译码**：解析指令的操作码和操作数
- **执行**：ALU 执行运算
- **写回**：将结果写回寄存器或存储器

### 2.3 寄存器

寄存器是 CPU 内部的高速存储单元，是汇编编程的核心：

**AMD64 通用寄存器**：

| 64位 | 32位 | 16位 | 8位 | 用途 |
|------|------|------|-----|------|
| RAX | EAX | AX | AL | 累加器/返回值 |
| RBX | EBX | BX | BL | 基址寄存器 |
| RCX | ECX | CX | CL | 计数器 |
| RDX | EDX | DX | DL | 数据寄存器 |
| RSI | ESI | SI | SIL | 源索引 |
| RDI | EDI | DI | DIL | 目的索引 |
| RBP | EBP | BP | BPL | 帧指针 |
| RSP | ESP | SP | SPL | 栈指针 |
| R8-R15 | R8D-R15D | R8W-R15W | R8B-R15B | 扩展通用 |

### 2.4 内存层次

```
寄存器 < L1 Cache < L2 Cache < L3 Cache < 主存 < 磁盘
(快/贵/小)                                    (慢/便宜/大)
```

汇编编程需要关注：
- 寄存器数量有限，需合理分配
- 内存访问远慢于寄存器，尽量减少访存
- 对齐访问比非对齐访问快

## 三、常量和全局变量

> 参考《Go语言高级编程》3.3 节

程序中的一切变量初始值都直接或间接依赖常量或常量表达式生成。

### 3.1 常量

Go 汇编中的常量使用 `$` 前缀表示：

```asm
MOVQ $0, AX          // 整数常量
MOVQ $0x1234, BX     // 十六进制常量
MOVQ $"hello", CX    // 字符串常量（不常用）
```

### 3.2 全局变量

使用 `GLOBL` 指令定义全局变量，使用 `DATA` 指令初始化：

```asm
// 定义全局变量（未初始化，零值）
GLOBL ·count(SB), RODATA, $8

// 定义并初始化全局变量
GLOBL ·answer(SB), RODATA, $8
DATA ·answer+0(SB)/8, $42

// 定义字符串
GLOBL ·hello(SB), RODATA, $6
DATA ·hello+0(SB)/1, 'h'
DATA ·hello+1(SB)/1, 'e'
DATA ·hello+2(SB)/1, 'l'
DATA ·hello+3(SB)/1, 'l'
DATA ·hello+4(SB)/1, 'o'
DATA ·hello+5(SB)/1, '\n'
```

Go 端声明：
```go
var count int
var answer int
var hello []byte
```

### 3.3 GLOBL 指令

```asm
GLOBL ·name(SB), flags, $size
```

| 标志 | 说明 |
|------|------|
| RODATA | 只读数据段 |
| NOPTR | 不包含指针，GC 无需扫描 |
| DUPOK | 允许重复定义（链接器去重） |

### 3.4 DATA 指令

```asm
DATA ·name+offset(SB)/size, $value
```

- `offset`：偏移量（字节）
- `size`：数据大小（1/2/4/8 字节）
- `value`：初始值

```asm
// 定义 int64 数组
GLOBL ·nums(SB), RODATA, $24
DATA ·nums+0(SB)/8, $10
DATA ·nums+8(SB)/8, $20
DATA ·nums+16(SB)/8, $30
```

### 3.5 用 Go 定义变量

在 Go 汇编中，建议通过 Go 语言来定义全局变量，只在汇编中引用：

```go
// var.go
var (
    count  int
    answer int = 42
    hello  = "hello, world\n"
)
```

```asm
// 使用 SB 伪寄存器引用
MOVQ ·count(SB), AX
MOVQ $100, ·count(SB)
```

## 四、函数

> 参考《Go语言高级编程》3.4 节

### 4.1 函数定义语法

```asm
TEXT ·FunctionName(SB), FLAGS, $framesize-argsize
```

- `·`：包名分隔符（Unicode 中点），表示当前包
- `(SB)`：表示符号属于全局地址空间
- `FLAGS`：函数标志
- `$framesize`：局部变量栈帧大小
- `argsize`：参数+返回值总大小

```asm
// 简单函数：无局部变量，16 字节参数
TEXT ·Add(SB), NOSPLIT, $0-24
    MOVQ a+0(FP), AX
    MOVQ b+8(FP), BX
    ADDQ BX, AX
    MOVQ AX, ret+16(FP)
    RET
```

### 4.2 函数标志

| 标志 | 说明 |
|------|------|
| NOSPLIT | 不需要栈分裂检查（叶子函数或栈帧小） |
| WRAPPER | 包装函数，不恢复栈 |
| NEEDCTXT | 需要闭包上下文 |
| NOFRAME | 不分配栈帧（特殊运行时函数） |
| TOPFRAME | 栈顶函数（Goroutine 入口） |

### 4.3 伪寄存器

| 伪寄存器 | 说明 |
|---------|------|
| `FP` | Frame Pointer，参数区基址（通过 `name+offset(FP)` 访问参数） |
| `PC` | Program Counter，程序计数器（跳转目标） |
| `SB` | Static Base，全局符号基址（`·name(SB)` 引用全局符号） |
| `SP` | Stack Pointer，栈顶（局部变量区，`offset(SP)` 访问局部变量） |

> **关键区别**：`FP` 访问参数/返回值，`SP` 访问局部变量。硬件 SP 寄存器通过 `SP` 伪寄存器间接使用。

### 4.4 参数与返回值访问

参数和返回值通过 `FP` 伪寄存器按声明顺序排列：

```go
func Example(a int, b float64, c []byte) (int, float64)
```

```asm
TEXT ·Example(SB), NOSPLIT, $0-56
    // 参数
    MOVQ  a+0(FP), AX        // int (8 bytes)
    MOVSD b+8(FP), X0        // float64 (8 bytes)
    MOVQ  c_base+16(FP), BX  // slice.Data
    MOVQ  c_len+24(FP), CX   // slice.Len
    MOVQ  c_cap+32(FP), DX   // slice.Cap
    // 返回值
    MOVQ  $0, ret1+40(FP)    // int 返回值
    MOVSD X0, ret2+48(FP)    // float64 返回值
    RET
```

**参数大小计算**：
- int → 8 字节
- float64 → 8 字节
- slice → 24 字节（ptr + len + cap）
- string → 16 字节（ptr + len）
- interface → 16 字节（type + data）

### 4.5 局部变量

局部变量通过 `SP` 伪寄存器访问：

```asm
TEXT ·Example(SB), $24-16
    // 24 字节局部变量，16 字节参数

    MOVQ a+0(FP), AX
    MOVQ b+8(FP), BX

    // 局部变量（通过 SP 访问）
    MOVQ AX, 0(SP)     // 局部变量 1
    MOVQ BX, 8(SP)     // 局部变量 2
    MOVQ $0, 16(SP)    // 局部变量 3

    // ... 计算 ...

    MOVQ 0(SP), AX
    MOVQ AX, ret+0(FP)
    RET
```

### 4.6 调用其他函数

Go 使用栈传递参数和返回值，调用函数前需要在栈上预留空间：

```asm
TEXT ·CallAdd(SB), NOSPLIT, $24-8
    // 在栈上准备参数
    MOVQ $10, 0(SP)    // 参数 a
    MOVQ $20, 8(SP)    // 参数 b

    // 调用函数
    CALL ·add(SB)

    // 获取返回值（在栈上 16(SP)）
    MOVQ 16(SP), AX
    MOVQ AX, ret+0(FP)
    RET
```

### 4.7 宏函数

Go 汇编支持简单的宏：

```asm
// 定义宏
#define PDATA(s, v) DATA s(SB)/8, $v

// 使用宏
GLOBL ·count(SB), RODATA, $8
PDATA(·count, 42)
```

## 五、控制流

> 参考《Go语言高级编程》3.5 节

### 5.1 顺序执行

不含分支、循环和 goto 的代码，按指令顺序执行：

```asm
TEXT ·SeqAdd(SB), NOSPLIT, $0-24
    MOVQ a+0(FP), AX
    ADDQ b+8(FP), AX
    MOVQ AX, ret+16(FP)
    RET
```

### 5.2 if/goto 跳转

```asm
// if a > b { return a } else { return b }
TEXT ·Max(SB), NOSPLIT, $0-24
    MOVQ a+0(FP), AX
    MOVQ b+8(FP), BX
    CMPQ AX, BX
    JG   return_a
    MOVQ BX, ret+16(FP)
    JMP  done
return_a:
    MOVQ AX, ret+16(FP)
done:
    RET
```

常用跳转指令：

| 指令 | 条件 | 说明 |
|------|------|------|
| JE/JZ | ZF=1 | 相等/零 |
| JNE/JNZ | ZF=0 | 不等/非零 |
| JL/JNGE | SF≠OF | 小于（有符号） |
| JLE/JNG | ZF=1 或 SF≠OF | 小于等于 |
| JG/JNLE | ZF=0 且 SF=OF | 大于 |
| JGE/JNL | SF=OF | 大于等于 |
| JB/JNAE | CF=1 | 小于（无符号） |
| JA/JNBE | CF=0 且 ZF=0 | 大于（无符号） |

### 5.3 for 循环

Go 汇编没有专门的循环指令，通过条件跳转实现：

```asm
// 计算 1+2+...+n
TEXT ·Sum(SB), NOSPLIT, $0-16
    MOVQ n+0(FP), CX     // 循环计数
    XORQ AX, AX           // 结果 = 0
    XORQ BX, BX           // i = 0

loop:
    INCQ BX               // i++
    ADDQ BX, AX           // result += i
    CMPQ BX, CX           // i < n?
    JL   loop             // 是则继续循环

    MOVQ AX, ret+8(FP)
    RET
```

## 六、再论函数

> 参考《Go语言高级编程》3.6 节

前面的函数都是叶子函数（不调用其他函数），本节讨论更复杂的函数场景。

### 6.1 栈分裂

Go 的 Goroutine 初始栈很小（2KB-8KB），可能动态增长。非叶子函数需要栈分裂检查：

```asm
// 叶子函数：不需要栈分裂检查
TEXT ·Leaf(SB), NOSPLIT, $0-8
    RET

// 非叶子函数：需要栈分裂检查
TEXT ·NonLeaf(SB), $0-8
    // 编译器自动插入栈分裂检查
    CALL ·other(SB)
    RET
```

- `NOSPLIT`：告诉编译器不需要栈分裂检查
- 不加 `NOSPLIT`：编译器自动在函数入口插入栈分裂检查代码
- 栈分裂检查会对比当前栈指针和栈警戒线，不够时触发栈扩容

### 6.2 递归函数

递归函数通过调用自身并在栈上保存状态：

```asm
// 递归计算 1+2+...+n
TEXT ·SumRec(SB), $16-16
    MOVQ n+0(FP), AX
    CMPQ AX, $0
    JG   recurse
    MOVQ $0, ret+8(FP)
    RET

recurse:
    // 保存 n-1 参数到栈上
    LEAQ -1(AX), BX
    MOVQ BX, 0(SP)
    CALL ·SumRec(SB)
    // 取返回值
    MOVQ 8(SP), BX
    // result = n + SumRec(n-1)
    ADDQ AX, BX
    MOVQ BX, ret+8(FP)
    RET
```

Go 的递归函数不用担心爆栈问题，因为栈可以根据需要自动扩容。

### 6.3 闭包

闭包是引用了外部变量的函数，Go 汇编中闭包通过 `NEEDCTXT` 标志和上下文指针实现：

```asm
TEXT ·closure·f(SB), NEEDCTXT, $0-16
    // 通过 DX 寄存器访问闭包上下文
    MOVQ 8(DX), AX    // 获取捕获的变量
    ADDQ val+0(FP), AX
    MOVQ AX, ret+8(FP)
    RET
```

### 6.4 可变参数

Go 的可变参数在汇编层面以切片形式传递：

```go
func Sum(vals ...int) int
```

```asm
// vals 作为 slice 传递：base + len + cap
TEXT ·Sum(SB), NOSPLIT, $0-32
    MOVQ vals_base+0(FP), SI
    MOVQ vals_len+8(FP), CX
    XORQ AX, AX

loop:
    TESTQ CX, CX
    JZ    done
    ADDQ  (SI), AX
    ADDQ  $8, SI
    DECQ  CX
    JMP   loop

done:
    MOVQ AX, ret+24(FP)
    RET
```

## 七、汇编语言的威力

> 参考《Go语言高级编程》3.7 节

汇编语言的真正威力来自两个维度：**突破框架限制**和**突破指令限制**。

### 7.1 系统调用

通过汇编直接发起系统调用，绕过 Go 标准库：

```asm
// Linux AMD64 系统调用
TEXT ·SysWrite(SB), NOSPLIT, $0-24
    MOVQ fd+0(FP), DI     // 参数1: fd
    MOVQ buf+8(FP), SI    // 参数2: buf
    MOVQ len+16(FP), DX   // 参数3: len
    MOVQ $1, AX           // syscall number: write
    SYSCALL
    MOVQ AX, ret+24(FP)
    RET
```

```go
func SysWrite(fd int, buf uintptr, len int) int

func main() {
    msg := "hello, syscall!\n"
    SysWrite(1, uintptr(unsafe.Pointer(&[]byte(msg)[0])), len(msg))
}
```

### 7.2 从汇编调用 C 函数

Go 汇编可以直接调用 C 函数（需要 CGO）：

```asm
// 调用 C 的 puts 函数
TEXT ·CallPuts(SB), NOSPLIT, $16-8
    MOVQ msg+0(FP), AX
    MOVQ AX, 0(SP)
    CALL C·puts(SB)
    RET
```

### 7.3 AVX2 高级指令

利用 AVX2 等 SIMD 指令实现极致性能：

```asm
// 使用 AVX2 加速 int64 数组求和
// +build amd64

TEXT ·SumInt64AVX2(SB), NOSPLIT, $0-32
    MOVQ ptr+0(FP), SI
    MOVQ len+8(FP), CX
    XORQ AX, AX

    TESTQ CX, CX
    JZ    done

    // 每次处理 4 个 int64 (AVX2, 256位)
    SHRQ $2, CX
    JZ   handle_tail

    VPXOR Y0, Y0, Y0        // Y0 = 0 (4×int64 累加器)

loop4:
    VMOVDQU 0(SI), Y1       // 加载 4 个 int64
    VPADDQ Y1, Y0, Y0       // 向量加法
    ADDQ   $32, SI          // 指针前移 32 字节
    DECQ   CX
    JNZ    loop4

    // 水平求和 Y0 的 4 个 int64
    VEXTRACTI128 $1, Y0, X1  // 提取高 128 位
    VPADDQ X1, X0, X0        // 高低 128 位相加
    VPSRLDQ $8, X0, X1       // 右移 8 字节
    VPADDQ X1, X0, X0        // 最终求和
    VMOVQ  X0, AX            // 结果放入 AX

handle_tail:
    // 处理剩余元素（len % 4）
    MOVQ len+8(FP), CX
    ANDQ $3, CX
    JZ   done

tail_loop:
    ADDQ (SI), AX
    ADDQ $8, SI
    DECQ CX
    JNZ  tail_loop

done:
    MOVQ AX, ret+16(FP)
    VZEROUPPER               // 清除 YMM 寄存器高半部分
    RET
```

### 7.4 原子操作

```asm
// Compare-And-Swap
TEXT ·Cas(SB), NOSPLIT, $0-25
    MOVQ ptr+0(FP), BX
    MOVQ old+8(FP), AX
    MOVQ new+16(FP), CX
    LOCK
    CMPXCHGQ CX, 0(BX)
    SETEQ ret+24(FP)
    RET

// 原子加法
TEXT ·AtomicAdd(SB), NOSPLIT, $0-24
    MOVQ ptr+0(FP), BX
    MOVQ delta+8(FP), AX
    LOCK
    XADDQ AX, 0(BX)
    ADDQ  AX, 0(BX)
    MOVQ 0(BX), AX
    MOVQ AX, ret+16(FP)
    RET
```

## 八、例子：获取 Goroutine ID

> 参考《Go语言高级编程》3.8 节

Go 语言刻意没有提供获取 Goroutine ID 的接口，但通过汇编可以直接访问 runtime 内部的 `g` 结构体。

### 8.1 通过 runtime.stack 获取

```go
func GetGoidByStack() int64 {
    var buf [64]byte
    n := runtime.Stack(buf[:], false)
    // 解析 "goroutine X [running]" 格式
    fields := strings.Fields(string(buf[:n]))
    if len(fields) > 1 && fields[0] == "goroutine" {
        id, _ := strconv.ParseInt(fields[1], 10, 64)
        return id
    }
    return -1
}
```

优点：跨平台，兼容性好
缺点：性能低（字符串解析开销），依赖 runtime 输出格式

### 8.2 通过汇编直接访问 g 结构体

AMD64 架构下，`g` 结构体指针存储在 TLS（Thread Local Storage）中，通过 `FS` 或 `GS` 段寄存器访问：

```asm
// getgoid_amd64.s
TEXT ·GetGoid(SB), NOSPLIT, $0-8
    MOVQ (TLS), CX        // 获取 g 指针
    MOVQ 8(CX), AX        // g.goid 偏移（可能因版本不同）
    MOVQ AX, ret+0(FP)
    RET
```

```go
// getgoid.go
func GetGoid() int64

func main() {
    fmt.Println("goid:", GetGoid())
}
```

> **注意**：`g.goid` 的偏移量依赖于 Go 版本，不同版本可能不同。需要通过 `runtime` 源码或 `go tool objdump` 确认偏移。

### 8.3 通用方案：通过 getg() 函数

Go runtime 提供了 `getg()` 内部函数，可以通过汇编调用：

```asm
TEXT ·GetGoid(SB), NOSPLIT, $0-8
    CALL runtime·getg(SB)  // 获取 g 指针，返回值在 AX
    MOVQ 8(AX), AX         // g.goid
    MOVQ AX, ret+0(FP)
    RET
```

## 九、Delve 调试器

> 参考《Go语言高级编程》3.9 节

Delve 是专门为 Go 语言设计的调试器，比 GDB/LLDB 对 Go 特性的支持更好。

### 9.1 安装

```bash
go install github.com/go-delve/delve/cmd/dlv@latest
```

### 9.2 基本使用

```bash
# 调试编译
dlv debug ./main.go
```

## 十二、常见陷阱

### 12.1 栈分裂遗漏

```asm
// 危险：大栈帧但标记了 NOSPLIT
TEXT ·Bad(SB), NOSPLIT, $8192-8
    // 如果 Goroutine 栈不够，直接栈溢出！
    RET

// 正确：大栈帧不加 NOSPLIT
TEXT ·Good(SB), $8192-8
    // 编译器自动插入栈分裂检查
    RET
```

### 12.2 参数大小计算错误

```asm
// 错误：string 是 16 字节（ptr+len），不是 8
TEXT ·Bad(SB), $0-16
    MOVQ s+0(FP), AX    // 只读了 ptr，漏了 len
    RET

// 正确
TEXT ·Good(SB), $0-24
    MOVQ s_ptr+0(FP), AX   // string.Data
    MOVQ s_len+8(FP), BX   // string.Len
    MOVQ AX, ret_ptr+16(FP)
    MOVQ BX, ret_len+24(FP)
    RET
```

### 12.3 寄存器保存

调用其他函数时，调用者保存的寄存器可能被修改：

```asm
// 错误：AX 在 CALL 后可能被修改
TEXT ·Bad(SB), $0-8
    MOVQ val+0(FP), AX
    CALL ·other(SB)    // AX 可能被修改
    MOVQ AX, ret+8(FP) // 值不对
    RET

// 正确：保存到栈或使用被调用者保存的寄存器
TEXT ·Good(SB), $8-8
    MOVQ val+0(FP), AX
    MOVQ AX, 0(SP)     // 保存到栈
    CALL ·other(SB)
    MOVQ 0(SP), AX     // 恢复
    MOVQ AX, ret+8(FP)
    RET
```

### 12.4 Go 汇编与 Plan 9 汇编的差异

Go 汇编不是标准 Plan 9 汇编，有重要差异：
- 操作数顺序：Go 汇编 `MOVQ src, dst`（与 AT&T 一致），Plan 9 原版 `MOVQ dst, src`
- 伪寄存器：Go 汇编特有 FP/SB/SP/PC
- 函数声明：`TEXT ·Name(SB)` 格式是 Go 特有
- 符号命名：Go 使用 `·`（中点）分隔包名

## 十三、最佳实践

1. **优先 Go 实现**：汇编仅用于性能关键路径或特殊需求
2. **保持简单**：汇编函数应单一职责，逻辑清晰
3. **Go 声明 + 汇编实现**：在 .go 文件中声明函数签名和文档，在 .s 文件中实现
4. **跨平台后备**：提供 Go 实现作为非优化架构的后备
5. **充分测试**：覆盖边界情况和各种输入
6. **避免硬编码偏移**：runtime 内部结构可能随版本变化
7. **使用 NOSPLIT 谨慎**：只在确保不会栈溢出时使用
