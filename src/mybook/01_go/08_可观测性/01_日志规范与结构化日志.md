# 日志规范与结构化日志

良好的日志规范是可观测性的基础，结构化日志便于检索和分析。

---

## 一、日志级别

### 1.1 级别定义

| 级别 | 含义 | 使用场景 |
|------|------|---------|
| DEBUG | 调试信息 | 开发调试 |
| INFO | 常规信息 | 正常流程 |
| WARN | 警告信息 | 潜在问题 |
| ERROR | 错误信息 | 需要关注 |
| FATAL | 致命错误 | 程序退出 |

### 1.2 级别选择原则

```go
log.Debug("Processing item", "id", itemID)
log.Info("User logged in", "user_id", userID)
log.Warn("Cache miss", "key", key)
log.Error("Database connection failed", "error", err)
log.Fatal("Config file not found", "path", configPath)
```

## 二、结构化日志

### 2.1 使用 zap

```go
logger, _ := zap.NewProduction()
defer logger.Sync()

logger.Info("request received",
    zap.String("method", "GET"),
    zap.String("path", "/api/users"),
    zap.Int("status", 200),
    zap.Duration("latency", latency),
)
```

### 2.2 使用 slog (Go 1.21+)

```go
import "log/slog"

slog.Info("request received",
    "method", "GET",
    "path", "/api/users",
    "status", 200,
    "latency", latency,
)
```

## 三、日志规范

### 3.1 必要字段

每条日志应包含：

```go
type LogFields struct {
    Timestamp   time.Time
    Level       string
    Message     string
    TraceID     string
    SpanID      string
    ServiceName string
}
```

### 3.2 请求日志

```go
func LoggingMiddleware(logger *zap.Logger) gin.HandlerFunc {
    return func(c *gin.Context) {
        start := time.Now()
        traceID := c.GetHeader("X-Trace-ID")
        if traceID == "" {
            traceID = uuid.New().String()
        }

        c.Next()

        logger.Info("request",
            zap.String("trace_id", traceID),
            zap.String("method", c.Request.Method),
            zap.String("path", c.Request.URL.Path),
            zap.Int("status", c.Writer.Status()),
            zap.Duration("latency", time.Since(start)),
            zap.String("client_ip", c.ClientIP()),
        )
    }
}
```

### 3.3 错误日志

```go
if err != nil {
    logger.Error("operation failed",
        zap.Error(err),
        zap.String("operation", "create_user"),
        zap.Any("params", params),
    )
}
```

## 四、日志级别策略

### 4.1 动态级别调整

```go
var atomicLevel = zap.NewAtomicLevelAt(zap.InfoLevel)

config := zap.Config{
    Level: atomicLevel,
}

atomicLevel.SetLevel(zap.DebugLevel)
```

### 4.2 环境配置

```yaml
development:
  level: debug
  format: console

production:
  level: info
  format: json
```

## 五、日志轮转

### 5.1 使用 lumberjack

```go
import "gopkg.in/natefinch/lumberjack.v2"

w := &lumberjack.Logger{
    Filename:   "/var/log/app/app.log",
    MaxSize:    100,
    MaxBackups: 3,
    MaxAge:     28,
    Compress:   true,
}

core := zapcore.NewCore(
    zapcore.NewJSONEncoder(zap.NewProductionEncoderConfig()),
    zapcore.AddSync(w),
    zap.InfoLevel,
)
logger := zap.New(core)
```

### 5.2 按日期分割

```go
func dailyRotateLog() *os.File {
    filename := fmt.Sprintf("app-%s.log", time.Now().Format("2006-01-02"))
    f, _ := os.OpenFile(filename, os.O_APPEND|os.O_CREATE|os.O_WRONLY, 0644)
    return f
}
```

## 六、敏感信息处理

### 6.1 脱敏规则

```go
func maskSensitive(key, value string) string {
    sensitiveKeys := []string{"password", "token", "secret", "credit_card"}
    for _, k := range sensitiveKeys {
        if strings.Contains(strings.ToLower(key), k) {
            if len(value) > 4 {
                return value[:2] + "****" + value[len(value)-2:]
            }
            return "****"
        }
    }
    return value
}
```

### 6.2 不记录敏感信息

```go
logger.Info("user login",
    zap.String("username", username),
)
```

## 七、最佳实践

1. **使用结构化日志**：JSON 格式便于检索
2. **包含上下文信息**：trace_id、user_id 等
3. **统一字段命名**：snake_case 或 camelCase
4. **合理设置级别**：生产环境至少 INFO
5. **避免日志过多**：影响性能和存储
6. **敏感信息脱敏**：保护用户隐私
