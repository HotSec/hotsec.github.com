# 安全数据工程

## 安全场景数据特点

| 特点 | 描述 |
|------|------|
| 高吞吐 | 全流量分析场景可达10Gbps+ |
| 实时性 | 告警检测要求秒级延迟 |
| 多源异构 | 日志、PCAP、情报、资产等多种数据源 |
| 时序性强 | 事件按时间顺序，需时序查询和关联 |
| 保留周期长 | 合规要求日志保留180天以上 |

## 消息队列：Kafka

### 在安全场景中的角色

```
采集端 → Kafka → 消费端（检测引擎/存储/分析）
```

| 用途 | 描述 |
|------|------|
| 流量日志分发 | 将解析后的网络日志分发到多个消费者 |
| 告警事件总线 | 检测引擎产出告警，下游系统消费 |
| 数据缓冲 | 削峰填谷，应对流量突发 |
| 解耦 | 采集与处理解耦，各模块独立扩展 |

### 关键配置

| 配置 | 安全场景建议 | 说明 |
|------|-------------|------|
| num.partitions | 按源IP/日志类型分区 | 保证有序性和并行度 |
| retention.ms | 7天（原始日志） | 平衡存储和回溯需求 |
| compression.type | lz4 | 高吞吐场景优先速度 |
| acks | all | 告警数据不丢失 |

### Go 客户端（confluent-kafka-go / sarama）

```go
func ProduceAlert(producer sarama.SyncProducer, alert Alert) error {
    msg := &sarama.ProducerMessage{
        Topic: "security-alerts",
        Key:   sarama.StringEncoder(alert.RuleID),
        Value: sarama.ByteEncoder(alert.JSON()),
    }
    _, _, err := producer.SendMessage(msg)
    return err
}

func ConsumeAlerts(consumer sarama.ConsumerGroup, handler func(Alert)) {
    for {
        consumer.Consume(context.Background(), []string{"security-alerts"},
            &AlertConsumerHandler{Fn: handler})
    }
}
```

## 搜索引擎：OpenSearch / Elasticsearch

### 在安全场景中的角色

| 用途 | 描述 |
|------|------|
| 日志存储与检索 | 存储归一化后的安全日志 |

| 会话索引 | Arkime SPI 数据存储 |
| 可视化 | Dashboard / Discover 界面 |

### 索引设计

```json
{
  "mappings": {
    "properties": {
      "timestamp":    { "type": "date" },
      "rule_id":      { "type": "keyword" },
      "severity":     { "type": "keyword" },
      "src_ip":       { "type": "ip" },
      "dst_ip":       { "type": "ip" },
      "src_port":     { "type": "integer" },
      "dst_port":     { "type": "integer" },
      "protocol":     { "type": "keyword" },
      "alert_msg":    { "type": "text", "analyzer": "standard" },
      "http_uri":     { "type": "text", "analyzer": "standard" },
      "dns_query":    { "type": "keyword" },
      "tls_sni":      { "type": "keyword" },
      "tags":         { "type": "keyword" },
      "confidence":   { "type": "float" }
    }
  }
}
```

### 索引生命周期（ILM）

| 阶段 | 时间 | 操作 |
|------|------|------|
| Hot | 0-7天 | 读写，主分片+副本 |
| Warm | 7-30天 | 只读，缩减副本，Force Merge |
| Cold | 30-90天 | 只读，冻结索引 |
| Delete | 90天后 | 删除 |

## 列式数据库：ClickHouse

### 在安全场景中的角色

| 用途 | 描述 |
|------|------|
| 大规模日志分析 | 百亿级日志的聚合查询 |
| 统计报表 | 攻击趋势、TopN、分布统计 |
| 行为基线 | 基于历史数据计算正常行为基线 |
| 威胁狩猎 | 大范围数据探索性查询 |

### 表设计

```sql
CREATE TABLE security_events (
    timestamp DateTime64(3),
    event_type LowCardinality(String),
    src_ip IPv4,
    dst_ip IPv4,
    src_port UInt16,
    dst_port UInt16,
    protocol LowCardinality(String),
    rule_id String,
    severity LowCardinality(String),
    alert_msg String,
    http_uri Nullable(String),
    dns_query Nullable(String),
    tls_sni Nullable(String),
    bytes_in UInt64,
    bytes_out UInt64,
    tags Array(String)
)
ENGINE = MergeTree()
PARTITION BY toYYYYMM(timestamp)
ORDER BY (event_type, timestamp, src_ip, dst_ip)
TTL timestamp + INTERVAL 180 DAY
```

### 典型查询

```sql
SELECT
    src_ip,
    count() AS alert_count,
    uniq(dst_ip) AS target_count,
    groupArray(distinct rule_id) AS rules
FROM security_events
WHERE timestamp >= now() - INTERVAL 1 HOUR
GROUP BY src_ip
HAVING alert_count > 100
ORDER BY alert_count DESC
LIMIT 20
```

### ClickHouse vs Elasticsearch

| 维度 | ClickHouse | Elasticsearch |
|------|-----------|---------------|
| 写入性能 | 极高（批量） | 高 |
| 聚合查询 | 极快 | 中等 |
| 全文检索 | 不擅长 | 擅长 |
| 实时性 | 秒级延迟 | 近实时 |
| 存储成本 | 低（列式压缩） | 较高 |
| 适用场景 | 统计分析、报表 | 日志检索、全文搜索 |

## 缓存：Redis

### 在安全场景中的角色

| 用途 | 描述 |
|------|------|
| 告警去重 | 存储已处理告警的哈希，TTL自动过期 |
| 速率计数 | 滑动窗口计数，检测扫描和暴力破解 |
| 会话状态 | 存储活跃连接和会话信息 |
| 情报缓存 | 缓存威胁情报查询结果 |
| 分布式锁 | 多实例协同处理 |

### 典型用法

```go
func IsDuplicateAlert(rdb *redis.Client, alert Alert) bool {
    key := fmt.Sprintf("alert:dedup:%s:%s:%s:%d",
        alert.RuleID, alert.SrcIP, alert.DstIP, alert.Timestamp/300)
    result, _ := rdb.SetNX(context.Background(), key, 1, 5*time.Minute).Result()
    return !result
}

func CheckScanRate(rdb *redis.Client, srcIP string, window time.Duration) bool {
    key := fmt.Sprintf("rate:scan:%s", srcIP)
    count, _ := rdb.Incr(context.Background(), key).Result()
    if count == 1 {
        rdb.Expire(context.Background(), key, window)
    }
    return count > 100
}
```

## 数据处理架构

### Lambda 架构

```
                    ┌──────────────┐
                    │  批处理层     │ ──→ ClickHouse（历史分析）
                    │ (离线分析)    │
  Kafka ──────────→ ├──────────────┤
                    │  速度层       │ ──→ Elasticsearch（实时检索）
                    │ (实时流处理)  │
                    └──────────────┘
```

### 实时流处理

| 组件 | 适用场景 |
|------|---------|
| Go 自研 | 高性能定制化检测引擎 |
| Flink | 复杂事件处理（CEP） |
| Kafka Streams | 轻量级流处理 |
| Go + go-streams | 纯Go流处理方案 |

### Go 实时检测引擎架构

```
Kafka消费 → 规则匹配引擎 → 告警输出
              │
              ├── 签名检测（Aho-Corasick多模式匹配）
              ├── 统计检测（滑动窗口计数）
              ├── 行为检测（状态机/序列匹配）
              └── 模型推理（gRPC调用ML服务）
```
