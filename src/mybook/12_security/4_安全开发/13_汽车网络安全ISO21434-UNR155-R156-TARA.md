## 二、UN R155 — 车辆网络安全法规

### 2.1 基本信息

| 项目 | 内容 |
|------|------|
| **全称** | UN Regulation No. 155 — Cyber security and cyber security management system |
| **目的** | 确保车辆在整个生命周期内的网络安全 |
| **适用于** | UNECE 1958 协议缔约国（54 个国家，包括欧盟、日本、韩国、英国等） |
| **生效时间** | 2021 年 1 月 |
| **强制时间** | 2022 年 7 月（新车型） / 2024 年 7 月（所有新车） |

### 2.2 核心框架

```
UN R155 = CSMS 认证 + VTA 型式认证

车辆制造商必须：
  ┌─────────────────────────────────────────────┐
  │  Step 1: 获得 CSMS 认证                       │
  │  证明企业具备网络安全管理能力                   │
  │  ┌─────────────────────────────────────┐    │
  │  │ CSMS (Cyber Security Management     │    │
  │  │       System) 要求                   │    │
  │  │                                     │    │
  │  │ • 组织架构：设立网络安全负责人         │    │
  │  │ • 流程体系：风险管理、变更管理、        │    │
  │  │   文档管理、供应链管理                │    │
  │  │ • 监控响应：安全监控、事件响应、        │    │
  │  │   信息共享                         │    │
  │  │ • 生命周期：设计→开发→生产→运维→报废  │    │
  │  └─────────────────────────────────────┘    │
  └──────────────────────┬──────────────────────┘
                         │
                         ▼
  ┌─────────────────────────────────────────────┐
  │  Step 2: 获得 VTA 认证                        │
  │  证明具体车型满足网络安全要求                   │
  └─────────────────────────────────────────────┘
```

### 2.3 CSMS 评估维度

| 评估维度 | 要求 |
|---------|------|
| **组织层面** | 领导层承诺、资源分配、人员能力建设 |
| **流程层面** | 风险管理、威胁建模、配置管理、供应链管理 |
| **响应层面** | 事件监测、应急响应、信息共享机制 |
| **生命周期** | 从概念设计到报废回收的全流程安全管理 |

### 2.4 中国应对

中国虽未加入 UNECE 1958 协议，但已制定等效标准：

| 标准 | 对标 | 说明 |
|------|------|------|
| **GB 44495-2024** | ISO/SAE 21434 | 中国汽车网络安全国家标准（2024 年发布） |
| **GB/T 电动汽车相关标准** | UN R155/R156 | 中国民用汽车网络安全法规体系 |

### 3.4 R155 vs R156

| 维度 | UN R155（网络安全） | UN R156（软件升级） |
|------|-------------------|-------------------|
| 管理体系 | **CSMS**（网络安全管理体系） | **SUMS**（软件升级管理体系） |
| 关注点 | 整车生命周期网络安全 | 软件升级安全合规 |
| 典型场景 | TARA 风险分析、渗透测试 | OTA 安全推送、版本管理、回滚 |
| 认证流程 | CSMS → VTA | SUMS → VTA |
| 编号系统 | — | **RXSWIN**（软件标识号） |

## 五、TARA — 威胁分析与风险评估

### 5.1 什么是 TARA

**TARA = Threat Analysis and Risk Assessment（威胁分析与风险评估）**

是整个汽车网络安全工程实施的**起点和核心**。定义在 ISO/SAE 21434 第 15 章（附录 G），但也是法规 R155 和标准 21434 的共同要求。

**目的**：在车辆概念设计阶段，系统性识别资产、威胁场景，评估风险等级，导出网络安全目标，为后续设计提供依据。

### 5.2 TARA 分析流程（七步法）

```
Step 1: 项目定义 (Item Definition)
  │  确定分析边界、功能、接口、数据流
  │
  ▼
Step 2: 资产识别 (Asset Identification)
  │  识别需要保护的资产（数据、功能、硬件等）
  │
  ▼
Step 3: 威胁场景识别 (Threat Scenario Identification)
  │  基于 STRIDE 等方法识别威胁
  │
  ▼
Step 4: 影响评级 (Impact Rating)
  │  评估威胁成功后的安全影响（安全/财产/隐私/运营）
  │
  ▼
Step 5: 攻击路径分析 (Attack Path Analysis)
  │  分析攻击可行性、所需能力、接触方式
  │
  ▼
Step 6: 攻击可行性评级 (Attack Feasibility Rating)
  │  评估攻击实施的可行性（基于攻击潜力因子）
  │
  ▼
Step 7: 风险判定与处置 (Risk Value Determination & Treatment)
  │  综合影响+可行性 → 风险等级 → 安全目标
```

### 5.3 TARA 关键公式与评分

#### 5.3.1 风险值计算

```
风险值 = 影响等级 (Impact) × 攻击可行性 (Attack Feasibility)

影响等级：
  Severe (严重)    = 4
  Major (重大)     = 3
  Moderate (中等)  = 2
  Negligible (可忽略) = 1

攻击可行性：
  High (高)        = 4
  Medium (中)      = 3
  Low (低)         = 2
  Very Low (极低)  = 1

风险值 ≥ 9  → 需要处置（制订安全目标）
风险值 < 9  → 可接受或保留
```

#### 5.3.2 影响维度评估

| 维度 | 评级标准 |
|------|---------|
| **Safety（安全）** | 对驾乘人员/道路参与者的物理伤害 |
| **Financial（财产）** | 对车辆拥有者/制造商的直接经济损失 |
| **Operational（运营）** | 对车辆功能/服务的不可用影响 |
| **Privacy（隐私）** | 对用户隐私数据的泄露或滥用 |

### 5.4 威胁建模方法

| 方法 | 来源 | 说明 |
|------|------|------|
| **STRIDE** | 微软 | 欺骗/篡改/否认/信息披露/拒绝服务/权限提升，六大威胁分类 |
| **攻击树（Attack Tree）** | 通用 | 层级结构，攻击目标 → 子目标 → 攻击手段 |
| **EVITA** | 欧盟项目 | 汽车专用，基于安全属性评估 |
| **HEAVENS** | 欧盟项目 | 汽车网络安全威胁建模框架 |

```python
# TARA 风险计算简易实现
from dataclasses import dataclass
from enum import Enum

class ImpactLevel(Enum):
    NEGLIGIBLE = 1
    MODERATE = 2
    MAJOR = 3
    SEVERE = 4

class FeasibilityLevel(Enum):
    VERY_LOW = 1
    LOW = 2
    MEDIUM = 3
    HIGH = 4

@dataclass
class TARAResult:
    asset: str
    threat: str
    impact: ImpactLevel
    feasibility: FeasibilityLevel
    risk_value: int  # impact × feasibility

    @property
    def needs_mitigation(self) -> bool:
        return self.risk_value >= 9

    @property
    def risk_level(self) -> str:
        if self.risk_value >= 12:
            return "CRITICAL"
        elif self.risk_value >= 9:
            return "HIGH"
        elif self.risk_value >= 6:
            return "MEDIUM"
        else:
            return "LOW"

# 示例
result = TARAResult(
    asset="远程控车API",
    threat="未授权攻击者通过API远程控制车辆转向",
    impact=ImpactLevel.SEVERE,       # 4 → 安全影响
    feasibility=FeasibilityLevel.MEDIUM,  # 3 → 中等可行性
    risk_value=12  # 4 × 3 = 12 → CRITICAL, 必须处置
)
print(f"风险等级: {result.risk_level}, 需处置: {result.needs_mitigation}")
# 输出: 风险等级: CRITICAL, 需处置: True
```

### 5.5 TARA 分析示例（简化版）

| 资产 | 威胁（STRIDE） | 影响 | 可行性 | 风险值 | 处置 |
|------|---------------|------|--------|--------|------|
| 远程控车API | 欺骗 - 伪造身份控制车辆 | Severe(4) | Medium(3) | **12** | 双向TLS + 数字签名 |
| OTA升级包 | 篡改 - 注入恶意固件 | Severe(4) | Low(2) | **8** | 代码签名 + 完整性校验 |
| 用户位置数据 | 信息披露 - 泄露轨迹 | Major(3) | Medium(3) | **9** | 数据加密 + 脱敏 |
| 车载WiFi | 权限提升 - 入侵网关 | Major(3) | High(4) | **12** | 网络隔离 + 防火墙 |
| 诊断接口(OBD) | 拒绝服务 - 恶意指令 | Moderate(2) | High(4) | **8** | 认证 + 速率限制 |

> 风险值 ≥ 9 → **必须制订安全目标（Cybersecurity Goal）** 并采取缓解措施。

## 六、合规实施路线图

## 九、一句话总结

> **UN R155/R156 是"法律门槛"（不做不能卖车），ISO 21434 是"技术手册"（告诉你怎么做），TARA 是"核心引擎"（从风险出发推导安全需求）。三者构成汽车网络安全的完整三角：法规要求 → 标准落地 → 方法执行。**
