# 网络流量安全分析

## 全流量安全分析概述

### 定义

全流量安全分析（Full Traffic Analysis）是对网络中所有通信流量进行采集、解析、检测和分析的安全技术，是 NDR、IDS 等安全产品的核心能力。

### 核心能力

| 能力 | 描述 |
|------|------|
| 流量采集 | 镜像端口/旁路抓包，零侵入获取全量网络流量 |
| 协议解析 | 识别并解析各层网络协议，提取元数据和载荷 |
| 日志分析 | 从流量中提取会话日志、DNS日志、HTTP日志等 |
| 规则检测 | 基于签名规则匹配已知攻击模式 |
| 威胁发现 | 通过行为分析、统计模型发现未知威胁 |
| 资产识别 | 从流量中自动发现和识别网络资产 |

### 数据处理链路

```
流量采集 → 协议解析 → 会话重组 → 元数据提取 → 规则检测/行为分析 → 告警生成 → 关联分析 → 响应处置
```

## 网络协议解析

### 协议栈分层

| 层级 | 协议 | 安全关注点 |
|------|------|-----------|
| 网络层 | IP, ICMP | IP欺骗、分片攻击、ICMP隧道 |
| 传输层 | TCP, UDP | 端口扫描、SYN Flood、会话劫持 |
| 会话层 | TLS/SSL | 证书伪造、弱加密套件、SNI泄露 |
| 应用层 | HTTP, DNS, SMB, FTP | Web攻击、DNS隧道、SMB漏洞、FTP暴力破解 |

### TCP/IP 协议

#### TCP 三次握手与安全

```
客户端                    服务端
  |---- SYN (seq=x) ----->|        ← SYN Flood 攻击点
  |<-- SYN+ACK (seq=y, ---|        ← 会话劫持攻击点
  |    ack=x+1)           |
  |---- ACK (ack=y+1) -->|        ← 序列号预测攻击点
```

#### 关键字段

- **Flags**：SYN/ACK/FIN/RST/PSH/URG，用于识别扫描和异常行为
- **Sequence Number**：用于会话重组和劫持检测
- **Window Size**：流量控制和侧信道分析
- **Options**：MSS/Timestamp/SACK，指纹识别依据

### HTTP 协议

#### 安全关注点

| 攻击类型 | 检测方法 |
|---------|---------|
| SQL注入 | 请求参数中的SQL关键字和特殊字符模式匹配 |
| XSS | 响应中未转义的用户输入检测 |
| 命令注入 | 系统命令关键字和特殊字符模式匹配 |
| 文件包含 | 路径遍历特征（../、/etc/passwd） |
| Webshell | 上传文件内容和响应特征匹配 |
| C2通信 | User-Agent异常、心跳间隔、URI模式 |

#### 元数据提取

- 请求方法、URI、Host、User-Agent
- 响应状态码、Content-Type、Content-Length
- Cookie、Referer、X-Forwarded-For

### DNS 协议

#### 安全关注点

| 攻击类型 | 检测方法 |
|---------|---------|
| DNS隧道 | 域名长度、子域名层级、TXT记录异常 |
| DGA域名 | 域名熵值、n-gram分析、ML分类 |
| DNS劫持 | 响应IP与预期不符 |
| Fast Flux | 同域名短时间解析到大量不同IP |
| NXDOMAIN Flood | 大量不存在的域名查询 |

#### 关键字段

- 查询类型（A/AAAA/MX/TXT/CNAME/NS）
- 域名长度、标签数量、字符分布
- TTL值、响应码

### TLS 协议

#### 安全关注点

| 关注点 | 描述 |
|--------|------|
| SNI | 明文传输的服务器名称，可识别目标域名 |
| 证书链 | 自签名证书、过期证书、伪造CA |
| 加密套件 | 弱加密算法（RC4、DES）检测 |
| 协议版本 | SSLv3/TLS1.0 已不安全 |
| JA3/JA3S | TLS客户端/服务端指纹，识别恶意软件 |

#### JA3 指纹

对 TLS Client Hello 的关键字段做 MD5 哈希，生成客户端指纹：

```
JA3 = MD5(TLSVersion,Ciphers,Extensions,EllipticCurves,EllipticCurvePointFormats)
```

用途：识别恶意软件的TLS通信特征，即使无法解密流量也能检测。

### SMB 协议

#### 安全关注点

- **MS17-010 (EternalBlue)**：SMBv1 漏洞，远程代码执行
- **SMB签名**：未启用签名可被中间人攻击
- **SMB Relay**：NTLM中继攻击
- **横向移动**：PsExec、WMI、IPC$ 共享利用

#### 检测要点

- SMBv1 协议使用检测
- 异常共享访问（C$、ADMIN$）
- 横向移动模式（大量主机间SMB连接）

### FTP 协议

#### 安全关注点

- 明文传输凭据
- 匿名登录
- FTP Bounce 攻击
- 暴力破解

## 流量采集技术

### 采集方式

| 方式 | 原理 | 优缺点 |
|------|------|--------|
| 端口镜像 | 交换机将流量副本发送到监控端口 | 零侵入，但可能丢包 |
| 网络分路器(TAP) | 物理设备复制链路流量 | 精确，但需硬件部署 |
| 内核抓包 | libpcap/af_packet 直接读取 | 性能依赖内核优化 |
| eBPF | 内核态过滤和预处理 | 高性能，可编程 |

### 高性能抓包

| 技术 | 描述 |
|------|------|
| PF_RING | 内核模块加速包捕获，支持零拷贝 |
| DPDK | 用户态网卡驱动，绕过内核协议栈 |
| AF_PACKET V3 | Linux 原生高性能抓包，支持 mmap |
| XDP | eBPF 极速包处理，在网卡驱动层执行 |

### 数据包处理框架

| 框架 | 语言 | 特点 |
|------|------|------|
| libpcap | C | 最基础的抓包库 |
| gopacket | Go | Go语言封装，支持解码和注入 |
| scapy | Python | 灵活的包操作和协议分析 |
| dpkt | Python | 快速、简单的包解析 |
| pyshark | Python | Wireshark/tshark 的 Python 封装 |

## 会话重组与元数据提取

### 会话重组

网络流量是分片传输的，需要将数据包重组为完整的会话：

1. **IP分片重组**：处理MTU导致的IP分片
2. **TCP流重组**：按序列号排序，处理重传和乱序
3. **应用层协议识别**：基于端口、DPI、行为特征识别协议
4. **应用层数据提取**：从重组后的流中提取请求和响应

### 元数据（Metadata）

从流量中提取的关键信息，用于快速检索和分析：

| 类别 | 字段 |
|------|------|
| 五元组 | 源IP、目的IP、源端口、目的端口、协议 |
| 时间 | 开始时间、结束时间、持续时间 |
| 字节 | 上行字节、下行字节、总字节 |
| 包数 | 上行包数、下行包数 |
| 应用层 | HTTP URI/DNS域名/TLS SNI/SMB共享名 |

### PCAP 与 PCAPNG

| 格式 | 特点 |
|------|------|
| PCAP | 传统格式，单一切片，最大4GB |
| PCAPNG | 新格式，支持多接口、注释、自定义块 |
