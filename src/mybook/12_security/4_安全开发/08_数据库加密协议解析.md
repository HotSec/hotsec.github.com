# 数据库加密协议解析

## 概述

数据库加密协议是数据库客户端与服务端之间建立安全通信通道的协议，用于保护传输中的SQL语句、查询结果、认证凭据等敏感数据不被窃听和篡改。

### 各数据库加密方式总览

| 数据库 | 加密方式 | 默认端口 | 协议特点 |
|--------|---------|---------|---------|
| MySQL | SSL/TLS（握手嵌入MySQL协议） | 3306 | 自有协议内嵌TLS协商 |
| PostgreSQL | SSL/TLS（SSLRequest协商） | 5432 | 独立SSLRequest包协商 |
| SQL Server | TDS + TLS（Pre-Login协商） | 1433 | TDS协议内嵌加密协商 |
| Oracle | TNS + TLS/ANO | 1521 | TNS协议内嵌加密协商 |
| Redis | TLS（6.0+） | 6379 | 标准TLS握手 |
| MongoDB | TLS/SSL | 27017 | 标准TLS握手 |
| ClickHouse | TLS | 9000/8443 | 标准TLS握手 |

### 加密协商模式分类

| 模式 | 描述 | 代表 |
|------|------|------|
| 协议内嵌协商 | 数据库私有协议中嵌入加密协商字段 | MySQL、SQL Server、Oracle |
| 独立协商包 | 连接建立后先发送加密协商请求 | PostgreSQL |
| 标准TLS | 直接在TCP上做TLS握手 | Redis、MongoDB |

## MySQL 加密协议

### 连接阶段总览

```
客户端                              服务端
  |---- TCP连接 ------------------>|        三次握手
  |<--- Initial Handshake Packet --|        服务端发送握手包
  |---- SSL Connection Request --->|        客户端请求SSL（如需加密）
  |<=== TLS 握手 ===>             |        标准TLS握手过程
  |---- Handshake Response ------->|        认证信息（已加密）
  |<--- OK/ERR Packet ------------|        认证结果
```

### Initial Handshake Packet

服务端在TCP连接建立后发送的第一个包：

| 字段 | 长度 | 描述 |
|------|------|------|
| protocol_version | 1 | 协议版本（10=MySQL 4.1+） |
| server_version | string<EOF> | 服务端版本字符串 |
| connection_id | 4 | 连接/线程ID |
| auth_plugin_data_part_1 | 8 | 认证插件数据第一部分 |
| filler | 1 | 0x00 |
| capability_flag_1 | 2 | 能力标志低位 |
| character_set | 1 | 字符集 |
| status_flags | 2 | 状态标志 |
| capability_flag_2 | 2 | 能力标志高位 |
| auth_plugin_data_len | 1 | 认证插件数据长度 |
| reserved | 10 | 保留 |
| auth_plugin_data_part_2 | string<EOF> | 认证插件数据第二部分 |

### Capability Flags 与 SSL

客户端通过 capability flags 告知服务端是否支持 SSL：

| 标志 | 值 | 描述 |
|------|-----|------|
| CLIENT_SSL | 0x00002000 | 客户端支持SSL加密 |

判断流程：

```
1. 服务端在Initial Handshake Packet中设置CLIENT_SSL标志
2. 客户端检查服务端是否支持SSL
3. 如果客户端需要SSL且服务端支持：
   a. 客户端发送SSL Connection Request包
   b. 双方进行标准TLS握手
   c. TLS握手完成后，客户端在加密通道内发送Handshake Response
4. 如果不使用SSL：
   a. 客户端直接发送Handshake Response（明文）
```

### SSL Connection Request 包

```
4字节：payload长度
1字节：序列号=1
4字节：capability_flags（含CLIENT_SSL）
4字节：max_packet_size
1字节：character_set
23字节：reserved（全0）
```

此包之后立即开始标准 TLS 握手。

### MySQL 协议包通用格式

```
+------------------+------------------+------------------+
| payload_length   | sequence_id      | payload          |
| (3 bytes, LE)    | (1 byte)         | (variable)       |
+------------------+------------------+------------------+
```

| 字段 | 长度 | 描述 |
|------|------|------|
| payload_length | 3 | 载荷长度（小端序），最大16MB |
| sequence_id | 1 | 序列号，每轮递增 |
| payload | variable | 实际数据 |

### MySQL 加密配置

```ini
# my.cnf
[mysqld]
ssl-ca     = /etc/mysql/ca.pem
ssl-cert   = /etc/mysql/server-cert.pem
ssl-key    = /etc/mysql/server-key.pem
require_secure_transport = ON

[client]
ssl-ca     = /etc/mysql/ca.pem
ssl-cert   = /etc/mysql/client-cert.pem
ssl-key    = /etc/mysql/client-key.pem
ssl-mode   = REQUIRED
```

| ssl-mode 值 | 描述 |
|-------------|------|
| DISABLED | 不使用SSL |
| PREFERRED | 优先SSL，失败回退明文 |
| REQUIRED | 必须SSL，不验证证书 |
| VERIFY_CA | 必须SSL，验证CA证书 |
| VERIFY_IDENTITY | 必须SSL，验证CA和主机名 |

### 流量识别特征

| 特征 | 明文 | SSL |
|------|------|-----|
| 首包 | 包含MySQL版本字符串 | 同左（握手包在TLS之前） |
| 后续包 | 可见SQL语句明文 | TLS加密不可读 |
| 端口 | 3306 | 3306（同端口） |
| JA3指纹 | 无 | 可提取TLS客户端指纹 |

## PostgreSQL 加密协议

### 连接阶段总览

```
客户端                              服务端
  |---- TCP连接 ------------------>|        三次握手
  |---- SSLRequest --------------->|        请求SSL加密
  |<--- 'S' ----------------------|        服务端同意SSL
  |<=== TLS 握手 ===>             |        标准TLS握手
  |---- StartupMessage ----------->|        协议版本+参数（已加密）
  |<--- AuthenticationRequest ----|        认证请求
  |---- PasswordMessage --------->|        密码（已加密）
  |<--- AuthenticationOk --------|        认证成功
```

### SSLRequest 消息格式

```
+--------+--------+
| Length | Code   |
| 4字节  | 4字节  |
+--------+--------+
```

| 字段 | 值 | 描述 |
|------|-----|------|
| Length | 8 | 消息长度（含自身） |
| Code | 80877103 | SSL请求魔数 |

### 服务端响应

| 响应字节 | 含义 |
|---------|------|
| 'S' (0x53) | 同意SSL，接下来进行TLS握手 |
| 'N' (0x4E) | 拒绝SSL，客户端决定是否继续明文 |

### GSSAPI 加密请求

PostgreSQL 还支持 GSSAPI 加密：

| 请求类型 | 魔数 | 响应 |
|---------|------|------|
| SSLRequest | 80877103 | 'S'/'N' |
| GSSEncryptRequest | 80877104 | 'G'/'N' |

### 加密协商优先级

```
1. 如果配置了GSSAPI凭据缓存 → 先尝试GSSEncryptRequest
2. 如果GSSAPI失败或未配置 → 尝试SSLRequest
3. 如果SSL也被拒绝 → 根据sslmode配置决定是否继续
4. 如果都成功 → 设置ssl_done和gss_done标志
```

### StartupMessage 格式

SSL协商完成后发送：

```
+--------+----------------+----------+----------+-----+
| Length | ProtocolVersion| key1     | value1   | ... | \0 |
| 4字节  | 4字节          | string   | string   |     |    |
+--------+----------------+----------+----------+-----+
```

| 字段 | 描述 |
|------|------|
| ProtocolVersion | 3.0 = 0x00030000, 3.x = 196608 |
| key/value | user, database, application_name, client_encoding 等 |

### sslmode 参数

| sslmode | 描述 |
|---------|------|
| disable | 不使用SSL |
| allow | 优先非SSL，失败回退SSL |
| prefer | 优先SSL，失败回退非SSL（默认） |
| require | 必须SSL，不验证证书 |
| verify-ca | 必须SSL，验证CA证书 |
| verify-full | 必须SSL，验证CA和主机名 |

### PostgreSQL 加密配置

```ini
# postgresql.conf
ssl = on
ssl_ca_file = '/etc/postgresql/root.crt'
ssl_cert_file = '/etc/postgresql/server.crt'
ssl_key_file = '/etc/postgresql/server.key'
ssl_ciphers = 'HIGH:MEDIUM:+3DES:!aNULL'
ssl_prefer_server_ciphers = on

# pg_hba.conf
hostssl all all 0.0.0.0/0 md5
```

### 流量识别特征

| 特征 | 明文 | SSL |
|------|------|-----|
| 首包 | 8字节SSLRequest或StartupMessage | 同左（协商包在TLS之前） |
| 认证 | 明文可见用户名和密码哈希 | TLS加密 |
| 端口 | 5432 | 5432（同端口） |
| 协商包 | 8字节（Length=8, Code=80877103） | 同左 |

## SQL Server TDS 加密协议

### TDS 协议概述

TDS（Tabular Data Stream）是 SQL Server 的应用层通信协议，加密协商嵌入在 TDS 协议内部。

### TDS 版本

| TDS版本 | SQL Server版本 |
|---------|---------------|
| 4.2 | SQL Server 6.5 |
| 7.0 | SQL Server 7.0 |
| 7.1 | SQL Server 2000 |
| 7.2 | SQL Server 2005 |
| 7.3A/B | SQL Server 2008 |
| 7.4 | SQL Server 2012+ |

### 连接阶段总览

```
客户端                              服务端
  |---- TCP连接 ------------------>|        三次握手
  |---- TDS Pre-Login ------------>|        协商版本和加密
  |<--- TDS Pre-Login Response ---|        服务端响应
  |<=== TLS 握手 ===>             |        标准TLS握手（如需加密）
  |---- TDS Login7 --------------->|        登录认证（可能加密）
  |<--- TDS Login Response -------|        登录结果
  |---- TDS SQL Batch ------------>|        SQL请求
  |<--- TDS Response -------------|        查询结果
```

### TDS 包头格式（8字节）

```
+------+--------+--------+------+----------+--------+
| Type | Status | Length | SPID | PacketID | Window |
| 1B   | 1B     | 2B     | 2B   | 1B       | 1B     |
+------+--------+--------+------+----------+--------+
```

| 字段 | 描述 |
|------|------|
| Type | 包类型（0x12=Pre-Login, 0x10=Login7, 0x01=SQL Batch, 0x04=Response） |
| Status | 0x00=正常, 0x01=最后一个包 |
| Length | 包总长度（含包头） |
| SPID | 服务端进程ID |
| PacketID | 包序号 |
| Window | 保留 |

### Pre-Login 协商

Pre-Login 包用于协商连接参数，包括是否启用加密：

```
TDS包头(8B) + 字段指示头 + 负载数据
```

字段指示头格式：Token(1B) + Offset(2B) + Length(2B)

| Token | 值 | 描述 |
|-------|-----|------|
| VERSION | 0x00 | 客户端/服务端版本 |
| ENCRYPTION | 0x01 | 加密选项 |
| INSTOPT | 0x02 | 实例名 |
| THREADID | 0x03 | 客户端线程ID |
| MARS | 0x04 | MARS支持 |
| TRACEID | 0x05 | 跟踪ID |
| FEDAUTHREQUIRED | 0x06 | 联合认证 |
| TERMINATOR | 0xFF | 字段结束 |

### ENCRYPTION Token 值

| 值 | 描述 |
|-----|------|
| 0x00 | ENCRYPT_OFF（不加密，但可接受加密） |
| 0x01 | ENCRYPT_ON（必须加密） |
| 0x02 | ENCRYPT_NOT_SUP（不支持加密） |
| 0x03 | ENCRYPT_REQ（服务端要求加密） |

### 加密协商流程

```
客户端Encryption值    服务端Encryption值    结果
ENCRYPT_ON(0x01)  →  ENCRYPT_ON(0x01)    TLS握手 → 加密连接
ENCRYPT_OFF(0x00) →  ENCRYPT_OFF(0x00)   明文连接
ENCRYPT_OFF(0x00) →  ENCRYPT_REQ(0x03)   TLS握手 → 加密连接
ENCRYPT_ON(0x01)  →  ENCRYPT_NOT_SUP(0x02) 连接失败
ENCRYPT_NOT_SUP(0x02) → ENCRYPT_ON(0x01) 连接失败
```

### Login7 包格式

```
TDS包头(8B) + 登录报头(36B) + 字段指示头 + 信息
```

登录报头关键字段：

| 字段 | 长度 | 描述 |
|------|------|------|
| Length | 4 | 登录包总长度 |
| TDSVersion | 4 | TDS协议版本 |
| PacketSize | 4 | 包大小 |
| ClientProgVer | 4 | 客户端库版本 |
| ClientPID | 4 | 客户端进程ID |
| OptionFlags1 | 1 | 选项标志1（含加密标志） |
| OptionFlags2 | 1 | 选项标志2 |

字段指示头包含：HostName、UserName、Password、AppName、ServerName、CltIntName、Language、Database、SSPI等。

### TDS Response Token 类型

| TokenType | 值 | 描述 |
|-----------|-----|------|
| COLMETADATA | 0x81 | 列元数据 |
| ROW | 0xD1 | 数据行 |
| DONE | 0xFD | 完成 |
| ERROR | 0xAA | 错误 |
| INFO | 0xAB | 信息 |
| LOGINACK | 0xAD | 登录确认 |
| ENVCHANGE | 0xE3 | 环境变更 |
| RETURNSTATUS | 0x79 | RPC返回状态 |

### SQL Server 加密配置

```sql
-- 查看当前加密状态
SELECT encrypt_option FROM sys.dm_exec_connections;

-- 强制加密连接
-- SQL Server Configuration Manager:
-- SQL Server Network Configuration → Properties → ForceEncryption = Yes
```

连接字符串：

```
# 加密连接
Server=host;Database=db;User Id=user;Password=pwd;Encrypt=True;TrustServerCertificate=False;

# 不加密
Server=host;Database=db;User Id=user;Password=pwd;Encrypt=False;
```

### 流量识别特征

| 特征 | 明文 | 加密 |
|------|------|------|
| Pre-Login | 可见版本号、实例名 | 同左（Pre-Login在TLS之前） |
| Login7 | 可见用户名、密码 | TLS加密后不可见 |
| SQL语句 | 可见明文SQL | TLS加密 |
| 端口 | 1433 | 1433（同端口） |
| TDS包头 | Type=0x12(Pre-Login) | 同左 |

## Oracle TNS 加密协议

### TNS 协议概述

TNS（Transparent Network Substrate）是 Oracle 的网络通信协议，加密通过 TNS 协议内嵌的协商机制或 TLS 实现。

### TNS 包头格式（8字节）

```
+--------+--------+--------+--------+--------+--------+--------+--------+
| Length | Packet | Type   | Reserved| Header | Data   | Data   | Data   |
| (2B)   | Chksum | (1B)   | (1B)   | Chksum | Flags |        |        |
|        | (2B)   |        |        | (2B)   | (1B)   |        |        |
+--------+--------+--------+--------+--------+--------+--------+--------+
```

| 字段 | 长度 | 描述 |
|------|------|------|
| Length | 2 | 包长度 |
| Packet Checksum | 2 | 包校验和 |
| Type | 1 | 包类型 |
| Reserved | 1 | 保留 |
| Header Checksum | 2 | 头校验和 |
| Data | variable | 数据 |

### TNS 包类型

| Type值 | 描述 |
|--------|------|
| 0x01 | CONNECT（连接请求） |
| 0x02 | ACCEPT（接受连接） |
| 0x03 | ACK（确认） |
| 0x04 | REFUSE（拒绝） |
| 0x06 | DATA（数据传输） |
| 0x07 | RESEND（重发） |
| 0x08 | MARKER（中断标记） |
| 0x09 | ATTENTION（注意） |
| 0x0B | RECONNECT（重连） |

### 连接阶段总览

```
客户端                              服务端
  |---- TCP连接 ------------------>|        三次握手
  |---- TNS CONNECT --------------->|        连接请求（含服务名）
  |<--- TNS ACCEPT ----------------|        接受连接
  |---- TNS DATA (NSPTCN) -------->|        协商参数（含加密选项）
  |<--- TNS DATA (NSPTAC) --------|        接受协商
  |<=== TLS/ANO 握手 ===>         |        加密协商
  |---- TNS DATA (认证) ---------->|        认证数据（已加密）
  |<--- TNS DATA (认证结果) -------|        认证结果
```

### Oracle 网络加密方式

| 方式 | 描述 |
|------|------|
| TLS | 标准TLS加密，基于证书 |
| ANO（Advanced Network Option） | Oracle自有加密，支持RC4/AES等 |
| DH（Diffie-Hellman） | 密钥协商，不验证身份 |
| RSA | 基于RSA的密钥交换和身份验证 |

### sqlnet.ora 加密配置

```ini
# sqlnet.ora
SQLNET.ENCRYPTION_SERVER = REQUIRED
SQLNET.ENCRYPTION_TYPES_SERVER = (AES256, AES192, AES128)
SQLNET.CRYPTO_CHECKSUM_SERVER = REQUIRED
SQLNET.CRYPTO_CHECKSUM_TYPES_SERVER = (SHA256, SHA1)

SQLNET.ENCRYPTION_CLIENT = REQUIRED
SQLNET.ENCRYPTION_TYPES_CLIENT = (AES256, AES192, AES128)
SQLNET.CRYPTO_CHECKSUM_CLIENT = REQUIRED
SQLNET.CRYPTO_CHECKSUM_TYPES_CLIENT = (SHA256, SHA1)
```

| 参数值 | 描述 |
|--------|------|
| ACCEPTED | 接受加密但不要求 |
| REJECTED | 拒绝加密 |
| REQUESTED | 请求加密但不强制 |
| REQUIRED | 强制加密 |

### 流量识别特征

| 特征 | 明文 | 加密 |
|------|------|------|
| TNS CONNECT | 可见服务名、版本 | 同左（CONNECT在加密之前） |
| 后续DATA | 可见SQL语句 | 加密后不可见 |
| 端口 | 1521 | 1521（同端口） |
| 包头 | Type=0x01(CONNECT) | 同左 |

## Redis 加密协议

### TLS 支持

Redis 6.0+ 原生支持 TLS 加密。

### 连接阶段

```
客户端                              服务端
  |---- TCP连接 ------------------>|        三次握手
  |<=== TLS 握手 ===>             |        标准TLS握手
  |---- AUTH/PING ---------------->|        Redis命令（已加密）
  |<--- +OK/-ERR -----------------|        响应（已加密）
```

### RESP 协议

Redis 使用 RESP（REdis Serialization Protocol）协议，TLS 加密后 RESP 内容不可见：

```
*2\r\n$4\r\nAUTH\r\n$8\r\npassword\r\n
*1\r\n$4\r\nPING\r\n
*3\r\n$3\r\nSET\r\n$3\r\nkey\r\n$5\r\nvalue\r\n
```

### Redis TLS 配置

```ini
# redis.conf
port 0
tls-port 6379
tls-cert-file /etc/redis/server.crt
tls-key-file /etc/redis/server.key
tls-ca-cert-file /etc/redis/ca.crt
tls-auth-clients optional
tls-replication yes
tls-cluster yes
```

### 流量识别特征

| 特征 | 明文 | TLS |
|------|------|-----|
| 首包 | 可见RESP命令 | TLS握手 |
| 命令 | 可见SET/GET/AUTH | 加密不可见 |
| 端口 | 6379 | 6379 |

## MongoDB 加密协议

### 连接阶段

```
客户端                              服务端
  |---- TCP连接 ------------------>|        三次握手
  |<=== TLS 握手 ===>             |        标准TLS握手
  |---- OP_MSG/isMaster ---------->|        MongoDB命令（已加密）
  |<--- OP_MSG/isMaster响应 ------|        响应（已加密）
  |---- OP_MSG/saslStart --------->|        SASL认证（已加密）
  |<--- OP_MSG/saslStart响应 -----|        认证结果
```

### MongoDB Wire Protocol

| OP类型 | 值 | 描述 |
|--------|-----|------|
| OP_REPLY | 1 | 响应（已废弃） |
| OP_UPDATE | 2001 | 更新（已废弃） |
| OP_INSERT | 2002 | 插入（已废弃） |
| OP_QUERY | 2004 | 查询（已废弃） |
| OP_MSG | 2013 | 通用消息（3.6+推荐） |

### MongoDB TLS 配置

```yaml
# mongod.conf
net:
  tls:
    mode: requireTLS
    certificateKeyFile: /etc/mongodb/server.pem
    CAFile: /etc/mongodb/ca.pem
    allowConnectionsWithoutCertificates: false
```

| tls mode | 描述 |
|----------|------|
| disabled | 不使用TLS |
| allowTLS | 允许TLS和明文 |
| preferTLS | 优先TLS |
| requireTLS | 必须TLS |

### 流量识别特征

| 特征 | 明文 | TLS |
|------|------|-----|
| 首包 | OP_MSG/isMaster | TLS握手 |
| 命令 | 可见CRUD操作 | 加密不可见 |
| 端口 | 27017 | 27017 |

## 安全审计中的数据库加密协议解密

### 解密方式

| 方式 | 描述 | 适用场景 |
|------|------|---------|
| 证书导入 | 将数据库审计设备的CA证书导入数据库服务端 | 数据库审计产品 |
| 授权账户 | 使用数据库账户凭据进行SSL协商 | 旁路审计 |
| 代理模式 | 客户端→代理（解密）→服务端 | 中间人审计 |
| 会话密钥 | 从数据库进程内存提取会话密钥 | 取证分析 |

### 证书导入方式

```
1. 数据库审计设备生成CA证书
2. 将CA证书导入数据库服务端信任库
3. 审计设备作为中间人，与客户端和服务端分别建立TLS连接
4. 审计设备解密流量进行SQL审计
```

### 代理模式

```
客户端 ←→ 审计代理（解密+审计） ←→ 数据库服务端
   TLS-1              明文/重新TLS-2
```

### 各数据库解密要点

| 数据库 | 解密关键点 |
|--------|-----------|
| MySQL | 解析Initial Handshake Packet获取capability flags，识别SSL协商 |
| PostgreSQL | 识别8字节SSLRequest包（Code=80877103），协商后进行TLS |
| SQL Server | 解析TDS Pre-Login包ENCRYPTION Token，判断加密模式 |
| Oracle | 解析TNS CONNECT包，识别ANO协商参数 |
| Redis | 直接在TCP层进行TLS握手 |
| MongoDB | 直接在TCP层进行TLS握手 |

### MySQL 协议解析

```go
func ParseMySQLHandshake(data []byte) (*MySQLHandshake, error) {
    if len(data) < 4 {
        return nil, fmt.Errorf("packet too short")
    }
    offset := 0
    proto := data[offset]
    offset++

    versionEnd := bytes.IndexByte(data[offset:], 0x00)
    version := string(data[offset : offset+versionEnd])
    offset += versionEnd + 1

    connID := binary.LittleEndian.Uint32(data[offset:])
    offset += 4

    authData1 := data[offset : offset+8]
    offset += 8 + 1

    capLower := binary.LittleEndian.Uint16(data[offset:])
    offset += 2
    charset := data[offset]
    offset++
    statusFlags := binary.LittleEndian.Uint16(data[offset:])
    offset += 2
    capUpper := binary.LittleEndian.Uint16(data[offset:])
    offset += 2

    capability := uint32(capUpper)<<16 | uint32(capLower)
    hasSSL := capability&0x00002000 != 0

    return &MySQLHandshake{
        ProtocolVersion: proto,
        ServerVersion:   version,
        ConnectionID:    connID,
        AuthData1:       authData1,
        Capability:      capability,
        Charset:         charset,
        StatusFlags:     statusFlags,
        HasSSL:          hasSSL,
    }, nil
}
```

```go
func ParsePgSSLRequest(data []byte) (isSSLRequest bool, err error) {
    if len(data) < 8 {
        return false, fmt.Errorf("packet too short")
    }
    length := binary.BigEndian.Uint32(data[0:4])
    code := binary.BigEndian.Uint32(data[4:8])
    if length == 8 && code == 80877103 {
        return true, nil
    }
    return false, nil
```

### TDS Pre-Login 解析

```go
type TDSPreLogin struct {
    Version    []byte
    Encryption byte
    Instance   string
    ThreadID   []byte
    Mars       byte
}

func ParseTDSPreLogin(data []byte) (*TDSPreLogin, error) {
    if len(data) < 8 {
        return nil, fmt.Errorf("TDS header too short")
    }
    offset := 8
    result := &TDSPreLogin{}

    for offset < len(data) {
        token := data[offset]
        offset++
        if token == 0xFF {
            break
        }
        if offset+4 > len(data) {
            break
        }
        off := int(binary.BigEndian.Uint16(data[offset:]))
        offset += 2
        length := int(binary.BigEndian.Uint16(data[offset:]))
        offset += 2

        switch token {
        case 0x00:
            if off+length <= len(data) {
                result.Version = data[off : off+length]
            }
        case 0x01:
            if off+1 <= len(data) {
                result.Encryption = data[off]
            }
        case 0x02:
            if off+length <= len(data) {
                result.Instance = string(data[off : off+length])
            }
        case 0x03:
            if off+length <= len(data) {
                result.ThreadID = data[off : off+length]
            }
        case 0x04:
            if off+1 <= len(data) {
                result.Mars = data[off]
            }
        }
    }
    return result, nil
}
```

### 通用数据库流量识别

```go
type DBProtocol int

const (
    DBUnknown DBProtocol = iota
    DBMySQL
    DBPostgreSQL
    DBSQLServer
    DBOracle
    DBRedis
    DBMongoDB
)

func IdentifyDBProtocol(srcPort, dstPort uint16, payload []byte) DBProtocol {
    switch {
    case dstPort == 3306 || srcPort == 3306:
        if len(payload) > 0 && payload[0] == 10 {
            return DBMySQL
        }
    case dstPort == 5432 || srcPort == 5432:
        if len(payload) >= 8 {
            code := binary.BigEndian.Uint32(payload[4:8])
            if code == 80877103 || code == 80877104 || code == 196608 {
                return DBPostgreSQL
            }
        }
    case dstPort == 1433 || srcPort == 1433:
        if len(payload) >= 8 && payload[0] == 0x12 {
            return DBSQLServer
        }
    case dstPort == 1521 || srcPort == 1521:
        if len(payload) >= 8 && payload[2] == 0x01 {
            return DBOracle
        }
    case dstPort == 6379 || srcPort == 6379:
        if len(payload) > 0 && payload[0] == '*' {
            return DBRedis
        }
    }
    return DBUnknown
}
```
