# 等保2.0

## 概述

等保2.0即《信息安全技术 网络安全等级保护基本要求》（GB/T 22239-2019），于2019年5月10日发布，2019年12月1日正式实施，替代等保1.0（GB/T 22239-2008）。

### 核心变化

| 维度 | 说明 |
|------|------|
| 保护对象扩展 | 新增云计算、物联网、移动互联、工业控制系统、大数据五个扩展要求 |
| 理念转变 | 从"静态合规"转向"持续保护"，强调动态防御与持续监测 |
| 技术框架升级 | 从"一个中心三层防护"升级为"一个中心三重防护"，增加安全管理中心 |
| 标准体系完善 | 形成以GB/T 22239为核心，配套定级指南、测评要求等完整标准族 |
| 法律效力强化 | 与《网络安全法》衔接，等保成为法定义务 |

## 五个等级定义

| 等级 | 名称 | 适用对象 | 受损影响 |
|------|------|----------|----------|
| 第一级 | 自主保护级 | 一般信息系统 | 对公民法人合法权益造成损害 |
| 第二级 | 指导保护级 | 一般信息系统 | 对公民法人合法权益造成严重损害，或对社会秩序公共利益造成损害 |
| 第三级 | 监督保护级 | 重要信息系统 | 对社会秩序公共利益造成严重损害，或对国家安全造成损害 |
| 第四级 | 强制保护级 | 特别重要信息系统 | 对社会秩序公共利益造成特别严重损害，或对国家安全造成严重损害 |
| 第五级 | 专控保护级 | 极端重要信息系统 | 对国家安全造成特别严重损害 |

        │                    │                     │
┌───────▼───────┐  ┌────────▼────────┐  ┌────────▼────────┐

| 领域 | 核心要求 |
|------|----------|

## 等保2.0 vs 1.0 核心差异对照

| 对比项 | 等保1.0 | 等保2.0 |
|--------|---------|---------|
| 标准号 | GB/T 22239-2008 | GB/T 22239-2019 |
| 法律依据 | 《计算机信息系统安全保护条例》 | 《网络安全法》 |
| 保护对象 | 传统信息系统 | 信息系统+云计算+物联网+移动互联+工控+大数据 |
| 技术框架 | 一个中心三层防护（物理/网络/主机/应用/数据） | 一个中心三重防护（通信网络/区域边界/计算环境+管理中心） |
| 管理要求 | 安全管理制度/机构/人员/建设/运维 | 同左，内容细化增强 |
| 云安全 | 无 | 新增云计算安全扩展要求 |
| 工控安全 | 无 | 新增工业控制系统安全扩展要求 |
| 个人信息保护 | 无 | 明确要求 |
| 可信计算 | 未强制 | 逐步强制要求 |
| 安全管理中心 | 未独立要求 | 独立要求，集中管控 |
| 测评结论 | 优/良/中/差 | 符合/基本符合/不符合 |

## 云计算安全扩展要求

| 领域 | 要求要点 |
|------|----------|
| 安全物理环境 | 云计算基础设施位于中国境内 |
| 安全通信网络 | 网络隔离（虚拟网络隔离）、通信传输加密、网络入侵防范 |
| 安全区域边界 | 虚拟化边界防护、访问控制（安全组/网络ACL）、流量监控 |
| 安全计算环境 | 虚拟机隔离、镜像/快照安全、容器安全、数据驻留与跨境、数据销毁 |
| 安全管理中心 | 云平台集中管控、租户隔离管理、安全日志集中审计 |
| 责任共担 | 云服务商与云租户各自承担相应安全责任 |

### 责任共担模型

```
┌─────────────────────────────────────────────┐
│ IaaS  云服务商: 物理层/虚拟化层/基础设施     │
│       云租户:  OS/应用/数据/访问控制         │
├─────────────────────────────────────────────┤
│ PaaS  云服务商: 物理层/虚拟化层/平台运行时   │
│       云租户:  应用代码/数据/访问控制        │
├─────────────────────────────────────────────┤
│ SaaS  云服务商: 全栈安全责任                │
│       云租户:  数据/访问控制/配置            │
└─────────────────────────────────────────────┘
```

## 测评流程

```
定级 → 备案 → 建设整改 → 等级测评 → 监督检查
 │       │        │          │          │
 ▼       ▼        ▼          ▼          ▼
确定     公安     差距分析   测评机构   公安机关
等级     机关     整改方案   现场测评   定期检查
         备案     安全建设   出具报告
```

### 各阶段要点

| 阶段 | 关键活动 | 输出物 |
|------|----------|--------|
| 定级 | 确定定级对象、确定等级、专家评审 | 定级报告、专家评审意见 |
| 备案 | 准备备案材料、提交公安机关 | 备案证明 |
| 建设整改 | 差距分析、制定整改方案、安全建设 | 整改方案、安全建设记录 |
| 等级测评 | 选择测评机构、现场测评、出具报告 | 测评报告 |
| 监督检查 | 公安机关定期检查、整改跟踪 | 检查记录、整改报告 |

### 定级参考

| 等级 | 典型系统 |
|------|----------|
| 二级 | 一般业务系统、企业官网、内部OA |
| 三级 | 核心业务系统、政务系统、金融交易系统、医疗HIS |
| 四级 | 国家级关键基础设施、核心金融系统 |

## 常见问题与实战要点

### 常见问题

| 问题 | 说明 |
|------|------|
| 定级过高或过低 | 过高增加成本，过低不满足合规要求；三级及以上需专家评审 |
| 云环境责任不清 | 云服务商与租户责任边界模糊，需明确责任共担 |
| 测评整改周期长 | 建议提前6-12个月启动，预留充足整改时间 |
| 安全管理中心缺失 | 等保2.0新增要求，需部署集中管理平台 |
| 个人信息保护不足 | 需与《个人信息保护法》协同落实 |
| 供应链安全 | 第三方组件/外包开发安全管控不足 |

### 实战要点

1. **定级阶段**：准确识别定级对象，避免将多个系统打包定级或拆分过细
2. **备案阶段**：三级及以上系统需在确定等级后30日内向所在地设区的市级公安机关备案
3. **建设整改**：优先解决高危漏洞和核心差距，安全产品选型需通过公安部检测
4. **测评阶段**：三级系统每年至少测评一次，四级系统每半年至少测评一次
5. **持续合规**：等保不是一次性工作，需建立持续监测和改进机制
6. **技术与管理并重**：技术措施是基础，管理措施是保障，两者缺一不可
7. **文档先行**：完善安全管理制度、操作规程、记录表单，测评时文档是重要证据
8. **选择合格测评机构**：需选择经公安部认可的等级保护测评机构
