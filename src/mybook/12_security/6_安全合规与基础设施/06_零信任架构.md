# 零信任架构

## 零信任概述

### 核心理念

**Never trust, always verify**

零信任是一种安全范式转变：

| 维度 | 传统边界防御 | 零信任 |
|------|------------|--------|
| 信任基础 | 网络位置 | 身份与上下文 |
| 安全边界 | 物理网络边界 | 每个资源独立保护 |
| 访问控制 | 一次性认证 | 持续验证 |
| 威胁假设 | 外部威胁 | 内外皆威胁 |
| 网络可见性 | 信任内部流量 | 所有流量可观测 |

### 从边界防御到身份驱动

```
传统模型：
  外部 → [防火墙] → 信任内部网络 → 自由访问

零信任模型：
  任意位置 → [身份验证] → [策略判定] → [最小权限访问] → 资源
                ↑              ↑              ↑
            你是谁？      允许做什么？    持续监控
```

## NIST SP 800-207零信任架构标准

### 核心定义

NIST将零信任定义为：零信任是对企业网络进行微隔离以防止违规的网络安全范式的演进，其核心是消除隐式信任，基于上下文进行持续验证。

### 标准要点

- 零信任是策略而非产品
- 不依赖网络位置建立信任
- 每次访问都需要认证和授权
- 强调最小权限和动态策略
- 持续监控和验证安全态势

## 核心原则

### 持续验证

```
每次访问请求都需验证：
- 身份（Who）
- 设备（What）
- 上下文（Where/When）
- 行为模式（How）
- 风险评分（Risk Level）

验证频率：
- 会话级 → 请求级 → 持续级
```

### 最小权限

- 默认拒绝
- 按需授予
- 限时权限
- 动态调整

### 微隔离

- 资源级隔离
- 细粒度访问控制
- 东西向流量管控
- 限制横向移动

### 假设违规

- 始终假设已被入侵
- 设计爆炸半径最小化
- 快速检测和响应
- 分段遏制

### 设备健康

- 设备合规性检查
- 补丁级别验证
- 安全软件状态
- 设备信任评分

### 动态策略

- 基于上下文的策略调整
- 实时风险评估
- 自适应访问控制
- 策略即代码

## 三大逻辑组件

### 策略引擎（Policy Engine, PE）

```
输入：
├── 主体属性（身份/角色/历史行为）
├── 资源属性（敏感级别/分类）
├── 环境属性（时间/位置/威胁情报）
├── 设备属性（合规性/健康度）
└── 企业策略（访问规则/合规要求）

输出：
├── 允许 / 拒绝
└── 附加条件（如需要MFA）
```

### 策略管理员（Policy Administrator, PA）

```
职责：
1. 接收PE的判定结果
2. 建立或关闭到PEP的通信路径
3. 管理会话和凭证
4. 与PEP协同执行策略
```

### 策略执行点（Policy Enforcement Point, PEP）

```
位置：靠近资源的前端
功能：
1. 拦截所有访问请求
2. 转发至PE/PA进行策略判定
3. 执行允许/拒绝决策
4. 汇报访问日志

PEP ←→ PA ←→ PE
 ↑        ↑      ↑
执行     管理    判定
```

### 组件交互流程

```
主体 → PEP → PA → PE → 策略判定
                ↑         ↓
             凭证/会话   允许/拒绝
                ↓         ↑
              PEP ← ← ← ←
                ↓
              资源（允许访问）
```

### 信任评估

```
信任评分 = f(身份信任, 设备信任, 环境信任, 行为信任)

身份信任：认证强度 × MFA因子 × 历史行为
设备信任：合规状态 × 补丁级别 × 安全软件
环境信任：网络位置 × 时间窗口 × 威胁情报
行为信任：访问模式 × 异常检测 × 风险指标

评分阈值：
  ≥ 80：允许访问
  50-79：允许但需附加验证（如MFA）
  30-49：只读访问
  < 30：拒绝访问
```

## 微隔离技术

### 基于身份的微隔离

```
策略示例：
ALLOW identity.role == "frontend" → identity.role == "backend:api"
DENY  identity.role == "frontend" → identity.role == "database"

优势：
- 跟随工作负载移动
- 跨环境一致策略
- 不依赖IP地址
```

### 基于工作负载的微隔离

```
策略示例：
ALLOW workload.label == "web" → workload.label == "app"
ALLOW workload.label == "app" → workload.label == "db"
DENY  workload.label == "web" → workload.label == "db"

实现方式：
- 容器标签/注解
- 进程身份
- 服务账户
```

### 基于网络的微隔离

```
策略示例：
ALLOW subnet 10.1.0.0/24:8080 → subnet 10.2.0.0/24:8443
DENY  subnet 10.1.0.0/24 → subnet 10.3.0.0/24

实现方式：
- 防火墙规则
- VPC安全组
- 网络ACL
```

### 微隔离技术对比

| 维度 | 基于身份 | 基于工作负载 | 基于网络 |
|------|---------|------------|---------|
| 粒度 | 最细 | 细 | 粗 |
| 灵活性 | 高 | 高 | 低 |
| 实施难度 | 高 | 中 | 低 |
| 动态环境适配 | 优 | 优 | 差 |
| 跨云支持 | 优 | 优 | 中 |

## 零信任与SASE/ZTNA

### SASE（Secure Access Service Edge）

```
SASE = 网络即服务 + 安全即服务

核心组件：
├── SD-WAN（网络优化）
├── ZTNA（零信任访问）
├── SWG（安全Web网关）
├── CASB（云访问安全代理）
├── FWaaS（防火墙即服务）
└── DLP（数据防泄漏）

特点：
- 云原生交付
- 以身份为中心
- 全球分布PoP
- 统一策略管理
```

### ZTNA（Zero Trust Network Access）

```
ZTNA vs 传统VPN：

传统VPN：
  用户 → VPN隧道 → 内部网络 → 全量访问

ZTNA：
  用户 → 身份验证 → 策略判定 → 特定应用访问

| 维度 | VPN | ZTNA |
|------|-----|------|
| 访问粒度 | 网络级 | 应用级 |
| 信任模型 | 位置信任 | 身份信任 |
| 横向移动 | 可能 | 受限 |
| 性能 | 回传延迟 | 直连优化 |
| 用户体验 | 全有或全无 | 按需访问 |
```

## 常见误区与挑战

### 常见误区

| 误区 | 事实 |
|------|------|
| 零信任是产品 | 零信任是策略和架构理念 |
| 零信任要全部替换现有架构 | 渐进式实施，与现有架构共存 |
| 零信任只关注网络 | 覆盖身份/设备/网络/应用/数据 |
| 零信任消除所有风险 | 降低风险，不可能消除 |
| 零信任只适用于远程办公 | 适用于所有访问场景 |
| 买了ZTNA产品就是零信任 | 产品是工具，策略是核心 |

### 实施挑战

```
技术挑战：
├── 遗留系统兼容性
├── 策略复杂度爆炸
├── 性能开销
├── 多云环境一致性
└── 可观测性要求高

组织挑战：
├── 文化转变困难
├── 部门墙和利益冲突
├── 技能缺口
├── 预算和ROI证明
└── 用户体验影响

运营挑战：
├── 策略运维负担
├── 误报和访问阻断
├── 例外管理
├── 持续优化需求
└── 第三方集成
```

## 主流方案对比

### Zscaler

```
架构：云原生SASE平台
核心：ZIA（互联网访问）+ ZPA（私有应用访问）
优势：
- 全球最大安全云（150+ PoP）
- 代理架构，无VPN
- 完整SASE堆栈
劣势：
- 代理模式可能影响延迟敏感应用
- 高度依赖云连接
```

### Palo Alto Networks

```
架构：Prisma SASE + Prisma Cloud
核心：Prisma Access + Prisma Cloud
优势：
- NGFW基因，安全能力强
- 云+端+网一体化
- Strata/Cortex/XSIAM生态
劣势：
- 产品线复杂
- 成本较高
```

### Cisco

```
架构：Cisco Secure Access（原Duo+Umbrella+Meraki）
核心：Duo MFA + Umbrella + SecureX
优势：
- 网络设备生态
- 端点安全整合
- SecureX统一平台
劣势：
- 零信任起步较晚
- 产品整合仍在进行
```

### Akamai

```
架构：Enterprise Application Access（EAA）
核心：CDN边缘 + 零信任访问
优势：
- 全球CDN边缘节点
- Web应用优化
- 反DDoS能力
劣势：
- 零信任功能相对基础
- 非安全厂商出身
```

### Cloudflare

```
架构：Cloudflare One（WARP + Access + Gateway）
核心：Access（ZTNA）+ Gateway（SWG）+ WARP（客户端）
优势：
- 全球Anycast网络
- 免费层可用
- 开发者友好
- 快速部署
劣势：
- 企业级功能仍在完善
- 深度安全分析能力待加强
```
