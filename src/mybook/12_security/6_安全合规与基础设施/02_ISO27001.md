# ISO 27001

## 概述

ISO/IEC 27001是国际标准化组织（ISO）与国际电工委员会（IEC）联合发布的信息安全管理体系（ISMS）标准，最新版本为ISO/IEC 27001:2022。它为组织建立、实施、维护和持续改进信息安全管理体系提供了要求框架，是全球最广泛认可的信息安全管理标准。

### PDCA循环

ISO 27001基于PDCA（Plan-Do-Check-Act）持续改进模型：

```
        ┌───────────┐
        │   Plan    │
        │  规划     │
        │ 建立ISMS  │
        └─────┬─────┘
              │
    ┌─────────▼──────────┐
    │                    │
    │                    │
┌───▼─────┐        ┌────▼───┐
│  Act    │        │  Do    │
│  改进   │        │  实施  │
│持续改进  │        │运行ISMS│
└───┬─────┘        └────┬───┘
    │                    │
    │                    │
    └─────────┬──────────┘
              │
        ┌─────▼─────┐
        │  Check    │
        │  检查     │
        │ 监视评审  │
        └───────────┘
```

| 阶段 | 活动 |
|------|------|
| Plan（规划） | 确定ISMS范围、风险评估、风险处置计划、适用性声明 |
| Do（实施） | 实施风险处置计划、落实控制措施、培训与意识提升 |
| Check（检查） | 监视测量、内部审核、管理评审 |
| Act（改进） | 纠正措施、持续改进、更新ISMS |

## 标准族结构

| 标准 | 名称 | 作用 |
|------|------|------|
| ISO/IEC 27001 | 信息安全管理体系要求 | 认证标准，规定ISMS的强制性要求 |
| ISO/IEC 27002 | 信息安全控制实践指南 | 控制措施的实施指南，2022版从114项精简为93项 |
| ISO/IEC 27005 | 信息安全风险管理 | 风险评估与处置方法论指南 |
| ISO/IEC 27004 | 信息安全管理度量 | ISMS效能测量与评估指南 |
| ISO/IEC 27003 | ISMS实施指南 | ISMS项目实施的详细指导 |
| ISO/IEC 27006 | 认证机构要求 | 对ISMS认证机构的认可要求 |
| ISO/IEC 27007 | ISMS审核指南 | 管理体系审核指南 |

## 14个控制域（A.5-A.18）

基于ISO 27001:2013/2022附录A的控制域：

| 控制域 | 编号 | 核心内容 |
|--------|------|----------|
| A.5 信息安全方针 | 2项 | 方针制定与审批、方针传达与评审 |
| A.6 信息安全组织 | 9项 | 内部组织、移动设备与远程工作、资产职责 |
| A.7 人力资源安全 | 6项 | 任用前/中/后安全措施 |
| A.8 资产管理 | 10项 | 资产责任、信息分类、介质处理 |
| A.9 访问控制 | 9项 | 访问控制策略、用户管理、系统访问控制 |
| A.10 密码学 | 2项 | 密码策略、密钥管理 |
| A.11 物理与环境安全 | 13项 | 安全区域、设备安全 |
| A.12 操作安全 | 14项 | 操作程序与职责、恶意代码防范、备份、日志、漏洞管理 |
| A.13 通信安全 | 7项 | 网络安全、信息传输 |
| A.14 系统获取/开发/维护 | 11项 | 安全需求、开发安全、测试数据 |
| A.15 供应商关系 | 5项 | 供应商安全策略、供应商协议、供应链监控 |
| A.16 信息安全事件管理 | 7项 | 事件报告、事件管理、证据收集 |
| A.17 业务连续性 | 3项 | 信息安全连续性、冗余、可用性 |
| A.18 合规性 | 4项 | 法律法规合规、知识产权、隐私保护、密码合规 |

### 2022版主要变化

| 变化项 | 说明 |
|--------|------|
| 控制项精简 | 从114项合并为93项 |
| 新增主题 | 威胁情报、云安全、数据脱敏、物理安全监控、配置管理 |
| 结构重组 | 新增4个组织级控制、新增属性标签（类型/属性/主题） |
| 删除过时控制 | 合并重复项、移除不再适用的控制 |

## ISMS建设流程

```
范围界定 → 风险评估 → 风险处置计划 → 适用性声明(SoA)
    → 实施 → 内部审核 → 管理评审 → 认证审核
```

### 各阶段详解

| 阶段 | 关键活动 | 输出物 |
|------|----------|--------|
| 范围界定 | 确定ISMS边界、识别内外部环境、相关方需求 | ISMS范围文件、相关方需求清单 |
| 风险评估 | 资产识别、威胁分析、脆弱性评估、风险计算 | 风险评估报告、风险登记册 |
| 风险处置计划 | 制定处置策略（降低/接受/转移/规避）、选择控制措施 | 风险处置计划(RTP) |
| 适用性声明 | 确认适用的控制措施、说明实施状态与理由 | 适用性声明(SoA) |
| 实施 | 部署控制措施、制定制度流程、培训人员 | 管理制度、操作规程、培训记录 |
| 内部审核 | 审核ISMS符合性与有效性 | 内审报告、不符合项 |
| 管理评审 | 最高管理者评审ISMS适宜性/充分性/有效性 | 管理评审报告、改进决策 |
| 认证审核 | 第三方认证机构审核 | 认证证书 |

## 风险评估方法论

### 基本公式

```
风险值 = 可能性 × 影响
```

### 评估流程

```
资产识别 → 威胁识别 → 脆弱性识别 → 风险分析 → 风险评价
    │           │           │            │           │
    ▼           ▼           ▼            ▼           ▼
  资产价值    威胁频率   脆弱性严重度   可能性×影响  风险等级
  (C/I/A)    威势来源   利用难度      = 风险值    可接受/不可接受
```

### 资产识别

| 资产类型 | 示例 |
|----------|------|
| 信息资产 | 数据库、文档、源代码、设计图纸 |
| 软件资产 | 操作系统、中间件、业务应用 |
| 硬件资产 | 服务器、网络设备、终端设备 |
| 人员资产 | 关键岗位人员、专业技能 |
| 服务资产 | 云服务、网络服务、运维服务 |

### 风险等级矩阵

|  | 影响低 | 影响中 | 影响高 |
|---|--------|--------|--------|
| 可能性高 | 中 | 高 | 极高 |
| 可能性中 | 低 | 中 | 高 |
| 可能性低 | 极低 | 低 | 中 |

### 风险处置策略

| 策略 | 说明 |
|------|------|
| 风险降低 | 实施控制措施将风险降至可接受水平 |
| 风险接受 | 风险在可接受范围内，无需额外措施 |
| 风险转移 | 通过保险、外包等方式转移风险 |
| 风险规避 | 停止导致风险的活动 |

## 与等保2.0的对比

| 对比项 | ISO 27001 | 等保2.0 |
|--------|-----------|---------|
| 性质 | 国际自愿性认证标准 | 中国强制性合规要求 |
| 适用范围 | 全球各类组织 | 中国境内运营的信息系统 |
| 核心理念 | 基于风险的ISMS管理 | 基于等级的技术+管理防护 |
| 评估方式 | 自我评估+第三方认证 | 公安机关监督+测评机构测评 |
| 法律效力 | 无直接法律强制力 | 《网络安全法》法定义务 |
| 关注重点 | 信息安全管理体系成熟度 | 信息系统安全防护能力 |
| 更新机制 | PDCA持续改进 | 定期测评+监督检查 |
| 控制粒度 | 93项控制措施（2022版） | 五级分类+扩展要求 |
| 风险方法 | 自主选择风险评估方法 | 定级即确定风险等级 |
| 证书有效期 | 3年（年度监督审核） | 测评报告有效期1年（三级） |

## 认证流程与周期

### 认证流程

```
选择认证机构 → 一阶段审核(文件审核) → 二阶段审核(现场审核)
    → 不符合项整改 → 认证决定 → 颁发证书
```

| 阶段 | 内容 | 周期 |
|------|------|------|
| 一阶段审核 | 审查ISMS文件、确认审核范围、了解组织情况 | 1-2天 |
| 二阶段审核 | 现场审核、验证控制措施实施、访谈与检查 | 3-5天（视规模） |
| 不符合项整改 | 对审核发现的不符合项进行纠正 | 30-90天 |
| 认证决定 | 认证机构技术委员会评审 | 1-2周 |

### 证书维护周期

| 时间节点 | 活动 |
|----------|------|
| 获证后第1年 | 第一次监督审核 |
| 获证后第2年 | 第二次监督审核 |
| 获证后第3年 | 再认证审核（换证） |

### 认证费用参考

| 费用项 | 说明 |
|--------|------|
| 认证费 | 认证机构审核费用，按人天数计算 |
| 咨询费 | ISMS建设咨询（可选） |
| 工具费 | 风险评估工具、安全管理平台等 |
| 人力成本 | 内部团队投入 |
| 持续维护 | 年度监督审核、体系维护 |

## 实战要点

1. **高层支持**：ISMS建设需要管理层承诺和资源投入，缺乏高层支持是项目失败的首要原因
2. **范围适度**：首次认证范围不宜过大，建议从核心业务系统开始，逐步扩展
3. **文档体系**：建立四层文档体系——方针（一级）、制度（二级）、规程（三级）、记录（四级）
4. **风险评估务实**：避免过度评估，聚焦关键资产和高风险场景，确保评估结果可操作
5. **SoA完整性**：适用性声明必须覆盖所有93项控制措施，说明适用/不适用及理由
6. **内审独立性**：内审人员不得审核自己的工作，确保审核客观性
7. **持续改进**：利用PDCA循环，将安全事件、审计发现、变更需求纳入改进输入
8. **与等保融合**：技术措施复用等保建设成果，管理体系统一框架，减少重复工作
9. **供应链安全**：重视供应商安全评估，将安全要求纳入合同条款
10. **人员意识**：安全意识培训是成本效益最高的控制措施之一，需定期开展
