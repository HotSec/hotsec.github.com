# 渗透测试方法论

## 渗透测试概述

### 定义

渗透测试（Penetration Testing）是模拟攻击者视角，对目标系统进行授权的安全评估，发现可被利用的漏洞。

### 类型

| 类型 | 描述 |
|------|------|
| 黑盒 | 无任何内部信息，完全模拟外部攻击者 |
| 白盒 | 拥有完整系统信息（源码、架构、凭据） |
| 灰盒 | 部分信息已知（如普通用户账号） |
| 红队 | 模拟高级持续性威胁（APT），测试防御能力 |
| 紫队 | 红蓝队协作，实时改进防御 |

### 测试范围

- Web 应用
- 移动应用
- 网络基础设施
- 无线网络
- 社会工程
- 物理安全

## PTES 方法论

Penetration Testing Execution Standard（渗透测试执行标准）包含 7 个阶段：

### 1. 前期交互 (Pre-engagement Interactions)

- 确定测试范围和目标
- 签署授权书和保密协议
- 确定测试时间和窗口
- 定义紧急联系人
- 确认测试类型（黑/白/灰盒）
- 定义退出条件

### 2. 信息收集 (Intelligence Gathering)

#### 被动信息收集

```bash
whois example.com
dig example.com ANY
dig -x 1.2.3.4

theHarvester -d example.com -b all
maltego

shodan search "hostname:example.com"
censys search "example.com"

google dork: site:example.com filetype:pdf
google dork: inurl:admin site:example.com
google dork: intitle:"index of" site:example.com
```

#### 主动信息收集

```bash
nmap -sn 192.168.1.0/24
nmap -sV -sC -p- 192.168.1.100
nmap -O 192.168.1.100
nmap --script vuln 192.168.1.100

masscan -p1-65535 --rate=1000 192.168.1.0/24

nikto -h https://example.com
whatweb https://example.com
```

### 3. 威胁建模 (Threat Modeling)

- 识别资产和攻击面
- 分析潜在攻击路径
- 评估威胁等级
- 确定攻击优先级

### 4. 漏洞分析 (Vulnerability Analysis)

```bash
nmap --script vuln target
nessus scan
openvas scan
nuclei -u https://example.com

nikto -h https://example.com
wpscan --url https://example.com --enumerate u,p,t
```

### 5. 渗透攻击 (Exploitation)

- 利用发现的漏洞获取访问权限
- 验证漏洞可利用性
- 记录利用过程

### 6. 后渗透 (Post Exploitation)

- 权限提升
- 横向移动
- 数据收集
- 持久化
- 清理痕迹

### 7. 报告 (Reporting)

- 执行摘要（管理层）
- 技术细节（技术团队）
- 风险评级
- 修复建议
- 复测计划

## Web 渗透测试流程

### 1. 侦察

```
目标: example.com
├── 子域名枚举
│   ├── DNS 暴力破解
│   ├── 证书透明度日志
│   ├── 搜索引擎
│   └── 第三方服务（Shodan/Censys）
├── 技术栈识别
│   ├── HTTP 响应头
│   ├── Cookie 名称
│   ├── 页面源码特征
│   └── Wappalyzer
└── 端口扫描
    ├── 常见端口
    └── 全端口扫描
```

### 2. 漏洞扫描

```bash
nuclei -u https://example.com -t cves/
nuclei -u https://example.com -t vulnerabilities/
nuclei -u https://example.com -t misconfiguration/

nikto -h https://example.com
burp suite active scan
```

### 3. 手动测试

```
├── 认证测试
│   ├── 登录绕过
│   ├── 密码重置漏洞
│   ├── 会话管理
│   └── MFA 绕过
├── 授权测试
│   ├── IDOR
│   ├── 水平越权
│   └── 垂直越权
├── 输入验证
│   ├── SQL 注入
│   ├── XSS
│   ├── SSTI
│   └── 命令注入
└── 业务逻辑
    ├── 价格篡改
    ├── 竞态条件
    └── 工作流绕过
```

### 4. 漏洞利用

- 构造 PoC
- 验证影响范围
- 获取证据（截图/日志）
- 评估风险等级

### 5. 报告编写

```markdown
# 漏洞报告

## 漏洞标题
SQL 注入导致数据库信息泄露

## 风险等级
高危 (CVSS 9.8)

## 影响范围
- 受影响系统: https://example.com/api/users
- 受影响用户: 全部用户数据

## 漏洞描述
登录接口的 username 参数存在 SQL 注入漏洞...

## 复现步骤
1. 访问 https://example.com/login
2. 在 username 字段输入: ' OR 1=1--
3. 点击登录
4. 成功绕过认证

## 修复建议
1. 使用参数化查询
2. 输入验证和白名单
3. 最小权限原则
```

## 风险评级

### CVSS 评分

| 等级 | 分数 | 描述 |
|------|------|------|
| 严重 | 9.0-10.0 | 远程代码执行、完全接管 |
| 高危 | 7.0-8.9 | 数据泄露、权限提升 |
| 中危 | 4.0-6.9 | 有限信息泄露 |
| 低危 | 0.1-3.9 | 信息泄露（非敏感） |
| 信息 | 0.0 | 无安全影响 |

### DREAD 评估

| 维度 | 分值 1-10 |
|------|-----------|
| Damage (损害) | 被利用后的损害程度 |
| Reproducibility (可复现性) | 漏洞复现难度 |
| Exploitability (可利用性) | 利用难度 |
| Affected users (影响用户) | 受影响用户比例 |
| Discoverability (可发现性) | 被发现难度 |

## 法律与道德

- 始终获取书面授权
- 严格遵守测试范围
- 不超出授权边界
- 保护客户数据
- 及时报告严重漏洞
- 遵守当地法律法规
