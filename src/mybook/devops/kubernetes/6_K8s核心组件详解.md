# K8s 核心组件详解

## API Server

集群的 REST API 入口，所有操作都通过 API Server 进行。

### 认证

- X509 客户端证书
- Bearer Token
- OIDC（OpenID Connect）
- Webhook Token 认证

### 授权

- RBAC（Role-Based Access Control）
- ABAC（Attribute-Based Access Control）
- Node 授权
- Webhook 授权

### 准入控制

Admission Controller 在请求持久化前进行拦截和修改：

- NamespaceLifecycle
- LimitRanger
- ServiceAccount
- DefaultStorageClass
- ResourceQuota
- PodSecurityPolicy（→PSA）

### 高可用部署

多实例 + 负载均衡，后端共享 etcd 集群。

## etcd

分布式 KV 存储，K8s 的唯一状态存储后端。

### RAFT 一致性协议

- Leader 选举
- 日志复制
- 安全性保证

### 数据模型

- revision：全局递增版本号
- key-value：每个 key 对应多个历史 revision

### 备份恢复

```bash
etcdctl snapshot save snapshot.db
etcdctl snapshot restore snapshot.db
```

### 性能调优

- `--quota-backend-bytes`：数据库大小限制（默认 2GB）
- `--auto-compaction-retention`：自动压缩保留时间
- `--max-request-bytes`：请求大小限制

## Scheduler

负责将 Pod 调度到合适的 Node 上。

### 调度流程

1. 过滤（Filter）：排除不满足条件的 Node
2. 打分（Score）：对候选 Node 打分排序
3. 绑定（Bind）：将 Pod 绑定到得分最高的 Node

### 调度策略

- NodeSelector：标签选择
- NodeAffinity：节点亲和性（required/preferred）
- PodAffinity/PodAntiAffinity：Pod 亲和/反亲和
- Taint & Toleration：污点与容忍
- Priority & Preemption：优先级与抢占

### 自定义调度器

通过 `schedulerName` 字段指定自定义调度器。

### 调度框架（Scheduling Framework）

扩展点：Sort / PreFilter / Filter / PostFilter / PreScore / Score / NormalizeScore / Reserve / Permit / PreBind / Bind / PostBind

## Controller Manager

运行各种控制器，通过控制循环将集群状态向期望状态收敛。

### 控制器模式

- Informer：监听 API Server 资源变化
- Reflector：反射器，将 etcd 数据同步到本地缓存
- Indexer：本地索引缓存

### 核心控制器

- Deployment Controller：管理 ReplicaSet 滚动更新
- ReplicaSet Controller：维护 Pod 副本数
- Node Controller：监控节点状态
- Job Controller：管理 Job 和 CronJob

## kubelet

每个 Node 上的代理，负责 Pod 生命周期管理。

### Pod 生命周期管理

- Pod 创建、启动、停止
- 容器探针执行
- 资源使用上报

### CRI（容器运行时接口）

- containerd
- CRI-O
- dockershim（已移除）

### PLEG（Pod Lifecycle Event Generator）

- 周期性检测容器状态变化
- 生成 Pod 生命周期事件

### 探针

- Liveness Probe：存活探针，失败则重启容器
- Readiness Probe：就绪探针，失败则从 Service 移除
- Startup Probe：启动探针，用于慢启动应用

### 静态 Pod

通过 manifest 文件创建，不由 API Server 管理，路径：`/etc/kubernetes/manifests/`

## kube-proxy

实现 Service 的负载均衡和流量转发。

### iptables 模式

- 默认模式
- 通过 iptables 规则实现 DNAT
- 随机选择后端 Pod

### IPVS 模式

- 性能更好（O(1) 复杂度）
- 支持多种调度算法：rr / lc / wlc / sh
- 需要内核加载 ipvs 模块

### userspace 模式

- 旧模式，性能差，已不推荐

### conntrack 表

连接跟踪表，记录已建立连接的映射关系。

## CoreDNS

集群内 DNS 解析和服务发现。

### Service 发现

- `<service>.<namespace>.svc.cluster.local`
- Headless Service：直接返回 Pod IP

### 自定义 DNS 配置

- ConfigMap 修改 Corefile
- StubDomain：自定义域名转发
- Upstream：上游 DNS 服务器

### 调试

```bash
kubectl get pods -n kube-system -l k8s-app=kube-dns
kubectl logs -n kube-system <coredns-pod>
dig @<coredns-ip> <service>.<namespace>.svc.cluster.local
```
