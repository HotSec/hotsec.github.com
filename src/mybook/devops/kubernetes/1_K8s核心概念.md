## 二、工作负载

### 2.1 Pod

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: my-app
  labels:
    app: my-app
spec:
  containers:
  - name: app
    image: my-app:1.0
    ports:
    - containerPort: 8080
    resources:
      requests:
        cpu: "100m"
        memory: "128Mi"
      limits:
        cpu: "500m"
        memory: "512Mi"
    livenessProbe:
      httpGet:
        path: /healthz
        port: 8080
      initialDelaySeconds: 10
      periodSeconds: 10
    readinessProbe:
      httpGet:
        path: /ready
        port: 8080
      initialDelaySeconds: 5
      periodSeconds: 5
    env:
    - name: DB_HOST
      value: "mysql.default.svc.cluster.local"
    - name: DB_PASSWORD
      valueFrom:
        secretKeyRef:
          name: db-secret
          key: password
  - name: sidecar
    image: log-collector:1.0
```

### 2.2 Deployment

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
      - name: app
        image: my-app:2.0
        ports:
        - containerPort: 8080
```

```bash
kubectl apply -f deployment.yaml
kubectl rollout status deployment/my-app
kubectl rollout history deployment/my-app
kubectl rollout undo deployment/my-app
kubectl scale deployment my-app --replicas=5
```

### 2.3 StatefulSet

```yaml

kind: StatefulSet
metadata:
  name: mysql
spec:
  serviceName: mysql
  replicas: 3
  selector:
    matchLabels:
      app: mysql

    metadata:
      labels:

    spec:

        - name: data

  volumeClaimTemplates:
  - metadata:
      name: data
    spec:
      accessModes: ["ReadWriteOnce"]
```

## 三、服务与网络

### 3.1 Service

```yaml
# ClusterIP (默认，集群内部访问)
apiVersion: v1
kind: Service
metadata:
  name: my-app
spec:
  type: ClusterIP
  selector:
    app: my-app
  ports:
  - port: 80
    targetPort: 8080

---
# NodePort (外部通过节点端口访问)
apiVersion: v1
kind: Service
metadata:
  name: my-app-nodeport
spec:
  type: NodePort
  selector:
    app: my-app
  ports:
  - port: 80
    targetPort: 8080
    nodePort: 30080

---
# LoadBalancer (云厂商负载均衡器)
apiVersion: v1
kind: Service
metadata:
  name: my-app-lb
spec:
  type: LoadBalancer
  selector:
    app: my-app
  ports:
  - port: 80
    targetPort: 8080
```

### 3.2 Ingress

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: my-app-ingress
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
spec:
  ingressClassName: nginx
  tls:
  - hosts:
    - myapp.example.com
    secretName: myapp-tls
  rules:
  - host: myapp.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: my-app
            port:
              number: 80
      - path: /api
        pathType: Prefix
        backend:
          service:
            name: api-service
            port:
              number: 80
```

### 3.3 NetworkPolicy

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-frontend
spec:
  podSelector:
    matchLabels:
      app: backend
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: frontend
    ports:
    - port: 8080
      protocol: TCP
```

## 九、核心组件详解

### 9.1 API Server

API Server 是 K8s 控制面的前端，所有组件通过 REST API 与其交互。

**认证方式**：

| 方式 | 说明 |
|------|------|
| X509 证书 | `--client-ca-file` 指定 CA，kubeconfig 常用 |
| Bearer Token | ServiceAccount Token，`Authorization: Bearer <token>` |
| Bootstrap Token | 节点加入集群时的临时 Token |
| OIDC | 对接外部 IdP（如 Dex/Keycloak） |
| Webhook | 自定义认证服务 |

**授权方式**：

| 方式 | 说明 |
|------|------|
| RBAC | 基于角色的访问控制（最常用） |
| ABAC | 基于属性的访问控制 |
| Node | kubelet 自身权限控制 |
| Webhook | 自定义授权服务 |

**准入控制器**：

```bash
# 常用准入控制器
--enable-admission-plugins=NodeRestriction,LimitRanger,ResourceQuota,PodSecurityPolicy,MutatingAdmissionWebhook,ValidatingAdmissionWebhook
```

- MutatingAdmissionWebhook：修改请求（如注入 sidecar）
- ValidatingAdmissionWebhook：验证请求（如策略检查）
- NodeRestriction：限制 kubelet 只能修改自身 Node 的 Pod

**高可用部署**：

```bash
# 多实例 + 负载均衡
kube-apiserver --bind-address=0.0.0.0 --secure-port=6443 \
  --etcd-servers=https://etcd1:2379,https://etcd2:2379,https://etcd3:2379 \
  --advertise-address=192.168.1.10
```

### 9.2 etcd

etcd 是分布式一致性 KV 存储，保存 K8s 所有集群数据。

**数据模型**：

```
/registry/pods/default/my-pod
/registry/services/default/my-service
/registry/configmaps/default/my-config
/registry/secrets/default/my-secret
```

**常用操作**：

```bash
etcdctl get / --prefix --keys-only          # 列出所有键
etcdctl get /registry/pods/default/ --prefix # 列出default命名空间的Pod
etcdctl put /test/key "value"               # 写入
etcdctl del /test/key                        # 删除

etcdctl endpoint health                      # 健康检查
etcdctl endpoint status                      # 集群状态
etcdctl member list                          # 成员列表
etcdctl alarm list                           # 告警
```

**备份恢复**：

```bash
etcdctl snapshot save /backup/etcd-$(date +%Y%m%d).db
etcdctl snapshot status /backup/etcd-20250101.db --write-table

etcdctl snapshot restore /backup/etcd-20250101.db \
  --data-dir /var/lib/etcd-restore
```

**性能调优**：

```bash
--quota-backend-bytes=8589934592            # 8GB 存储配额
--auto-compaction-retention=1               # 1小时自动压缩
--max-request-bytes=10485760                # 10MB 请求上限
```

### 9.3 Scheduler

Scheduler 负责将未调度的 Pod 分配到合适的 Node。

**调度流程**：

```
1. 过滤（Filter）：排除不满足条件的 Node
2. 打分（Score）：对剩余 Node 打分排序
3. 绑定（Bind）：将 Pod 绑定到得分最高的 Node
```

**调度策略**：

```yaml
spec:
  nodeSelector:
    disktype: ssd

  affinity:
    nodeAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        nodeSelectorTerms:
        - matchExpressions:
          - key: zone
            operator: In
            values: ["east", "west"]
    podAffinity:
      preferredDuringSchedulingIgnoredDuringExecution:
      - weight: 100
        podAffinityTerm:
          labelSelector:
            matchLabels:
              app: cache
          topologyKey: kubernetes.io/hostname

  tolerations:
  - key: "dedicated"
    operator: "Equal"
    value: "gpu"
    effect: "NoSchedule"

  priorityClassName: high-priority
```

**Scheduling Framework**：

```
QueueSort → PreFilter → Filter → PostFilter → PreScore → Score → NormalizeScore → Reserve → Permit → PreBind → Bind → PostBind
```

可自定义插件扩展调度行为。

### 9.4 Controller Manager

Controller Manager 运行核心控制器，每个控制器通过 Informer 机制监听 API Server。

**Informer 机制**：

```
API Server → Reflector（ListAndWatch）→ Delta FIFO → Informer → Indexer → Controller 事件处理
```

**核心控制器**：

| 控制器 | 职责 |
|--------|------|
| Deployment Controller | 管理 ReplicaSet 滚动更新 |
| ReplicaSet Controller | 确保 Pod 副本数 |
| Node Controller | 监控节点健康状态 |
| Service Controller | 管理 Service 与 Endpoints |
| Endpoints Controller | 维护 Service 后端 Pod 列表 |
| Namespace Controller | 删除命名空间时清理资源 |
| ServiceAccount Controller | 创建默认 ServiceAccount |
| DaemonSet Controller | 确保每个 Node 运行 Pod |
| Job Controller | 管理 Job 生命周期 |

### 9.5 kubelet

kubelet 是每个 Node 上的代理，负责 Pod 生命周期管理。

**核心功能**：

- Pod 生命周期管理（创建/启动/停止/删除）
- 容器运行时接口（CRI）调用
- 探针执行（Liveness/Readiness/Startup）
- 资源使用上报给 API Server
- 静态 Pod 管理（`/etc/kubernetes/manifests/`）

**PLEG 机制**：

```
PLEG（Pod Lifecycle Event Generator）
1. 定期查询容器运行时获取 Pod 状态
2. 对比当前状态与期望状态
3. 产生事件触发同步操作
```

**探针配置**：

```yaml
livenessProbe:
  httpGet:
    path: /healthz
    port: 8080
  initialDelaySeconds: 15
  periodSeconds: 10

readinessProbe:
  httpGet:
    path: /ready
    port: 8080
  initialDelaySeconds: 5
  periodSeconds: 5

startupProbe:
  httpGet:
    path: /started
    port: 8080
  failureThreshold: 30
  periodSeconds: 10
```

### 9.6 kube-proxy

kube-proxy 实现 Service 的负载均衡和流量转发。

**三种模式**：

| 模式 | 原理 | 性能 | 适用场景 |
|------|------|------|----------|
| userspace | 用户空间转发 | 最差 | 已弃用 |
| iptables | iptables 规则 | 中等 | 默认，小集群 |
| IPVS | IPVS 内核模块 | 最好 | 大规模集群 |

**iptables 模式**：

```
Client → KUBE-SERVICES → KUBE-SVC-XXX → KUBE-SEP-XXX → Pod
```

随机概率选择后端 Pod，规则数与 Service×Endpoint 成正比。

**IPVS 模式**：

```bash
kube-proxy --proxy-mode=ipvs
ipvsadm -Ln                        # 查看 IPVS 规则
ipvsadm -Ln -t 10.96.0.1:443      # 查看 Service 规则

# 支持的调度算法
--ipvs-scheduler=rr                # 轮询（默认）
--ipvs-scheduler=lc                # 最少连接
--ipvs-scheduler=wrr               # 加权轮询
--ipvs-scheduler=wlc               # 加权最少连接
--ipvs-scheduler=sh                # 源地址哈希
```

### 9.7 CoreDNS

CoreDNS 提供集群内 DNS 解析和服务发现。

**解析规则**：

```
<service>.<namespace>.svc.<cluster-domain>
my-service.default.svc.cluster.local

# 简写
my-service                        # 同命名空间
my-service.kube-system            # 跨命名空间
```

**自定义 DNS 配置**：

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: coredns
  namespace: kube-system
data:
  Corefile: |
    .:53 {
        errors
        health {
            lameduck 5s
        }
        ready
        kubernetes cluster.local in-addr.arpa ip6.arpa {
            pods insecure
            fallthrough in-addr.arpa ip6.arpa
            ttl 30
        }
        prometheus :9153
        forward . /etc/resolv.conf {
            max_concurrent 1000
        }
        cache 30
        loop
        reload
        loadbalance
    }
```

**DNS 策略**：

```yaml
spec:
  dnsPolicy: Default              # 使用节点DNS
  dnsPolicy: ClusterFirst         # 使用CoreDNS（默认）
  dnsPolicy: ClusterFirstWithHostNet  # hostNetwork时使用CoreDNS
  dnsPolicy: None                 # 自定义DNS
  dnsConfig:
    nameservers:
    - 8.8.8.8
    searches:
    - mycompany.com
    options:
    - name: ndots
      value: "2"
```
