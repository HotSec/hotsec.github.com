# 浏览器原理

## 浏览器架构

### 多进程架构

| 进程 | 职责 |
|------|------|
| Browser | 地址栏、书签、前进/后退、网络请求 |
| Renderer | 页面渲染、JS 执行 |
| GPU | 3D CSS、Canvas、视频解码 |
| Network | 网络请求处理 |
| Plugin | 插件运行（已弃用） |
| Utility | 音频服务、存储服务等 |

每个标签页对应一个 Renderer 进程（同站点可能共享）。

### 站点隔离

- 不同站点运行在不同 Renderer 进程
- 防止 Spectre 类侧信道攻击
- iframe 也可能独立进程

## 渲染流程

### 关键渲染路径

```
HTML → DOM Tree
CSS  → CSSOM Tree
         ↓
    Render Tree (Layout Tree)
         ↓
      Layout (计算位置大小)
         ↓
       Paint (绘制像素)
         ↓
      Composite (合成图层)
```

### DOM 构建

```html
<html>
<head>
    <title>Example</title>
    <link rel="stylesheet" href="style.css">
</head>
<body>
    <div class="container">
        <h1>Hello</h1>
        <p>World</p>
    </div>
    <script src="app.js"></script>
</body>
</html>
```

1. 解析 HTML → 构建 DOM Tree
2. 遇到 CSS → 构建 CSSOM Tree
3. 遇到 JS → 阻塞 DOM 构建（除非 async/defer）

### 脚本加载策略

```html
<script src="app.js"></script>

<script defer src="app.js"></script>

<script async src="analytics.js"></script>

<script type="module" src="app.js"></script>
```

| 属性 | DOM 解析 | 执行时机 | 顺序保证 |
|------|----------|----------|----------|
| 无 | 阻塞 | 立即 | 按顺序 |
| defer | 不阻塞 | DOM 解析后 | 按顺序 |
| async | 不阻塞 | 下载完立即 | 不保证 |
| module | 不阻塞 | DOM 解析后 | 按顺序 |

### 布局 (Layout / Reflow)

计算元素的精确位置和大小。触发条件：

- 添加/删除 DOM 元素
- 修改 CSS 属性（width/height/margin/padding/display 等）
- 读取布局属性（offsetWidth/scrollTop/getBoundingClientRect 等）
- 窗口 resize
- 字体变化

### 绘制 (Paint)

将元素绘制为像素。触发条件：

- color/background/border/shadow 变化
- outline/visibility 变化

### 合成 (Composite)

将多个图层合成最终画面。仅触发 composite 的属性：

- transform
- opacity

**性能优化**：优先使用 transform/opacity 做动画，避免触发布局重排。

***

## 图层与合成

### 隐式创建图层

- position: fixed/sticky
- opacity < 1
- transform 非 none
- filter 非 none
- will-change
- overflow: hidden（部分情况）
- video/canvas/iframe

### will-change

```css
.animated-element {
    will-change: transform, opacity;
}

.animated-element.moving {
    transform: translateX(100px);
}
```

- 提前告知浏览器将要变化的属性
- 浏览器可提前创建独立图层
- 不要滥用，过多图层反而消耗内存

## V8 引擎

### 执行流程

```
JavaScript 源码
      ↓
  Parser (解析)
      ↓
   AST (抽象语法树)
      ↓
  Ignition (解释器)
      ↓
  字节码执行
      ↓ (热点代码)
  TurboFan (优化编译器)
      ↓
  优化机器码
      ↓ (类型变化/去优化)
  回退到字节码
```

### 隐藏类 (Hidden Classes)

V8 为对象创建隐藏类以优化属性访问：

```javascript
function Point(x, y) {
    this.x = x;
    this.y = y;
}

const p1 = new Point(1, 2);
const p2 = new Point(3, 4);
```

p1 和 p2 共享相同的隐藏类（相同属性顺序）。

```javascript
const p3 = new Point(5, 6);
p3.z = 7;
```

p3 的隐藏类与 p1/p2 不同，导致去优化。

**最佳实践**：
- 以相同顺序初始化对象属性
- 避免动态添加属性
- 避免删除属性（`delete`）

### 内联缓存 (Inline Cache)

```javascript
function getX(obj) {
    return obj.x;
}

const a = {x: 1, y: 2};
const b = {x: 3, y: 4};

for (let i = 0; i < 10000; i++) {
    getX(a);
    getX(b);
}
```

V8 会缓存 `obj.x` 的访问路径，后续调用直接使用缓存。

### 垃圾回收

V8 使用分代回收：

| 代 | 特点 | 算法 |
|----|------|------|
| 新生代 (Young) | 短命对象，小 (1-8MB) | Scavenge (Cheney) |
| 老生代 (Old) | 长命对象，大 | Mark-Sweep + Mark-Compact |

**晋升条件**：
- 经历过一次 Scavenge 回收
- To 空间使用率超过 25%

**优化建议**：
- 避免创建大量临时对象
- 复用对象（对象池）
- 避免闭包引用大对象
- 及时解除引用

## 事件循环

### 浏览器事件循环

```
┌─────────────────────────────┐
│         Call Stack           │
└──────────────┬──────────────┘
               │
┌──────────────▼──────────────┐
│      Microtask Queue         │  Promise.then, MutationObserver
│  (执行完所有再继续)           │  queueMicrotask
└──────────────┬──────────────┘
               │
┌──────────────▼──────────────┐
│      Macrotask Queue         │  setTimeout, setInterval
│  (每次取一个执行)             │  MessageChannel, I/O
└─────────────────────────────┘
```

执行顺序：

1. 执行同步代码（Call Stack）
2. Call Stack 清空后，执行所有 Microtask
3. 取一个 Macrotask 执行
4. 重复 2-3

```javascript
console.log('1');

setTimeout(() => console.log('2'), 0);

Promise.resolve()
    .then(() => console.log('3'))
    .then(() => console.log('4'));

console.log('5');

// 输出: 1, 5, 3, 4, 2
```

### requestAnimationFrame

```javascript
function animate() {
    updateState();
    render();
    requestAnimationFrame(animate);
}

requestAnimationFrame(animate);
```

- 在下一帧渲染前执行
- 适合动画逻辑
- 与浏览器刷新率同步（通常 60fps）

### requestIdleCallback

```javascript
requestIdleCallback((deadline) => {
    while (deadline.timeRemaining() > 0 && tasks.length > 0) {
        doSmallTask(tasks.pop());
    }
    if (tasks.length > 0) {
        requestIdleCallback(processRemaining);
    }
});
```

- 在浏览器空闲时执行
- 适合低优先级任务
- deadline.timeRemaining() 返回剩余空闲时间

## 网络请求

### 请求生命周期

```
DNS 查询 → TCP 连接 → TLS 握手 → HTTP 请求 → HTTP 响应
```

### 资源加载优化

| 策略 | 说明 |
|------|------|
| DNS 预解析 | `<link rel="dns-prefetch" href="//cdn.example.com">` |
| 预连接 | `<link rel="preconnect" href="//cdn.example.com">` |
| 预加载 | `<link rel="preload" href="font.woff2" as="font" crossorigin>` |
| 预获取 | `<link rel="prefetch" href="next-page.js">` |
| 懒加载 | `<img loading="lazy" src="image.jpg">` |

### 缓存策略

| 头部 | 作用 |
|------|------|
| Cache-Control | 缓存指令（max-age, no-cache, no-store） |
| ETag | 资源指纹 |
| Last-Modified | 最后修改时间 |
| If-None-Match | 条件请求（配合 ETag） |
| If-Modified-Since | 条件请求（配合 Last-Modified） |

```
强缓存: Cache-Control: max-age=31536000
协商缓存: Cache-Control: no-cache + ETag
不缓存: Cache-Control: no-store
```

## 性能优化

### 关键指标

| 指标 | 含义 | 目标 |
|------|------|------|
| FCP | 首次内容绘制 | < 1.8s |
| LCP | 最大内容绘制 | < 2.5s |
| FID | 首次输入延迟 | < 100ms |
| CLS | 累积布局偏移 | < 0.1 |
| TTFB | 首字节时间 | < 800ms |

### 渲染优化

- 减少 DOM 操作（批量更新）
- 使用 DocumentFragment
- 使用虚拟滚动（大列表）
- CSS 动画用 transform/opacity
- 避免强制同步布局

```javascript
const fragment = document.createDocumentFragment();
items.forEach(item => {
    const li = document.createElement('li');
    li.textContent = item.name;
    fragment.appendChild(li);
});
list.appendChild(fragment);
```

### 代码分割

```javascript
const LazyComponent = React.lazy(() => import('./HeavyComponent'));

function App() {
    return (
        <Suspense fallback={<Spinner />}>
            <LazyComponent />
        </Suspense>
    );
}
```

### 图片优化

- 使用 WebP/AVIF 格式
- 响应式图片：`<picture>` + `srcset`
- 懒加载：`loading="lazy"`
- CDN 加速

```html
<picture>
    <source srcset="image.avif" type="image/avif">
    <source srcset="image.webp" type="image/webp">
    <img src="image.jpg" alt="description" loading="lazy"
         width="800" height="600">
</picture>
```
