## 任务 1：修复鱼骨图连线问题并优化显示

### 问题分析

当前鱼骨图（`updateTree` 函数）存在以下问题：

1. **连线起点/终点计算不准确**：`fishLinkPath` 函数中使用 `_fishBubbleX` 和 `_fishBubbleW` 计算气泡边缘，但这些值在首次渲染时可能还未设置（默认为 0 和 60），导致连线位置偏移
2. **根节点连线逻辑**：当 `d.source.depth === 0` 时使用圆弧路径，但圆弧半径 `r=8` 在节点间距较大时显得太小，视觉效果不佳
3. **非根节点连线**：使用简单的直角折线 `H midX V ty H tgtEdge`，缺乏视觉美感
4. **节点重叠**：`leafGap=42` 和 `levelGap=160` 在某些情况下仍然不够，特别是 summary 节点较多时

### 实施步骤

1. **修复连线计算时序问题**：
   - 在 `renderFishNodes` 中先计算所有节点的气泡尺寸和位置
   - 然后再计算连线路径，确保 `_fishBubbleX/W/H` 已正确设置
   - 具体做法：将 `renderFishNodes` 拆分为两步——先设置气泡尺寸，再渲染连线

2. **优化根节点连线**：
   - 增大圆弧半径 `r` 从 8 到 16，使转弯更平滑
   - 使用三次贝塞尔曲线替代二次贝塞尔曲线，使连线更流畅
   - 根节点连线从气泡边缘出发，不穿过气泡

3. **优化非根节点连线**：
   - 使用平滑的 S 形曲线替代直角折线
   - 添加中间控制点使连线更自然
   - 连线颜色使用父节点颜色，透明度 0.4

4. **优化节点间距**：
   - 动态计算 `leafGap`：根据叶子节点的文字长度调整间距
   - summary 节点使用更小的 `leafGap`
   - `levelGap` 从 160 调整为 180，给予更多水平空间

## 任务 2：手绘图样式修改为 Excalidraw 手绘风格

### 问题分析

当前 `updateSketch` 函数已实现基本的 Excalidraw 风格，但存在以下不足：

1. **Virgil 字体加载不稳定**：使用 `https://excalidraw.com/Virgil.woff2` 可能因跨域问题加载失败
2. **弧形边框抖动不够自然**：`excalidrawRect` 的 jitter 值较小（1.5-2），看起来不够"手绘"
3. **斜线填充（hachure）密度和角度不够自然**：当前 gap=6，angle=-45°，看起来过于规律
4. **连线风格**：当前使用 `excalidrawPolyline` 拼接多段曲线，在转弯处不够平滑
5. **配色方案**：当前使用与其他布局相同的配色，Excalidraw 通常使用更柔和、更淡的颜色

### 实施步骤

1. **优化字体加载**：
   - 添加 Virgil 字体的 fallback：先尝试 CDN，失败后使用本地 cursive
   - 添加字体加载状态检测，加载完成前使用备用字体
   - 可选：将 Virgil.woff2 下载到本地 `fonts/` 目录

2. **增强手绘边框效果**：
   - 增大 `excalidrawRect` 的 jitter 值：从 1.5-2 增加到 2-4
   - 添加边框的"重叠"效果：在矩形角落处稍微多画一点，模拟手绘时的笔触重叠
   - 为不同深度的节点使用不同的抖动程度（深层节点抖动更大）

3. **优化斜线填充**：
   - 增大 hachure gap 从 6 到 8-10，使填充更稀疏自然
   - 为每条斜线添加随机偏移，避免过于平行
   - 斜线角度添加随机变化（±5°）
   - 根节点使用更密集的填充，叶子节点使用更稀疏的填充

4. **优化连线风格**：
   - 使用单条三次贝塞尔曲线替代多段拼接
   - 连线添加轻微的弯曲和抖动
   - 连线粗细根据深度递减

5. **调整配色方案**：
   - Excalidraw 风格使用更柔和的颜色（降低饱和度 20%）
   - 边框颜色比填充颜色更深
   - 文字颜色使用深灰色而非纯黑/纯白
   - 添加微妙的阴影效果（SVG filter）

## 任务 3：提取 details 中的 summary 作为子节点

### 问题分析

当前 `parseHeadings` 函数已实现 summary 解析，但存在以下问题：

1. **summary 层级计算**：当前 `level2 = lastHeadingLevel + 1`，这意味着 summary 的层级取决于上方最近的标题。但 H4 下的 summary 应该是 H5 级别，而当前代码将其设为 H4+1=H5，这是正确的
2. **summary 节点在树中的挂载**：`buildHeadingTree` 使用栈结构，summary 作为子节点挂载到上方最近的标题下，这是正确的
3. **summary 节点的视觉区分**：当前使用 `isSummary` 标记，在渲染时有不同的 padding 和圆角，但区分度不够明显
4. **summary 内容获取**：`getSectionContent` 已支持获取 details 内的内容

### 实施步骤

1. **验证 summary 解析逻辑**：
   - 确认 `<summary>` 标签的正则匹配覆盖所有格式（包括带空格、多行等情况）
   - 添加对 `<details>` 标签内嵌套 `<summary>` 的支持
   - 处理 summary 文本中的特殊字符（如 `&`、`<`、`>` 等 HTML 实体）

2. **优化 summary 节点在树中的显示**：
   - summary 节点使用更小的气泡和字体
   - 添加小图标（如 📄 或 ◻）标识 summary 节点
   - summary 节点的连线使用虚线或更细的线
   - summary 节点气泡使用不同的形状（如圆角更大的矩形，接近椭圆形）

3. **优化 summary 内容弹窗**：
   - 点击 summary 节点时，优先尝试从 mybook 加载对应 md 文件（任务 4）
   - 如果加载失败，显示 ALL.md 中 details 内的内容
   - 弹窗标题显示 summary 文本，面包屑显示完整路径

4. **处理特殊情况**：
   - H3 下直接包含 summary（如 "6.3 云与容器安全"）的情况
   - summary 文本与 H4 文本相同的情况（如 "4.1 语言基础 > 基础语法 > 基础语法"）

## 任务 4：跳转最后一级节点点击打开 mybook 对应 markdown 文档

### 问题分析

这是最复杂的任务。当前 `resolveMdPath` 函数存在严重问题：

1. **文件名不匹配**：mybook 中的文件名带有数字前缀（如 `2_数据类型.md`），而当前代码直接使用 summary 文本作为文件名（如 `数据类型.md`）
2. **文件名与 summary 文本不完全对应**：
   - summary "GMP 调度模型" → 文件 "7_Golang协程调度器原理-GMP模型.md"
   - summary "Goroutine & Channel" → 文件 "9_并发.md"
   - summary "包-模块-库" → 文件 "11_包-模块-库.md"
3. **H4 层级不对应目录**：ALL.md 中的 H4（如"基础语法"、"工程实践"）在 mybook 中没有对应的子目录
4. **目录结构差异**：不同类别（go/cpp/python/web 等）的目录命名规则不同

### 解决方案

由于文件名与 summary 文本之间的映射关系复杂且不统一，最佳方案是**构建一个完整的映射表**，手动或半自动地将每个 summary 映射到对应的文件路径。

### 实施步骤

1. **构建 summary → 文件路径映射表**：
   - 创建 `summaryFileMap` 对象，key 为 summary 的 slug，value 为相对于 mybook 的文件路径
   - 扫描 mybook 各目录，为每个 summary 找到对应的 md 文件
   - 对于无法精确匹配的，使用模糊匹配或手动指定

2. **重写 `resolveMdPath` 函数**：
   - 首先在 `summaryFileMap` 中查找精确匹配
   - 如果未找到，尝试在对应子目录中模糊匹配文件名
   - 如果仍未找到，返回 null

3. **实现多路径尝试机制**：
   - 对于每个 summary，生成多个可能的文件路径
   - 按优先级依次尝试 fetch
   - 第一个成功的路径即为正确路径
   - 缓存已验证的路径，避免重复尝试

4. **优化弹窗显示**：
   - 成功加载 mybook 文件时，显示"打开源文件"链接
   - 链接使用 `file://` 协议指向本地文件
   - 同时保留 ALL.md 内容作为 fallback
   - 弹窗中显示文件路径信息

5. **具体映射规则**（按类别）：

   **Go 类** (`go/`)：
   - H3 "1.1 语言基础" → `go/1_语言基础/`
   - H3 "1.3 并发编程（重点）" → `go/3_并发编程/`
   - H3 "1.4 内存管理（重点）" → `go/4_内存管理/`
   - H3 "1.6 常用标准库" → `go/6_常用标准库/`
   - H3 "1.7 常用框架" → `go/7_常用框架/`
   - summary "数据类型" → `2_数据类型.md`
   - summary "函数与方法" → `4_函数.md`
   - summary "接口" → `7_接口.md`
   - summary "GMP 调度模型" → `7_Golang协程调度器原理-GMP模型.md`

   **C/C++ 类** (`cpp/`)：
   - H3 "2.1 C语言教程" → `cpp/C语言教程/`
   - H3 "2.2 C++专题" → `cpp/C++专题/`
   - H4 "基础语法" → `cpp/C++专题/基础语法/`
   - H4 "现代特性" → `cpp/C++专题/现代特性/`

   **Python 类** (`python/`)：
   - H3 "3.1 语言基础" → `python/1_语言基础/`
   - H3 "3.6 Web开发" → `python/6_Web开发/`

   **Web 类** (`web/`)：
   - H3 "5.1 前端基础" → `web/1_前端基础/`
   - H3 "5.2 前端框架" → `web/2_前端框架/`

   **通用基础类** (`general`)：
   - H3 "7.1 数据结构与算法" → `algorithms/`
   - H3 "7.2 操作系统 & Linux" → `os-linux/`（需确认实际目录名）
   - H3 "7.3 架构设计" → `architecture/`
   - H3 "7.4 DevOps & 基础设施" → `devops/`
   - H3 "7.5 智能体开发" → `agents/`

6. **实现文件路径模糊匹配**：
   - 在已知子目录下，遍历所有 .md 文件名
   - 去除文件名中的数字前缀（如 `2_数据类型.md` → `数据类型`）
   - 与 summary 文本进行相似度比较
   - 相似度超过阈值的视为匹配成功
   - 由于浏览器无法列出目录内容，需要预先生成文件列表嵌入代码中

## 风险与注意事项

1. **跨域问题**：从 onlinenote 目录 fetch mybook 目录的文件可能遇到跨域限制，需要通过本地 HTTP 服务器访问
2. **字体加载**：Virgil 字体从 excalidraw.com 加载可能不稳定，建议下载到本地
3. **映射表维护**：summary → 文件路径的映射表需要随 ALL.md 和 mybook 目录的变化更新
4. **性能**：大量节点的鱼骨图布局计算可能较慢，需要优化算法
