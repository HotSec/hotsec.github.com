# 安全产品规则库

## 一、降噪规则（Aviator 规则）

### 1.1 概述

降噪规则用于在海量安全告警中过滤误报、低风险、重复事件，使安全运营人员聚焦真正有价值的攻击事件。Aviator 是 Google 内部的安全自动化平台，其降噪策略已成为业内最佳实践。

### 1.2 降噪维度

- **资产维度**：基于资产重要性分级（核心资产/普通资产/测试资产）
- **攻击链维度**：根据攻击阶段（侦察/武器化/投递/利用/安装/C2/目的达成）评估风险
- **情报维度**：结合威胁情报交叉验证告警真实性
- **环境维度**：匹配目标系统的实际版本、配置、补丁状态

### 1.3 降噪策略

| 策略 | 描述 | 示例 |
|------|------|------|
| 白名单 | 明确安全的 IP/域名/操作 | 内部安全扫描器 IP |
| 抑制规则 | 已知误报模式的过滤 | 某些中间件的正常心跳请求 |
| 阈值规则 | 单次触发忽略、多次触发升级 | 单次登录失败 vs 1分钟内 100 次 |
| 资产感知 | 非受影响版本不告警 | CVE-2024-xxx 仅影响 nginx <1.26，对 1.26+ 抑制 |
| 时间窗口 | 有限时间内聚合告警 | 同一源 IP 的同类告警 5 分钟内合并为一条 |

### 1.4 降噪效果评估指标

- **降噪比（NRR）**：降噪后告警数 / 原始告警数
- **真阳性率（TPR）**：正确告警中未被误过滤的比例
- **误过滤率**：真实攻击被错误降噪的比例，理想值为 0

## 二、Suricata 规则

### 2.1 Suricata 规则概述

Suricata 是高性能的网络 IDS/IPS/NSM 引擎，通过规则匹配网络流量中的恶意模式。规则语法兼容 Snort，支持多线程检测。

### 2.2 规则基本结构

```
action protocol src_ip src_port direction dst_ip dst_port (rule_options)
```

- **action**：alert / drop / pass / reject
- **protocol**：tcp / udp / icmp / http / dns / tls / smb 等
- **direction**：`->` 单向 / `<>` 双向

### 2.3 常用规则选项

#### 内容匹配

| 关键字 | 说明 |
|--------|------|
| `content` | 匹配负载中的字节序列（支持 `!` 取反） |
| `nocase` | 不区分大小写 |
| `depth` | 从起始搜索的深度 |
| `offset` | 从指定偏移开始搜索 |
| `distance` | 距前一个 content 的偏移 |
| `within` | 在前一个 content 后 N 字节内匹配 |
| `pcre` | Perl 兼容正则表达式 |

#### 元数据

| 关键字 | 说明 |
|--------|------|
| `msg` | 告警描述信息 |
| `sid` | 规则唯一 ID（\<1000000 为保留/Sourcefire，>=1000000 为本地） |
| `rev` | 规则修订版本 |
| `reference` | CVE / URL 等外部参考 |
| `classtype` | 告警分类 |
| `priority` | 优先级（1=最高） |
| `metadata` | 自定义元数据（如 `created_at`、`signature_severity`） |

#### 流与阈值

| 关键字 | 说明 |
|--------|------|
| `flow` | 流向控制：`to_server` / `to_client` / `established` |
| `flowbits` | 跨数据包状态跟踪 |
| `threshold` | 告警阈值（`limit`/`threshold`/`both` + `count`/`seconds`/`track`） |
| `detection_filter` | 检测过滤 |

#### 协议感知关键字

| 关键字 | 说明 |
|--------|------|
| `http_uri` / `http_method` / `http_user_agent` | HTTP 特定字段匹配 |
| `dns_query` | DNS 查询域名匹配 |
| `tls_sni` / `tls.subject` / `tls.issuerdn` | TLS 证书信息匹配 |
| `app-layer-protocol` | 指定应用层协议 |

### 2.4 规则示例

**检测 CVE-2021-44228（Log4Shell）：**
```
alert http $EXTERNAL_NET any -> $HOME_NET $HTTP_PORTS (
    msg:"EXPLOIT Apache Log4j Log4Shell RCE Attempt (CVE-2021-44228)";
    content:"${jndi:"; nocase; fast_pattern;
    http_uri; pcre:"/\$\{jndi:(ldap[s]?|rmi|dns)\:/Ui";
    reference:cve,2021-44228;
    classtype:attempted-admin;
    sid:1000001; rev:1;
)
```

**检测 DNS 隧道：**
```
alert dns $HOME_NET any -> any any (
    msg:"Potential DNS Tunneling";
    dns_query; content:".xyz"; nocase;
    pcre:"/^[a-zA-Z0-9]{30,}\.xyz$/";
    threshold:type limit, track by_src, count 10, seconds 60;
    classtype:policy-violation;
    sid:1000002; rev:1;
)
```

### 2.5 规则管理

- **规则来源**：ET Open / ET Pro / VRT / Snort Community / 自定义
- **更新机制**：`suricata-update` 工具自动拉取更新
- **规则测试**：`suricata -T` 语法检查 / `suricata --engine-analysis` 性能分析
- **性能调优**：使用 `fast_pattern` 加速 / 避免深度 PCRE 嵌套 / 合理设置 `depth` 和 `offset`

## 三、Falco 规则

### 3.1 Falco 规则概述

Falco 是 CNCF 毕业的云原生运行时安全项目，通过内核模块/eBPF 监控系统调用，基于规则检测异常行为。

### 3.2 规则语法

```yaml
- rule: <规则名称>
  desc: <规则描述>
  condition: <触发条件（Falco 条件语法）>
  output: <告警输出格式（支持 %变量）>
  priority: <EMERGENCY|ALERT|CRITICAL|ERROR|WARNING|NOTICE|INFO|DEBUG>
  tags: [tag1, tag2, ...]
  enabled: true|false
```

### 3.3 条件语法

#### 事件类型

- `syscall` 类型：`open` / `openat` / `execve` / `connect` / `accept` / `ptrace`
- 所有系统事件：`evt.type=<syscall_name>`

#### 条件运算符

| 运算符 | 说明 | 示例 |
|--------|------|------|
| `and` / `or` / `not` | 逻辑运算 | `evt.type=open and fd.name=/etc/shadow` |
| `=` / `!=` / `<` / `>` | 比较 | `proc.cmdline != bash` |
| `in` | 范围匹配 | `proc.cmdline in (bash, zsh)` |
| `contains` | 字符串包含 | `fd.name contains /etc/` |
| `startswith` / `endswith` | 前缀/后缀 | `proc.name startswith python` |
| `pmatch` | 路径前缀匹配 | `fd.name pmatch (/etc, /root/)` |
| `exists` | 字段非空 | `proc.vpid exists` |
| `glob` | glob 模式 | `fd.name glob /home/*/.ssh/*` |
| `intersects` | 集合交集 | `proc.env intersects (HTTP_PROXY)` |

#### 常用输出字段

| 字段 | 说明 |
|------|------|
| `%evt.time` | 事件时间戳 |
| `%evt.type` | 事件类型 |
| `%proc.name` | 进程名 |
| `%proc.cmdline` | 完整命令行 |
| `%proc.pid` / `%proc.ppid` | 进程 / 父进程 ID |
| `%user.name` / `%user.uid` | 用户名 / UID |
| `%fd.name` | 文件描述符名称 |
| `%container.id` / `%container.name` | 容器 ID / 名称 |
| `%k8s.ns.name` / `%k8s.pod.name` | Kubernetes 命名空间 / Pod 名称 |
| `%fd.cip` / `%fd.sip` | 客户端 / 服务端 IP |
| `%fa.rip` | 远程 IP |

### 3.4 宏（Macros）与列表（Lists）

```yaml
# 列表：定义一组可复用的值
- list: shell_binaries
  items: [bash, zsh, sh, dash, ash]

- list: sensitive_files
  items: [/etc/shadow, /etc/sudoers, /root/.ssh/authorized_keys]

# 宏：定义可复用的条件片段
- macro: spawned_process
  condition: evt.type in (execve, execveat)

- macro: is_shell
  condition: proc.name in (shell_binaries)

- macro: sensitive_mount
  condition: evt.type=openat and fd.name startswith /proc/self/ and fd.name contains /
```

### 3.5 典型规则示例

**检测容器内敏感文件读取：**
```yaml
- rule: Read Sensitive File Inside Container
  desc: 检测容器内读取 /etc/shadow 等敏感文件
  condition: >
    open_read
    and container
    and fd.name in (sensitive_files)
  output: >
    敏感文件被读取 (user=%user.name
    container=%container.name file=%fd.name
    cmdline=%proc.cmdline)
  priority: WARNING
  tags: [container, filesystem, mitre_credential_access]
```

**检测非预期网络连接：**
```yaml
- rule: Unexpected Outbound Connection
  desc: 检测进程发起非预期的外部连接
  condition: >
    evt.type=connect
    and evt.dir=<
    and container
    and fd.sport != 443
    and not proc.name in (curl, wget, apt, yum)
    and not fd.sip.name in (allowed_destinations)
  output: >
    非预期外部连接 (cmdline=%proc.cmdline
    destination=%fd.sip:%fd.sport)
  priority: NOTICE
  tags: [network, container]
```

**检测容器逃逸尝试：**
```yaml
- rule: Container Escape Attempt
  desc: 检测 mount 敏感目录的容器逃逸行为
  condition: >
    sensitive_mount
    and container
    and proc.name != falco
    and proc.name != symlink
  output: >
    容器逃逸尝试 (user=%user.name
    container=%container.name
    proc=%proc.name file=%fd.name)
  priority: CRITICAL
  tags: [container, mitre_privilege_escalation]
```

### 3.6 规则管理

- **默认规则**：`/etc/falco/falco_rules.yaml`
- **本地规则**：`/etc/falco/falco_rules.local.yaml`
- **规则热加载**：`kill -1 $(cat /var/run/falco.pid)`
- **规则覆盖**：`append: true` 追加 / 重新定义 `condition` 覆盖
- **规则禁用**：`enabled: false` 或使用 `-D <pattern>` 启动参数

## 四、复杂事件关联规则（Sigma 规则）

### 4.1 Sigma 规则概述

Sigma 是通用的 SIEM 检测规则格式，一份规则可转换为多种 SIEM 平台的查询语言（Splunk / Elastic / QRadar / Sentinel 等），实现"write once, run anywhere"。

### 4.2 规则结构

```yaml
title: <规则标题>                        # 必填
id: <UUID>                               # 必填，全局唯一标识
status: stable|test|experimental|deprecated  # 必填
description: <描述>                       # 必填
references:                               # 可选，外部参考
  - https://attack.mitre.org/techniques/Txxxx
author: <作者>
date: <YYYY/MM/DD>
modified: <YYYY/MM/DD>
tags:                                     # 可选，分类标签
  - attack.txxxx
  - attack.command_and_control
  - detection.emerging_threats
logsource:                                # 必填，日志源
  category: process_creation
  product: windows
  service: security
detection:                                # 必填，检测逻辑
  selection:
    EventID: 4688
    CommandLine|contains: 'whoami'
  condition: selection
falsepositives:                           # 可选，已知误报场景
  - 运维脚本定期执行
level: low|medium|high|critical           # 必填
```

### 4.3 字段修饰符

| 修饰符 | 说明 | 示例 |
|--------|------|------|
| `|contains` | 字符串包含 | `CommandLine|contains: 'mimikatz'` |
| `|startswith` / `|endswith` | 前缀/后缀 | `Image|endswith: '\powershell.exe'` |
| `|re` | 正则匹配 | `CommandLine|re: '.* -enc [A-Za-z0-9+/=]{100,}'` |
| `|all` / `|base64` | 全部匹配/base64编码 | `CommandLine|base64: 'ZWNobyBoZWxsbw=='` |
| `|windash` | 将 `/` 统一为 `\` | `Image|windash: '\system32\cmd.exe'` |
| `|cidr` | CIDR 网络匹配 | `SourceIp|cidr: '10.0.0.0/8'` |
| `|expand` | 环境变量展开 | `CommandLine|expand: '%TEMP%\test.exe'` |

### 4.4 检测条件组合

```yaml
detection:
  # 基础选择器
  selection_base:
    EventID: 4688
  # 选择器可以多个
  selection_powershell_enc:
    CommandLine|contains|all:
      - '-enc'
      - 'powershell'
  selection_suspicious_parent:
    ParentImage|endswith:
      - '\winword.exe'
      - '\excel.exe'
  # 组合条件
  condition: >
    selection_base
    and (selection_powershell_enc or selection_suspicious_parent)
    and not filter_legitimate
  # 白名单/过滤
  filter_legitimate:
    User|contains: 'NT AUTHORITY\SYSTEM'
```

### 4.5 关联规则

Sigma 支持跨时间窗口的事件关联：

```yaml
correlation:
  type: event_count             # 关联类型
  rules:                        # 关联的规则 ID 列表
    - 07ec3b07-f227-4c11-92e5-5017cda5c0f2
    - 6e4e6f7c-0fde-4eb0-8ab1-58663df3d982
  group-by:                     # 分组字段
    - ComputerName
    - User
  timespan: 5m                  # 时间窗口
  condition:
    count >= 3                  # 阈值条件
```

### 4.6 典型规则示例

**检测 PowerShell 编码执行：**
```yaml
title: PowerShell Encoded Command Execution
id: 8f70e5e2-7a3f-4c84-85d4-65a39c2f5a2c
status: stable
description: 检测 PowerShell 通过 -EncodedCommand 执行混淆命令
logsource:
  category: process_creation
  product: windows
detection:
  selection:
    Image|endswith: '\powershell.exe'
    CommandLine|contains: '-EncodedCommand'
  condition: selection
level: medium
tags:
  - attack.execution
  - attack.t1059.001
```

**检测 Linux 反向 Shell：**
```yaml
title: Linux Reverse Shell
id: a1b2c3d4-e5f6-7890-abcd-ef1234567890
description: 检测通过 /dev/tcp 或 nc 建立的反向 Shell
logsource:
  category: process_creation
  product: linux
detection:
  dev_tcp:
    CommandLine|re: '.*bash.*/dev/tcp/[0-9.]+/[0-9]+'
  nc_reverse:
    CommandLine|contains|all:
      - 'nc '
      - '-e '
      - '/bin'
  condition: dev_tcp or nc_reverse
falsepositives:
  - 管理员调试
level: high
tags:
  - attack.execution
  - attack.t1059.004
```

### 4.7 转换引擎（Sigma CLI）

```bash
# 安装
pip install sigma-cli

# 转换为 Splunk 查询
sigma convert -t splunk rule.yml

# 转换为 Elastic 查询
sigma convert -t es-qs rule.yml

# 转换为 Sentinel KQL
sigma convert -t sentinel-rule rule.yml
```

## 五、情报规则

### 5.1 威胁情报规则概述

威胁情报规则基于外部情报源（IOC 情报、TTP 情报、行业情报）对安全事件进行匹配和告警。情报类型包括 IP/域名/URL/Hash/邮件/ATT&CK 技术等。

### 5.2 情报类型（IOC）

| 类型 | 示例 | 描述 |
|------|------|------|
| IP | `185.130.5.253` | C2 服务器 / 扫描源 / 恶意代理 |
| Domain | `evil.example.com` | 钓鱼域名 / DGA 域名 |
| URL | `http://evil.com/malware.exe` | 恶意软件下载地址 |
| Hash | MD5 / SHA1 / SHA256 | 恶意文件哈希 |
| Email | `phish@evil.com` | 钓鱼邮件发件人 |
| SSL Cert | 证书指纹/序列号 | 恶意证书 |
| User-Agent | 特定 UA 字符串 | 恶意工具特征 |
| ATT&CK | T1059 / T1055 / T1003 | 攻击技术标识 |
| YARA Rule | 恶意软件特征规则 | 文件/内存检测 |

### 5.3 情报来源分类

- **开源情报（OSINT）**：AlienVault OTX / MalShare / URLhaus / ThreatFox / Feodo Tracker / SSL Blacklist
- **商业情报**：Recorded Future / FireEye / CrowdStrike / Mandiant
- **行业情报**：ISAC（行业信息共享分析中心）/ CERT 通报
- **内部情报**：历史事件 IOC / 蜜罐数据 / Red Team 演练数据

### 5.4 情报规则集成示例

#### Suricata 集成威胁情报

```
# 使用 Suricata 的 iprep 功能
alert ip any any -> any any (
    msg:"Traffic to Known Malicious IP";
    iprep:dst,>,6;
    classtype:trojan-activity;
    reference:url,feodotracker.abuse.ch;
    sid:1000003; rev:1;
)

# 使用 dataset 规则集匹配恶意域名
alert dns any any -> any any (
    msg:"DNS Query to Malicious Domain";
    dns.query; dataset:isset,malicious_domains,type string,load domain_list.txt;
    classtype:trojan-activity;
    sid:1000004; rev:1;
)
```

#### Falco 集成威胁情报

```yaml
- rule: Outbound Connection to Threat Intel IP
  desc: 检测到与威胁情报中恶意 IP 的通信
  condition: >
    evt.type=connect
    and evt.dir=<
    and fd.sip in (threat_intel_ip_list)
  output: >
    连接到威胁情报IP (ip=%fd.sip:%fd.sport
    process=%proc.cmdline)
  priority: CRITICAL
  tags: [network, threat_intel]
```

#### Sigma 集成情报

```yaml
title: Suspicious Process Communicating with Malicious IP
logsource:
  category: firewall
detection:
  selection:
    dst_ip:
      - 185.130.5.253
      - 95.215.44.77
      - 156.146.45.178
  condition: selection
```

### 5.5 情报生命周期

| 阶段 | 描述 | 关键活动 |
|------|------|----------|
| 收集 | 从多种来源获取原始情报 | API 拉取 / 爬虫 / 邮件列表 |
| 处理 | 去重、标准化、富化 | 格式统一 / 添加上下文 / 关联分析 |
| 评估 | 评估情报质量和可信度 | 时效性 / 来源可信度 / 相关性评分 |
| 分发 | 推送到检测系统 | 自动化推送 / 规则更新 |
| 反馈 | 收集检测效果反馈 | 真阳性率 / 误报率 / 情报功效评估 |

### 5.6 情报质量评估维度

- **时效性（Timeliness）**：情报从产生到可用的时间差，IOC 有效期通常 7-30 天
- **准确性（Accuracy）**：情报的误报率和真阳性率
- **相关性（Relevancy）**：与本组织资产、行业的匹配度
- **完整性（Completeness）**：情报附带的上下文信息是否充分
- **可操作性（Actionability）**：情报能否直接转化为检测规则或防护措施

## 六、规则工程最佳实践

### 6.1 规则开发流程

1. **需求分析**：确认要检测的攻击场景 / TTP
2. **数据收集**：获取攻击样本、正常流量基线
3. **规则编写**：按对应格式编写规则
4. **测试验证**：
   - 阳性测试：确保能检测攻击样本
   - 阴性测试：确保不误报正常流量
   - 压力测试：确保不影响系统性能
5. **灰度上线**：先在少量机器观察，再全量部署
6. **持续优化**：根据误报/漏报反馈迭代

### 6.2 规则管理规范

- 每个规则必须有唯一 ID、描述、参考来源
- 分类标签统一使用 MITRE ATT&CK
- 定期清理过期/失效规则
- 版本管理：使用 Git 管理规则库，记录变更历史
- CI/CD 集成：规则变更自动语法检查 → 自动化测试 → 灰度发布

### 6.3 常见问题

| 问题 | 表现 | 解决方案 |
|------|------|----------|
| 规则膨胀 | 规则数量过多，无法维护 | 合并相似规则，使用正则/macro 泛化 |
| 告警风暴 | 规则触发大量告警 | 添加阈值（threshold）/ 降噪规则 |
| 性能退化 | 规则影响检测引擎性能 | 优化 content/PCRE，使用 fast_pattern |
| 规则过时 | 老规则无法检测新变种 | 定期评审，社区同步最新规则 |
